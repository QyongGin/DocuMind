# 용어집 (glossary)

> 문서·코드·대화에서 한 개념에 한 이름만 쓴다. 새 용어를 만들거나 바꿀 때는 이 표를 먼저 고친다. 2026-10-08 평가셋 용어를 실무 용어로 통일했다(코드는 PR #143, 보고서 `docs/rag/m1/평가셋-용어-통일-20261008.md`).

## 평가셋

| 용어 | 영어 | 뜻 | 코드·데이터 이름 | 예전 이름 |
|---|---|---|---|---|
| 평가셋 | evaluation set | 챗봇 품질을 재는 질문·정답 묶음 | `Assets/eval/evalset.jsonl` | — |
| 평가셋 파일 | — | 평가셋 문항을 한 줄씩 쓴 JSONL 파일(학교 글이라 git 제외) | `schema.py` | 정본 |
| 정답 | ground truth | 문항마다 적은 정답 문장·필수 사실·금지 값·근거 | `answer`·`facts`·`forbidden`·`evidence` | 정답지 |
| 필수 사실 / 허용 표기 | required facts | 답에 꼭 들어가야 하는 값과 같은 뜻의 다른 표기 | `facts[].values` | — |
| 금지 값 | forbidden value | 답에 나오면 틀림으로 치는 값(지난해 값·옆 칸 값 등) | `forbidden` | — |
| 답 유형 | answer type | 값·목록·절차·예아니오·설명·답없음 중 하나 | `shape` | 답의 모양 |
| 태그 | tag | 집계용 표시(표 근거, 연도 시험 등) | `tags` | 꼬리표 |
| 답 없는 문항 | unanswerable question | 문서에 답이 없어 "확인할 수 없다"고 해야 맞는 문항 | `shape: "답없음"`, `unanswerable` | 거절 문항 |
| 부재 확인 | absence check | 답 없는 문항이 정말 답이 없는지 색인 전체를 검색한 기록 | `unanswerable.check` | — |
| 자동 검증 | automated validation | 사람이 보기 전에 형식·인용·근거 문서·중복을 프로그램이 거르는 단계 | `evalset validate`, `validation` | 기계 검사 |
| 독립 이중 라벨링 | independent double annotation | 정답을 만든 세션과 분리된 세션이 정답 없이 같은 질문에 답해 비교하는 것 | `evalset double-annotate`, `second_annotation` | 교차 확인 |
| 불일치 판정 | adjudication | 이중 라벨링 결과가 다르면 사람이 어느 쪽이 맞는지 정하는 것 | `review_reason: "불일치"` | — |
| 세션 격리 | session isolation | 이중 라벨링 세션이 작업 폴더 밖(정답)을 못 읽게 막는 것 | `evalset isolation-test` | 폴더 밖 차단 |
| 작업 단위 | packet | 이중 라벨링 세션 하나에 주는 질문·원본 묶음 | `Packet` | 꾸러미 |
| 규칙 기반 채점 | rule-based scoring | 금지 값·필수 사실·답 없음 규칙으로 맞음·일부·모름·틀림·애매를 매김 | `scoring.score`, `evalset score` | 규칙 판정 |
| 거절(답변 거절) | abstention | 챗봇이 "확인할 수 없다"고 답하는 것 | `score()`의 `abstained` | — |
| 휴먼 리뷰 | human review | 사람이 꼭 볼 문항만 리뷰 화면에서 판정하는 것 | `evalset select-review`, `review_reason`, `review` | 검수, 꼭 볼 문항 |
| 리뷰 화면 / 리뷰 기록 / 병합 | review UI / review log / merge | 판정용 HTML, 판정 결과 JSONL, 평가셋 파일에 반영 | `evalset review-html`, `evalset merge` | 검수 화면 / 검수 기록 / 합치기 |
| 개발셋 / 테스트셋 | dev set / test set (held-out) | 고칠 때 열어 보는 몫 / 정해진 때 점수만 재는 몫 | `part: "dev"` / `"test"` | 개발용·확인용 → 연습용·실전용 |
| 분할 | split | 문서 묶음 단위로 개발셋 60 : 테스트셋 40 | `evalset split` | 나누기 |
| 버전 고정 | freeze | 리뷰가 끝난 평가셋에 버전과 SHA-256을 매겨 잠금 | `evalset freeze` | 고정 |
| 베이스라인 | baseline | 비교의 출발점이 되는 첫 측정 점수 | — | 기준점 |

## 문서·색인

| 용어 | 영어 | 뜻 | 코드·데이터 이름 |
|---|---|---|---|
| 문서 대장 | document registry | 수집한 파일마다 출처·형식·용도·개인정보 상태를 적은 SQLite | `Assets/corpus/ledger.sqlite` |
| 문서 묶음 | document group | 같은 글의 판·첨부를 묶은 단위(분할·용도 고정의 단위) | `group_id` |
| 평가 몫 / 학습 몫 | eval split / train split | 문서 묶음 단위로 고정한 용도 | 대장·평가셋 파일의 `split` |
| 색인 | index | 챗봇이 검색하는 Chroma·BM25 데이터 | — |
| 청크 | chunk | 색인에 넣는 글 조각 | — |
| 표 사실 | table fact | 표의 한 칸을 행·열 이름과 함께 풀어 쓴 검색용 문장 | `chunk_role: table_fact` |
