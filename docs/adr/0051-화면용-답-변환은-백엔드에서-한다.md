# ADR-0051: 화면용 답 변환은 백엔드에서 한다 — AI 서버는 모델 원문을 그대로 내고, 참고한 문서에 쓸 대장 정보는 백엔드 문서 테이블에 둔다

- 상태: 채택
- 날짜: 2026-11-02
- 관련: ADR-0050(사용자 화면 답 모양 — 결정 2·3·5·6의 '서버'를 백엔드로 정함), ADR-0024(CI), 이슈 #204(7단계 상위)·#205, `docs/rag/m2/1회차-준비-작업계획-20261101.md` 7단계

## 맥락

- [실측] 답이 화면까지 가는 길: AI 서버 `/query/stream`이 모델 답을 글자 그대로 흘려보내고 끝에 검색 후보 8개를 보낸다. 백엔드는 후보에 업로드 시각·파일 크기를 붙여 대화 기록에 저장하고 전달한다(`SourceDocumentMetadataEnricher`). 화면은 흐르는 답을 보이다가 끝에 백엔드가 보낸 최종 답으로 바꾸고, 후보 8개를 청크 미리보기와 함께 보인다(`ChatPage.jsx`).
- [실측] 평가 실행기(`tools/corpus` `evalset run`)는 백엔드를 거치지 않고 AI 서버 `/query`를 직접 부른다. 1회차 작업 계획 7단계는 평가를 화면용으로 바꾸기 전 모델 원문으로 채점하게 한다(출처 번호로 근거를 확인한다).
- [실측] 참고한 문서에 필요한 사이트·게시판·게시글 제목·첨부의 부모 게시글은 문서 테이블(`documents`)에도 색인 메타데이터에도 없다. 있는 것은 대장 ID, 원문 주소, 게시일, 학년도, 파일 이름이다. 서비스 색인 문서 700개 중 첨부 73개(부모 게시글이 대장에 있는 것 41개).
- [실측] 백엔드에는 관리자 역할(ADMIN)과 대화 기록(`chat_messages`)이 있다.

## 결정

2026-11-02 결정.

1. ADR-0050의 화면용 변환(출처 번호 지우기, 답이 쓴 근거만 참고한 문서로, 거절 문장만 있는 답에 정해 둔 안내, 링크 처리)은 백엔드가 한다. AI 서버는 모델 원문(출처 번호 포함)과 근거 순서대로의 후보 목록을 지금처럼 낸다.
2. 참고한 문서에 쓸 문서 대장 정보(사이트 코드·이름, 게시판, 제목, 첨부의 게시글 제목·주소)는 백엔드 문서 테이블에 둔다. 업로드 때 받고, 이미 올린 문서는 대장 ID로 채운다. 화면 문구('학교 홈페이지', '학사 공지' 등)로 바꾸는 규칙은 변환 한 곳에 둔다.
3. 대화 기록에는 모델 원문과 화면용 답을 함께 저장한다(관리자 개발자 모드와 다시 보기).
4. 답이 흐르는 동안에도 출처 번호가 보이지 않게 백엔드가 흘려보내는 글을 거른다.

## 버린 대안

- AI 서버에서 변환: 출처 번호와 근거 순서를 아는 곳이지만 대장 정보·권한·대화 기록이 없다. 평가 실행기가 바뀐 답을 받게 되어 원문으로 채점하려면 끄는 스위치가 따로 필요하다.
- 프론트엔드에서 변환: 대화 기록과 다른 창구가 같은 모양을 얻지 못하고, 출처 번호가 든 원문과 검색 후보가 일반 사용자 브라우저로 그대로 간다.
- 대장 정보를 색인 메타데이터(Chroma)에 넣기: 다시 색인하거나 메타데이터를 일괄로 고쳐야 하고, 모델 입력과 상관없는 화면 정보가 AI 서버에 쌓인다.

## 네 관점

- 서비스: 화면, 대화 기록, 관리자 개발자 모드가 같은 변환을 거친다. 기록을 다시 열어도 같은 모양이다.
- 비즈니스: 대장 정보를 문서 테이블에 한 번 채우면 된다. 다시 색인하지 않는다.
- 유지보수: AI 서버는 모델 입출력(근거 블록, 출처 번호)만 맡고, 화면 규칙은 백엔드 한 곳이다. 평가 실행기는 지금처럼 원문으로 채점한다.
- 확장: 메신저 채널 같은 다른 창구가 생겨도 백엔드 API 한 곳에서 같은 모양을 낸다.

## 결과

- 확신도: 높음(평가는 원문 그대로, 대장 정보의 자리). 중간(흐르는 동안 글을 거를 때 사용자가 느끼는 지연 — 구현 뒤 잰다).
- 검증 시점: 변환과 화면 하위 작업 뒤 시연, 학습한 모델을 올리기 전 개발셋 실행에서 화면 처리 확인(1회차 작업 계획 10단계).
