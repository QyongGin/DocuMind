# ADR-0011: 서빙 GPU 구성과 모델 배포 경로

- 상태: 채택
- 날짜: 2026-10-01
- 관련: `docs/project/설계6단계-결정근거대장-20261001.md` 안건 5, `docs/rag/m1/업로드-파이프라인-보강-PR2-설정정리-20261003.md`

## 맥락

12GB GPU 하나에 생성 모델과 임베딩 모델을 함께 올리고, 학습한 모델을 안전하게 교체하는 경로가 필요했다.

## 결정

- 생성 문맥 8,192 + 임베딩 문맥 2,048(임베딩 4B 유지). 사고(thinking) 모드는 끈다.
- 배포 경로: AWS에서 병합 → GGUF Q4_K_M → 데스크탑이 직접 받아 해시 확인 → 채팅 템플릿 검증 → 평가 전후 비교 → 교체(이전 모델 보관). 모델 대장(표 하나)에 기록한다.
- 재학습은 프롬프트·기반 모델 변경이나 행동 지표 하락 때만, 전체 재색인은 청킹·임베딩 변경 때만 한다.

## 버린 대안

- vLLM 멀티 LoRA 서빙: 학교 규모와 인계에 과하다.
- 임베딩 0.6B로 교체: 재색인·품질 재측정 비용이 있어 필요할 때로 미룬다.

## 근거

- [실측] 문맥 4,096에서 프롬프트가 잘렸다. 임베딩 글은 약 700토큰 이하.
- [실측] 바꾸기 전 10,470 → 바꾼 뒤 10,896MiB, 나누지 않으면 임베딩이 밀려난다.
- [원문] Unsloth·Ollama 문서의 1대 GPU 직접 운영 경로와 같다.
