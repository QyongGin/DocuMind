# ADR-0025: 두 실행의 '의미 있는 차이'는 같은 문항 짝 비교(매크니마 검정)로 정한다

- 상태: 채택
- 날짜: 2026-10-12
- 관련: 이슈 #130, ADR-0004(판단 원칙의 '의미 없는 차이'), ADR-0009(채택 기준의 '의미 있는 차이'), ADR-0018(테스트셋 봉인), ADR-0023(지표), `docs/rag/m1/베이스라인-측정-20261012.md`

## 맥락

- 13번 모델 비교의 판단 원칙(ADR-0004)은 "국산 계보가 의미 없는 차이 안이면 국산 우선", M2 채택 기준(ADR-0009)은 "의미 있는 차이 이상"이다. 차이의 크기는 베이스라인 뒤에 정하기로 했다.
- [실측] 베이스라인 본 테스트셋 정답률은 35.0%(28/80)이고 95% 신뢰구간이 25~46%다. 한 번 재서 5%p(4문항) 오른 결과는 문항을 어떻게 뽑았느냐에 따른 우연일 수 있다.
- 두 실행은 같은 평가셋의 같은 문항에 답한다. 따로 잰 두 점수의 신뢰구간을 비교하면 이 짝 정보를 버린다.

## 결정

1. **짝 비교**: 같은 평가셋 판의 같은 문항으로 두 실행을 짝 짓는다. 지표마다 문항별로 예/아니오를 정하고, 한쪽만 예인 문항 수(A만 b, B만 c)로 정확 이항 검정(매크니마 검정, McNemar test)을 한다. 양측 p < 0.05면 **의미 있는 차이**, 아니면 **같은 수준**으로 본다. 둘 다 예이거나 둘 다 아니오인 문항은 차이에 쓰지 않는다.

   | 지표 | 문항 묶음 | 문항별 '예' |
   |---|---|---|
   | 정답률 | 답 있는 문항 | 맞음 |
   | 환각률 | 전체 문항 | 틀림 |
   | 과잉 거절률 | 답 있는 문항 | 모름 |
   | 출처 정확도 | 답 있는 문항 | 화면 출처에 허용 근거 문서가 있음 |
   | 답없음 거절 | 답 없는 문항 | 맞음 |
   | 안내 충실도 | 안내 사실이 있는 문항 | 충족 |

2. **비교할 문항 묶음**
   - 13번 모델 비교: 본 개발셋과 본 테스트셋을 합친다(답 있는 200문항, 전체 250문항). 아직 어느 후보에 맞춰 고친 적이 없어 개발셋도 공정하다. 쉬운 문항은 따로 같은 방식으로 잰다.
   - M2 개선 전후: 고칠 때는 개발셋으로 비교하고, 테스트셋은 정해진 때(M2 끝·제안·학기 측정)에만 짝 비교 합계를 낸다(ADR-0018).
3. **테스트셋 봉인 유지**: 짝 비교 도구가 봉인 파일을 읽어 b·c·p와 합계만 낸다. 문항 ID·질문은 출력하지 않는다.
4. **애매가 남은 실행은 비교하지 않는다.** 사람(또는 위임받은 판정) 판정을 먼저 채운다.
5. 한 실행의 지표는 지금처럼 Wilson 95% 신뢰구간과 함께 보고한다. 신뢰구간은 '얼마나 정확히 쟀나', 짝 비교는 '둘이 다른가'를 답한다.

## 버린 대안

- **고정 폭(예: 5%p 이상이면 의미 있음)**: 설명은 쉽지만 문항 수를 반영하지 않는다. 본 테스트셋 80문항에서 5%p는 4문항이라 우연과 구별되지 않는다.
- **두 신뢰구간이 겹치지 않을 때만**: 짝 정보를 버려 너무 엄격하다. [계산] 35% 근처 80문항이면 약 20%p 차이가 나야 겹치지 않아, 거의 늘 '같은 수준'이 된다.
- **짝지은 부트스트랩(paired bootstrap)**: 같은 짝 정보를 쓰고 결과도 비슷하지만, 우리 지표는 모두 문항별 예/아니오라 정확 검정으로 충분하다. 매크니마 검정은 "한쪽만 맞힌 문항 수 비교"로 담당자에게 한 줄로 설명된다.
- **테스트셋 80문항만으로 모델 비교**: [계산] 10~15%p 차이가 나야 가려진다. 후보 사이 차이가 그보다 작으면 판단 원칙의 '품질 1위'를 정하지 못한다.

## 근거

- [원문] Dietterich(1998), *Approximate Statistical Tests for Comparing Supervised Classification Learning Algorithms*, Neural Computation 10(7). 초록: "A fourth test, McNemar's test, is shown to have low type I error." / "For algorithms that can be executed only once, Mc-Nemar's test is the only test with acceptable type I error." — 우리 비교는 정해진 모델을 고정된 평가셋에 한 번 돌리는 경우다.
- [계산] 정확 이항 검정으로 의미 있는 차이가 되는 최소 차이(두 실행에서 결과가 갈리는 문항 비율을 가정):

  | 문항 수 | 갈림 10% | 갈림 20% | 갈림 30% |
  |---|---|---|---|
  | 80(본 테스트셋) | 10.0%p | 12.5%p | 15.0%p |
  | 120(본 개발셋) | 6.7%p | 10.0%p | 11.7%p |
  | 200(본 개발셋+테스트셋) | 5.0%p | 7.0%p | 9.0%p |

- [계산] 고친 결과가 다른 문항을 하나도 망가뜨리지 않으면(c = 0) 새로 맞힌 문항 6개부터 의미 있는 차이다(p = 2 × 0.5⁶ ≈ 0.031). 개발셋 120문항에서 5%p다. 망가뜨린 문항이 생길수록 더 많이 맞혀야 한다.
- [판단] 13번 후보는 4개라 1위와 나머지를 하나씩 비교한다(최대 3번). 여러 번 비교에 따른 보정(Holm 등)은 하지 않는다. 보정하면 필요한 차이가 더 커져 대부분 '같은 수준'이 되고, 그때는 판단 원칙이 국산 계보를 고르므로 잘못 고른 비용이 작다.

## 네 관점

- 서비스: 우연한 2~3문항 차이로 모델·설정을 바꾸지 않는다.
- 비즈니스: 학교에 "나아졌다"고 말할 때 우연이 아니라는 근거를 함께 낸다.
- 유지보수: 규칙은 "한쪽만 맞힌 문항 수를 비교한다" 한 줄이고 명령 하나로 낸다. 학기 측정 때 담당자가 같은 명령을 쓴다. 테스트셋 봉인도 그대로다.
- 확장: 학기마다 문항이 늘면 같은 규칙으로 더 작은 차이까지 가려진다. 지표가 늘어도 문항별 예/아니오만 정하면 된다.

## 결과

- 짝 비교 명령(`evalset compare-runs`)을 13번 전에 tools/corpus에 더한다. 입력은 두 실행 폴더와 같은 평가셋, 출력은 지표마다 b·c·p·판정, 테스트셋은 합계만.
- 어느 지표로 '품질 1위'를 정하는지, 성공 기준 목표치는 따로 정한다(총괄계획 §1.5).
- 확신도: 높음(방법), 중간(필요한 차이 범위 — 결과가 갈리는 문항 비율은 가정).
- 검증 시점: 13번 첫 비교에서 실제 갈림 비율을 보고 위 표를 실측으로 바꾼다. 베이스라인 설정을 한 번 더 돌려 같은 설정에서도 갈리는 문항이 있는지(온도 0의 재현성) 함께 본다.
