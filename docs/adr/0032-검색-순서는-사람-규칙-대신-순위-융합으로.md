# ADR-0032: 검색 순서는 사람이 만든 규칙 대신 순위 융합으로 — 표 값 우선 거르기·근거 좁히기·우선 경로 답을 뺀다

- 상태: 제안(2026-10-14, 사용자 확인 대기)
- 날짜: 2026-10-14
- 관련: 이슈 #129 이후 M2, ADR-0009(ML은 남은 실패에만), ADR-0015(표 사실 캐시), ADR-0025(짝 비교), ADR-0026(목표), `docs/rag/m2/실패원인-분석-20261014.md`, `docs/rag/m2/검색개선-설계-20261014.md`, `docs/rag/research/검색개선-근거조사-20261014.md`

## 맥락

- 지금 AI 서버는 벡터·BM25·표 사실 검색 결과를 이어 붙인 뒤, 사람이 만든 규칙 세 개로 순서를 정한다: 표 값 질문 우선 거르기(`_prioritize_query_results`), 규칙 재순위(`_rerank_by_query_analysis`), 질문 맞춤 근거 좁히기(`_focus_candidates_with_query_evidence`). 그리고 규칙이 확실하다고 보면 모델을 거치지 않고 근거를 그대로 답으로 붙인다(우선 경로 답).
- [실측] 개발셋 본 문항 121개에서 검색 후보에는 정답 청크가 119개(98%) 있는데 최종 후보 5개에는 72개(60%)만 남는다. 우선 거르기는 후보를 지운 42문항 중 19문항에서 정답을 지웠다.
- [실측] 정답 청크가 프롬프트에 없으면 어떤 생성 모델도 거의 못 맞힌다(45문항 중 1문항). 검색 순서가 답변 정확도의 상한을 정한다.

## 결정

1. 검색 결과(표 사실·BM25·벡터)는 순위 융합(RRF, k=60)으로 한 줄로 세워 상위 k개를 쓴다.
2. 사람이 만든 규칙 세 개와 우선 경로 답은 쓰지 않는다. 한 릴리스 동안은 `retrieval_mode=rules`로 되돌릴 수 있게 남기고, M2 2단계(상위 k 결정)가 끝나면 코드에서 지운다.
3. 순서를 더 다듬는 일은 규칙이 아니라 학습된 재순위(cross-encoder)로 한다(M2 3단계에서 실측 뒤 결정).

## 버린 대안

- **규칙 문턱만 조정**: 규칙은 질문 유형마다 늘어나고, 한 유형을 고치면 다른 유형이 깨진다. 특정 표·문구에 맞춘 조건문은 AGENTS.md가 금지한다.
- **규칙 위에 재순위만 더하기**: 규칙이 이미 지운 정답 청크는 재순위가 되살리지 못한다.
- **우선 경로 답 유지**: 모델 호출을 아끼지만 12문항 중 3문항이 틀렸고, 순위 융합 쪽이 응답 시간도 짧았다.

## 근거

- [실측] 실험 E1(2026-10-14, 데스크탑, 개발셋 205문항, EXAONE 3.5 7.8B, 생성 설정·색인 동일): 베이스라인 대비 본 정답률 43.8% → 62.0%(갈린 문항 8 / 30, p=0.0005), 오답률 8.1% → 2.0%(10 / 1, p=0.012), 과잉 거절 38.0% → 20.7%(28 / 7, p=0.0005), 출처 정확도 67.8% → 90.9%, 쉬운 문항 정답률 70.9% → 94.5%(p=0.001). 응답 시간 중앙 2.54 → 2.46초, 상위 5% 5.54 → 4.45초, 프롬프트 잘림 1 → 0.
- [실측] 실험 E3(같은 융합 프롬프트를 13번 상위 두 모델에, 개발셋, 같은 모델끼리 짝 비교): A.X 4.0 Light 본 정답률 48.8% → 71.1%(p=0.0001)·과잉 거절 33.1% → 11.6%, Gemma 4 12B 53.7% → 74.4%(p=0.0002)·오답률 6.0% → 0.7%(p=0.02). 효과가 생성 모델에 따라 달라지지 않았다.
- [계산] 기록된 후보 재연: RRF 상위 5개에 정답 청크 99/121, 상위 10개 113/121(지금 72/121).
- [원문] Cormack 외(SIGIR 2009): RRF는 점수 정규화 없이 순위만 합친다. Anthropic Contextual Retrieval(2024-09): BM25와 임베딩을 합치고 재순위를 더할수록 검색 실패율이 줄었다(5.7% → 2.9% → 1.9%).
- [판단] 결정 주체: 사용자 확인 전 제안(본 세션).

## 결과

- 운영 기본값을 바꾸는 PR의 전제(고른 생성 모델로 같은 효과)는 E3로 확인했다. 그 PR은 기본 생성 모델을 ADR-0031 1순위(Gemma 4 12B)로 바꾸는 설정과 함께 올린다.
- 규칙 관련 점검 스크립트(`ai-server/check_query_evidence_priority.py` 등)와 테스트는 규칙 코드를 지울 때 함께 정리한다.
- 검증 시점: M2 끝 테스트셋 측정(ADR-0018)에서 같은 방향인지 확인한다. 확신도: 높음(개발셋 p<0.001), 테스트셋 미확인.
