# ADR-0050: 사용자 화면의 답은 결론 → 안내 → 참고한 문서로 보인다. 출처 번호와 거절 문장은 서버가 바꾸고, 청크와 검색 후보는 개발자 모드에서만 보인다

- 상태: 채택
- 날짜: 2026-11-01
- 관련: ADR-0039(목표 답 모양 — 결정 3을 이 ADR이 대체), ADR-0037(학습 데이터 검토), ADR-0047(날짜 줄), ADR-0010(Claude 출력은 학습에 쓰지 않음), 총괄계획 문제 B6(출처가 답과 맞지 않음), `docs/rag/m2/6단계-새제작법-결과-20261101.md`
- 변경(2026-11-02): 결정 3을 바꾼다 — 거절 문구는 모델이 학습으로 바로 쓴다. 답이 없을 때 '학교 홈페이지 안내에서 이 내용을 찾지 못했습니다.', 일부만 없을 때 '(없는 것)은 학교 홈페이지 안내에서 찾지 못했습니다.' 서버는 문구를 바꾸지 않고, 거절 문장만 있는 답에 정해 둔 안내만 붙인다. 학습 데이터는 다시 만들지 않고 내보낼 때 옛 문장을 글자 그대로 바꾼다(목표 답과 입력의 운영 규칙 9·11 함께 — 둘이 어긋나면 규칙과 다르게 답하는 버릇이 된다). 운영 프롬프트가 바뀌므로 학습 전 기준선을 다시 잰다. 이유: 모델이 하는 말과 사용자가 보는 말이 같아지고 서버 규칙이 하나 준다. 나중에 문구를 바꿀 때 다시 학습해야 하는 대가는 작다(필요하면 서버가 덮어쓸 수 있다).
- 변경(2026-11-02, 측정 뒤): 거절 문장은 '학교 홈페이지 안내에서 찾지 못했습니다.' 하나로 정한다(답이 없을 때와 일부만 없을 때 같은 문장). 운영 규칙 9·11은 옛 모양 그대로 두고 따옴표 안 문장만 바꾼다. 처음 함께 넣은 '질문의 일부만 근거에 없으면 있는 것은 답하고' 지시는 학습 전 A.X가 답이 없는 질문에서도 근거 속 다른 안내로 단정하게 해 개발셋(본) 틀린 답 12 → 16/149·답없음 거절 23 → 19/28로 빼고, 문장만 바꾼 규칙은 12 → 13·23 → 23으로 같은 수준이다 [실측, 같은 기준으로 다시 판정]. 근거 `docs/rag/m2/거절문장-기준선-20261102.md`.

## 맥락

- [실측] 지금 채팅 화면의 출처 칸은 검색 후보 8개 전부와 청크 본문, '문서 내 N번째 청크', 업로드 시각을 일반 사용자에게 보인다(`frontend/src/features/chat/ChatPage.jsx`). 개발자가 볼 정보다.
- [실측] 운영 A.X 답 205개 중 7개는 '[출처' 글자를 화면에 그대로 낸다(2026-10-31 개발셋 실행, 날짜 줄 켬). 학습 목표 답은 끝에 `[출처 N]`을 달게 만들었으므로(ADR-0039 결정 1), 학습한 모델은 거의 모든 답에 번호를 단다 [판단].
- [실측] 근거 블록의 '문서:' 줄은 파일 이름이라 따옴표와 빗금이 깨진다('%22', '~10/4' → '~10 4'). 사람이 읽을 이름과 원문 주소는 문서 대장의 제목과 주소다.
- [판단] 운영 거절 문장('제공된 문서에서는 확인할 수 없습니다.')은 시스템 용어('제공된 문서')이고, 문장만 있으면 사용자에게 다음 할 일이 없다.
- [실측] 링크: 통과한 학습 예시 273개 중 59개에 링크가 있고, 서로 다른 링크 65개 중 11개가 2026-11-01에 열리지 않거나 마감됐으며 3개는 접속되지 않았다(신청 양식 링크는 24개 중 8개). 예시는 질문 재료가 올라온 날 기준이라 그날엔 살아 있던 링크다. 모델은 링크가 지금 열리는지 알 수 없다.
- [실측] 문서 대장의 유효 기간은 3,900개 중 3,895개에 있지만 추정값이다. 신청 기간이 2026-09-03 ~ 12-17인 2027학년도 수시 안내가 2026-08-31로 잡혀 있다.
- [실측] 말투: 운영 A.X 답의 문장 끝은 합니다체 655개, 해요체 17개다(같은 개발셋 실행). 통과한 학습 예시 273개에는 해요체 문장이 없다.
- [원문] 대화 설계 지침: Google은 더 도울 수 없을 때 다른 방법으로 일을 마칠 길을 알려 주고, 사용자 탓을 하거나 막연한 약속을 하지 말라고 한다. Amazon Alexa는 무엇이 잘못됐는지와 해결할 행동을 함께 말하고 막다른 길을 만들지 말라고 한다. Microsoft Copilot Studio는 두 번 다시 물은 뒤 상담원에게 넘기고, 못 답한 질문을 모아 개선에 쓰라고 한다. 카카오 i 오픈빌더는 못 알아들었을 때의 기본 문구를 서비스에 맞게 바꾸고 버튼을 붙이게 한다.

## 결정

2026-11-01 결정.

1. 사용자 화면의 답은 **결론 → 근거에 있는 다음 할 일(방법·기한·문의처·사이트) → 참고한 문서**로 보인다. 말투는 합니다체다.
2. 출처 번호는 모델 출력에만 둔다(ADR-0039 결정 1의 목표 답 모양 그대로). 서버가 화면에 보내기 전에 지우고, 그 번호가 가리키는 근거의 문서 대장 정보(사이트, 게시판, 게시글 제목, 첨부 파일 이름, 게시일, 원문 주소)로 '참고한 문서'를 만든다. 답이 쓴 근거만 보인다(문제 B6). 문서 이름과 주소는 모델이 쓰지 않는다.
3. 거절: 모델은 운영 거절 문장을 그대로 쓰고, 서버가 화면에서 '학교 홈페이지 안내에서 (이 내용을) 찾지 못했습니다'로 바꾼다. 답이 전혀 없을 때(거절 문장만)는 서버가 정해 둔 안내를 붙인다 — 학과·학년도·학기를 넣어 다시 묻기, 학교 홈페이지의 교내 전화번호 안내. 근거에 문의처가 있으면 모델이 쓴 문의처를 그대로 보인다. '없습니다'로 단정하지 않는다(못 찾은 것과 없는 것을 가를 수 없다).
4. 거절 문장 뒤에 출처 번호만 있는 학습 예시는 학습 파일로 내보낼 때 번호를 지운다. 서버도 이때는 참고한 문서를 보이지 않는다.
5. 링크: 서버가 색인 문서 속 링크 상태를 정기적으로 확인해, 열리지 않는 링크는 답에서 빼고 '지금 열리지 않음'으로 보인다. 유효 기간이 지난 공지 표시('지난 안내')는 문서 대장의 유효 기간을 바로잡은 뒤에 한다. 그때까지는 참고한 문서에 게시일을 보인다.
6. 개발자 모드: 관리자로 로그인했을 때만 모델 원문 답(출처 번호 포함), 근거 8개(문서, 청크 본문, 검색 점수), 프롬프트, 단계별 시간, 화면 처리 내역(지운 번호, 바꾼 문구, 숨긴 링크), 못 답한 질문 목록을 보인다. 일반 사용자 화면에는 청크, 검색 후보, 업로드 시각을 보이지 않는다.
7. 1회차에서 인용형(근거 줄 인용 → 결론) 비교를 하지 않는다(ADR-0039 결정 3 대체). 근거 글을 사용자에게 그대로 보이는 모양이다. 1회차 학습 파일은 결론 먼저 모양 200개 한 벌이다.
8. 순서: 학습한 모델을 운영에 올리기 전에 결정 2·3·5·6의 서버·화면 작업을 끝낸다.

## 버린 대안

- 모델이 참고 문장('○○ 공지의 ○○ 파일을 참고했습니다')을 직접 쓰기: 문서 이름과 주소를 지어낼 수 있고, 학습 데이터와 검사를 다시 만들어야 한다.
- 출처 번호를 모델 출력에서도 없애기: 답이 쓴 근거를 알 수 없어, 값이 그 근거에 있는지 보는 자동 검사와 문제 B6를 할 수 없다.
- 거절 문구를 학습 데이터에서 바꾸기: 목표 답, 운영 프롬프트(규칙 9·11), 자동 검사, 평가 채점을 모두 바꿔야 한다. 서버가 바꾸면 모델 쪽은 그대로다.
- 해요체: 목표 답 약 550개를 다시 만들고 판정과 사람 30개 확인을 다시 해야 하며, 운영 거절 문장과 프롬프트도 바꿔야 한다. 운영 A.X도 합니다체로 답한다.
- 상담원 연결: 상담 창구가 없다.
- 대장의 유효 기간으로 '지난 안내'를 지금 바로 표시: 추정값이라 유효한 공지를 지난 것으로 보인다(맥락의 수시 안내).

## 네 관점

- 서비스: 사용자는 결론과 할 일, 실제 문서 이름과 원문 링크를 본다. 답이 없을 때도 다음 할 일이 있고, 열리지 않는 링크를 받지 않는다.
- 비즈니스: 모델과 학습 데이터는 그대로다(거절 뒤 번호 지우기만 더함). 서버·화면 작업이 는다.
- 유지보수: 화면 문구, 정해 둔 안내, 참고 문서 모양은 서버 설정 한 곳이다. 모델이 지키는 약속(출처 번호, 운영 거절 문장)은 그대로다.
- 확장: 다른 학교도 문서 대장만 있으면 같은 방식이다. 상담 창구가 생기면 정해 둔 안내에 연결만 더한다.

## 결과

- 확신도: 높음 — 출처 번호를 모델 출력에 남기면 자동 검사와 B6를 유지한다. 중간 — 바꾼 거절 문구와 정해 둔 안내가 사용자에게 충분한지(실사용 확인 전).
- 검증 시점: 서버·화면 구현 뒤 시연, 학습한 모델을 올리기 전 개발셋 실행에서 화면 처리(번호 지움, 문구 바꿈, 링크 숨김)를 확인한다.
- 다시 볼 조건: 상담 창구가 생길 때, 문서 대장의 유효 기간을 바로잡을 때(결정 5의 '지난 안내'), 정해 둔 안내를 쓰는 사용자가 거의 없을 때.
- ADR-0039에 변경 메모를 단다(결정 3을 이 ADR이 대체, 결정 1의 목표 답 모양은 모델 출력으로 유지).
