# ADR-0014: 업로드 파이프라인: 문서 메타데이터, 중복 차단, 대량 업로드

- 상태: 채택
- 날짜: 2026-10-02 (2026-10-03 보완)
- 관련: 이슈 #126, PR #136, `docs/rag/m1/업로드-파이프라인-보강-설계-20261002.md`

## 맥락

문서 대장 정보를 서비스로 넘기고, 같은 파일이 두 번 들어가는 것을 막고, 700개 문서를 안정적으로 올려야 했다.

## 결정

- 대장 정보(대장 ID·원래 주소·게시일·학년도)는 서비스 DB `documents`의 칸으로 두고(빈칸 허용), 업로드 때 AI 서버에 넘겨 청크 메타데이터로 넣는다.
- 대장의 주제는 서비스의 카테고리로 합친다(같은 뜻의 칸을 두 개 두지 않음). 청크에는 카테고리 번호·이름.
- 같은 파일은 파일 지문(SHA-256)으로 판단해 살아 있는 문서와 같으면 409로 막는다(DB 유일 제약). 글만 같은 다른 파일은 대장에서 정리한다.
- 대량 업로드는 `tools/corpus`의 `upload` 명령(비밀번호는 실행 때 입력, 한 문서씩 끝날 때까지 대기, 이어 올리기, 연속 5번 실패하면 멈춤).
- 관리 화면: 추가 정보 입력 칸, 실패 이유 저장·표시. 실패한 문서는 같은 파일 검사에서 뺀다.
- 서비스 색인은 대장 경로(`corpus upload`)로만 만든다(2026-10-03, 예전 직접 업로드 문서 정리).

## 근거

- [원문 설정] 백엔드 문서 처리 실행기가 스레드 1개·대기열 20칸이라 기다리지 않으면 거절된다.
- [실측] 서비스 색인 대상 704행에서 같은 파일 0, 글만 같은 행 8(4쌍).
- [판단] 인계 뒤 학교 담당자는 대장 없이 화면으로 올리므로 서비스 DB가 기준이어야 한다.
