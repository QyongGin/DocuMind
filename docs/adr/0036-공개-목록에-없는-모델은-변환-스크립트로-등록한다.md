# ADR-0036: 공개 목록에 없는 생성 모델은 저장소의 변환 스크립트로 등록하고, compose의 모델 준비 단계는 이미 등록된 모델을 내려받지 않는다

- 상태: 채택
- 날짜: 2026-10-20
- 관련: ADR-0011(배포 경로·모델 대장), ADR-0012(인계), ADR-0034(기반 모델 A.X 4.0 Light, 결정 4), `docs/rag/m2/2단계-A.X-새기준선-20261020.md` §1·§6, `docs/rag/research/A.X-4.0-Light-사용권-조사-20261017.md` §3

## 맥락

- [코드] 데스크탑 compose의 모델 준비 단계(`docker-compose.gpu.yml`의 `ollama-llm-model`·`ollama-embedding-model`)는 `ollama pull`만 한다. AI 서버는 이 단계가 성공해야 뜬다.
- [실측] A.X 4.0 Light는 Ollama 공개 목록에 공식판이 없다. 그래서 SKT 공식 원본(Hugging Face `skt/A.X-4.0-Light`, 커밋 `ba21c20`)을 GGUF로 바꿔 데스크탑 Ollama에 `ax40light:q4km`으로 직접 등록해 썼다. 생성 모델 기본값을 A.X로 바꾸면 모델 준비 단계가 내려받기에 실패해 AI 서버가 뜨지 않는다. 2단계 측정은 `up --no-deps`로 이 단계를 건너뛰어 돌렸다.
- [실측] 변환 스크립트와 채팅 틀(Modelfile)은 데스크탑에만 있어, 다른 사람이 같은 모델을 다시 만들 수 없다.
- 학습 회차(계획 7·8단계)의 결과물도 공개 목록에 없는, 직접 등록하는 모델이다(ADR-0011 배포 경로).

## 결정

1. 모델 준비 단계는 모델이 Ollama에 이미 등록돼 있으면 내려받지 않고 끝낸다. 등록돼 있지 않을 때만 내려받고, 내려받기에 실패하면 변환·등록 절차 문서를 가리키는 메시지를 남기고 실패한다. 생성 모델과 임베딩 모델 단계에 같은 규칙을 쓴다(2026-10-20 사용자 결정).
2. 공개 목록에 없는 생성 모델(A.X 4.0 Light, 학습한 모델)은 저장소의 변환·등록 스크립트로 등록한다: 공식 원본(커밋 고정) → 16비트 GGUF → Q4_K_M → 채팅 틀을 지정해 Ollama에 등록 → 파일 해시를 모델 대장과 대조. 변환 도구(llama.cpp 이미지)도 판을 고정한다.
3. 모델 대장(ADR-0011)을 그 스크립트 폴더의 README 표로 시작한다. 칸: Ollama 이름, 원본과 커밋, 변환 도구 판, 파일 SHA256, 라이선스, 채팅 틀.
4. 운영 기본 생성 모델(`OLLAMA_LLM_MODEL`)을 `ax40light:q4km`으로 바꾼다(ADR-0034 결정 4).

## 버린 대안

- compose가 변환까지 자동으로: 처음 올릴 때 원본 14.5GB와 변환 도구 이미지 4.2GB를 받고 약 8분 CPU로 변환해야 하며, 모델마다 변환 설정을 compose에 둬야 한다. 학습한 모델은 AWS에서 만든 결과물이라 이 길에 맞지 않는다.
- 변환본을 공개 저장소(Hugging Face·Ollama 목록)에 올리고 내려받기: 공개 배포가 되어 LICENSE·NOTICE·수정 표시 의무와 외부 계정 관리가 생긴다. 학교 문서로 학습한 모델은 공개하지 않으므로 학습 회차에는 쓸 수 없다.
- 지금처럼 무조건 내려받고 실행할 때마다 `--no-deps`로 우회: 담당자가 우회를 알아야 하고, 다른 서비스의 의존 확인까지 함께 건너뛴다.

## 근거

- [실측] 2단계 보고서 §1 발견 ①②.
- [실측] 2026-10-01 변환 기록(`docs/rag/research/기반모델-후보-데스크탑-실측-20261001.md` §1·§2): llama.cpp build 11312(커밋 `0c1e57098`), bf16 13,847MiB → Q4_K_M 4,226MiB, SHA256 `a1681e9b…f35b`, 내려받기 포함 7.5분, 채팅 틀로 만든 입력 토큰 수가 공식 틀과 같음(6).
- [판단] 이미 등록된 모델을 다시 내려받지 않으면, 공개 목록의 같은 이름이 새 판으로 바뀌어도 데스크탑 모델이 조용히 바뀌지 않는다. 임베딩 모델이 바뀌면 재색인이 필요하고, 생성 모델이 바뀌면 짝 비교의 전제가 깨진다. 새 판을 쓸 때는 일부러 내려받고 측정한다.

## 네 관점

- 서비스: 데스크탑을 다시 올려도 이미 등록된 A.X로 바로 뜬다. 내려받기 대기가 없다.
- 비즈니스: 모델 파일을 외부에 공개하지 않는다. 학교에 넘길 때는 모델 파일과 LICENSE·NOTICE·수정 표시를 인계 패키지로 넘긴다(사용권 조사 §3.3).
- 유지보수: 새 담당자는 스크립트를 한 번 돌려 같은 해시의 파일을 만들 수 있다. 모델 대장 한 곳에서 어떤 모델이 어디서 왔는지 본다.
- 확장: 학습한 모델도 같은 등록 부분과 모델 대장 행 하나로 더한다. 운영 클라우드(ADR-0030)에서도 같은 스크립트로 등록한다.

## 결과

- 확신도: 높음.
- 검증: 데스크탑에서 스크립트로 다시 만든 Q4_K_M 파일의 SHA256이 2026-10-01 값과 같은지, 기본값 A.X로 compose가 우회 없이 뜨는지 확인한다.
- 학습 회차 결과물을 등록할 때 같은 스크립트의 등록 부분과 모델 대장을 쓴다.
