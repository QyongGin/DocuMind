# ADR-0020: 평가셋 독립 이중 라벨링

- 상태: 채택
- 날짜: 2026-10-05 (2026-10-06 구현 보완)
- 관련: 이슈 #129, PR #142, `docs/rag/m1/평가셋-도구-구현2-20261006.md`

## 맥락

정답을 만든 Claude 세션이 원문을 잘못 읽거나 옮겨 쓰다 실수하면, 같은 글을 읽는 챗봇도 같이 틀려 결과에서 숨는다.

## 결정

- 독립 이중 라벨링(independent double annotation): 정답을 만든 세션과 분리된 Claude Code 세션(`claude -p`)이 정답을 보지 않고 질문과 원본만 받아 답한다. 답은 규칙 기반 채점으로 정답과 비교해 일치·불일치·애매를 남기고, 일치가 아니면 휴먼 리뷰로 보낸다(불일치 판정, adjudication).
- 원본은 서비스 변환을 거치지 않은 것: HTML은 원본 HTML(꾸밈만 지우고 rowspan·colspan 유지), PDF는 쪽 이미지 + 같은 쪽 PDFium 텍스트, HWP는 수집기 텍스트 추출.
- 근거 문서 전체를 주고 정답이 인용한 위치는 알려 주지 않는다.
- 세션 격리: 저장소 밖 임시 폴더의 작업 단위(packet) 안에서 `--tools Read,Grep,Glob --restricted --safe-mode --permission-prompts none`으로 실행한다. 격리 여부는 `evalset fence`로 시험한다.
- 답과 덧붙임을 나눠 받는다(덧붙임이 거절 문구로 잡혀 애매가 늘지 않게).

## 버린 대안

- 비교 후보가 아닌 작은 오픈 모델(Mi:dm 2.0 Base 등): 이해 오류는 거의 못 잡고 헛걸음만 늘려 사람 시간을 쓴다.
- 정답이나 인용 위치를 보여 주기: 같이 틀린다.
- 하위 에이전트: 격리를 지시로만 막는다.

## 근거

- [실측] `fence`: 작업 폴더 밖 가짜 정답 읽기 시도 3건 모두 거절.
- [실측] 합성 4문항 실제 실행: 일치 3·애매 1 → 덧붙임 분리 뒤 일치 4. 실제 평가 문서 221개 원본 읽기 실패 0.

## 결과

- 한계: Claude가 같은 식으로 잘못 이해한 문항은 못 잡는다(테스트셋 표본 30이 맡는다). Claude Code 판이 바뀌면 `fence`를 다시 돌린다.
