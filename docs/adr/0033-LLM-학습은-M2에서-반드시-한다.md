# ADR-0033: LLM 학습(LoRA)은 M2에서 반드시 한다 — 학습한 모델을 운영에 쓸지만 전후 비교로 정한다

- 상태: 채택
- 날짜: 2026-10-17
- 관련: ADR-0009(대체하는 문장: "ML은 필수가 아니다"), ADR-0010(학습 데이터), ADR-0026(성공 기준), ADR-0030(학습 서버), ADR-0034(기반 모델), `docs/rag/m2/A.X-기준-계획-20261017.md`

## 맥락

- [원문] ADR-0009와 총괄계획 §1.3은 "ML은 필수가 아니다"(2026-09-30)라고 적어, 학습이 선택처럼 읽혔다. 반면 총괄계획 M2 할 일("학습 직전 상위 2개 기반 모델 재비교 → 생성 모델 행동 교정 LoRA")과 ADR-0026 보강("검색 개선과 파인튜닝을 모두 마친 뒤 잰다")은 학습을 전제한다.
- [실측] 2026-10-16 개발셋에서 검색 개선만으로 성공 목표를 넘자, Claude가 "학습은 남은 실패가 목표를 막을 때만"으로 바꾸자고 제안했다. 사용자(2026-10-17): 학교에서 받은 AWS 학습 서버로 LLM을 학습하는 것이 목표인데 이를 잊었다.

## 결정

1. M2에서 생성 모델 LoRA 학습을 반드시 한다. 여러 회차로 나눠 하고, 회차마다 개발셋에서 학습 전후를 같은 문항으로 짝 비교한다(ADR-0025).
2. 학습한 모델을 운영 모델로 쓸지는 전후 비교로 정한다. 오답률이 의미 있게 늘거나 성공 기준의 선(오답률 5% 이하·답없음 거절 90% 이상)을 넘지 못하면 쓰지 않는다.
3. 순서: 학습 데이터는 서비스 프롬프트 형식 그대로 만들므로(ADR-0010), 본 학습은 프롬프트 단계가 굳은 뒤 한다. 학습 서버에서의 학습 가능성 실측과 학습 데이터 준비는 검색·프롬프트 개선과 나란히 시작한다.
4. ADR-0009의 "ML은 필수가 아니다"는 생성 모델 학습에 대해 이 결정으로 바뀐다. 임베딩·재순위 학습은 ADR-0009대로 남은 실패가 있을 때만 한다.

## 버린 대안

- 남은 실패가 목표를 막을 때만 학습(2026-10-16 Claude 제안): 개발셋 목표를 이미 넘어 사실상 학습을 하지 않게 된다. 학교 학습 서버와 포트폴리오 목표에 어긋난다.
- 다른 일을 멈추고 지금 바로 학습: 프롬프트가 바뀌면 학습 데이터를 다시 만들고 다시 학습해야 한다.

## 근거

- [원문] ADR-0009 "주 대상: 생성 모델 행동 교정(LoRA, 프롬프트가 굳은 뒤)", ADR-0010 "학습 데이터는 서비스 파이프라인을 거친 결과로 만든다".
- [실측] 학습이 겨냥할 몫: 정답 근거가 프롬프트에 있는데 못 맞힌 문항(지금 운영 11 / 121), 안내 충실도 32%(목표 50%), A.X 4.0 Light의 틀린 답(같은 프롬프트에서 10 / 149, Gemma 4 12B 1 / 149).
- [원문, 반대 근거] 최신 오픈 모델에서는 RAG용 미세조정의 정확도 효과가 없었다는 보고(ADR-0026 보강, Sager 외) — 그래서 효과를 가정하지 않고 결정 2처럼 전후 비교로 쓸지를 가른다.

## 네 관점

- 서비스: 학습한 모델은 나빠지지 않을 때만 들어간다.
- 비즈니스: 학교가 준 학습 서버를 목적대로 쓰고, 학교 제안 때 "학교 문서로 학습한 모델"을 근거로 낸다.
- 유지보수: 재학습 절차를 스크립트·문서로 남겨 인계한다(ADR-0011·0012).
- 확장: 운영 질문이 쌓이면 같은 파이프라인으로 다시 학습한다.

## 결과

- 확신도: 높음(학습을 한다는 방향), 중간(효과 크기).
- 검증 시점: 학습 1회차(시험 학습) 전후 비교.
- 총괄계획 §1.3·M2 할 일 표, ADR-0009에 이 ADR을 가리키는 메모를 단다.
