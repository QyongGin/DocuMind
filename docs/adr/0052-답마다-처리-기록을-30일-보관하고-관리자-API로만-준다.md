# ADR-0052: 답마다 처리 기록을 30일 보관하고, 개발자 정보와 검색 후보는 관리자 API로만 준다

- 상태: 채택
- 날짜: 2026-11-02
- 관련: ADR-0050(결정 6 개발자 모드), ADR-0051(화면용 답 변환은 백엔드), 이슈 #213(관리자 개발자 모드)·#204(7단계 상위), `docs/project/챗봇-답변-형식.md` §4

## 맥락

- [실측] AI 서버 `/query/stream`은 답 글과 끝의 검색 후보 목록만 보낸다. 프롬프트와 단계별 시간은 서버 로그에만 남고, 후보별 검색 점수는 평가용 `/query`의 `include_eval_trace`와 `/debug/rag-trace`(답을 만들지 않고 검색만 다시 돌림)에만 있다.
- [실측] 운영 모양 프롬프트의 UTF-8 크기: 1회차 학습 입력 200개 중앙 14.5KB, 최대 31.4KB. 평가용 기록(`include_eval_trace`)은 단계마다 후보 글 전체를 담아 답 하나에 중앙 117KB, 최대 232KB다(2026-11-02 개발셋 실행 205개).
- [실측] 채팅 응답(흐르는 답의 끝, 바로 받는 답, 대화 기록)은 검색 후보(청크 미리보기, 업로드 시각, 파일 크기)를 모든 사용자에게 보낸다. 화면만 관리자에게 보이게 숨긴다(#212). 보안 설정은 `/api/admin/**`을 관리자(ADMIN)만 부르게 한다.
- [실측] 대화 기록(`chat_messages`)에는 질문, 화면용 답, 모델 원문 답, 검색 후보 목록이 있고 지우는 기간이 없다. 거절 문장만 나간 답을 따로 찾을 칸이 없다.

## 결정

2026-11-02 결정.

1. 처리 기록은 모든 답에 남긴다(흐르는 답과 바로 받는 답). 백엔드가 AI 서버에 `include_trace`로 요청하면 AI 서버가 답 끝에 처리 기록을 함께 보내고, 백엔드는 대화 기록과 따로 둔 표에 답 하나당 한 행으로 저장한다.
2. 처리 기록에 담는 것: 프롬프트(근거 블록 포함), 단계별 걸린 초(임베딩, 벡터 검색, 키워드·표 검색, 재순위, 근거 블록 만들기, 검색 전체, 첫 글자까지, 생성, 전체), 근거 후보마다 찾은 검색기와 순위·점수, 순위 융합 순위, 재순위 점수, 모델 설정. 근거 글은 프롬프트에 있으므로 따로 담지 않는다.
3. 처리 기록은 30일 지나면 지운다(백엔드 설정으로 바꾼다). 모델 원문 답과 검색 후보 목록은 대화 기록에 남으므로 30일 뒤에도 개발자 정보에서 보인다.
4. 개발자 정보와 못 답한 질문 목록은 관리자 API(`/api/admin/**`)로만 준다. 채팅 응답에서는 검색 후보를 빼서 모든 사용자에게 같은 모양으로 보낸다.
5. 못 답한 질문은 거절 문장만 나간 답(정해 둔 안내를 붙인 답)의 질문이다. 답을 저장할 때 표시하고 최근 것부터 보인다. 일부만 없는 답은 넣지 않는다(답변 형식 §4).

## 버린 대안

- 관리자가 직접 물은 답만 저장: 사용자가 겪은 실패를 보려면 같은 질문을 다시 물어야 하고, 그때는 답이 달라질 수 있다.
- 저장하지 않고 개발자 모드에서 다시 돌리기(`/debug/rag-trace`): 색인, 모델, 관리자 프롬프트가 바뀌면 그때와 다른 결과가 나오고, 생성 시간은 다시 잴 수 없다.
- 평가용 기록을 그대로 저장: 답 하나에 중앙 117KB로 처리 기록의 약 6배다. 단계별 후보 글 전체는 평가 채점(실패 위치)에 필요하고 운영 진단에는 근거 후보 8개면 된다.
- 처리 기록을 대화 기록 칸에 함께 두기: 30일 뒤 지우는 일이 칸을 비우는 수정이 되고, 대화 기록을 읽을 때마다 큰 칸을 함께 읽는다.
- 채팅 응답에 관리자일 때만 검색 후보 넣기: 권한 판단이 채팅 응답 세 곳에 생기고, 흐르는 답은 로그인 정보를 세션 등록 때 따로 넘겨야 한다. 관리자 API 한 곳이면 지금 보안 설정이 그대로 지킨다.

## 근거

- [실측] 프롬프트 크기: `Assets/train/round1/round-ga.jsonl`(로컬) 입력 200개. 평가용 기록 크기: `Assets/eval/runs/20261102-m2-s6-refusal-sentence-asof1031/answers.jsonl`(로컬) 205개.
- [계산] 처리 기록 하나 ≈ 프롬프트 14.5KB + 근거 후보 8개의 점수 기록 약 3~9KB → 약 20KB, 최대 약 40KB. 하루 답 1,000개를 가정하면 30일 보관에 약 0.6GB다.

## 네 관점

- 서비스: 관리자는 사용자가 실제로 받은 답을 그때의 프롬프트와 근거, 점수로 바로 진단한다. 일반 사용자 응답에는 내부 정보가 없다.
- 비즈니스: AI 서버는 이미 만든 프롬프트와 이미 잰 값을 돌려줄 뿐이라 계산이 늘지 않는다. 저장은 30일 치만 쌓인다.
- 유지보수: 처리 기록 표 하나, 지우는 작업 하나, 관리자 API 한 곳이다. 후보별 검색기 기록은 `/debug/rag-trace`와 같은 함수를 쓴다.
- 확장: 못 답한 질문과 그 처리 기록을 평가셋 후보로 모을 수 있다. 운영 서버를 클라우드로 옮겨도(ADR-0030) 표와 설정을 그대로 쓴다.

## 결과

- 확신도: 높음 — 저장 범위와 권한 경계. 중간 — 크기(근거 후보 기록은 계산값이라 데스크탑에서 실제 답으로 잰다).
- 검증 시점: 백엔드 저장 작업 뒤 데스크탑에서 실제 답의 처리 기록 크기와 30일 지우기를 확인한다.
- 다시 볼 조건: 운영(M6)에서 하루 답 수가 가정보다 크게 많을 때, 대화 기록 자체의 보관 기간을 정할 때(질문에 개인정보가 들어올 수 있다).
