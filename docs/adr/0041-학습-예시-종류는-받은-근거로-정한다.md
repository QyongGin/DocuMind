# ADR-0041: 학습 예시 종류(답할지 거절할지)는 계획이 아니라 챗봇이 받은 근거 8개로 정한다

- 상태: 채택
- 날짜: 2026-10-26
- 관련: ADR-0037(학습 데이터 검토), ADR-0039(목표 답 모양), ADR-0040(초안 모델), `docs/rag/m2/6단계-학습예시-설계-20261021.md` §2·§6, `docs/rag/m2/6단계-학습예시-방식-점검-20261025.md` 문제 1, `docs/rag/research/학습셋-평가셋-최신실무-20261025.md`

## 맥락

- 학습 예시는 입력(질문 + 운영과 같은 검색으로 받은 근거 8개)과 출력(목표 답)이다. 예시 종류(`kind`)는 그 예시로 가르칠 행동이다 — 답 계열(`fact`·`procedure`·`table`·`multi`), 일부만 있음(`partial`), 거절(`refuse_guide`·`refuse_offtopic`).
- 지금까지 종류는 묶음 계획(`plan`)에서 정했고, Gemma는 질문을 만들 때 질문 재료 청크 하나만 본다. 목표 답은 그 뒤 근거 8개를 보고 쓴다. 자동 검사(`checks.shape_check`)는 목표 답을 계획한 종류와 비교했다.
- [실측] 첫 묶음 `r1-c`에서 질문 56개 중 20개가 '계획과 받은 근거가 어긋남'(모양 검사·질문 청크가 근거에 없음·답 근거가 지워짐 중 하나 이상)으로 버려졌다. 예: `r1-c-0011`은 거절 계획(`refuse_guide`)으로 만든 질문인데, 질문 재료(장학금지급규정)에 없던 답이 다른 문서(장학금지급규정 시행세칙)에 있어 검색이 가져왔고, 목표 답은 근거대로 답했지만 버려졌다.
- 원인은 설계의 가정 "질문 재료 청크에 없으면 학교 문서 전체에도 없다"였다. 학교 문서는 규정·시행세칙·공지·FAQ에 같은 내용이 되풀이된다. 질문을 만드는 시점에는 검색 결과를 알 수 없다(근거 8개는 질문으로 검색해야 생긴다).

## 결정

1. 예시 종류는 **목표 답과 챗봇이 받은 근거 8개 기준으로 다시 정하고**, 그 종류로 자동 검사한다(2026-10-26 결정). 계획한 종류는 `kind_planned`에 남긴다.
2. 판단은 주 모양(가) 목표 답의 행동으로 한다: 운영 거절 문장으로 시작하면 거절, 답 속에 거절 말투가 섞이면 일부만 있음, 아니면 답(쓴 근거 번호가 둘 이상이면 `multi`, 아니면 `fact`).
3. 답 계획을 거절·일부만 있음 쪽으로 바꾸는 것은 **계획한 답 근거가 프롬프트에 오지 않았을 때만** 한다(질문 재료 청크가 근거 8개에 없거나, 답 근거 글이 프롬프트에 없음). 청크가 검색됐고 답 근거도 남았는데 거절했다면 목표 답이 틀린 것이라 바꾸지 않고 떨어뜨린다.
4. 거절 계획에서 바뀐 답에는 답 근거·왕복 검색 검사를 하지 않는다(답 근거가 없다). 값이 없는 말글 답은 글자 겹침으로 가르지 않고 Claude 판정에 확인 메모를 넘긴다. 종류를 바꾼 예시에는 모두 "받은 근거에 정말 그 답이 있는지(없는지) 확인" 메모를 단다.
5. 운영 거절 문장이 아닌 거절 말투("확인이 어렵습니다", "모르겠습니다" 등)는 답으로 보지 않는다 — 답 예시로 바뀌지 않고 모양 검사에서 떨어진다.
6. 종류별 개수(1회차 비율)는 바뀐 종류로 센다. 다음 묶음 계획에서 모자란 종류를 더 배정한다.

## 버린 대안

- 지금처럼 버리기: 근거대로 맞게 쓴 목표 답을 버리고, 버려지는 예시가 바로 가르치고 싶은 경우다 — 다른 문서에 답이 있어도 찾아 답하기(학습 전 A.X 과잉 거절 7.4%), 받은 근거에 없으면 지어내지 않기(오답률 6.0%).
- 질문 단계에서 계획을 더 정확히 맞추기(질문 모델 바꾸기, 더 많은 청크 보여 주기): 근거 8개는 질문으로 검색해야 생겨서, 어떤 모델이 만들어도 검색 결과를 미리 알 수 없다.
- 어긋난 예시를 질문부터 다시 만들기: 같은 일이 되풀이되고 데스크탑 시간이 든다.

## 근거

- [실측] 첫 묶음 복사본에 적용(2026-10-26): 종류가 바뀐 예시 14개, 자동 검사 통과 34 → 46개. 바뀐 방향은 거절 계획 → 답 6, 일부만 있음 → 답 3, 답 → 거절 3(질문 청크가 검색되지 않은 경우), 바뀌었지만 다른 검사로 떨어짐 2. 청크가 검색됐는데 거절한 `r1-c-0050`은 바꾸지 않았다.
- [원문] Anthropic "Reduce hallucinations"(공식 문서): 문서에 정보가 없으면 "I don't have enough information"이라 말하게 하고 "only use information from provided documents".
- [원문] OpenAI "Supervised fine-tuning"(공식 문서): 좋은 예시는 "Whatever prompts and outputs you expect in your application, as realistic as possible".
- [원문] Peng 외(Salesforce Research), "Unanswerability Evaluation for Retrieval Augmented Generation", ACL 2025: 문서에 없는 질문은 만든 뒤 원래 색인에서 검색해 "each chunk is checked to confirm it does not contain the answer".
- [판단] 학습 입력이 근거 8개이므로 맞는 행동도 근거 8개로 정해야 입력과 정답이 어긋나지 않는다(학습-운영 불일치, training-serving skew를 데이터 단계에서 막음).

## 네 관점

- 서비스: 챗봇이 운영 때와 같은 기준(받은 근거)으로 답할지 거절할지를 배운다. 틀린 정답은 자동 검사와 Claude 판정이 그대로 거른다.
- 비즈니스: 같은 데스크탑 시간에 쓸 수 있는 예시가 늘어난다(첫 묶음 통과 +12).
- 유지보수: 답할지 거절할지를 근거 8개 한 곳에서 정한다 — 계획과 정답 두 곳에서 정하던 것을 없앴다. 바꾼 이유가 예시마다 남아 인계 뒤에도 추적된다.
- 확장: 거절 종류를 늘릴 때(틀린 전제·정보 부족 질문) 같은 방식으로 받은 근거로 확정한다.

## 결과

- 확신도: 높음(받은 근거 기준이 맞다는 것), 중간(규칙으로 가른 행동이 맞는지 — Claude 판정과 첫 묶음 사람 표본에서 본다).
- 검증 시점: 고친 방식으로 만든 새 첫 묶음의 Claude 판정에서 '종류 바꿈' 예시의 탈락률, 사람 30개 표본.
- 다시 검토할 조건: 종류를 바꾼 예시의 Claude 탈락률이 바꾸지 않은 예시보다 뚜렷이 높으면 바꾸는 조건(결정 2·3)을 좁힌다.
- 구현: `tools/corpus/corpus/trainset/checks.py` `decide_kind`, `pipeline.run_checks`(종류와 `kind_planned` 기록).
