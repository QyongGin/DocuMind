# ADR-0002: 마일스톤 M0~M6와 진행 순서

- 상태: 채택
- 날짜: 2026-09-30 (2026-10-01·10-04 갱신)
- 관련: 총괄계획 §4

## 맥락

예전 로드맵 두 개(R0~R4, P0~P4)가 겹쳐 있었고, 즉각적인 실행 제안이 이어져 흐름을 따라가기 어려웠다.

## 결정

- 실행 계획은 마일스톤 M0~M6(출발선 정리 → 실제 문서·평가셋 → 답변 품질 → 사용자·권한 → 운영 준비 → 학교 제안 → 학교 운영)로 하고, 예전 로드맵은 여기에 흡수한다.
- 품질(M2)을 사용자·권한(M3)보다 먼저 한다.
- 설계를 먼저 끝내고 순서대로 실행한다. ML 설계를 설계 6단계로 추가해 M1 전에 끝냈다(2026-10-01).
- M1 순서: 문서 대장 → 수집 → 개인정보 확인 → 용도 고정 → 형식 지원 → 업로드 보강 → 표본 테스트 → 서비스 색인 → (데이터셋용 색인) → 평가셋 → 채점기 → 베이스라인 → 모델 비교. 2026-10-04에 평가셋을 데이터셋용 색인보다 먼저 하도록 바꿨다(데이터셋용 색인은 M2 학습 데이터의 재료라 평가셋의 전제가 아님).

## 근거

- [판단] 제안의 핵심 근거가 답변 품질이고, 권한·계정은 표준 웹 개발이라 예측이 쉽다.
- [판단] M1의 수집·평가셋이 곧 학습 데이터와 맞물려, 학습·평가 분리 규칙을 수집 전에 정해야 했다.

## 결과

- 진행 상태는 GitHub Issues·Projects(마일스톤 M1~M6)에서 본다. 순서표는 총괄계획 §4.2.
