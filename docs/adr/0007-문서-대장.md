# ADR-0007: 문서 대장(document registry)

- 상태: 채택
- 날짜: 2026-10-01
- 관련: 이슈 #123, `docs/rag/m1/문서대장-형식-20261001.md`

## 맥락

수집·개인정보·용도·업로드 상태를 문서마다 추적할 기준이 필요했다.

## 결정

- 문서 대장은 SQLite 파일 하나(`Assets/corpus/ledger.sqlite`)를 원본으로 두고, 사람이 확인할 칸만 CSV로 내보내고 받는다.
- 한 행은 파일 하나(본문·첨부 각각, 상위 글 ID로 연결). 필드는 출처·파일(자동), 내용 판단(자동 추정 → 사람 확인), 용도(규칙)로 묶는다.
- 대장 ID는 원래 주소에서 나오는 `사이트/종류/번호`, 문서 묶음은 `종류:대표이름`. 유효 기간이 지나면 "보관"으로 바뀐다.
- 원본 문서는 맥북 `Assets/corpus/`에 모으고, 챗봇의 업로드 기능으로 데스크탑에 올린다.

## 버린 대안

- CSV 하나: 수집기와 사람이 서로 덮어쓸 위험.
- 서비스 MySQL: 데스크탑을 켜야 수집할 수 있고, 업로드하지 않을 문서까지 들어간다.

## 근거

- [원문] SQLite 공식 문서 "SQLite competes with fopen()"(응용 프로그램 파일 형식).
- [판단] 다시 수집해도 같은 ID가 나와야 이어 받기·중복 검사가 된다.
