| 한 번 하고 끝난 운영 작업(브랜치 정리, 예전 Docker 자원 삭제, 예전 색인 정리 등) | 그 작업의 PR과 보고서 |

| 지금 위치와 다음 할 일 | `docs/project/현재-상태.md` |

## 쓰는 법

1. 새 결정은 다음 번호로 파일을 만든다: `NNNN-짧은-제목.md`.
2. 결정을 바꿀 때는 옛 ADR을 고치지 않는다. 새 ADR을 쓰고, 옛 ADR의 상태를 `대체됨 → ADR-NNNN`으로 바꾸고, 새 ADR의 결과에 "대체: ADR-NNNN"을 적는다.
3. 이 README의 목록 표를 함께 고친다.
4. 같은 PR에 결정의 근거가 된 보고서를 함께 넣는다.

```markdown
# ADR-NNNN: 제목

- 상태: 제안 | 채택 | 대체됨 → ADR-NNNN
- 날짜: YYYY-MM-DD
- 관련: 이슈·PR·문서

## 맥락
왜 정해야 했나. 무엇이 문제였나.

## 결정
무엇을 하기로 했나.

## 버린 대안
대안과 버린 이유.

## 근거
[실측] 직접 잰 값 · [원문] 공식 문서·논문 원문 · [계산] 계산 · [판단] 판단(누가)

## 결과
결정 뒤 따라오는 일, 검증 시점, 대체 관계.
```
