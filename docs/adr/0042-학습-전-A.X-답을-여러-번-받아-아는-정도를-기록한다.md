# ADR-0042: 학습 예시마다 학습 전 A.X 답을 여러 번 받아 아는 정도를 기록하고, 틀린 답은 선호 학습 재료로 남긴다

- 상태: 채택
- 날짜: 2026-10-26
- 관련: ADR-0033(학습 필수), ADR-0039(목표 답 모양), ADR-0040(초안 모델), ADR-0041(종류는 받은 근거로), `docs/rag/m2/6단계-학습예시-방식-점검-20261025.md` 문제 2, `docs/rag/research/학습셋-평가셋-최신실무-20261025.md` [4]·[5]·[10]·[15]

## 맥락

- 학습 예시를 만들 때 학습 전 A.X 답을 한 번(운영 설정 temperature 0) 받아 두었지만 전후 비교용으로만 두고 쓰지 않았다(설계 §4). A.X가 이미 맞히는 예시와 틀리게 단정하는 예시가 같은 비중으로 들어간다.
- 운영 설정은 temperature 0이라 같은 프롬프트로 여러 번 불러도 같은 답이 나와, 아는 정도(가끔 맞히는지)를 잴 수 없다.

## 결정

1. 근거를 붙인 직후(`trainset probe`) 같은 운영 프롬프트로 학습 전 A.X 답을 **4번 더** 받는다. 모델·문맥 길이·답 길이는 근거를 붙일 때 AI 서버가 알려 준 운영값(`ax40light:q4km`, 12,288, 512)을 쓰고, temperature만 0.7로 둔다.
2. 자동 검사 때 운영 답 1개 + 표본 4개를 규칙으로 채점해 예시마다 `probe`(답 수·판단한 수·맞힌 수·틀린 답)를 남긴다. 규칙: 거절 종류면 거절했으면 맞음. 답 종류면 거절하지 않고 목표 답의 값을 하나 이상 말하고 말한 값이 모두 근거에 있으면 맞음. 목표 답에 값이 없으면 판단하지 않는다.
3. 1회차 학습 데이터에는 아직 쓰지 않는다(기록만). 쓰는 법 — 이미 다 맞히는 예시 줄이기, 틀린 답을 '나쁜 답'으로 둔 선호 학습(DPO) — 은 7단계 학습 설계에서 1회차 결과를 보고 정한다.

## 버린 대안

- 지금처럼 한 번만: 아는 정도를 잴 수 없다.
- 학생 답을 교사가 토큰마다 채점하는 온정책 증류(Qwen3 기술 보고서): 교사·학생 토크나이저가 같아야 하는데 Gemma와 A.X가 다르고, A10G 24GB에 두 모델을 함께 올리기 어렵다.
- A.X 답 중 통과한 것을 목표 답으로 쓰기: 운영 A.X 답은 출처 번호를 거의 달지 않아(첫 묶음 56개 중 1개) 목표 답 모양(ADR-0039)에 맞지 않는다.
- 1회차부터 아는 정도로 학습 비중 조절: 1회차는 ADR-0039의 두 모양 비교가 이미 있어, 바꾸는 것을 하나 더 넣으면 무엇이 효과였는지 가를 수 없다.

## 근거

- [원문] Meta, "The Llama 3 Herd of Models"(arXiv 2407.21783) §4.3.6: "post-training should align the model to 'know what it knows' rather than add knowledge" — 학생 모델 답을 여러 번 뽑아 원문 대비 채점하고, 일관되게 틀리게 단정하는 질문에 거절 답을 만든다. §4.2.2: 최신 모델의 여러 답 중 보상 모델이 고른 것을 지도 학습 데이터로 쓴다.
- [원문] Gekhman 외(Google Research·Technion), "Does Fine-Tuning LLMs on New Knowledge Encourage Hallucinations?", EMNLP 2024: 모델이 맞히는 정도로 예시를 Known/Unknown으로 가르고, 모르던 사실을 담은 예시는 지어내기를 늘리며, Unknown 예시를 "I don't know"로 바꾸면 과적합이 준다.
- [원문] Lee 외(NAVER Cloud·서울대·KAIST), "Knowledge-Weighted Fine-Tuning", Findings of EMNLP 2026: 여러 번 샘플링해 예시마다 아는 정도를 점수로 내고 학습 신호를 조절한다.
- [원문] Anthropic "Reduce hallucinations"(공식 문서): "Run Claude through the same prompt multiple times... Inconsistencies across outputs could indicate hallucinations".
- [원문] Hugging Face TRL `DPOTrainer`(공식 문서): 기준 모델을 따로 주지 않으면 학습 시작 모델을 쓴다 — 틀린 답을 '나쁜 답'으로 두는 선호 학습을 모델 한 벌로 할 수 있다.
- [판단] temperature 0.7, 4번: 0이면 같은 답만, 너무 높으면 엉뚱한 답이 늘어 아는 정도를 흐린다. 4번은 데스크탑 시간(예시당 A.X 생성 4번)과 정밀도의 타협이다. 1회차 결과로 다시 본다.

## 네 관점

- 서비스: 학습이 A.X가 실제로 틀리는 곳(틀린 단정, 과잉 거절)을 겨냥할 수 있게 된다.
- 비즈니스: 데스크탑 시간이 예시당 A.X 생성 4번만큼 는다. 사람 시간은 늘지 않는다.
- 유지보수: 같은 운영 프롬프트·설정으로 받아 기록하므로, 재학습 때 같은 명령으로 다시 잰다.
- 확장: 틀린 답이 쌓이면 선호 학습(2회차)의 재료가 된다.
