# ADR-0034: 학습하고 운영할 기반 모델은 A.X 4.0 Light — 약점인 틀린 답은 프롬프트와 학습으로 줄인다

- 상태: 채택
- 날짜: 2026-10-17
- 관련: ADR-0031(대체), ADR-0026·0027·0030·0033, `docs/rag/m2/모델선정-비교계획-20261015.md`(대체), `docs/rag/research/A.X-4.0-Light-사용권-조사-20261017.md`, `docs/rag/m2/A.X-기준-계획-20261017.md`

## 맥락

- ADR-0031은 M2 검색 실험 모델을 Gemma 4 12B로 두고, 학습·운영 모델은 M2 끝(베이스라인 ②)에 Gemma 4 12B와 A.X 4.0 Light 중에서 고르기로 했다.
- 학습을 반드시 하기로 하면서(ADR-0033) 학습 계획을 한 모델에 맞춰 세울 필요가 생겼다.
- [실측] 미리 정한 고르는 순서(ADR-0027: 학습 조건 → 틀린 답이 가장 적은 후보와 짝 비교해 의미 있게 많은 후보를 뺌 → 정답률 1위 → 같은 수준이면 한국어 지문 읽기)의 결과는 프롬프트에 따라 갈렸다. 13번 비교(사람 규칙 검색의 프롬프트, 본 250문항)에서는 A.X가 뽑혔다 — 틀린 답 짝 비교 p=0.077로 거르기를 통과하고, 정답률은 Gemma와 같은 수준, 우리 설정의 KorQuAD 1.0에서 EM 78.2 대 74.2(p=0.038)로 앞섰다. E3(지금 쓰는 순위 융합의 프롬프트, 개발셋 149문항)에서는 틀린 답 10 / 1(p=0.012)로 A.X가 빠져 Gemma가 1순위가 됐다(ADR-0031, `docs/rag/m1/모델비교-20261014.md`).
- [판단] 이 결정은 E3의 순서 결과 대신, 학습을 반드시 한다는 전제(ADR-0033)에서 속도·크기·학습 뒤 합치기를 더 무겁게 보고 A.X의 약점(틀린 답)은 프롬프트와 학습으로 겨냥한다는 사용자 판단이다(2026-10-17). 그래서 틀린 답이 줄지 않으면 Gemma를 다시 보는 조건을 둔다(결과).

## 결정

1. 학습하고 운영할 기반 모델은 A.X 4.0 Light(SKT, 7.26B, Apache 2.0)다(2026-10-17 사용자 결정). ADR-0031을 대체한다.
2. A.X의 약점(틀린 답, 답없는 질문의 거절)은 프롬프트 단계와 학습 1회차가 먼저 겨냥한다. M2 끝 성공 판정(ADR-0026)의 선은 그대로다.
3. 앞으로의 M2 실험에서 답을 만드는 모델은 A.X 4.0 Light다. 먼저 지금 운영 설정(순위 융합·근거 8개)으로 A.X 새 기준선을 잰다. Gemma 4 12B는 그 비교 기준으로만 남긴다.
4. 운영 기본 모델(`OLLAMA_LLM_MODEL`)은 A.X 새 기준선을 잰 뒤 바꾼다.

## 버린 대안

- Gemma 4 12B 유지: 틀린 답이 가장 적지만(1 / 149) 생성이 약 2배 느리고(생성만 잰 응답 시간 중앙 3.28초 대 1.58초), 16비트 가중치(23.92GB)가 학습 서버의 RAM 16GB에도 GPU 24GB에도 한 번에 들어가지 않아 학습 뒤 합칠 때 나눠 합치기·스왑 같은 우회가 필요하다. A.X(14.52GB)는 GPU 24GB 안에서 합칠 수 있다[계산 — 학습 가능성 실측(계획 3단계)에서 확인].
- 베이스라인 ②까지 결정을 미룸: 학습 데이터·학습 설정을 한 모델에 맞춰 준비할 수 없다.

| 쉬운 정답률 | 92.9% (52/56) | 100% (56/56) | [실측] 같은 수준 p=0.125 |

- [실측] A.X 틀린 10건 = 근거 없이 답함 3(정답 근거가 프롬프트에 없음 1, 답없는 문항 2) · 표 잘못 읽음 5 · 글 잘못 읽음 2. 2026-10-20 결과 파일로 다시 확인했다(`모델비교-20261014.md`의 "9건이 잘못 읽음"은 고침).
- [실측·판단] 두 모델은 같은 프롬프트(E1의 순위 융합 상위 5개)로 비교해 공정하지만, 그 프롬프트의 근거 블록 61%(624 / 1,025)는 원문 없이 발췌만 들어갔고 A.X가 잘못 읽은 7건 중 6건은 정답 문서 블록 일부가 발췌만이었다(`청크-임베딩-평가-20261020.md`). 근거 블록에 원문을 넣은 뒤(계획 4단계) 틀린 답 차이가 달라질 수 있다.
- [계산] 서빙 크기가 작아 데스크탑 12GB에 생성 모델 + 임베딩(4.1GB) + 재순위 서버(약 1.3~2GB)가 함께 올라갈 여지가 생긴다 — Gemma로는 못 올렸다(3단계 보고서 §7). 실측으로 확인한다.

## 네 관점

- 서비스: 답이 약 2배 빨리 나오고 과잉 거절이 적다. 틀린 답은 학습·프롬프트로 줄여야 하며, 줄지 않으면 운영에 넣지 않는다(ADR-0033 결정 2).
- 비즈니스: 작은 모델이라 운영 GPU 비용이 낮다. 국산 기업(SKT) 모델이지만 바탕은 Alibaba Qwen2.5라 학교 제안서에서 설명한다.
- 유지보수: 7B라 학습·병합·변환이 학습 서버 한 대 안에서 끝난다(GPU에서 합칠 수 있는지는 계획 3단계에서 실측).
- 확장: 최대 문맥 16,384토큰 — 근거를 크게 늘리는 설계는 이 한도 안에서 한다.

## 결과

- 확신도: 중간 — A.X의 틀린 답이 프롬프트·학습으로 목표선 아래로 내려가는지는 아직 모른다.
- 검증 시점: A.X 새 기준선, 프롬프트 단계(근거 블록 원문 넣기 포함), 학습 1회차 전후 비교.
- 근거 재확인(2026-10-20): 표의 실측값은 결과 파일(`Assets/eval/work/m2/compare_e3_ax_vs_gemma.json`, 두 실행의 생성 기록)에서, 원문값은 Hugging Face 저장소(A.X 커밋 `ba21c20` — 2026-10-01 변환 때와 같음, LICENSE·모델 카드·`config.json`의 `max_position_embeddings` 16384)와 Gemma 4 라이선스 페이지에서 다시 확인했다.
- 결정 4 이행(2026-10-20): A.X 새 기준선(`docs/rag/m2/2단계-A.X-새기준선-20261020.md`)을 잰 뒤 운영 기본 생성 모델을 `ax40light:q4km`으로 바꿨다. 변환·등록 절차와 모델 대장은 ADR-0036.
- 다시 검토할 조건: 프롬프트·학습 뒤에도 A.X가 오답률 5% 이하·답없음 거절 90% 이상을 넘지 못하면, Gemma 4 12B 학습을 다시 검토한다.
