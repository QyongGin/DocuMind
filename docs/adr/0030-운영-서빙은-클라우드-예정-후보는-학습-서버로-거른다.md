# ADR-0030: 운영 서빙은 클라우드 예정 — 모델 후보는 서빙 GPU가 아니라 학습 서버로 거른다

- 상태: 채택
- 날짜: 2026-10-13
- 관련: ADR-0003(실행 환경), ADR-0004(생성 모델 후보·배포 조건), ADR-0011(서빙 GPU 구성과 모델 배포), ADR-0027(모델 선택 1단계), ADR-0029(Mi:dm 2.0 Base), ADR-0006·0010(학교 자료·AWS 데이터 범위), 총괄계획 M6

## 맥락

- ADR-0004와 ADR-0027 1단계는 "데스크탑 12GB GPU에 생성 문맥 8,192 + 임베딩 4B와 함께 올라감"을 배포 조건으로 두었다. 이 조건 때문에 A.X 3.1 Light(KV 캐시가 토큰당 512KB)는 품질 비교용으로, Mi:dm 2.0 Base(11.5B)는 교사 후보로만 넣었다(ADR-0029).
- 2026-10-13 사용자: 학교 운영 서버는 클라우드에서 돌릴 계획이라 서빙 GPU 크기는 제약이 아니다. 학습 서버에는 들어가야 한다.

## 결정

1. 학교 운영(M6) 서빙은 클라우드에서 할 예정이다. 지금 개발·평가·색인은 그대로 데스크탑에서 한다(AGENTS.md §3).
2. 모델 후보 조건에서 '데스크탑 12GB 서빙'을 뺀다. 대신 학습 서버(AWS g5.xlarge, A10G 24GB, RAM 16GB)에서 LoRA 또는 QLoRA로 학습이 되는지로 거른다. ADR-0027 1단계를 이 조건으로 바꾼다.
3. 그래서 A.X 3.1 Light와 Mi:dm 2.0 Base도 서비스 후보다. 13번 비교에서 고르기 대상에 넣는다. Mi:dm의 '교사 후보' 역할(ADR-0029)은 서비스 후보로 바뀐다.
4. 클라우드 제공사, 클라우드에 올릴 데이터 범위(색인 전체·사용자 질문 기록), 비용, 학교의 이용 허락과 개인정보 검토는 M6 전에 따로 정한다. 그때까지 ADR-0006·0010의 데이터 범위는 그대로다.

## 버린 대안

- 12GB 서빙 조건 유지: 실제 운영 환경과 다른 제약으로 후보를 미리 뺀다.
- 클라우드 제공사·데이터 범위까지 지금 정하기: 학교 이용 허락(M5)과 개인정보 검토가 먼저라 지금 정할 근거가 없다.

## 근거

- [판단] 사용자 계획(2026-10-13): 운영은 클라우드에서, 학습은 AWS 학습 서버에서.
- [계산] 학습 서버 조건(`docs/rag/research/기반모델-후보-상세조사-20261001.md` §9): 7~8B는 QLoRA 약 6GB로 여유, 16비트 LoRA는 약 22GB로 빠듯. Mi:dm 2.0 Base(11.5B)는 QLoRA 약 7.5GB로 가능, 16비트 약 29GB로 불가. 11~12B는 학습 뒤 병합할 때 RAM 16GB가 빠듯하다(학습 단계 실측 필요).
- [실측] A.X 3.1 Light는 12GB에서 임베딩과 함께 못 올라가서 배포 후보에서 빠졌다(ADR-0004). 그 조건이 사라지면 후보로 돌아온다.
- [원문] ADR-0010: "AWS에는 학습 몫만 올린다" — 클라우드 운영은 이 범위를 넘으므로 M6 전에 다시 정해야 한다.

## 네 관점

- 서비스: 후보가 둘 늘어 더 나은 모델을 고를 여지가 생긴다. 응답 속도는 클라우드 GPU에 따라 달라 M6에서 다시 잰다.
- 비즈니스: 데스크탑 전기 요금 대신 클라우드 비용이 생긴다. 학교 문서와 질문이 외부로 나가는 것에 대한 설명과 허락이 필요하다. 중국 계보 모델을 "학교 서버 안에서만 돌아 데이터가 나가지 않는다"로 설명하던 논리(`A안-후보모델-심층조사-20261001.md` §3.4)도 다시 써야 한다.
- 유지보수: 운영 환경이 정해질 때까지 개발·평가는 데스크탑이라 지금 절차는 그대로다. 모델 선택 조건이 "학습 서버에서 학습되는가" 하나로 단순해진다.
- 확장: 클라우드는 GPU를 키울 수 있지만, 학습 서버(A10G 24GB)가 새 상한이다. 더 큰 모델은 학습 서버를 키워야 한다.

## 결과

- ADR-0027 1단계를 바꾸고, ADR-0004·0029에 이 ADR을 가리키는 메모를 단다. 총괄계획 M6에 "운영 서빙은 클라우드 예정"을 적고, AGENTS.md §3에 한 줄을 더한다.
- 2026-10-13 같은 기준으로 후보를 둘 더한다(사용자: "학습 서버에 들어갈 수 있다면 후보"): **Gemma 4 12B**(Google, 11.95B, Apache 2.0)와 **Qwen3-14B**(Alibaba, 14.8B, Apache 2.0). 둘 다 [계산] QLoRA 약 8~10GB로 학습 서버에 들어가고, [원문] 라이선스 파일로 학교 챗봇 사용을 확인했다(`docs/rag/research/후보모델-학교챗봇-사용가능-재확인-20261013.md`). 학습 뒤 병합 메모리(RAM 16GB)는 Mi:dm 2.0 Base와 같이 학습 단계에서 실측한다.
- 13번 비교에서 하려던 "12GB 배포 조건 실측(`ollama ps`)"은 하지 않는다.
- 확신도: 높음(후보 조건 변경), 낮음(클라우드 운영 세부 — 아직 정하지 않음).
- 검증 시점: M6 계획 때 클라우드 제공사·데이터 범위·비용을 ADR로 정한다. 학습 단계에서 Mi:dm 2.0 Base를 고르게 되면 병합 메모리를 실측한다.
