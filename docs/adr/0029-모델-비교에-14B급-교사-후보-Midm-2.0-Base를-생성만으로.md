# ADR-0029: 13번 모델 비교에 14B급 교사 후보로 Mi:dm 2.0 Base(11.5B)를 더해 생성만 잰다

- 상태: 채택
- 날짜: 2026-10-13
- 관련: 이슈 #130, ADR-0004(생성 모델 후보·판단 원칙), ADR-0009(구조 먼저, ML은 남은 실패에만), ADR-0010(학습 데이터), ADR-0025(짝 비교), ADR-0027(모델 선택 순서), 현재 상태 '모델 재검토(2026-10-08)'

## 맥락

- 교수님 제안(2026-10-08): 24GB 학습 서버에 맞는 큰 모델로 품질을 최대화하자. 사용자 의견: 서빙 GPU가 12GB라 8B급으로 서빙하고, 14B급과의 품질 차이를 13번에서 생성 단계만 재서 지식 증류(14B급 교사가 만든 답으로 8B급 학생을 학습)를 할지 정한다.
- '생성만 잰다'는 2단계 평가(ADR-0004)다. 베이스라인 실행에 기록된 프롬프트(질문 + 검색 결과)를 그대로 쓰고 답을 쓰는 모델만 바꿔 같은 채점으로 비교한다. 학습은 하지 않는다.
- 교사로 쓰려면 라이선스가 그 모델의 답으로 다른 모델을 학습하는 것을 막지 않아야 하고, 학교에 인계할 학생 모델에 조건이 붙지 않아야 한다.

## 결정

13번 비교 대상에 **KT Mi:dm 2.0 Base(11.5B, Instruct)** 를 더한다(2026-10-13 사용자 결정). 서비스 후보가 아니라 교사 후보로, 12GB에 단독으로 올려 생성만 잰다. 8B급 후보 4개(A.X 4.0 Light, A.X 3.1 Light, Gemma 4 E4B, Qwen3-8B)와 베이스라인 EXAONE 3.5도 같은 방식으로 잰다.

- 모델 파일은 A.X처럼 공식 가중치(Hugging Face `K-intelligence/Midm-2.0-Base-Instruct`)에서 직접 GGUF Q4_K_M으로 변환한다(남이 만든 양자화 파일을 쓰지 않음).
- 증류를 할지는 13번 결과로 M2에서 정한다. 이 ADR은 측정 대상만 정한다.

## 버린 대안

| 후보 | 버린 이유 |
|---|---|
| Qwen3-14B(알리바바, Apache 2.0) | 라이선스 조건은 없지만 국산이 아니고 12GB 단독에도 빠듯하다([계산] 가중치 9.3GB + 문맥 8,192 KV 1.25GB). 함께 재면 판정 몫이 실행 하나만큼 는다 |
| HyperCLOVA X SEED 14B Think(네이버) | [원문] 그 모델의 답으로 학습한 모델 이름 앞에 "HyperCLOVA X"를 붙이고 "Powered by HyperCLOVA X"를 표시해야 한다(라이선스 3.1조). 자체 구조(`trust_remote_code`)라 Ollama 적재도 확인되지 않았다 |
| Kanana 1.5 15.7B-A3B(카카오) | [원문] 답으로 학습한 모델을 배포하면 이름 앞에 "Kanana", "Powered by Kanana" 표시(라이선스 3.1조 v). 학교 인계가 배포다. 회사 표의 KMMLU(Instruct 0-shot CoT 48.92)가 같은 회사 8B(48.28)와 비슷하다 |
| Gemma 3 12B(구글) | [원문] 약관이 답으로 학습한 모델도 '파생 모델'로 정의해("methods based on the generation of synthetic data Outputs") 학생 모델에 사용 제한이 따라붙는다 |
| Gemma 4 26B-A4B·31B | Apache 2.0이지만 12GB에 올라가지 않는다 |
| 14B급을 재지 않음 | 증류 여부를 근거 없이 정하게 된다 |

## 근거

- [원문] Mi:dm 2.0 Base 모델 카드: "An 11.5B parameter dense model", "Mi:dm 2.0 is licensed under the MIT License", "extends an 8B-scale model by applying the Depth-up Scaling (DuS) method"(원래 8B급 모델 이름은 카드에 없다), 공개 2025-07-04. MIT는 출력 사용을 제한하지 않는다.
- [원문, 회사 발표] 같은 카드의 KT 평가(설정 미기재): KMMLU 57.3(Qwen3-14B 55.4, EXAONE 3.5 7.8B 52.6), HAERAE 81.5(68.4, 72.9). **제3자 근거는 찾지 못했다** — 13번 측정이 첫 독립 확인이다.
- [원문] `config.json`: Llama 구조, 48층, KV 헤드 8, 헤드 차원 128. [계산] KV 캐시 토큰당 192KiB → 문맥 8,192에서 1.5GiB, 가중치 Q4_K_M 약 7GB → 12GB 단독 적재 가능, 임베딩 모델(약 3.4~4.4GB)과 함께는 넘친다 → 서비스 후보가 아니다.
- 기존 8B급 후보의 라이선스는 2026-10-01에 공식 원문으로 확인했다(`docs/rag/research/생성모델-라이선스-및-학습데이터-조사-20261001.md` §2, `A안-후보모델-심층조사-20261001.md`). 모델의 학습 데이터 저작권은 각 회사 책임이며 우리가 검증할 수 없다.

## 네 관점

- 서비스: 서빙은 8B급 12GB 그대로다. 14B급이 의미 있게 나으면 증류로 8B 답 품질을 올릴 근거가 생긴다.
- 비즈니스: MIT라 학교 인계 때 학생 모델 이름·표시 조건이 없다. 국산 모델로 설명할 수 있다.
- 유지보수: Llama 구조라 llama.cpp 변환·Ollama 서빙이 다른 후보와 같다.
- 확장: 증류를 하면 AWS g5.xlarge(24GB)에서 교사로 바로 쓴다. 평가 데이터는 데스크탑 밖으로 보내지 않는다(ADR-0008·0010).

## 결과

- 확신도: 높음(라이선스), 중간(한국어 품질 — 회사 수치뿐).
- 검증 시점: 13번 결과. 8B급 1위와 짝 비교(ADR-0025)에서 정답률이 의미 있게 높고 환각률이 의미 있게 높지 않으면 M2에서 증류를 검토한다. 같은 수준이면 증류는 하지 않는다.
