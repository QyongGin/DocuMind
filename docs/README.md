## 2. 폴더 구조

| 폴더 | 역할 | 커밋 |
|---|---|---|
| `project/` | 현재 상태(인수인계 노트), 총괄계획, 설계 6단계 근거 대장 | 함 |
| `adr/` | 설계·기술 결정 기록(결정 하나 = 파일 하나) | 함 |
| `workflow/` | 작업 흐름, PR·브랜치·문서 작성 규칙, AGENTS 운영 기준, 클라우드 세션 절차 | 함 |
| `development/` | 환경값 표, 데스크탑 작업 절차, 알려진 문제 | 함 |
| `deployment/` | 백업·복원 절차 | 함 |
| `rag/m1/` | M1(문서 대장·수집·형식 지원·업로드·색인·평가셋) 설계·구현 보고서 | 함 |
| `rag/research/` | 기반 모델·라이선스·학교 문서 원천·대기업 사례 조사(2026-10~) | 함 |
| `archive/` | 지난 기록(옛 memory-bank, 옛 결정 기록·세션 로그 포함): RAG 이슈 #18·#71~#73, layout 분석, 백엔드·프론트 보고서, GCP·옛 Docker 배포, 세션 인수인계, 과제·포트폴리오, 옛 조사·계획 | **안 함**(로컬 전용) |
| `local/` | 접속 정보(`접속정보.md`), 외부 제출물·포트폴리오 같은 개인 문서 | **안 함**(로컬 전용) |

`archive/` 안은 옮기기 전 경로를 그대로 유지한다(예: `docs/rag/issue-73/…` → `docs/archive/rag/issue-73/…`). 현재 문서의 링크도 그렇게 바꿔 두었다. 클라우드 세션에서는 `archive/`가 없으므로, 필요하면 맥북 로컬 세션에서 연다.

## 3. 새 문서 위치

| 문서 성격 | 위치 |
|---|---|
| 프로젝트 전체 계획 | `project/` (총괄계획 본문) |
| 설계·기술 결정 | `adr/` 새 ADR (`adr/README.md`의 쓰는 법) |
| 지금 위치·다음 할 일 | `project/현재-상태.md` (작업이 끝날 때마다 고침) |
| 작업 방식, 브랜치·PR·문서 규칙 | `workflow/` |
| 실행 환경, 데스크탑·맥북 절차 | `development/` |
| 배포, 백업·복원, 학교 서버 | `deployment/` |
| 마일스톤 작업의 설계·구현 보고서 | `rag/m1/`처럼 마일스톤 폴더(M2부터는 `rag/m2/` 등 새로 만든다) |
| 외부 조사 | `rag/research/` |
| 접속 주소·계정, 개인 제출물 | `local/` (커밋 안 함) |

보고서 작성 규칙은 `workflow/문서-작성-및-학습-보고-규칙.md`.

## 4. 관리 원칙

- `docs/` 루트에는 이 파일만 둔다. 새 문서는 하위 폴더에 넣는다.
- 문서를 지우지 않는다. 더 쓰지 않는 문서는 `archive/`로 옮기고(경로 유지), 현재 문서의 링크를 함께 고친다. `archive/`와 `local/`은 git 밖이라 지우면 되돌릴 수 없다.
- 공개 문서에는 비밀번호·토큰, Tailscale 주소·사용자 이름, 학교 문서 원문 대량 인용, 개인정보를 쓰지 않는다. 주소는 `<WSL IP>` 같은 자리표시로 쓴다.
- 문서 변경은 그 작업의 PR에 함께 커밋한다.
- 루트 `AGENTS.md`나 AI 운영 체계를 바꿀 때는 `workflow/AGENTS-및-AI문서-운영기준.md`를 먼저 본다.
