# 데이터셋용 색인 절차

> 학습 데이터의 질문에 운영과 같은 모양의 근거를 붙이려고, 서비스와 같은 코드로 학습 몫 문서만 따로 색인한다(ADR-0010·0038, 이슈 #128).
> 스택: compose 프로젝트 `documind_dataset` = `docker-compose.yml` + `docker-compose.gpu.yml` + `docker-compose.dataset.yml`. 화면은 띄우지 않는다.
> 넣는 문서: 학습 몫 묶음마다 한 판(유효한 판이 있으면 그 판, 없으면 가장 최근 보관 판). 평가 몫·'제외' 행은 넣지 않는다.

## 지킬 것

- 프로젝트 이름은 늘 `--project-name documind_dataset`. 빠뜨리면 다른 이름으로 빈 스택이 뜬다.
- 서비스 스택(`documind_desktop`)과 **한 번에 하나만** 띄운다. GPU와 모델 볼륨(`documind_desktop_ollama_data`)을 함께 쓴다.
- `docker compose down -v` 금지(색인·DB 볼륨이 지워진다). 다시 만들 때도 먼저 백업한다(`deploy/backup.sh documind_dataset`).
- 포트는 데스크탑 안쪽 주소에만 연다: 백엔드 `127.0.0.1:18180`, AI 서버 `127.0.0.1:18100`, Ollama `127.0.0.1:11535`(학습 예시 초안 모델). 맥북은 SSH 터널로 부른다.

## 1. 올리기 (데스크탑 WSL)

서비스 스택을 멈추기 전에, 맥북 저장소 루트에서 서비스 색인에 든 대장 ID를 뽑아 둔다(§3에서 비교).

```bash
mkdir -p Assets/corpus/index_ids
ssh desktop-win "wsl -d Ubuntu -- docker exec -i documind_desktop-ai-server-1 python -" < deploy/index_ledger_ids.py > Assets/corpus/index_ids/service.txt
```

그다음 데스크탑 WSL에서 서비스 스택을 멈추고 데이터셋 스택을 올린다.

```bash
cd ~/DocuMind && git pull --ff-only
docker compose --project-name documind_desktop -f docker-compose.yml -f docker-compose.gpu.yml --env-file .env stop -t 60
DOCKER_CONFIG=~/.docker-nocreds docker compose --project-name documind_dataset -f docker-compose.yml -f docker-compose.gpu.yml -f docker-compose.dataset.yml --env-file .env up -d --build
docker compose --project-name documind_dataset -f docker-compose.yml -f docker-compose.gpu.yml -f docker-compose.dataset.yml --env-file .env ps
```

- `ps`에서 mysql·chromadb·ollama·ai-server·backend가 healthy이고 모델 준비 두 개가 `Exited (0)`이면 된다. 관리자 계정은 `.env`의 `DOCUMIND_ADMIN_*`로 처음 뜰 때 만들어진다(서비스와 같은 아이디·비밀번호).

## 2. 문서 올리기 (맥북)

터널을 연다(맥북 터미널, 열어 둔다).

```bash
ssh -N -L 18180:127.0.0.1:18180 -L 18100:127.0.0.1:18100 -L 11535:127.0.0.1:11535 desktop-win
```

다른 맥북 터미널에서 저장소의 `tools/corpus`로 가서 고른 행을 먼저 본다(요청 없음).

```bash
.venv/bin/python -m corpus upload --set dataset --base-url http://localhost:18180 --dry-run
```

표본 10개를 올려 문서당 시간과 결과를 본 뒤, 전체를 올린다. 비밀번호는 실행할 때 묻는다(서비스 관리자 비밀번호).

```bash
.venv/bin/python -m corpus upload --set dataset --base-url http://localhost:18180 --limit 10
.venv/bin/python -m corpus upload --set dataset --base-url http://localhost:18180
```

- 진행은 대장의 `uploads` 표(대상 `dataset`)에 적힌다. 끊기면 같은 명령을 다시 실행하면 끝난 문서는 건너뛴다. 실패한 문서만 다시 하려면 `--retry-failed`.
- 맥북이 잠들면 업로드가 멈춘다. 오래 걸리면 맥북을 깨워 둔다.

## 3. 나뉘었는지 확인 (맥북, 저장소 루트)

업로드 기록(`uploads` 표)이 아니라 색인에 실제로 든 문서를 본다. 올린 뒤 지운 문서는 기록에만 남기 때문이다.

```bash
ssh desktop-win "wsl -d Ubuntu -- docker exec -i documind_dataset-ai-server-1 python -" < deploy/index_ledger_ids.py > Assets/corpus/index_ids/dataset.txt
sqlite3 Assets/corpus/ledger.sqlite "CREATE TEMP TABLE ids(doc_id TEXT);" ".import Assets/corpus/index_ids/dataset.txt ids" "SELECT l.split, l.index_status, count(*) FROM ids JOIN ledger l USING(doc_id) GROUP BY 1,2;"
sqlite3 Assets/corpus/ledger.sqlite "CREATE TEMP TABLE ids(doc_id TEXT);" ".import Assets/corpus/index_ids/service.txt ids" "SELECT l.split, l.index_status, count(*) FROM ids JOIN ledger l USING(doc_id) GROUP BY 1,2;"
```

- 데이터셋 색인: 평가 몫이 없어야 한다(학습·색인과 학습·보관만).
- 서비스 색인: 보관·제외 행이 없어야 한다(색인만). 2026-10-21 기준 698개 = 평가 226 + 학습 472.

## 4. 내리고 서비스 스택 되살리기 (데스크탑 WSL)

```bash
cd ~/DocuMind
docker compose --project-name documind_dataset -f docker-compose.yml -f docker-compose.gpu.yml -f docker-compose.dataset.yml --env-file .env stop -t 60
docker compose --project-name documind_desktop -f docker-compose.yml -f docker-compose.gpu.yml --env-file .env up -d
```

- 데이터셋 스택은 `stop`만 한다. 볼륨이 남아 있어 다음에 `up -d`로 같은 색인을 다시 쓴다.
