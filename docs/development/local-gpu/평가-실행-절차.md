# 평가 실행 절차 (M1 12번 베이스라인 · 13번 모델 비교)

> 챗봇(데스크탑)에 평가셋 질문을 묻고 채점한다. 실행기(`evalset run`)는 **맥북**에서 돌고, AI 서버는 **데스크탑**에서 돈다. 평가셋 파일(`Assets/eval/`)은 맥북에만 둔다.
> 결정: 2026-10-12 사용자 결정 ① — 평가 때만 쓰는 compose 덮어쓰기(`docker-compose.eval.yml`)로 ai-server를 데스크탑 `127.0.0.1:18000`에만 열고, 맥북에서 SSH 터널로 부른다. 근거·대안은 `docs/rag/m1/채점기-설계-20261012.md` §8·§10.

## 왜 이렇게 하나 (근거)

- [코드] `docker-compose.yml`의 `ai-server`는 포트를 열지 않는다(`expose: 8000`만). 백엔드만 컨테이너 안에서 부른다.
- [코드] AI 서버에는 인증이 없다(`ai-server/main.py`에 인증 코드 없음). 랜·tailnet에 열면 누구나 질의·업로드 API를 부를 수 있다.
- [원문] Docker 문서(Port publishing): "If you include the localhost IP address (127.0.0.1, or ::1) with the publish flag, only the Docker host can access the published container port." 같은 문서는 28.0.0보다 낮은 판에서는 같은 로컬 네트워크의 다른 기기가 localhost에 연 포트에 닿을 수 있었다고 적는다 → 아래 2단계에서 판을 확인한다.

## 1. 데스크탑 켜고 최신 코드로 올리기

원격(SSH)으로 빌드하면 Docker의 Windows 자격 증명 도우미가 실패해 공개 이미지도 못 받는다("A specified logon session does not exist", 2026-10-12 재현). 빈 설정 폴더를 써서 빌드한다(데스크탑 WSL에서 한 번만 만들어 두면 된다):

```bash
mkdir -p ~/.docker-nocreds && echo '{}' > ~/.docker-nocreds/config.json && ln -sfn ~/.docker/cli-plugins ~/.docker-nocreds/cli-plugins
```

아래 올리기 명령 앞에 `DOCKER_CONFIG=~/.docker-nocreds`를 붙인다.

데스크탑을 켜는 것까지는 `데스크탑-작업-시작-종료-절차.md`의 '작업 시작' 1~3단계와 같다. 4단계 대신 아래처럼 평가용 파일을 함께 써서 올린다(평가용 질의 옵션 PR #156, 응답 버퍼 PR #158이 들어간 develop `b5be08b` 이후).

맥북에서:

```bash
ssh desktop 'cd ~/DocuMind && git pull --ff-only && git log --oneline -1 && DOCKER_CONFIG=~/.docker-nocreds docker compose --project-name documind_desktop -f docker-compose.yml -f docker-compose.gpu.yml -f docker-compose.eval.yml --env-file .env up -d --build'
```

## 2. 열린 곳 확인 (데스크탑 안에서만 열렸나)

맥북에서:

```bash
ssh desktop 'docker version --format "{{.Server.Version}}" && curl -s http://127.0.0.1:18000/health && docker compose --project-name documind_desktop -f ~/DocuMind/docker-compose.yml -f ~/DocuMind/docker-compose.gpu.yml -f ~/DocuMind/docker-compose.eval.yml --env-file ~/DocuMind/.env port ai-server 8000'
```

- Docker 판이 28 이상이고, `{"status":"ok"}`가 나오고, 포트가 `127.0.0.1:18000`이면 된다.
- WSL 안에서 `127.0.0.1:18000`이 안 닿으면(Docker Desktop이 포트를 Windows 쪽에만 열 때) 3단계 터널을 `desktop` 대신 `desktop-win`(Windows SSH)으로 연다.
- [실측 2026-10-12] Docker 29.4.0, WSL 안과 Windows(`curl.exe`) 양쪽에서 `127.0.0.1:18000`이 응답하고, 맥북에서 데스크탑 Tailscale 주소의 18000번으로는 닿지 않는다(포트가 밖에 열리지 않음).

## 3. 맥북에서 SSH 터널 열기

맥북 터미널 하나를 이 터널에 쓴다(창을 닫으면 터널도 닫힌다).

```bash
ssh -N -L 18000:127.0.0.1:18000 desktop
```

- `ssh desktop`(WSL)이 키 교환에서 멈추면(`SSH2_MSG_KEXINIT sent`에서 진행 없음 — 알려진 증상) Windows SSH로 연다. Docker Desktop이 포트를 Windows 쪽 127.0.0.1에도 열어 이 길로도 닿는다(2026-10-12 실측).

```bash
ssh -N -L 18000:127.0.0.1:18000 desktop-win
```

- 맥북에 다른 VPN(예: Unicorn HTTPS)이 켜져 있으면 Tailscale 주소 대역(`100.64/10`)을 공유기로 보내는 경로가 생겨 SSH가 시간 초과된다(2026-10-12 실측: `netstat -rn`에 `100.64/10 → 192.168.35.1 en0`). 데스크탑 작업 동안 그 VPN을 끈다.

다른 맥북 터미널에서 확인:

```bash
curl -s http://localhost:18000/health
```

## 4. 관리자 프롬프트 확인

운영 백엔드는 관리자 화면에서 바꾼 시스템 프롬프트를 보낸다. 관리자 화면 → 프롬프트 설정이 기본값("너는 인하공업전문대학 문서를 근거로 답변하는 안내 챗봇이다.")이면 그대로 둔다. 바뀌어 있으면 그 글을 파일로 저장해 실행에 `--system-prompt-file 파일`을 붙인다(실행 기록에 지문이 남는다).

## 5. 시험 실행 (개발셋 3문항)

시험 실행은 **개발셋 문항만** 쓴다. 테스트셋 문항의 답을 열어 보면 그 문항은 개발셋으로 옮겨야 한다(ADR-0018 규칙 ③). 2026-10-12 첫 시험 실행은 `--limit 3`으로 앞 3문항을 물어 테스트셋 1문항(ev-0002)을 열어 봤다.

맥북, 저장소 `tools/corpus`에서 개발셋 문항 ID 세 개를 골라:

```bash
python3 -c "import json; print(','.join([r['id'] for r in map(json.loads, open('../../Assets/eval/evalset.jsonl')) if r.get('part') == 'dev'][:3]))"
```

```bash
.venv/bin/python -m corpus evalset run --ai-url http://localhost:18000 --out ../../Assets/eval/runs/<날짜>-try --index repro-20261010-develop15e776c --version v2 --ids <위에서 나온 ID>
```

`Assets/eval/runs/20261013-try/answers.jsonl`에서 `eval_trace.generation.done_reason`(stop·length)과 단계별 후보(`stages`)가 들어왔는지, `manifest.json`의 `runtime`(모델·온도·문맥)을 본다.

## 6. 전체 실행과 채점

```bash
.venv/bin/python -m corpus evalset run --ai-url http://localhost:18000 --out ../../Assets/eval/runs/20261013-baseline --index repro-20261010-develop15e776c --version v2
```

- 질문 346개를 하나씩 묻는다. 중간에 끊기면 같은 명령을 다시 실행하면 이어서 돈다(받은 문항은 건너뜀).
- 끝나면 채점한다. 테스트셋은 합계만 보인다.

```bash
.venv/bin/python -m corpus evalset score-run --run-dir ../../Assets/eval/runs/20261013-baseline
```

- 채점 뒤 '애매'(규칙이 정하지 못한 답)는 사람 판정 파일(`Assets/eval/judgments.jsonl`)에 판정을 적고 같은 명령으로 다시 채점한다. **테스트셋 문항의 판정 자료에는 질문·정답·챗봇 답·허용 근거 원문만 넣는다.** 프롬프트·검색 단계 기록(`answers.jsonl`의 평가용 기록)은 실패 원인 자료라, 보면 그 문항을 개발셋으로 옮겨야 한다(ADR-0018 보완 2026-10-12).
- 평가셋 판을 올린 뒤 옛 실행을 새 판으로 다시 채점할 때는(실행은 그대로) 결과를 실행 폴더 밖에 쓴다. 질문이 바뀐 문항은 '질문 바뀜'으로 빠지고, 지표 파일에 채점한 판이 남는다(`docs/rag/m1/평가셋-v3-20261013.md` §2-2).

```bash
.venv/bin/python -m corpus evalset score-run --run-dir ../../Assets/eval/runs/20261012-baseline --rescore --out ../../Assets/eval/runs/20261012-baseline.v3
```

- 두 결과를 비교할 때는(13번 모델 비교, M2 고치기 전후) 같은 평가셋 판으로 채점한 결과 폴더 둘을 짝 비교한다(ADR-0025). 기본은 개발셋만이고, 13번처럼 테스트셋을 함께 볼 때만 `--part all`(테스트셋은 합계만). 애매가 남은 결과는 거부하므로 판정을 먼저 채운다(`docs/rag/m1/짝비교-명령과-틀림-종류-20261013.md`).

```bash
.venv/bin/python -m corpus evalset compare-runs --a ../../Assets/eval/runs/20261012-baseline.v3 --b ../../Assets/eval/runs/<후보 결과> --part all
```

## 6-1. 모델 비교: 생성만 다시 돌리기 (13번, ADR-0004·0029)

기준 실행(베이스라인)에 기록된 프롬프트를 다른 생성 모델에 그대로 넣는다. 검색은 기준 실행과 같고 답을 쓰는 모델만 바뀐다. AI 서버는 거치지 않고 Ollama를 직접 부르므로, 평가용 덮어쓰기 파일이 Ollama도 데스크탑 `127.0.0.1:11435`에 연다(1단계 명령 그대로). 맥북 터미널 하나를 이 터널에 쓴다.

```bash
ssh -N -L 11435:127.0.0.1:11435 desktop-win
```

- 문맥 길이는 모델마다 가장 긴 프롬프트가 잘리지 않게 정한다. 토크나이저가 달라 같은 프롬프트도 모델마다 토큰 수가 다르다(가장 긴 ev-0254는 EXAONE 기준 약 8,900토큰). 결과의 '프롬프트 잘림'이 0이어야 한다.
- 모델마다 결과 폴더를 따로 두고, 평가셋 판이 실행 때와 다르면 `--rescore`로 다시 채점한 뒤 짝 비교한다(6단계).

```bash
.venv/bin/python -m corpus evalset regenerate --from-run ../../Assets/eval/runs/20261012-baseline --out ../../Assets/eval/runs/<날짜>-gen-<모델>-<문맥> --ollama-url http://localhost:11435 --model <Ollama 태그> --num-ctx <문맥>
```

- [실측 2026-10-13] 베이스라인과 같은 모델·같은 문맥(EXAONE, 8,192)으로 다시 돌리면 입력 토큰 수는 똑같고, 온도 0이어도 일부 문항은 문장이 달라진다(GPU 계산 순서). 갈린 비율은 13번 보고서에 적는다.

## 7. 끝내기 (포트 닫기)

터널 터미널에서 `Ctrl+C`로 터널을 닫고, 데스크탑은 평가용 파일 없이 다시 올려 포트를 닫는다.

```bash
ssh desktop 'cd ~/DocuMind && docker compose --project-name documind_desktop -f docker-compose.yml -f docker-compose.gpu.yml --env-file .env up -d'
```

데스크탑을 끌 때는 `데스크탑-작업-시작-종료-절차.md`의 '작업 끝'을 따른다. `docker compose down -v`는 쓰지 않는다(색인·DB 볼륨이 지워진다).

## 6-2. 검색 방식: 순위 융합 (M2, ADR-0032 확정)

AI 서버의 검색 순서는 순위 융합(RRF, k=60) 하나다. 표 사실·BM25·벡터 결과를 순위 융합해 상위 `--top-k`개를 쓰고, 사람이 만든 규칙과 우선 경로 답은 2026-10-16에 코드에서 지웠다(#169). 그래서 검색 방식을 고르는 설정값(`AI_RETRIEVAL_MODE`)과 실행기 옵션(`--retrieval-mode`)도 없다. 규칙 경로로 다시 재야 하면 그 전 커밋(develop `e55e6a0`)을 데스크탑에 올려 돈다.

반복 실험은 개발셋만 묻는다(ADR-0018). 개발셋 문항 ID 목록은 로컬 `Assets/eval/work/m2/dev_ids.txt`(205개).

맥북, 저장소 `tools/corpus`에서:

```bash
.venv/bin/python -m corpus evalset run --ai-url http://localhost:18000 --out ../../Assets/eval/runs/<날짜>-exp-<실험>-<모델> --index repro-20261010-develop15e776c --version v3 --ids "$(cat ../../Assets/eval/work/m2/dev_ids.txt)"
```

- 실행 기록(`manifest.json`)에는 `retrieval_mode: rrf`가 남는다. 규칙 경로로 돈 옛 실행 폴더(값이 `rules`이거나 이 칸이 없는 #168 전 기록)에 이어 붙이려 하면 거부한다.
- 같은 검색 결과를 다른 생성 모델로 보려면 그 실행 폴더를 `regenerate --from-run`에 준다(6-1).
- [실측 2026-10-14] EXAONE + rrf 상위 5개: 개발셋 205문항 9분 20초, 실패 0, 프롬프트 잘림 0.

## 6-3. 재순위 켜고 재기 (M2 3단계, #174)

재순위 서버(Hugging Face TEI, `bge-reranker-v2-m3`)는 GPU 덮어쓰기 파일의 `reranker` 프로필로만 뜬다. 기본은 꺼져 있다.

1. 데스크탑 `.env`에 재순위 주소를 적는다(바꾸기 전에 `.env`를 백업한다).

```bash
AI_RERANKER_URL=http://reranker:80
```

2. 맥북에서 프로필을 붙여 올린다(데스크탑에서 실행).

```bash
ssh desktop 'cd ~/DocuMind && DOCKER_CONFIG=~/.docker-nocreds docker compose --project-name documind_desktop -f docker-compose.yml -f docker-compose.gpu.yml -f docker-compose.eval.yml --env-file .env --profile reranker up -d --build'
```

- 처음 뜰 때 재순위 모델(약 2.3GB)을 Hugging Face에서 받는다. 이미 받아 둔 모델을 쓰려면 모델 파일을 볼륨 `documind_desktop_reranker_data`의 `models--BAAI--bge-reranker-v2-m3/snapshots/<리비전>/`에 실제 파일로 넣는다(새 Hugging Face 캐시는 큰 파일을 공용 `hub/blobs`에 두고 모델 폴더에는 링크만 둔다).
- 확인: 평가 요청 응답의 `eval_trace.rerank.used`가 참이고, 실행 기록(`manifest.json`)의 `runtime.reranker.model`에 모델 id와 리비전이 남는다.
- 끌 때는 `.env`에서 `AI_RERANKER_URL`을 비우고 프로필 없이 다시 올린다. 재순위 서버가 응답하지 않으면 AI 서버는 순위 융합 순서로 답한다.
