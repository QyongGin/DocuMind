# 평가 실행 절차 (M1 12번 베이스라인 · 13번 모델 비교)

> 챗봇(데스크탑)에 평가셋 질문을 묻고 채점한다. 실행기(`evalset run`)는 **맥북**에서 돌고, AI 서버는 **데스크탑**에서 돈다. 평가셋 파일(`Assets/eval/`)은 맥북에만 둔다.
> 결정: 2026-10-12 사용자 결정 ① — 평가 때만 쓰는 compose 덮어쓰기(`docker-compose.eval.yml`)로 ai-server를 데스크탑 `127.0.0.1:18000`에만 열고, 맥북에서 SSH 터널로 부른다. 근거·대안은 `docs/rag/m1/채점기-설계-20261012.md` §8·§10.

## 왜 이렇게 하나 (근거)

- [코드] `docker-compose.yml`의 `ai-server`는 포트를 열지 않는다(`expose: 8000`만). 백엔드만 컨테이너 안에서 부른다.
- [코드] AI 서버에는 인증이 없다(`ai-server/main.py`에 인증 코드 없음). 랜·tailnet에 열면 누구나 질의·업로드 API를 부를 수 있다.
- [원문] Docker 문서(Port publishing): "If you include the localhost IP address (127.0.0.1, or ::1) with the publish flag, only the Docker host can access the published container port." 같은 문서는 28.0.0보다 낮은 판에서는 같은 로컬 네트워크의 다른 기기가 localhost에 연 포트에 닿을 수 있었다고 적는다 → 아래 2단계에서 판을 확인한다.

## 1. 데스크탑 켜고 최신 코드로 올리기

데스크탑을 켜는 것까지는 `데스크탑-작업-시작-종료-절차.md`의 '작업 시작' 1~3단계와 같다. 4단계 대신 아래처럼 평가용 파일을 함께 써서 올린다(평가용 질의 옵션 PR #156, 응답 버퍼 PR #158이 들어간 develop `b5be08b` 이후).

맥북에서:

```bash
ssh desktop 'cd ~/DocuMind && git pull --ff-only && git log --oneline -1 && docker compose --project-name documind_desktop -f docker-compose.yml -f docker-compose.gpu.yml -f docker-compose.eval.yml --env-file .env up -d --build'
```

## 2. 열린 곳 확인 (데스크탑 안에서만 열렸나)

맥북에서:

```bash
ssh desktop 'docker version --format "{{.Server.Version}}" && curl -s http://127.0.0.1:18000/health && docker compose --project-name documind_desktop -f ~/DocuMind/docker-compose.yml -f ~/DocuMind/docker-compose.gpu.yml -f ~/DocuMind/docker-compose.eval.yml --env-file ~/DocuMind/.env port ai-server 8000'
```

- Docker 판이 28 이상이고, `{"status":"ok"}`가 나오고, 포트가 `127.0.0.1:18000`이면 된다.
- WSL 안에서 `127.0.0.1:18000`이 안 닿으면(Docker Desktop이 포트를 Windows 쪽에만 열 때) 3단계 터널을 `desktop` 대신 `desktop-win`(Windows SSH)으로 연다.

## 3. 맥북에서 SSH 터널 열기

맥북 터미널 하나를 이 터널에 쓴다(창을 닫으면 터널도 닫힌다).

```bash
ssh -N -L 18000:127.0.0.1:18000 desktop
```

다른 맥북 터미널에서 확인:

```bash
curl -s http://localhost:18000/health
```

## 4. 관리자 프롬프트 확인

운영 백엔드는 관리자 화면에서 바꾼 시스템 프롬프트를 보낸다. 관리자 화면 → 프롬프트 설정이 기본값("너는 인하공업전문대학 문서를 근거로 답변하는 안내 챗봇이다.")이면 그대로 둔다. 바뀌어 있으면 그 글을 파일로 저장해 실행에 `--system-prompt-file 파일`을 붙인다(실행 기록에 지문이 남는다).

## 5. 시험 실행 (3문항)

맥북, 저장소 `tools/corpus`에서:

```bash
.venv/bin/python -m corpus evalset run --ai-url http://localhost:18000 --out ../../Assets/eval/runs/20261013-try --index repro-20261010-develop15e776c --version v2 --limit 3
```

`Assets/eval/runs/20261013-try/answers.jsonl`에서 `eval_trace.generation.done_reason`(stop·length)과 단계별 후보(`stages`)가 들어왔는지, `manifest.json`의 `runtime`(모델·온도·문맥)을 본다.

## 6. 전체 실행과 채점

```bash
.venv/bin/python -m corpus evalset run --ai-url http://localhost:18000 --out ../../Assets/eval/runs/20261013-baseline --index repro-20261010-develop15e776c --version v2
```

- 질문 346개를 하나씩 묻는다. 중간에 끊기면 같은 명령을 다시 실행하면 이어서 돈다(받은 문항은 건너뜀).
- 끝나면 채점한다. 테스트셋은 합계만 보인다.

```bash
.venv/bin/python -m corpus evalset score-run --run-dir ../../Assets/eval/runs/20261013-baseline
```

## 7. 끝내기 (포트 닫기)

터널 터미널에서 `Ctrl+C`로 터널을 닫고, 데스크탑은 평가용 파일 없이 다시 올려 포트를 닫는다.

```bash
ssh desktop 'cd ~/DocuMind && docker compose --project-name documind_desktop -f docker-compose.yml -f docker-compose.gpu.yml --env-file .env up -d'
```

데스크탑을 끌 때는 `데스크탑-작업-시작-종료-절차.md`의 '작업 끝'을 따른다. `docker compose down -v`는 쓰지 않는다(색인·DB 볼륨이 지워진다).
