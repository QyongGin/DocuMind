# 평가셋 v3와 베이스라인 다시 채점 (M1 12번 마무리, 이슈 #130) — 2026-10-13

> 베이스라인(`베이스라인-측정-20261012.md`)과 재확인에서 나온 평가셋 문제를 고쳐 v3로 고정하고, 같은 실행을 v3로 다시 채점해 13번 모델 비교와 M2가 비교할 기준 숫자를 다시 냈다. 실행은 다시 하지 않았다(데스크탑 불필요). 사람 시간은 0이다.
> 관련: ADR-0018(테스트셋 봉인), ADR-0026(목표치 — v3로 바뀌면 다시 채점해 보고), ADR-0028(규칙 '맞음' 중 판정으로 보낼 두 경우), `채점기-설계-20261012.md` §12

- v2보다 낮아진 것은 대부분 채점 보강(ADR-0028) 때문이다. 규칙이 '맞음'으로 봤지만 판정으로 보낸 답 21개 중 5개가 맞음이 아니었다(일부 2 · 틀림 3). [실측]
- 평가셋 v3: 정답 보강 6문항 + 질문 다듬기 1문항(개정 번호 올림), ev-0002 테스트셋 → 개발셋, 답없음 개발셋 28문항에 부재 확인 두 번째 겹 기록. 본 개발셋 149 · 테스트셋 101, 쉬운 96, 지문 `1df70782…`. [실측]
- 채점 코드 두 가지: 굵게 표시 기호(`*`)를 지우는 정규화, 옛 실행을 새 평가셋 판으로 다시 채점하는 옵션(`score-run --rescore --out`). [코드]

## 2. 채점 코드

### 2-1. 굵게 표시 기호 정규화

- **증상**: 본 개발셋 ev-0013의 답 '학생의 **부**와 **모** 모두'가 허용 표기 '부·모'와 어긋나 애매가 됐다.
- **측정** [실측]: 베이스라인 346개 답 중 130개(38%)가 굵게 기호를 쓴다. 기호를 지우고 다시 채점해도 **바뀐 판정은 0개**였다. EXAONE은 '**30,000원**'처럼 값 전체를 감싸므로 허용 표기가 끊기지 않는다. ev-0013도 기호가 아니라 '부**와** 모'(허용 표기는 '부·모')가 원인이었다 → 정규화로 해결되지 않아 v3에서 허용 표기 '부와 모'를 더했다(§3).
- **그래도 넣은 이유** [판단]: 13번은 모델 네 개를 비교한다. 값 안쪽만 굵게 쓰는 모델('**30,000**원')은 지금 규칙에서 '30000**원'이 되어 허용 표기 '30000원'과 어긋난다. 같은 답이 모델의 꾸밈 버릇 때문에 다르게 채점되면 비교가 공정하지 않다.
- **부작용과 처리** [실측]: 판정 재사용 열쇠(문항 ID + 개정 번호 + 정규화한 답의 해시)가 정규화를 함께 쓰고 있었다. 기존 판정 55건 중 28건이 굵게 쓴 답이라, 정규화만 바꾸면 그 판정이 붙지 않는다. 열쇠는 기호를 지우기 전 정규화를 그대로 쓰도록 나눴다(`scoring.key_text`). v2로 다시 채점해 판정 재사용 수가 그대로인 것을 확인했다.
- 이중 라벨링 채점도 같은 함수(`scoring.score`)를 쓰므로 함께 적용된다(테스트로 확인).

### 2-2. 옛 실행을 새 평가셋 판으로 다시 채점

- **문제**: `score-run`은 실행 기록의 평가셋 지문이 지금 파일과 다르면 거부한다(다른 판으로 잘못 채점하는 것을 막는 장치). 평가셋을 v3로 올리면 베이스라인 실행을 다시 돌려야 v3 숫자가 나온다 — 데스크탑을 켜고, 같은 설정이라도 답이 조금 달라질 수 있다.
- **바꾼 것** [코드]: `score-run --rescore --out <폴더>`
  - 문항 ID로 답을 맞춘다. 실행 때 물은 질문(답 기록의 `question`)이 지금 질문과 다르면 그 문항은 '질문 바뀜'으로 빼고 지표에 수만 남긴다 — 다른 질문에 대한 답을 새 질문으로 채점하지 않는다.
  - 결과는 실행 폴더가 아닌 `--out` 폴더에 쓴다. 실행 폴더의 결과 파일은 실행 때 판(v2)의 채점으로 남는다. `--out`이 실행 폴더와 같으면 거부한다.
  - 지표 파일에 어느 판으로 채점했는지(`scored_with`: 판 이름·지문·실행과 같은 판인지·실행 폴더)를 남긴다. 판 이름은 평가셋 옆 버전 고정 기록(`frozen_<판>.txt`) 중 지문이 같은 것에서 읽는다.
  - 고친 문항은 개정 번호가 올라 옛 판정이 붙지 않으므로, 애매가 되면 다시 판정한다(기존 동작).
- **버린 대안**
  - 실행을 다시 돌림: 데스크탑을 켜야 하고, 실행이 바뀌면 v2와 v3 숫자 차이가 평가셋 때문인지 실행 때문인지 섞인다.
  - 지문 검사를 끄는 옵션만 둠: 질문이 바뀐 문항을 옛 답으로 채점하게 되고, 결과가 실행 폴더의 v2 결과를 덮는다.
