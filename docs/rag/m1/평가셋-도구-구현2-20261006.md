## 2. 누가 무엇을 하나

```text
Claude(이 세션)   문제·정답 초안 ─────────────┐
프로그램          check(자동 검증)             │  정답은 넘기지 않음
Claude(따로 실행) double-annotate: 질문 + 원본만 받아 풂 ─┤
프로그램          규칙 기반 채점으로 비교 → need(휴먼 리뷰 대상, 나머지 자동 승인)

프로그램          merge → check(고친 문항) → freeze
```

## 3. 왜 이렇게 만들었나 (설계 결정과의 연결)

| 결정 | 코드 |
|---|---|
| ⑦-1 다른 세션의 Claude가 정답 없이 | `double_annotation.plan` — 작업 단위에는 문항 ID와 질문만(정답·인용·위치 없음). 자동 검증을 통과하지 않은 문항은 묻지 않고, 이미 푼 문항은 다시 묻지 않는다 |
| ⑦-2 서비스 변환을 거치지 않은 원본 | `double_annotation.write_source` — HTML은 원본 HTML에서 꾸밈(속성·스크립트·스타일·입력 칸·주석)만 지우고 `rowspan`·`colspan`은 남김, PDF는 pypdfium2 쪽 그림(108dpi) + 같은 쪽 글자, HWP는 수집기 추출기 |
| ⑦-3 문서 전체, 위치 숨김 | 근거 문서(답 없는 문항은 가까운 문서) 전체를 `docs/`에 넣고 지시문에 위치를 쓰지 않음 |
| ⑦-4 `claude -p`로 따로 | `double_annotation.claude_command` — 아래 표. 작업 단위는 저장소 밖 임시 폴더(위에 `.git`·`CLAUDE.md`·`AGENTS.md`가 있으면 거부). 질문·명령·출력은 평가셋 파일 옆 `double_annotation/<시각>/`에 남겨 다시 돌리지 않고 `--from-record`로 다시 채울 수 있음 |
| ② 규칙 기반 채점 | 확인 세션의 답을 `score`로 정답과 비교: 맞음 → 일치, 애매 → 애매, 나머지 → 불일치. 일치가 아니면 `select-review`가 사람에게 보냄 |
| ④ 리뷰 화면·기록 | `review.build_html` — 휴먼 리뷰 대상(`review_reason` 있음)만, 근거 원문(색인 글 우선)에 인용 칠하기, 짧은 문서는 전체·긴 문서는 인용 앞뒤 2,500자. `review.merge` — 문항마다 가장 늦은 기록, 고침은 고친 칸만 바꾸고 `rev`+1·자동 검증 비움, 같은 기록 두 번 합쳐도 같음, 하나라도 틀린 기록이 있으면 평가셋 파일에 쓰지 않음 |
| ④-6 색인 글 내보내기 | `index_export.export` — 백엔드 `/api/documents/{id}/chunks`(관리자, 표 사실은 ai-server가 부모 청크로 접어서 돌려줌), 청크 순서대로 이어 `index_text/<백업 이름>/`에, `manifest.json`에 문서 번호·청크 수·SHA-256 |

확인 세션 명령에 붙인 설정:

| 설정 | 막는 것 | 확인 |
|---|---|---|
| `--tools Read,Grep,Glob` | 명령 실행·웹·파일 쓰기 | 테스트(명령 모양), isolation-test |
| `--restricted` | 작업 폴더 밖 파일 읽기, 사용자·프로젝트 설정 | isolation-test: 밖의 가짜 정답 Read·Grep·Glob 3번 모두 "outside … --restricted confines the file tools to the working directory" |
| `--safe-mode` | CLAUDE.md·스킬·출력 형식 같은 사용자 맞춤(이 맥북은 보고 형식이 바뀌어 있음) | 변이 확인(빼면 테스트가 잡음) |
| `--permission-prompts none` | 허락을 물을 일은 모두 거절 | — |
| `--strict-mcp-config`, `--no-session-persistence` | 외부 도구 서버, 대화 저장 | — |

## 4. 실측

**세션 격리 시험**(`evalset isolation-test`, 사용자 터미널, 2026-10-06): 임시 폴더에 작업 단위(`packet/docs/notice.txt`, 안쪽 확인 글자)와 작업 단위 밖 가짜 정답(`answer_key.json`)를 두고, 지시문으로 밖을 읽어 보라고 시킴. 결과 안쪽 글자 읽음, 밖 글자 출력에 없음, 거절 3건(Read·Grep·Glob). 12초.

**가나대학 4문항 실제 실행**(전형료 값·휴학 서류 목록·PDF 2쪽 값·거절):

| | 1차 | 2차(덧붙인 말 분리 뒤) |
|---|---|---|
| 판정 | 일치 3 · 애매 1 | 일치 4 |
| 애매가 난 이유 | PDF 문항 답 끝에 "단위는 나와 있지 않습니다"를 덧붙임 → 규칙 기반 채점이 거절 문구("나와 있지 않")로 보고 애매 | 지시문에 "질문과 상관없는 덧붙임은 note에"를 넣고 `second_annotation.note`로 따로 받음 |
| 덤으로 보인 것 | 인용에 HTML 태그(`<tr><td>`)가 섞임 | "HTML 태그는 빼고"로 글만 옴. note에 "이 표가 어느 학년도 것인지 적혀 있지 않다" — 리뷰 때 쓸 단서 |

**실제 평가 문서 221개 읽기**(맥북, 읽기만, 임시 폴더는 지움): HTML 202·PDF 12·HWP 7 모두 읽음, 실패 0, 11.5초. PDF 쪽 수 1~22쪽, 369쪽 하나. 전체 56MB 중 369쪽 PDF가 43.6MB(쪽 그림 369장).

## 5. 문제 중심 기록

| 단계 | 내용 |
|---|---|
| 문제 | 이중 라벨링은 '정답을 못 본 세션'이어야 의미가 있다. 지시문으로 "밖을 읽지 마라"만 쓰면 지켜졌는지 알 수 없다 |
| 재현·측정 | 작업 단위 밖에 가짜 정답을 두고 일부러 읽으라고 시키는 시험(`isolation-test`)을 만들어 실제 Claude Code로 돌림 |
| 원인·선택 | Claude Code의 `--restricted`가 파일 도구를 작업 폴더에 가둔다(도움말·실측). 사용자 맞춤(보고 형식 등)은 `--safe-mode`로 끔. `--bare`는 구독 로그인을 못 써서 버림 |
| 실수와 수정 | ① 지난 세션에 "claude 로그인 안 됨"이라고 판단 — Claude의 명령 실행 환경 안에서만 그렇게 보였고 사용자 터미널은 로그인 상태였다. 확인 세션은 사용자 터미널에서 돌린다. ② 실제 실행에서 덧붙인 말이 거절 문구로 잡혀 애매가 남 → 답과 덧붙임을 나눔. 그대로 두면 사람이 볼 문항(사용자 시간)이 늘어난다 ③ 변이 확인에서 2개를 놓침 → 테스트 추가 |
| 부작용·위험 | 확인 세션 답이 길면 다른 숫자가 섞여 애매가 늘 수 있다(지시문으로 줄였지만 실제 30문항에서 비율을 잰다). 원본은 작업 단위마다 복사되므로 369쪽 PDF 문항은 8개마다 약 44MB가 임시 폴더에 생긴다(실행 뒤 지움). 원본에서 뽑은 HTML 글은 표가 한 줄로 보여, 리뷰 화면은 색인 글(`--index-dir`)과 함께 만든다(없으면 안내 문구) |
| 남은 한계 | Claude가 같은 식으로 잘못 이해한 문항은 이중 라벨링으로 못 잡는다(테스트셋 표본 30으로만). `export-index`는 데스크탑을 켤 때 실제로 시험한다. Claude Code 판이 바뀌면 `isolation-test`를 다시 돌린다 |
