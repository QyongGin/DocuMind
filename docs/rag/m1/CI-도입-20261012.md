# CI 도입 — PR마다 바뀐 모듈의 테스트 자동 실행 (이슈 #146, M1 11번 전)

> 상태: 🔧 PR 대기(2026-10-12). 결정은 ADR-0024.

## 1. 문제

테스트가 작성자 맥북에서만 돌았다. PR은 자동 검사 없이 머지됐고, 의존성 목록 누락이나 커밋하지 않은 파일에 기대는 코드는 작성자 환경에서 드러나지 않는다. 인계 뒤 담당자가 혼자 고칠 때 안전망도 없다(총괄계획 §3 D4). 11번 채점기부터 코드가 다시 쌓이므로 그 전에 넣는다.

## 2. 만든 것

`.github/workflows/ci.yml` 하나.

| 잡 | 하는 일 |
|---|---|
| 바뀐 모듈 찾기 | PR의 기준 커밋과 `git diff`로 바뀐 경로를 보고 네 모듈 중 돌릴 것을 고른다. 워크플로 파일을 고쳤거나 수동 실행이면 모두 |
| tools/corpus | Python 3.12, `requirements-dev.txt` → pytest |
| ai-server | Python 3.12, `requirements.txt`·`requirements-dev.txt` → pytest |
| backend | JDK 21(temurin) → `./gradlew test` |
| frontend | Node 22 → `npm ci` → lint → build |
| ci-ok | 위 잡 결과를 모아 실패·취소가 하나라도 있으면 실패. 브랜치 규칙의 필수 검사는 이것 하나 |

- 학교 데이터(`Assets/`)·GPU·Ollama·Chroma 서버 없이 돈다. 테스트 데이터는 가나대학 합성 데이터와 H2 메모리 DB다.
- 같은 PR에 새 커밋이 오면 앞 실행을 취소한다(`concurrency`). 권한은 저장소 읽기만(`contents: read`).
- 절차 문서: `docs/workflow/PR-작성-및-머지-절차.md` §2(CI 행)·§4(머지 전 `ci-ok` 확인), 루트 `AGENTS.md` §5.

## 3. 확인

| 확인 | 결과 |
|---|---|
| 맥북에서 네 모듈 검사 | tools/corpus 140 passed · ai-server 89 passed, 1 skipped(라이브 Chroma 진단 도구) · backend 테스트 성공 · frontend lint·build 성공 |
| 워크플로 문법 | YAML 읽기 확인. 액션 입력 이름은 각 액션 최신판(checkout v7·setup-python v7·setup-java v6·setup-node v7)의 action.yml과 대조 |
| GitHub에서 실제 실행 | 이 PR에서 확인(워크플로 파일을 고친 PR이라 네 모듈 모두 돈다) |

## 4. 남은 것

- develop 브랜치 규칙(ruleset `develop`)에 'PR 필수'와 '`ci-ok` 통과 필수'를 더한다. 저장소 설정 변경이라 사용자 확인 뒤 한다.
- 프론트엔드는 테스트가 없어 lint·빌드만 본다. 화면 테스트는 M3·M4 화면 작업 때 다시 본다.
