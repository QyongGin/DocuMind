# 평가셋 분할 도구 보완 — 버린 문항 빼기, 답 없는 문항도 장 단위로 (2026-10-12)

> M1 10번(이슈 #129). 본 문항 250을 다 모은 뒤 분할을 저장하지 않고 미리 돌려 보다가 찾은 도구 빈틈 두 개를 고쳤다(사용자 결정 2026-10-12). 분할 규칙(ADR-0018·0022)은 그대로다.

## 1. 문제

분할은 같은 문서 묶음의 문항을 한쪽(개발셋 또는 테스트셋)에 함께 보내고, 문항이 10개를 넘는 묶음은 장 단위로 나눈다. 미리 돌려 보니 두 가지가 맞지 않았다.

| 문제 (코드에서 확인) | 실제 평가셋에서 |
|---|---|
| 휴먼 리뷰에서 버린 문항도 나눈다(`split.assign_parts`가 모든 문항을 받음). 분할 명령의 문항 수에도 들어간다 | 버린 2문항이 섞여 분할 명령이 '본 문항 252'로 나옴. 단위 크기와 주제별 40% 계산에도 들어감 |
| 답 없는 문항은 근거가 없어 장 이름을 달 자리가 없다(`units`가 `evidence[0].section`만 봄) | 큰 묶음 근처의 답없음 24문항(학교 FAQ 15 · 2027 모집요강 7 · 봄내 공지 2)이 묶음마다 '장 없음' 한 덩어리가 되어 통째로 한쪽에 감. 테스트셋에 들어가는 답없음 수가 씨앗에 따라 7~32로 흔들림(목표 20) |

## 2. 변경 내용

| 파일 | 바꾼 것 |
|---|---|
| `tools/corpus/corpus/evalset/schema.py` | 공용 판단 `dropped`(버린 문항인가), `section_of`(장 이름: 답 있는 문항은 첫 근거, 답 없는 문항은 `unanswerable.section`). `unanswerable.section`이 있으면 비어 있지 않은 글인지 검사 |
| `split.py` | 분할 단위가 `section_of`를 씀. `assign_parts`가 버린 문항을 받지 않음. 버전 고정은 버린 문항의 분할을 요구하지 않음 |
| `cli.py` | `split` 명령이 버린 문항에 분할을 쓰지 않고, 출력에 '버림 N문항은 나누지 않음'을 붙임 |
| `report.py` | '장이 빠진 큰 묶음' 검사가 `section_of`를 씀(답 없는 문항의 장도 봄) |
| 문서 | 파일 형식(`unanswerable.section`), 도구 안내(`evalset split`) |

평가셋 파일(커밋하지 않음)에는 작업 스크립트 `Assets/eval/work/add_unanswerable_sections.py`로 답없음 문항에 장 이름을 달았다. 학교 FAQ는 가까운 FAQ의 제목(답 있는 문항과 같은 규칙), 모집요강·봄내 공지는 질문이 다루는 장을 표로 정했다(예: 2028 수시 1차 원서 접수 → Ⅱ 전형일정, 1인당 면접 시간 → Ⅲ 면접고사).

## 3. 확인

| 확인 | 방법 | 결과 |
|---|---|---|
| 테스트 | 가나대학 합성 데이터. 새 테스트 6개: 버린 문항을 나누지 않음, 버전 고정이 버린 문항의 분할을 요구하지 않음, 답 없는 문항이 같은 장의 답 있는 문항과 같은 쪽, 장 없는 답없음만 '장 없음' 단위, 분포 보고가 답없음의 장을 봄, 장 이름 형식 검사, 분할 명령이 버린 문항을 건너뜀 | 138개 통과(기존 132 + 6) |
| 변이 확인 | 커밋 뒤 고친 동작 6가지를 하나씩 되돌림(분할에서 버림 빼기, 답없음 장 읽기, 장 이름 형식 검사, 고정에서 버림 예외, 분할 명령에서 버림 빼기, 보고의 답없음 장) | 6번 모두 테스트 실패로 잡힘. 되돌린 파일만 복구 |
| 실제 평가셋 | 같은 씨앗 20개로 고치기 전·뒤 비교(저장하지 않음) | 아래 표 |

| 나눔 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 나누는 본 문항 | 252(버린 2 포함) | 250 |
| 테스트셋 문항 수 | 101~109(평균 103.2) | 101~107(평균 102.7) |
| 테스트셋에 들어가는 답없음 | 7~32 | 16~27 |
| 가장 큰 분할 단위 | 16문항 | 14문항(모집요강 Ⅱ 전형일정) |
| '장이 빠진 큰 묶음' | 3묶음 | 없음 |

## 4. 남은 것

- 테스트셋은 여전히 목표(100)보다 1~7문항 많다. 문서 묶음 단위로 나누는 규칙(ADR-0018)에서 오는 오차로, 이번 범위에서 바꾸지 않는다.
- 분할 씨앗은 버전 고정 기록(`split_seed`)에 남긴다. 씨앗을 고르는 기준은 분할 때 정한다.
