## 3. 실패 위치 판정 (PR 2)

답 있는 문항에서, 허용 근거 문서(근거 + 허용 근거)의 후보가 핵심 사실을 모두 담고 있는지를 단계마다 본다. 핵심 사실마다 허용 표기 하나라도 그 단계 후보 글(또는 문맥)에 있으면 담고 있다고 본다.

| 단계 | 평가용 응답에서 |
|---|---|
| 검색 | `vector` · `bm25` · `table_fact` · `expanded` 후보 |
| 최종 후보 | `final`(top_k까지 자른 뒤, 출처와 같음) |
| 문맥 | `context`(프롬프트에 들어간 근거 글) |

| 판정 | 실패 위치 |
|---|---|
| 맞음 | 검색 단계에 없으면 '외운 답 의심', 있으면 '통과' |
| 맞음이 아님(일부·모름·틀림·애매·빈 답) | 검색에 없음 → '검색 실패' / 검색엔 있고 최종 후보에 없음 → '후보 탈락' / 최종 후보엔 있고 문맥에 없음 → '문맥 탈락' / 문맥에 있음 → '생성 실패' |

- 답 잘림: `done_reason`이 length면 표시한다.
- 답 없는 문항은 실패 위치를 붙이지 않는다(틀림이면 '지어낸 답').
- 임베딩 잘림(근거 청크가 임베딩 문맥 2,048토큰을 넘음)은 토크나이저가 필요해 이번에는 빼고, 근거 청크 글자 수만 기록한다.

## 4. 버린 대안

- 백엔드 채팅 API로 묻기: 화면과 가장 같지만 평가 질문 346개가 채팅 기록 DB에 쌓이고(개인정보·통계 오염), 단계별 후보를 받을 수 없다. 백엔드는 출처에 메타데이터만 보태므로 답·출처는 AI 서버와 같다.
- 검색 기록 API를 그대로 쓰기: 위 '고친 것' 첫 줄.
- 판정 모델(LLM)로 채점: ADR-0017에서 쓰지 않기로 했다. 사람 판정이 쌓이면 일치율을 재서 정한다.

## 5. 네 관점

- 서비스: 틀린 답이 검색 탓인지 생성 탓인지 나뉘어, M2에서 고칠 곳(검색 범위·재정렬·프롬프트)이 바로 보인다.
- 비즈니스: 학교에 낼 숫자에 신뢰구간과 실행 기록이 붙어, 같은 숫자를 다시 만들어 보일 수 있다.
- 유지보수: 운영 응답은 그대로이고(옵션 기본값 끔), 평가용 기록은 실제 검색 코드에서 나오므로 검색 코드를 고쳐도 따로 맞출 코드가 없다.
- 확장: 13번 모델 비교·M2 전후 비교·학기 측정이 같은 실행기와 같은 실행 기록 형식을 쓴다.

## 8. 12번 베이스라인 전에 정할 것

- **실행기가 AI 서버에 닿는 길**: compose의 `ai-server`는 포트를 열지 않는다(`expose: 8000`만, 백엔드만 컨테이너 안에서 부름). 안: ① 평가 때만 쓰는 compose 덮어쓰기 파일로 `127.0.0.1:8000`에 열고 맥북에서 SSH 터널(`ssh -L`)로 부른다 — 인증 없는 내부 API를 랜·tailnet에 열지 않는다. ② 데스크탑 WSL에서 실행기를 돌린다 — 평가셋 파일(`Assets/`)을 데스크탑에 복사해야 한다. 12번에서 정한다.
- 실행 기록의 코드 커밋은 실행기를 돌린 쪽(맥북) 커밋이다. 데스크탑이 같은 커밋을 pull해 빌드했는지 함께 적는다.

## 9. PR 3 — 이슈 #149 FastAPI 응답 버퍼 한도 (2026-10-12)

**문제**: 큰 문서의 청크 목록 API(`GET /api/documents/{id}/chunks`)가 HTTP 500(`DataBufferLimitException: … 262144`). `FastApiWebClientConfig`가 `WebClient.builder()`로 직접 만든 빌더라 기본 한도 256KB가 걸리고, 스프링 부트의 `spring.codec.max-in-memory-size`도 닿지 않는다.

**바꾼 것**: FastAPI 일반 응답용 WebClient(`fastApiBlockingWebClient`)에 `fastapi.max-in-memory-size`(기본 16MB, 환경 변수 `FASTAPI_MAX_IN_MEMORY_SIZE`)를 코덱 한도로 건다. 스트리밍용 WebClient는 이벤트가 작아 그대로 둔다.

**원문 근거**: [원문] Spring Framework WebClient 문서(MaxInMemorySize): "By default those are set to 256KB. If that’s not enough you’ll get the following error: … DataBufferLimitException" — 같은 문서의 해결법이 `WebClient.builder().codecs(configurer -> configurer.defaultCodecs().maxInMemorySize(…))`다. [원문] Spring Boot 문서: "Spring Boot creates and pre-configures a prototype WebClient.Builder bean for you. It is strongly advised to inject it … to … reflect codecs setup" — 우리 코드는 이 빈을 주입하지 않고 `WebClient.builder()`를 직접 불러([코드] `FastApiWebClientConfig.createWebClient`) 스프링 부트의 코덱 설정이 닿지 않는다.

**값의 근거**: [실측] 재현 색인 글에서 가장 큰 문서(안전진단 보고서, 739청크)의 청크 글만 1,016KB, 둘째(2027 모집요강) 176KB. [계산] 청크마다 메타데이터가 붙어 응답은 약 1~1.5MB로 본다 → 약 10배 여유로 16MB. 요청 하나가 그만큼 메모리를 쓸 수 있지만, 관리자 화면·`export-index`만 부르는 API라 동시 요청이 적다.

**확인**: 백엔드 테스트 전체 통과. 새 테스트(합성 데이터): 256KB를 넘는 청크 목록(400청크)을 설정한 한도로 끝까지 읽고, 한도를 256KB로 두면 같은 응답에서 실패한다(이슈 재현). 변이 확인 1/1(한도 설정을 빼면 실패). **데스크탑에서 두 문서(서비스 문서 21·461)의 청크 목록이 200인지는 12번 때 확인**(이슈 완료 기준).

## 10. 결정 — 실행기는 SSH 터널로 데스크탑 안쪽 주소의 AI 서버를 부른다 ✅ (2026-10-12 사용자 결정 ①)

**결정**: 평가 때만 쓰는 compose 덮어쓰기 파일 `docker-compose.eval.yml`이 ai-server를 데스크탑 `127.0.0.1:18000`에만 연다. 맥북 실행기는 `ssh -N -L 18000:127.0.0.1:18000 desktop` 터널로 부른다. 평가가 끝나면 이 파일 없이 다시 올려 포트를 닫는다. 절차는 `docs/development/local-gpu/평가-실행-절차.md`.

**근거**
- [코드] `docker-compose.yml`의 `ai-server`는 `expose: 8000`만 있고 포트를 열지 않는다. AI 서버에는 인증이 없다(`main.py`에 인증 코드 0건).
- [원문] Docker 문서(Port publishing): "If you include the localhost IP address (127.0.0.1, or ::1) with the publish flag, only the Docker host can access the published container port." / "Publishing container ports is insecure by default." 28.0.0보다 낮은 판은 같은 로컬 네트워크의 기기가 localhost 포트에 닿을 수 있었다는 주의가 있어 절차 2단계에서 판을 확인한다.
- [실측] 맥북에서 `docker compose -f docker-compose.yml -f docker-compose.gpu.yml -f docker-compose.eval.yml config`: ai-server 포트가 `host_ip: 127.0.0.1`, `published: 18000`, `target: 8000`으로 합쳐진다.

**버린 대안**
- 데스크탑 WSL에서 실행기를 돌린다: 학교 데이터가 든 평가셋 파일을 데스크탑에도 둬야 하고, tools/corpus 환경을 하나 더 관리한다.
- 포트를 `0.0.0.0`에 연다(AGENTS.md §3의 일반 규칙): 인증 없는 질의·업로드 API가 랜·tailnet에 열린다. 화면(프론트)처럼 사람이 쓰는 포트와 달리, 이 포트는 실행기만 쓰므로 밖에 열 이유가 없다.

**네 관점**
- 서비스: 운영 compose는 그대로라 사용자 화면·백엔드 경로가 바뀌지 않는다.
- 비즈니스: 평가 중에도 인증 없는 API를 외부에 노출하지 않는다(개인정보·온프레미스 설명 유지).
- 유지보수: 파일 하나(`-f docker-compose.eval.yml`)를 붙였다 떼는 것뿐이라 담당자도 같은 절차로 학기 측정을 한다.
- 확장: 13번 모델 비교(모델을 바꿔 여러 번 실행)도 같은 터널·같은 실행기를 쓴다.

**확인 시점**: 12번 첫 실행 — WSL 안에서 `127.0.0.1:18000`이 닿는지(Docker Desktop이 Windows 쪽에만 열면 `desktop-win` 터널로), Docker 판 28 이상인지.
