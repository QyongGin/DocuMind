# HWP·HTML 표 변환 방식 조사 (이슈 #125 설계, 2026-10-02)

> 목적: 이슈 #125(HTML·HWP 문서 형식 지원)의 첫 결정 — HWP·HTML의 **표를 무엇으로, 어떻게** 마크다운으로 바꿀지 — 를 실측과 원문 근거로 정한다.
> 상태: 조사 완료, 결론 제안(사용자 결정 대기). 시험판 코드는 세션 임시 폴더에만 있고 저장소에 넣지 않았다.
> 관련: ADR-0008·0010("HTML·HWP 변환도 데이터셋용으로 따로 만들지 않고 ai-server 로더에 넣어 같이 쓴다"), 수집 결과 `수집기-구현-및-시험수집-20261002.md` §8

## 1. 결론

1. **HWP 5.0·HWPX·HTML 모두 AI 서버(파이썬)에서 직접 표 격자를 만들어 마크다운으로 바꾼다.** HWP는 olefile(BSD) + 한컴 공개 문서로 직접 읽고, HWPX는 XML의 칸 주소·병합을 읽고, HTML은 BeautifulSoup으로 표만 따로 처리한 뒤 나머지는 지금처럼 MarkItDown에 맡긴다. 세 형식이 **표 격자 → 마크다운** 코드 하나를 같이 쓴다.
2. **병합 칸은 세로 병합만 아래 행에 같은 값을 채우고, 가로 병합은 첫 칸에만 둔다**(머리 행은 가로도 채움). 행 하나만 읽어도 뜻이 통하게 하면서, 가로까지 채울 때보다 글이 절반이다.
3. 자바 hwplib(Apache-2.0)은 서비스에 넣지 않고, **개발 중 결과를 맞춰 보는 기준(오라클)** 으로 쓴다.
4. 한컴 공개 문서를 참고하므로 **"본 제품은 한컴의 HWP 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다."** 를 소스(수집기·AI 서버)와 서비스 이용안내·설명서에 적는다.

## 4. HTML — MarkItDown(0.1.5) 그대로는 표가 깨진다

| 실측(표 1,276개) | 개수 | 결과 |
|---|---|---|
| 세로 병합이 있는 표 | 372 | MarkItDown 출력에서 **369개 칸 밀림** — 병합된 칸이 아래 행에서 빠짐 |
| 머리 칸(`th`) 없는 표 | 1,107 | 빈 머리 행이 생기고 진짜 머리가 본문 행으로 밀림(예: 통학버스 안내 `|  |  |  |  |` 다음에 `| 구분 | 구매 가능 시기 | …`) → 표 사실에서 열 이름을 잃음 |

→ HTML 표는 BeautifulSoup으로 격자를 만들어(병합 펼침, `th`가 없으면 첫 행을 머리로) 같은 마크다운 코드로 내고, 표 밖 글만 MarkItDown으로 바꾼다.
- 참고: DOCX도 MarkItDown(내부적으로 HTML을 거침)이라 병합 표에서 같은 문제가 있을 수 있다. #125에서 같은 격자 코드를 쓸 수 있는지 확인한다.

### 7.3 결정 1 — HWP 5.0을 무엇으로 읽나 → **A 파이썬 직접 확정** (2026-10-02 사용자 결정)

결정 이유: JRE는 이미 있어 B를 막는 이유가 아니지만, B는 우리가 지킬 코드를 자바·파이썬 두 언어로 나누고 자바 빌드 단계를 더한다(인계 부담). hwplib도 사실상 1인 관리라 "외부가 관리해 준다"는 이점이 작다. A는 hwplib과 표 구조가 2,276/2,276 같다. ### 7.4 결정 2 — 표를 마크다운 표로 옮기는 규칙 → **확정** (2026-10-02 사용자 결정)

### 7.5 결정 3 — DOCX도 #125에서 같은 표 격자로 고치나 → **고친다 확정** (2026-10-02 사용자 결정)

[실측, 합성 파일 `Assets/test_docs/인하공업전문대학_학사안내.docx`(표 4개, 병합 없음), `docx_synthetic_compare2.py`] 지금 경로(MarkItDown)는 빈 머리 줄을 만들고 첫 줄을 본문으로 내린다. 표 1~3은 `_is_probable_subheader_row` 보정으로 열 이름을 되찾지만 열 이름에 굵은 글씨 표시(`**부서**`)가 남는다. **표 4는 첫 줄("기간 | 1학기 | 2학기")에 숫자가 있어 보정이 꺼지고 열 이름을 모두 잃어 표 사실 0개**다. mammoth HTML → 첫 줄을 머리로 쓰는 경로에서는 열 이름 "기간·1학기·2학기", 표 사실 5개. 병합 표(합성 `docx_merge_test.py`)는 §7.2대로 세로 병합 줄이 밀린다.

결정: DOCX는 MarkItDown과 같은 순서(`pre_process_docx` → `mammoth.convert_to_html`)로 HTML을 만든 뒤 HTML 경로(표는 공통 격자, 나머지는 MarkItDown HTML 변환)에 태운다. XLSX·PPTX는 그대로 둔다. 이유: 갈라지는 자리가 mammoth HTML 다음이라 HTML 표 코드를 그대로 쓰고, 지금 DOCX 표는 병합 줄이 밀리고 병합 없는 표도 열 이름을 잃는 경우가 있다(위 실측). 수집 DOCX는 7개(서비스 색인 1개)라 당장 영향은 작지만 인계 후 학교 담당자가 워드 파일을 올릴 수 있다. 감수할 것: 옛 합성 평가의 DOCX 14런 표 출력이 바뀐다(형식 파싱 확인용이라 받아들임). 기존 DOCX 시험은 그대로 통과해야 한다.
