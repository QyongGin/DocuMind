## 2. 왜 이렇게 만들었나 (설계 결정과의 연결)

| 결정 | 코드 |
|---|---|
| ① 답의 모양 + 꼬리표 | `schema.SHAPES`·`TAGS`, 검증 |
| ② 핵심 사실 + 규칙 판정, 애매만 사람 | `judge.judge` — 금지 값이 있으면 틀림, 거절 문구만 있으면 모름, 필수 사실 일부면 일부(목록·절차·설명·예아니오), 근거에 없는 숫자는 애매. 표기 맞추기(3만 원 = 30,000원, 2026. 9. 8. = 9월 8일), 숫자 경계(30,000 ≠ 130,000) |
| ③ 거절 문항 | 거절 문구만이면 맞음, 금지 값·구체 숫자 단정이면 틀림, 거절하며 숫자를 덧붙이면 애매. 부재 확인 기록이 없으면 돌려보냄, 걸린 글이 있으면 경고 |
| ④ 기계 검사·정본 한 파일·지문 | `checks.check_all`, `schema.save`(ID 순, 임시 파일 뒤 바꾸기), `schema.fingerprint` |
| ⑤ 문서 묶음 단위 60:40 | `split.assign_parts` — 주제마다 실전용 40%, 문항이 10개를 넘는 묶음은 장 단위 |
| ⑥ 분포 목표 | `report.build` — 모양·주제·꼬리표·문서당 상한·FAQ 근거 비율 |
| ⑦ 꼭 볼 문항만 | `split.choose_needs` — 불일치·경고·실전용 거절·표본 30, 나머지 자동 승인. 표본 오류 2개 이상이면 `more_sample` |

## 3. 문제 중심 기록

| 단계 | 내용 |
|---|---|
| 문제 | 평가셋 346문항을 사람이 전부 보면 약 9시간. 사람이 꼭 볼 문항만 남기려면 '자동으로 믿어도 되는 문항'을 가르는 장치가 필요했다 |
| 대안과 버린 이유 | 엑셀 왕복(값이 날짜로 바뀜, 근거를 따로 찾음), 판정 모델 채점(판정이 흔들림·GPU·외부 전송) — 설계 문서 §4 |
| 실수와 수정 | ① 거절 문항 판정이 질문에 있던 '2028학년도'를 답이 지어낸 숫자로 잘못 봤다 → 질문에 있던 숫자는 빼고 보게 고침(테스트가 먼저 잡음). ② 변이 확인에서 '표 구분선을 빼고 인용 대조'를 지워도 테스트가 통과했다(시험 데이터의 인용에도 구분선이 있었음) → 구분선 없는 인용 테스트를 더해 잡히게 함 |
| 부작용·위험 | 날짜 표기 맞추기가 '숫자. 숫자.' 모양을 날짜로 본다 → 목록 번호와 드물게 겹칠 수 있다. 원본 추출 글은 색인 글과 다르다 → 인용 대조는 색인 글을 먼저 쓴다(`--index-dir`) |
| 이름 | 처음 붙인 '개발용·확인용'은 무엇을 하는 몫인지 이름만으로 읽히지 않았다(사용자가 두 번 되물음). 일상 예(연습 문제·실전 시험)로 설명한 뒤 그 이름으로 바꿨다. 코드·문서·정본 값을 한 번에 바꿨고, 정본 파일은 아직 없어서 옛 값이 남은 데이터는 없다 |
| 남은 한계 | 교차 확인·검수 화면이 아직 없어 `need`를 실제 데이터로 돌릴 수 없다(PR 2). 문항당 검수 시간·불일치 비율은 첫 30문항에서 잰다 |
