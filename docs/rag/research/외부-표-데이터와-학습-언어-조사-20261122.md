# 표 읽기 학습용 외부 표 데이터와 학습 언어 조사

## 요약

결론: 학습 데이터의 언어, 특히 표 내용의 언어는 유의미하다. 그래서 외부 표는 한국어 표인 KorWikiTQ를 먼저 쓰는 것이 맞다 [판단].

- [원문] 다른 언어 표로만 학습한 모델은 새 언어의 표로 잘 옮겨 가지 않았다. 벵골어 표 질의응답으로 학습한 모델을 힌디어 표에서 재니 표 정답 일치(Table EM)가 0이었고, 답을 힌디어로 번역하는 후처리를 해도 5.74~19.01에 그쳤다. 힌디어로 학습하면 33.06이었다 [1] 표 1·2.
- [원문] 같은 모델이라도 표와 글이 영어가 아니면 성능이 평균 19.4% 떨어졌다(프롬프트만, 학습 없음) [2]. 틀린 원인의 48%는 질문 속 개체를 표의 칸과 잇는 단계였다 [2] 그림 7.
- [원문] 반대 근거: 일반 지시 학습에서는 영어만으로 배운 7B~13B도 다른 언어로 옮겨 갔다. 다만 학습 데이터가 충분하고 학습률을 맞출 때만이었고, 사실 정확도가 낮았다 [4]. 영어 학습셋에 다국어 예시 40개만 섞어도 크게 나아졌다 [3].
- [원문] 다른 언어로 먼저 학습한 뒤 목표 언어로 이어 학습하면 더 나았다(41.32 대 33.06) [1]. 영어 표는 한국어 표를 대신하기보다 보태는 자리라면 쓸 수 있다 [판단].
- 확인 못 함: 영어 표에 한국어 질문과 답을 붙인 혼합을 학습해 효과를 잰 심사 논문. 질문 언어와 표 언어가 다를 때를 잰 것은 70B 프롬프트 실험 하나뿐이다 [2].
- 추천 데이터: KorWikiTQ의 표(약 2만 개, 5~15행, 10열 이하) [5·6]. CC BY-SA 4.0이라 상업 이용과 변경을 허락하고 국외 제한이 없다. 표가 2차원 목록이라 칸 정보로 바로 풀린다. 위키 표라 머리글이 한 줄이고 운영 표의 병합 머리글과는 다르다.

## 1. 배경과 조사 질문

- 왜 조사하나: 2026-11-22 시험 학습 2에서 목표 답을 「확인한 행: … (해당/해당 없음) + 결론」으로 바꾸자, 여러 행 모으기를 처음 보는 표 38개 중 22개 맞혔다(학습 전 6개). 다음은 예시 수를 늘리는 일이다. 외부 표를 가져와 우리 생성 코드로 질문과 목표 답을 만든다. 외부 데이터의 질문과 답은 쓰지 않는다.
- 정하려는 것: 어느 외부 표를 쓰나, 한국어 표만 써야 하나.
- 조사 질문:
  1. 학습 데이터 언어가 평가 언어와 다르면 효과가 얼마나 옮겨 가나(표 질의응답 우선)
  2. 표 내용의 언어와 질문·답의 언어를 나눠 보면 어떤가
  3. 한국어 표 데이터와 영어 표 데이터 후보의 출처, 라이선스, 규모, 파일, 형식, 칸 정보로 풀리는지

## 3. 질문별 결과

### 질문 1. 학습 언어와 평가 언어가 다를 때

- [원문] 표 질의응답, 학습 [1]: 위키 표에서 SQL 틀로 질의를 만들어 질문으로 바꾼 데이터로 학습했다(우리 생성 코드와 같은 방식). 벵골어는 표 1만 9천 개에 학습 예시 200만, 힌디어는 표 2천 개에 64만 3천이다. Llama-7B는 4비트 LoRA, 학습률 1e-4로 학습했다. 벵골어 모델을 힌디어 표에서 학습 없이 재니 원문은 "BanglaTabQA models are able to perform table reasoning in Hindi indicating semantic information transfer across languages."라고 썼지만, 표 정답 일치는 모든 모델에서 0이었다. 답의 표 값을 힌디어로 번역하는 후처리를 하면 Llama 5.74, mBART 19.01, M2M 18.18이었다. 힌디어로 학습한 mBART는 33.06, 벵골어로 먼저 학습하고 힌디어로 이어 학습하면 41.32였다 [1] 표 1·2.
- [원문] 같은 논문은 틀린 답 모양도 적었다: "Table headers and numbers generated from math operations are often in Bengali instead of Hindi" [1] 부록 A.7. 학습한 언어의 머리글을 답에 그대로 쓰는 버릇이다.
- [원문] 표 질의응답, 다국어 학습 [7]: 중국어와 영어 표 50개를 97개 언어로 번역해 평가셋을 만들고, 학습셋도 97개 언어로 합성했다. Qwen3-8B를 전체 학습(학습률 1e-5, 5번 반복)하니 평균 10.46점 올랐다 [7] 표 4. 모든 언어를 함께 학습한 실험이라 "한 언어로 배워 다른 언어로 옮겨 가나"에는 답하지 않는다.
- [원문] 일반 지시 학습 [3·4]: LLaMA-2 7B와 13B를 영어만으로 지시 학습해도 프랑스어, 포르투갈어, 러시아어 질문에 그 언어로 답했다. 다만 "only if multiliguality is taken into account in hyperparameter tuning and with large enough IT data"였고, "suffer from low factuality"였다 [4]. PaLM 2-S에서는 영어 학습셋에 다국어 예시 40개만 넣어도 다국어 지시 따르기가 크게 나아졌다 [3]. 표 과제가 아닌 일반 지시 따르기다.
- 우리로 옮길 때의 차이: A.X는 한국어를 주로 배운 모델이다. 영어 표 읽기를 배워 한국어 표로 옮기는 일은 [1]의 벵골어 → 힌디어(문자가 다름)보다 쉬울 수도, 어려울 수도 있다. 잰 근거가 없다.

### 질문 2. 표 내용의 언어와 질문·답의 언어

- [원문] 표와 글을 10개 언어로 번역하니, 영어보다 평균 19.4% 떨어졌다 [2]. Llama3.1-8B와 70B, 프롬프트만 썼다. 한국어는 10개 언어에 없다. 영어에서 맞고 다른 언어에서 틀린 50개 가운데 48%가 질문 속 개체를 표의 칸과 잘못 이은 경우였다 [2] 그림 7.
- [원문] 질문 언어와 표 언어를 다르게 둔 실험도 있다("where the languages of the question and context are inconsistent"). 자원이 적은 언어에서 많은 언어로 갈 때는 대체로 나아지고, 반대로 갈 때는 나빠졌다 [2] 4.3.2절. Llama3.1-70B 프롬프트 실험이다.
- [판단] 우리는 질문과 목표 답을 한국어로 직접 만든다. 영어 표를 쓰면 한국어 질문이 영어 칸 이름을 부르고, 목표 답의 「확인한 행」에 영어 칸 값이 들어간다. 운영 프롬프트에는 이런 혼합이 없다. [2]의 칸 잇기 오류와 [1]의 머리글 언어 버릇이 우리 목표 답 모양(칸 값을 옮겨 적는 줄)과 바로 부딪힌다.
- 확인 못 함: 영어 표 + 한국어 질문·답 혼합으로 학습했을 때 이롭거나 해롭다는 심사 논문.

## 6. 반대 근거와 한계

- 언어가 달라도 옮겨 간다는 결과가 있다 [3·4]. 다만 일반 지시 따르기이고 표 과제가 아니다. 표 과제 [1]도 "semantic information transfer"를 말하지만 표 정답 일치는 0이었다.
- [1]은 2024 논문이고 Llama-7B, mBART라 지금 모델과 다르다. 답이 표 전체인 과제라 우리 「확인한 행 + 결론」 답과도 다르다.
- [2]는 학습 없이 프롬프트만 썼고 한국어가 없다.
- 한국어 표에서 언어 전이를 잰 심사 논문은 찾지 못했다(KorWikiTQ 논문 [5]에도 영어 데이터와 견준 실험은 없다).

## 7. 선택지와 권고

| 관점 | KorWikiTQ 표 먼저(추천) | AI허브 표 정보 질의응답 | 영어 표(HiTab, WTQ) |
|---|---|---|---|
| 서비스 | 한국어라 칸 잇기 문제가 적다. 머리글이 한 줄이라 병합 머리글 읽기는 못 배운다 | 공공 문서 표, 계층 머리글이 있어 운영 표와 가장 가깝다 | 계층 머리글(HiTab)은 가깝지만 영어 칸 값이 목표 답에 섞인다 |
| 비즈니스 | 승인 없이 받을 수 있다 | 내국인 신청과 승인을 기다린다 | 받기 쉽다 |
| 유지보수 | 2차원 목록이라 칸 정보 변환 코드가 짧다 | 표 문자열 모양을 받아 봐야 변환을 짤 수 있다 | WTQ는 CSV, HiTab은 머리글 나무로 바로 풀린다 |
| 확장 | CC BY-SA라 바꾼 데이터를 공유하면 같은 조건으로 | 학교 인계에 넣을 수 없다 | C-UDA(HiTab)는 계산 목적으로만 |

- 권고 [판단]: KorWikiTQ의 표만 가져와 우리 생성 코드로 예시를 만든다. 첫 묶음은 지금 처음 보는 표 38개와 표 질문 43문항으로 효과를 잰다. 계층 머리글이 부족하면 AI허브 표 정보 질의응답을 다음 후보로 신청한다(리전 확인 뒤). 영어 표는 한국어 표만으로 모자랄 때 소량만 섞고 따로 잰다.
- 내려받기 승인에 필요한 값(KorWikiTQ): 파일 `KorWikiTQ/KorWikiTQ_ko_train.json`(247 MB), `KorWikiTQ/KorWikiTQ_ko_dev.json`(49.3 MB). 출처 https://github.com/LG-NLP/KorWikiTableQuestions (Git LFS). 라이선스 CC BY-SA 4.0. 저작자를 밝히고, 바꾼 데이터를 공유하면 같은 라이선스로 공유해야 한다. 표만 쓰고 크라우드 질문과 답은 쓰지 않는다.
- 버린 것: KorQuAD 2.1(변형물 공유 금지), TableBench(평가셋), 영어 표만으로 늘리기(질문 1·2의 근거).

## 8. 확신도와 다음 확인

- 확신도: 언어가 유의미하다는 판단은 중간이다. 방향은 [1·2]가 같지만 한국어와 A.X로 잰 근거가 없다. 데이터 후보의 라이선스와 파일 값은 높음(원문).
- 다음 확인: KorWikiTQ 표로 만든 첫 묶음과 같은 수의 영어 표(WTQ) 묶음을 따로 학습해 처음 보는 표 38개로 견주면 우리 설정에서 언어 효과를 잴 수 있다.
- 다시 볼 조건: 학습 서버 리전이 확인될 때(AI허브), 국립국어원 약정서를 볼 때.
