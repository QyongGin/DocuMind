# 작은 모델 표 읽기 학습의 방법과 데이터 조사

## 요약

결론 요약(질문마다 한두 줄, 근거 강도, 우리 설정으로 옮길 때의 차이).

1. 학습 방법: 7~8B에 표 질문 지도 학습(SFT)을 하면 표 과제가 오른다. 2,600개(TAMA) [1], 2만 개(TableBench) [2], 2만 7천 개(TableDreamer, 평균 49.07 → 60.69) [3]. 선호 학습(DPO)은 지도 학습 뒤 덧붙이는 자리에서 8천 쌍으로 영역 안 최대 5%, 밖 2.4%를 더 올렸다 [4]. 근거 강도 보통. 영어 표, 대부분 전체 파라미터 학습이다.
2. 학습 위험: 학습률이 크면 일반 능력이 무너진다. 학습률 2e-5로 지도 학습한 8B 표 모델은 IFEval 평균이 74.83에서 28.53으로 떨어졌다 [2·3]. QLoRA는 학습률 약 5.0e-5에서 성능이 급락하고, 예시 90개 뒤로 이득이 느려졌다 [1]. 우리 1~3회차 지도 학습은 QLoRA 학습률 1e-4였다. 근거 강도 보통(모델과 데이터가 다르다).
3. 코드로 정답을 계산한 합성 질문: 표 과제가 아닌 Text-to-SQL에서 강한 근거가 있다. 질문 틀은 코드가 만들고 질문 문장은 언어 모델이 쓰게 하며(역번역) [5·6], 말투 9종을 돌려 쓴다 [6]. 공개 학습셋만 배운 7B는 영역 밖 데이터에서 43.8%, 31.4%로 낮았다 [6]. 근거 강도 보통. 한국어 표와 실제 이용자 질문으로 옮겨지는지 잰 심사 논문은 없다.
4. 여러 행 모으기: SQL은 계산과 긴 표에, 바로 답하기는 모호한 질문과 표준이 아닌 머리글에 강했다 [7]. 작은 모델은 코드를 써서 실행하는 방식에서 크게 나빴다 [처리 9]. 7~8B에서 "학습으로 모으기"와 "서버가 모으기"를 직접 비교한 근거는 없다. 근거 강도 약함.
5. 물은 해 고르기: 검색 단계에서 연도로 딱 자르는 거르기는 오히려 나빴고(nDCG@5 0.2087 → 0.1683), 시점 거리를 순위에 섞는 재순위가 나았다(0.2821) [8]. 한국어 학사 규정 같은 개정 문서 평가셋이다. 생성 모델 학습으로 해를 고르게 한 새 근거는 찾지 못했다. 근거 강도 보통.
6. 한국어 공개 데이터: AI허브에 표 질의응답 100만 건 [12]과 표 정답 추출형 13만 1,068건 [13] 등이 있다. 그러나 이용정책이 국외 반출에 별도 합의를 요구한다 [11]. 우리 학습 서버는 미국 동부(us-east-1)라 지금은 올릴 수 없다. KorWikiTQ(약 7만 쌍)는 CC BY-SA 4.0 [19], KorQuAD 2.0은 CC BY-ND 2.0 KR(변형물 공유 불가) [17·18]이다. 근거 강도 강함(약관 원문).
7. 학습 뒤 일반 능력이 유지되는지는 표 학습 논문들이 따로 잰다(IFEval, MMLU) [1·3]. 우리도 표 학습 뒤 일반 질문과 답없음 거절을 같이 잰다.

## 이 프로젝트에 주는 뜻

정할 것 다섯 가지. 추천은 모두 [판단]이다. 기대효과 숫자는 우리 설정(한국어, 7B, QLoRA, 학교 PDF 표)으로 잰 외부 근거가 없어 "모른다"가 기본이다. 비교 기준은 2026-11-21 측정이다([표 질문 문제 정의](../m2/표-질문-문제-정의-20261121.md) 4절): 완전한 정답 표만 줘도 A.X 14/43, Gemma 4 12B 25/43, Claude Opus 43/43. 표 사실 줄 모양이면 A.X 22/35.

### 정할 것 1. 학습 방법

| 선택지 | 근거 | 우리에게 |
|---|---|---|
| 가. 표 질문 지도 학습 | 7~8B에서 표 과제가 오름 [1·2·3] | 코드가 정답을 주므로 목표 답을 바로 만든다. 1~3회차의 과잉 거절이 다시 생길 수 있다 |
| 나. 선호 학습만(지금 4~6회차 방식) | 지도 학습한 모델 위에서 8천 쌍으로 +5%, +2.4% [4] | 모델이 실제로 틀린 답이 있어야 쌍이 된다. 5회차는 53쌍뿐이었다 |
| 다. 지도 학습 뒤 선호 학습 | [4]는 지도 학습 모델을 출발점으로 썼다 | 두 단계, 학습 서버 두 번 |

- 추천 [판단]: 가. 표 질문 지도 학습을 작게 시작한다. 확신도 중간.
- 이유: ① 코드로 계산한 정답이 있어 선호 답을 찾는 단계(쌍이 줄어든 원인, ADR-0057)가 필요 없다. ② 표 학습 근거는 거의 모두 지도 학습이다 [1·2·3]. ③ 위험은 학습률과 예시 수로 관리한다. QLoRA 급락점 약 5.0e-5 [1]보다 낮게(예: 1e-5~2e-5), 수백 개부터 늘린다. 1~3회차의 1e-4는 그 급락점보다 높았다. 과잉 거절의 원인이 학습률이었는지는 확인하지 않았다.
- 바꾸는 것: ADR-0057(선호 쌍만 늘림)과 방향이 다르다. 6회차 설계를 바꿀지 정해야 한다.
- 기대효과: 모른다. 같은 입력에서 Gemma 4 12B가 25/43이라 같은 크기대가 읽을 수 있는 수준은 그쯤이다 [실측]. 기대하지 않는 것: 표 학습으로 답없음 거절이나 일반 질문 정답이 좋아지는 것.

### 정할 것 2. 학습 데이터 제작

- 추천 [판단]: PDF 표의 칸 정보(JSON)에서 코드가 질문 틀과 정답을 만들고, 질문 문장과 답 문장은 Gemma 4 12B가 쓴다(Claude는 쓰지 않는다, ADR-0010). 코드가 답 문장 속 값이 정답과 같은지 검사한다. 확신도 중간.
- 근거: 질문 틀을 코드로 만들고 문장은 모델이 쓰게 한 방식 [5·6], 말투 9종 돌려 쓰기 [6], 대상 모델이 틀린 문항을 골라 다음 묶음을 만드는 방식(TableDreamer, 8B 평균 11.62점 상승) [3]. 우리 ADR-0044(실제 이용자 말투)와 같은 방향이다.
- 위험: 질문 말투가 틀에 묶이면 실제 질문으로 옮겨지지 않는다. 공개 학습셋만 배운 7B는 영역 밖에서 43.8%, 31.4%였다 [6]. 그래서 평가는 지금 표 질문 43문항(사람이 만든 것에 가까운 질문)으로 한다. 학습 위험: 답이 늘 "값 하나"면 근거에 없는 질문에도 값을 지어낼 수 있다. 거절 예시 비율(ADR-0043)을 지킨다.
- 예시 수: QLoRA는 90개 뒤로 이득이 느려졌고 1,500개에서 LoRA와 같았다 [1]. 8B는 4천 개 미만으로 70B를 넘었다 [2]. 첫 묶음 수백 개, 많아야 1,500개로 시작한다.
- 표 모양: 학습 예시의 근거 블록은 운영과 같은 표 사실 줄로 만든다. 우리 측정에서 A.X는 표 사실 줄 22/35, 마크다운 표 13/35였다 [실측]. 논문은 계층 머리글에 HTML, 평평한 표에 마크다운을 썼다 [3].
  - 대체됨(11-24): 표 사실 문장을 모델 입력에서 빼고 원본 표(합친 칸을 채운 표)를 준다(11-24 표 읽기 학습 계획 P5, 입력 틀 명세 6절, 둘 다 로컬 문서).

### 정할 것 3. 외부 데이터

- 추천 [판단]: 학습에는 지금 쓰지 않는다. KorWikiTQ는 학습 뒤 "일반 표 읽기가 망가지지 않았나"를 보는 점검용으로만 검토한다. 확신도 높음(약관 원문).
- 이유: ① AI허브: "본 AI데이터 등의 국외 반출을 위해서는 수행기관 등 및 한국지능정보사회진흥원과 별도로 합의가 필요합니다" [11]. 학습 서버가 us-east-1이라 합의 없이는 올릴 수 없다(ADR-0010 2026-11-03 변경 메모). 승인 없는 제3자 제공도 금지라 학교 인계에 넣을 수 없다 [11]. ② AI허브 표 데이터는 답이 지문 속 위치(`answer_start`)인 추출형이다 [12·13]. 칸 하나 찾기 위주라, 우리가 못 하는 여러 행 모으기와 물은 해 고르기에 닿지 않는다. ③ KorQuAD 2.0은 변형물 공유 금지 라이선스라 우리 프롬프트 모양으로 바꾼 데이터를 인계할 수 없다 [17·18].
- 기대효과: 모른다. AI허브 데이터의 표 원문 문자열 모양은 내려받기 전이라 확인 전이다.

### 정할 것 4. 물은 해 고르기

- 추천 [판단]: 검색 단계(서버)에서 푼다. 기준 날짜로 「작년」을 학년도로 바꾸고(지난 조사의 설정 표 안 [상대 1·2]), 근거 블록에 학년도를 표시하고, 순위에 시점 거리를 섞는다. 연도로 딱 자르는 거르기는 하지 않는다. 학습은 "표시된 학년도를 보고 고르는" 예시를 섞는 정도로 한다. 확신도 중간.
- 근거: 개정 문서 평가셋에서 연도 거르기는 거르지 않은 검색보다 나빴고(BM25 nDCG@5 0.2087 → 0.1683), 시점 재순위는 0.2821, 정답 시점을 아는 거르기는 0.3323이었다 [8]. 지난 조사도 같은 방향이다(거르면 재현율 54.6% → 49.0%, 순위로 맞추면 44.0% → 49.2%) [상대 15·16]. AWS는 질문과 메타데이터 정의로 모델이 거르기 조건을 만드는 기능을 공식 제공한다 [10].
- 주의 [실측]: 정답 표만 줘도 A.X는 「작년」 5문항 중 2문항만 맞혔다. 고르기 전에 읽기에서도 틀린다. 서버가 학년도를 풀어 줘도 5문항이 다 풀린다고 기대하지 않는다.

### 정할 것 5. 여러 행 모으기

- 추천 [판단]: 정할 것 2의 데이터에 "조건에 맞는 행을 모두 나열" 예시를 코드로 넣어 학습으로 먼저 잰다. 학습 뒤에도 남는 문항으로 서버 모으기(모델은 열과 조건만 고르고 서버가 행을 모음)를 정한다. 세기와 합은 서버 계산 쪽이 근거가 더 있다. 확신도 낮음.
- 근거: 계산과 긴 표는 SQL이 낫고 표준이 아닌 머리글은 바로 답하기가 낫다 [7]. 우리 표는 학교 PDF라 머리글이 표준이 아닌 쪽이다. 작은 모델은 코드 실행 방식에서 나빴다 [처리 9]. 7B를 SQL 쓰기로 학습한 결과는 좋지만 [5·6] 깨끗한 DB 표다. 같은 입력에서 Gemma 4 12B는 「모집인원이 100명 넘는 일반동아리는 어디예요?」(정답 네 곳)에 네 곳을 모두 답했고, A.X는 한 곳만 답했다 [실측].
- 기대효과: 모른다. 모양과 무관하게 A.X가 못 읽은 12문항이 모두 모으기 질문인지도 확인 전이다.

## 1. 배경과 조사 질문

- 왜 조사하나: 2026-11-21 측정으로 표 질문 오답이 검색보다 읽기에서 생긴다는 것을 확인했다. 2026-11-21에 답변 모델을 더 큰 모델로 바꾸지 않고 학습으로 풀기로 정했다([표 질문 문제 정의](../m2/표-질문-문제-정의-20261121.md) 6절).
- 정하려는 것: 위 정할 것 다섯 가지.
- 조사 질문:
  1. 7~14B LLM에 표 읽기를 학습시킨 방법과 효과(방식, 데이터 크기, 표 모양, 전후 정확도, LoRA와 전체 학습, 효과 없음과 다른 능력 하락)
  2. 코드로 정답을 계산한 합성 표 질문으로 학습한 사례, 틀 질문의 위험과 줄인 방법, 필요한 예시 수
  3. 여러 행 모으기와 세기: 모델이 바로 답하기 대 질의나 코드를 쓰고 프로그램이 실행하기, 작은 모델 먼저
  4. 여러 해의 같은 문서에서 물은 해 고르기: 검색 단계 거르기 대 생성 모델 학습, 「작년」 처리
  5. 한국어 표·문서 질의응답 공개 데이터의 목록, 규모, 표 모양, 이용 조건 원문

## 2. 범위와 방법

- 자료 기준: 이 폴더 `README.md`와 `AGENTS.md` 4장. 심사를 통과한 논문, 모델과 클라우드를 만드는 회사의 공식 문서, 데이터 제공 기관의 이용정책과 라이선스 원문만 근거로 쓴다.
- 기간: 2025~2026 자료를 먼저 봤다. 2024 자료(SynTQA [7])는 현상 근거로만 쓴다.
- 겹침 줄이기: 지난 조사 7편의 참고 문헌을 먼저 읽고 이미 확인한 자료는 다시 찾지 않았다. 아래에서 이렇게 부른다. ## 3. 질문별 결과

### 질문 1. 작은 LLM 표 읽기 학습의 방법과 효과

- [원문] 지도 학습: LLaMA 3.1 8B Instruct에 표 지시 2,600개로 GPT-3.5와 비슷하거나 나은 표 성능을 냈다 [1]. TableBench는 7~8B 다섯 모델을 2만 개(19,661개)로 지도 학습했고, Llama-3-8B는 4천 개 미만으로 Qwen1.5-70B를 넘었다 [2]. TableDreamer는 GPT-4o로 만든 2만 7천 개로 Llama3.1-8B 평균을 49.07%에서 60.69%로 올렸다 [3].
- [원문] 선호 학습: p²-TQA는 Qwen-2.5-7B와 LLaMA-3.1-8B에 단계별 선호 쌍 8천 개(Llama 6.7천)로 DPO를 했고, 영역 안 최대 5%, 영역 밖 최대 2.4% 올랐다 [4]. 출발점은 이미 표 질문으로 학습한 모델이다. 학회 짧은 논문(short)이다.
- [원문] LoRA와 QLoRA: TAMA 부록 D.5는 Llama 3.1-8B로 LoRA와 QLoRA(AWQ 4비트)를 다시 쟀다. 급락점이 LoRA와 QLoRA는 "around 5.0e-5", 전체 학습은 "usually around 1.0e-6"이었다. QLoRA는 예시 90개 뒤로, LoRA는 600개 뒤로 이득이 느려졌고, 1,500개에서 둘이 비슷했다 [1]. 반대로 Text-to-SQL에서는 7B 전체 학습이 LoRA보다 대체로 나았다(14B에서는 차이가 줄었다) [6].
- [원문] 효과가 없거나 나빠진 보고: 기존 표 모델들은 학습률 2e-5를 썼고 영역 밖 표 과제와 일반 능력이 기반 모델보다 떨어졌다 [1]. TableBench 학습 모델(Llama3.1-8B, 학습률 2e-5 [2])은 IFEval 평균 74.83 → 28.53, MMLU 69.41 → 15.55였다. TableDreamer(학습률 1e-6)는 74.11, 69.73으로 유지했다 [3] 표 15.
- [원문] 표 모양: TableDreamer는 계층 머리글 표를 HTML로, 평평한 표를 마크다운으로 넣었다 [3]. 행을 문장으로 푼 모양을 학습 입력으로 비교한 심사 논문은 이번에 찾지 못했다. 표를 글로 바꾸는 방법 비교는 지난 조사에 있다 [여러행] [처리 1].
- 우리로 옮길 때의 차이: 모두 영어 표, 대부분 전체 파라미터 학습, 질의응답 벤치마크(WTQ, HiTab 등)다. 한국어 학교 PDF 표, QLoRA r16, 근거 8개가 섞인 RAG 입력과 다르다. 숫자를 그대로 옮기지 않는다.

### 질문 2. 코드로 정답을 계산한 합성 질문

- [원문] SQLForge: Spider와 BIRD의 SQL 1만 8천 개를 구문 나무로 바꿔 틀로 만들고, 새 분야(1,000개 넘게)에 맞춰 SQL을 만든 뒤 질문 문장으로 역번역했다. GPT-4로 2만 5천 개를 만들어 CodeLlama 7B/13B, Qwen2 0.5B/7B를 LoRA(r128)로 학습했다 [5]. 13B가 Spider Dev 85.7%, BIRD Dev 59.8% [5]. 합성 데이터 양을 늘릴수록 꾸준히 올랐다 [5] 그림 3.
- [원문] OmniSQL: SQL을 복잡도별로 만들고 질문으로 역번역할 때 말투 9종(formal, colloquial, imperative, interrogative, descriptive, concise, vague, metaphorical, conversational)을 골라 지시했다. 합성은 오픈 모델(Qwen2.5, DeepSeek-Coder)로 했고 250만 개를 남겼다 [6]. 공개 학습셋만 배운 Qwen2.5-Coder-7B는 영역 밖 데이터에서 43.8%, 31.4%였다 [6].
- [원문] TableDreamer: 표와 질문을 함께 합성하고, 대상 모델이 기준 답보다 못한 문항(약점)을 판정 모델로 골라 다음 합성의 씨앗으로 썼다 [3]. 우리 4~6회차가 "모델이 실제로 틀린 것"을 모은 것과 같은 생각이다.
- 찾지 못한 것: 한국어 표에서 틀로 만든 질문이 실제 이용자 질문으로 옮겨지는지 잰 심사 논문. 표 질의응답에서 질문 말투 다양화의 효과만 따로 뗀 실험.

### 질문 3. 여러 행 모으기: 바로 답하기 대 프로그램 실행

- [원문] SynTQA: "Text-to-SQL demonstrates superiority in handling questions involving arithmetic operations and long tables; E2E TQA excels in addressing ambiguous questions, non-standard table schema, and complex table contents." 둘의 답을 고르는 단계로 합치면 각각보다 나았다 [7].
- [원문] 작은 모델: TableBench에서 작은 모델은 코드 실행 방식(PoT)에서 크게 나빴고 바로 답하기가 나았다. 가장 잘한 GPT-4 Turbo도 실행되는 코드가 78.67%였다 [처리 9]. 연산과 열만 목록에서 고르고 계산은 서버가 하는 쪽이 작은 모델에 맞다는 지난 판단 [여러행 요약]은 7~8B로 잰 심사 논문이 없다는 한계가 그대로다.
- [원문] SQL 쓰기 학습: 7B를 합성 SQL로 학습하면 깨끗한 DB에서는 강하다 [5·6]. 우리 표는 PDF에서 뽑은 병합 머리글 표라 그 결과를 옮기기 어렵다.
- 찾지 못한 것: 7~8B에서 같은 표 질문을 "학습으로 바로 답하기"와 "서버가 행을 모아 주기"로 나란히 잰 비교.

### 질문 4. 물은 해의 문서 고르기

- [원문] TimelyRAG(KAIST 등, Findings of EMNLP 2026): 개정이 겹치는 문서(법, 대학 학사 규정, 회사 규정, 약관)에서 시점 거리를 순위에 섞는 재순위를 냈다. 평가셋 TimelyQABench는 한국어로 만들었다(Llama-3.3-70B 생성, 세 모델 합의로 검증). 비교(nDCG@5, BM25): 거르지 않음 0.2087, 질문에 시점을 덧붙여 다시 쓰기 0.1486, 규칙으로 시행일 거르기 0.1683, GPT-4o-mini 재순위 0.1948, TimelyRAG 0.2821, 정답 시점으로 거르기(상한) 0.3323 [8] 표 5. 대학 영역에서 BM25 대비 nDCG@10 최대 24.8% 올랐다 [8].
- [원문] TimelyRAG는 질문의 기준 시점(질문 시각, 질문이 가리키는 시점)과 문서의 유효 기간을 나눠 쓰고, 질문보다 뒤에 나온 문서는 근거로 쓰지 않는다 [8] 3.3.1절.
- [원문] Re³(ACL 2026): 시간 신호를 검색 표현에 넣고 옛 판을 걸러내는 단계로 생성 정확도를 평균 9.7% 올렸다 [9]. 초록만 확인했다.
- [원문] AWS Bedrock 지식 기반은 질문과 메타데이터 정의로 모델이 거르기 조건을 만들어 적용하는 기능(implicit metadata filtering)을 공식 제공한다 [10].
- 생성 모델 학습: 근거에 시점 표시를 붙여 학습한 연구는 지난 조사에 있다 [시점 8]. 이번에 새로 찾은 것은 없다.
- 우리로 옮길 때의 차이: TimelyQABench는 모델이 만든 합성 문서와 질문이다. 우리 「작년」 질문은 5문항뿐이다.

## 5. 반대 근거와 한계

- 표 학습이 일반 능력을 무너뜨린 사례가 있다: IFEval 74.83 → 28.53, MMLU 69.41 → 15.55(학습률 2e-5, 8B) [3] 표 15. 우리 1~3회차에서 과잉 거절이 늘어난 것과 같은 종류의 위험이다.
- 7B에서는 전체 학습이 LoRA보다 나았다 [6]. QLoRA는 이득이 일찍 멈췄다(90개) [1]. QLoRA로는 논문 숫자만큼 오르지 않을 수 있다.
- 코드 실행 방식은 작은 모델에서 나빴다 [처리 9]. 연도로 자르는 거르기는 오히려 나빴다 [8] [상대 15].
- 선호 학습의 근거 [4]는 짧은 논문 한 편이고, 출발점이 이미 표 학습한 모델이다. 지도 학습 없이 선호 학습만 한 우리 4~5회차와 조건이 다르다.
- 합성 데이터 논문 셋 [3·5]은 GPT-4, GPT-4o로 데이터를 만들었다. 우리는 Claude를 못 쓰고 Gemma 4 12B를 쓴다. [5] 그림 7은 합성 모델을 오픈 모델(Llama-3-70B, Qwen-2-72B)로 바꿨을 때 틀에서 출발한 SQLForge는 안정적이고, 바로 만들게 한 방식은 크게 흔들렸다고 적었다(1천 개 규모, 수치는 옮기지 않음). 12B로 만들면 틀에서 출발하는 쪽이 더 중요하다 [판단].
- 모든 논문이 영어(또는 중국어) 표이고, TimelyQABench만 한국어인데 합성 데이터다.
- 찾았지만 없음: 한국어 표 QLoRA 학습 결과, 7~8B의 "학습 모으기 대 서버 모으기" 비교, 생성 모델 학습으로 해 고르기를 가르친 새 연구(ACL Anthology와 arXiv에서 table instruction tuning, LoRA forgetting, program-of-thought small models, time-sensitive RAG, version-aware retrieval로 찾았다).

## 6. 선택지와 권고

정할 것 다섯 가지의 선택지와 추천은 앞 절 「이 프로젝트에 주는 뜻」에 있다. 네 관점으로 본 것:

| 관점 | 표 질문 지도 학습 + 서버의 해 풀이(추천) | 선호 쌍만 늘림(ADR-0057) |
|---|---|---|
| 서비스 | 표 읽기를 직접 겨냥. 과잉 거절 재발 위험은 학습률과 거절 비율로 관리 | 쌍이 표 질문에서 잘 안 나옴(선호 답 없음 43문항) |
| 비즈니스 | 데이터는 데스크탑에서 코드와 Gemma로 만든다. 학습 서버 1회 | 학습 서버 1회, 쌍 만들기에 26B 시험 등 단계가 많음 |
| 유지보수 | 정답을 코드가 계산해 판정 단계가 줄어듦. 새 학년도 표가 오면 다시 생성 | 판정 모델 셋을 쌍마다 기록 |
| 확장 | 새 표 종류는 칸 정보만 있으면 같은 코드로 | 운영 질문이 쌓여야 쌍이 늚 |

- 권고: 지도 학습 첫 묶음(수백 개, QLoRA 학습률 5e-5 미만)을 표 질문 43문항, 개발셋 일반 문항, 답없음 거절로 잰 뒤 늘릴지 정한다.
- 버린 선택지와 이유: AI허브 데이터로 학습(리전과 인계 조건), 모델이 SQL이나 파이썬을 쓰게 하기(작은 모델에 반대 근거 [처리 9], 우리 표는 깨끗한 DB가 아님), 연도로 딱 자르는 검색 거르기(반대 근거 [8]).

## 7. 확신도와 다음 확인

- 확신도: 외부 데이터 판단은 높음(약관 원문). 학습 방법과 데이터 제작은 중간(방향은 여러 논문이 같지만 언어와 학습 방식이 다름). 여러 행 모으기는 낮음(직접 비교 없음).
- 다음 확인: 지도 학습 첫 묶음 뒤 43문항과 개발셋으로. 학습률 1e-4와 1e-5를 같은 데이터로 비교하면 1~3회차 과잉 거절의 원인 하나를 가를 수 있다.
- 다시 볼 조건: 학습 서버가 서울 리전으로 바뀔 때(AI허브), 국립국어원 약정서 원문을 볼 때, 한국어 표 학습 심사 논문이 나올 때.
