# 학습 데이터·평가셋에서 사람 검토가 남는 자리 — 실무 조사 (2026-10-21)

> 목적: M2 6단계(학습 데이터) 전에 사람 검토 범위를 정하면서 사용자가 물은 "AI 판정에 맡기지 않고 사람이 붙어야 하는 이유"와 "실무는 학습 데이터·평가셋을 어떻게 만드는가"에 답한다.
> 방법: 조사 네 갈래(AI 판정 신뢰도, 학습 데이터 제작 실무, 평가셋 제작 실무, 사람·AI 협업 검수 설계)를 조사 에이전트로 나눠 모은 뒤, 결정에 쓴 근거는 본 세션이 원문으로 다시 확인했다. 확인하지 못한 주장은 §7에 따로 두고 결정에 쓰지 않았다.
> 쓰인 곳: ADR-0037(학습 데이터 검토 방식), `docs/rag/m2/A.X-기준-계획-20261017.md` §5·§6.

## 1. 결론

1. 실무도 학습 데이터·평가 채점을 사람이 하나하나 보지 않는다. 대량 생성과 판정은 모델이 하고, 사람은 **기준을 만들고 AI 판정자를 검증하는 자리**에 남는다. [원문 1·2·3]
2. 사람이 붙어야 하는 이유는 세 가지다. ① 판정 기준은 실제 출력을 봐야 생긴다(기준 표류). ② AI 판정자의 신뢰도는 과제마다 달라 우리 과제에서 사람과 대조해 봐야 한다. ③ 답이 없는 예시처럼 현장 판단이 필요한 몫은 사람 데이터가 앞섰다. [원문 4·5·6]
3. 그래서 사람 표본은 끝이 아니라 **처음에** 두는 것이 맞다 — 첫 묶음에서 AI 판정과 나란히 보고 판정 지침을 굳힌 뒤 나머지를 AI가 판정한다. [판단, ADR-0037]

## 2. 실무에서 AI가 맡는 일

| 일 | 사례 | 근거 |
|---|---|---|
| 학습 데이터 대량 생성 | NVIDIA Nemotron-4 340B: "over 98% of data used in our model alignment process is synthetically generated" | [원문 1] |
| 좋은 답 고르기(선호 라벨) | AI2 Tülu 3: 여러 모델의 답을 LLM 판정으로 짝 비교해 선호 라벨을 붙임 | [원문 2] |
| 평가 채점 | Anthropic 평가 문서: 자동 채점 문항을 많이 두는 쪽을 권함("Prioritize volume over quality"), 사람 채점은 "Avoid if possible", 생성한 모델과 다른 모델로 채점하기를 권함 | [원문 3] |

- 사람 전수 검토는 실무의 기본값이 아니다. 이 점은 우리 ADR-0010의 '사람 무작위 200개'를 줄이는 쪽 근거다(반대 근거가 아니라 같은 방향).

## 3. 사람이 남는 자리

### 3.1 기준 만들기 — 출력을 봐야 기준이 생긴다

- Shankar 외(2024)는 LLM 판정 기준을 정하는 사용자 실험에서 기준 표류(criteria drift)를 보고했다: "users need criteria to grade outputs, but grading outputs helps users define criteria". [원문 4]
- 우리에게 뜻하는 것: 판정 지침을 미리 다 써 둘 수 없다. 사람이 첫 출력을 보고 기준을 굳힌 뒤 대량 판정을 돌려야, 2천여 개를 판정한 뒤 기준이 틀린 것을 알고 전부 다시 판정하는 일을 피한다. [판단]

### 3.2 AI 판정자 검증 — 신뢰도는 과제마다 다르다

- Bavaresco 외(ACL 2025)는 20개 평가 과제에서 LLM 판정과 사람 판단을 비교해 모델·데이터셋에 따른 편차가 크다고 보고하고, "LLMs should be carefully validated against human judgments before being used as evaluators"라고 결론 냈다. [원문 5]
- 우리 과제(한국어 학교 문서, 표 읽기, 근거 8개 중 맞는 근거 고르기)는 일반 벤치마크 점수로 대신할 수 없다. 첫 묶음에서 사람과 Claude 판정이 얼마나 맞는지를 직접 잰다. [판단]
- 작은 팀은 도메인 전문가 한 명이 판정 기준을 맡는 것이 효과적이라는 실무 지침이 있다("benevolent dictator"). [원문 7]

### 3.3 답없음 예시 — 사람 데이터가 앞선 곳

- NVIDIA ChatQA는 사람이 쓴 대화 7천 개(답없음 1.5천 턴 — 질문에 맞는 근거 부분을 지워 만들고, 정해진 거절 문장을 정답으로)와 GPT-3.5로 만든 같은 규모 합성 데이터를 비교했다. 평균 점수는 거의 같았지만(54.14 대 54.08) 답없음 문항이 많은 평가셋 두 개에서는 사람 데이터가 앞섰고, 저자들은 답없음 예시의 품질 차이로 봤다. [원문 6]
- 우리 A.X 기준선의 남은 약점도 근거 없이 단정하는 틀린 답이다(오답률 6.0%, 답없음 거절 89.3%). 사람 표본에 거절 예시를 반드시 넣는다. [실측 — `../m2/2단계-A.X-새기준선-20261020.md`, 판단]

## 4. 틀린 학습 데이터의 비용

- Gekhman 외(EMNLP 2024): 모델이 모르던 사실을 담은 미세조정 예시는 늦게 학습되고, 학습될수록 지어내는 경향을 선형으로 늘렸다. [원문 8] → 근거 블록에 없는 값을 담은 목표 답은 '근거에 없는 사실로 답하기'를 가르친다. 자동 검사(답의 값·인용이 근거 글에 있는지, 정답이 근거 블록에 남았는지)로 먼저 거른다.
- 모델이 만든 학습 데이터의 품질(옛 기준선): Self-Instruct 200개 표본에서 모든 칸이 맞은 비율 54%. [원문 9, 2022~2023]
- 사람이 만든 평가셋도 틀린다: MMLU 문항의 6.49%에 오류가 있다고 추정했고, Virology는 분석한 문항의 57%에 오류가 있었다. [원문 10] → 사람 판단도 정답으로 가정하지 않고, 검사자를 엇갈리게 둔다(우리 평가셋의 이중 라벨링 ADR-0020과 같은 생각).

## 5. 표본 크기

- 오류 0개를 본 표본 n개의 오류율 95% 상한은 약 3/n이다(rule of three): 30개 약 10%, 200개 약 1.5%. [계산]
- 표본 30개로는 학습 데이터 전체 오류율을 좁게 잴 수 없다. 우리 표본의 목적은 오류율 보증이 아니라 ① 판정 기준을 굳히고 ② Claude가 우리 과제에서 사람과 같은 판단을 하는지 확인하는 것이다. 학습 데이터의 최종 품질은 학습 전후 개발셋 짝 비교(ADR-0033 결정 2, ADR-0035)로 본다. [판단]
- 사람 시간: 지난 Claude 판정 확인 10개에 8분 35초(문항당 약 52초) — 30개 약 30분. [실측 — `../m1/베이스라인-측정-20261012.md`, 계산] 학습 예시는 근거 8개(프롬프트 중앙 3,422토큰)가 붙어 판정 이유·인용 줄 표시 없이 보면 1~2분이 든다 — 200개 3.3~6.7시간. [계산·판단]

## 6. 우리 안에 반영한 것과 반영하지 않은 것

| 조사에서 나온 것 | 반영 | 이유 |
|---|---|---|
| 기준 표류 | 사람 표본을 첫 묶음에, Claude 판정과 나란히 | 대량 판정 전에 지침을 굳힘 |
| 판정자 검증 | 사람과 Claude가 2개 이상 어긋나면 지침 고치고 새 30개 | 평가셋 표본 규칙(ADR-0019)과 같은 문턱 |
| 탈락 쪽 오류 | 표본에 Claude가 탈락시킨 예시도 넣음 | 좋은 거절 예시를 지나치게 버리면 비율이 틀어짐 |
| 답없음 예시 품질 | 표본을 답 · 거절 + 안내 · 표 질문으로 고르게 | ChatQA, 우리 A.X 약점 |
| 새 지식 예시의 지어내기 | 근거에 없는 값·지워진 정답·모호한 표 근거는 자동 검사로 거름 | Gekhman 외, 5단계 보고서 §8 |
| 사람 무작위 200개(ADR-0010) | 반영 안 함 | 3.3~6.7시간 × 데이터 만들 때마다, 기준 표류는 못 막음 |
| 여러 모델 판정자(배심원 방식) | 반영 안 함 | 판정 비용·운영이 늘고, 판정자 검증은 그래도 사람 몫. 효과 숫자는 원문으로 확인 못 함 |
| 판정 확신도로 사람에게 보낼 예시 고르기 | 반영 안 함 | 확신도와 정확도의 관계를 모델·과제마다 따로 재야 하고, 확신하며 틀린 예시는 빠져나감 |

## 7. 조사 중 나왔지만 원문으로 확인하지 못한 것 (결정에 쓰지 않음)

- 과제별 판정 일치도(κ) 숫자, 모델별 판정 확신도 분포, 2026년 arXiv 문헌 몇 편(안전 판정 불일치, 표 읽기 부주의, 일치도 지표 보고법), 사람·LLM 업무 배분의 성능 향상 비율, 판정 보정에 드는 사람 표본 수(150~300), Phi-4 합성 비율, 제3자 블로그가 옮긴 OpenAI 평가 지침 인용, 데이터 라벨링 업체의 감사 비율.
- 조사 에이전트 초안에 있던 '실제 데이터와 50:50 이상 섞으라'는 권고는 인용 논문(모델 붕괴, Gerstgrasser 외 2024)에 없었다. 그 논문은 모델 출력으로 세대를 거듭해 다시 학습하는 경우를 다루며, 우리처럼 학교 문서 근거로 한 번 행동을 가르치는 LoRA와는 상황이 다르다.
