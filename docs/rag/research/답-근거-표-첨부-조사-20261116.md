# 답변에 근거 원본 표를 함께 보여 주는 방법 조사

## 요약

- [원문] 근거를 보여 주면 틀린 답을 받아들이는 비율이 줄지만 조금이다. 출처 링크를 준 조건에서 틀린 답에 동의한 비율은 78.2%에서 68.2%로 줄었고, 참가자 308명 중 189명은 출처를 한 번도 누르지 않았다 [16]. 다른 실험에서는 출처 링크를 단 답 1,976개 중 9.77%만 열렸고, 무작위로 단 출처도 신뢰를 올렸다 [17]. 근거 글을 화면에 바로 보이는 방식은 모델의 풀이 글보다 과신이 덜했다 [18·19](질문 1).
- [원문] 모델 제작사 제품은 모두 「답의 어느 구간이 어느 문서의 어디에서 왔나」를 돌려준다(글자 위치, 쪽 번호, 인용한 글, 근거 점수). 표 칸 위치를 인용으로 돌려주는 제품은 없고, 표를 인용 단위로 다루는 것은 Google의 표 주석(표와 그 설명을 한 청크로 묶음) 하나다 [1~13](질문 2).
- [원문] 8B 모델에게 프롬프트로 인용을 시키면 인용 F1이 19.7이고, 인용 예시로 학습하면 72.0이다 [23]. 모델 안쪽 값으로 서버가 고르는 방법은 7B 모델에서 스스로 붙인 인용과 비슷하거나 낫지만 모델 내부 접근이나 추가 추론 32번이 든다 [24·25]. 표 행·열 단위로 근거를 잇는 공개 방법은 GPT-4o 여러 번 호출이다 [26](질문 3).
- [원문·판단] 큰 표는 표만 따로 가로·세로 스크롤 상자에 넣는 것이 접근성 기준에 맞다 [14]. 관련 행만 강조, 접기를 사용자 실험으로 비교한 최근 심사 논문은 찾지 못했다. 쪽 그림 위에 근거 영역을 그리는 모델은 7B가 후보 문서 3개에서 32.3%만 맞혔다 [27](질문 4).
- 권고 [판단]: 서버가 모델의 출처 번호로 표 하나를 골라, 답에 나온 값이 든 행과 머리글을 펼친 채 보이고 전체 표는 접어 두며, 표 위에 게시일과 학년도, 아래에 원문 쪽 링크를 단다(선택지 나). 붙이기 전에 표 질문 47개로 「출처 번호가 정답 표를 가리키는 비율」과 「값으로 고른 행이 정답 행인 비율」을 먼저 잰다. 확신도 중간.

## 1. 배경과 조사 질문

- 왜 조사하나: 2026-11-16 측정에서 표 조각이 검색되면 그 표 전체와 기호 주석을 프롬프트에 넣었더니 표 질문 47개 중 맞음이 21에서 26으로 늘었다. 못 맞춘 21개 중 10개는 프롬프트의 표 안에 정답이 다 있었다(여러 행을 훑어 골라야 하는 질문 10개, 다른 해의 표를 읽은 질문 5개 등). 그래서 「답 아래에 원본 표와 범례를 함께 보여 주자」는 방향이 정해졌다. 표는 모델이 쓰지 않고 서버가 저장된 원문에서 붙인다.
- 정하려는 것: 표를 붙일지, 붙인다면 어느 표를(프롬프트에 든 표는 문항당 중앙값 4개, 최대 11개), 어떤 모양으로(33행 12열 같은 큰 표, 폰 화면), 다른 해의 표나 PDF에서 잘못 뽑힌 표를 어떻게 막을지.
- 지금 답변 형식(ADR-0050): 결론 → 안내 → 참고한 문서. 모델은 출처 번호를 쓰고 서버가 지운 뒤 그 번호가 가리키는 문서 대장 정보로 「참고한 문서」를 만든다. 청크와 출처 번호는 관리자 개발자 모드에만 보인다.
- 조사 질문:
  1. 생성형 답 옆에 근거 원문(문단, 표, 인용)을 보여 주면 사용자가 틀린 답을 얼마나 알아채는가. 신뢰와 과신에는 어떤 영향이 있나. 반대 결과도 찾는다.
  2. 모델 제작사의 제품과 API는 답에 근거를 어떤 모양으로 붙이나. 표가 근거일 때는 어떻게 하나.
  3. 근거가 여러 개일 때 답에 실제로 쓰인 근거를 고르는 방법은 무엇이고 얼마나 정확한가. 7~8B 모델이 스스로 인용하는 방식과 서버가 고르는 방식을 나눈다.
  4. 큰 표를 채팅 답 안에 보여 주는 방법(관련 행 강조, 접기, 원본 쪽 링크나 쪽 그림)과 한계는 무엇인가.

## 2. 범위와 방법

- 자료 기준: `AGENTS.md` §4와 이 폴더 README 머리말. 근거는 학회·학술지 심사를 통과한 논문, 모델을 만드는 회사의 공식 문서, 표준 문서(W3C, IETF)만 쓴다(A). 공식 예제 문서는 사례(B)로만 쓴다. 프리프린트, 개인 블로그, 업체 글, 검색 요약, 하위 에이전트 보고는 실마리로만 썼다.
- 기간: 2025~2026년 자료를 먼저 찾았다. 2021~2024년 자료([18·20~22·24~26])는 「그런 현상이 있다」는 근거로만 쓰고, 그때 모델의 숫자를 A.X 4.0 Light에 옮기지 않는다.
- 포함 / 제외: 사용자 실험이 있는 HCI·NLP·IR 논문, 인용 생성과 근거 연결(attribution) 논문, 제작사 API 문서의 인용 구조, 표 화면 표준. 일반 설명(XAI)만 다룬 실험(미로 과제 등)과 불확실성 표현 실험은 뺐다(부록 A).
- 검색한 곳과 날짜: 2026-11-16. platform.claude.com, developers.openai.com, aistudio.google.com(ai.google.dev가 옮겨 감), docs.cloud.google.com, learn.microsoft.com, api.ncloud-docs.com, w3.org, rfc-editor.org, ACL Anthology, OpenAlex·Crossref(게재처 조회), arXiv(정식판 원고 대조용). 하위 에이전트 셋이 후보를 모으고, 게재처 조회와 원문 대조는 이 세션이 직접 했다.
- 고른 기준 / 뺀 기준: 논문은 `venue_check.py`로 게재처를 확인했다. ACM 논문집 PDF는 자동 접근이 막혀(403) 같은 저자의 arXiv 판으로 문장을 대조하고 게재처와 쪽은 Crossref에서 적었다.
- 건수: 하위 에이전트 후보 약 60건(겹침 포함) → 게재처 조회 26건(게재 확인 20, 프리프린트만 6) → 원문을 받아 대조 27건(논문 12, 공식 문서·표준 15). 인용 문장과 숫자 41개를 `quote_check.py`로 원문 글과 대조했고 모두 「있음」이다. 하위 에이전트 보고 중 Bansal 외 [20]의 저자 목록이 원문과 달라 원문대로 고쳤다.
- 제작사·기관 체크리스트: Anthropic 찾음 [1] · OpenAI 찾음 [2·3] · Google Gemini API 찾음 [4·5] · Google Vertex AI Search 찾음 [6·7] · Microsoft 찾음 [8~11] · NAVER CLOVA Studio 찾음 [12·13] · NAVER Cloud RAG 개요 안내는 403으로 열지 못함 · Meta, NVIDIA, LG, SKT, KT, Upstage, Kakao는 답에 인용을 붙이는 공식 API 문서를 찾지 못함 · W3C 찾음 [14] · IETF 찾음 [15].

## 3. 질문별 결과

### 질문 1. 근거를 함께 보여 주면 틀린 답을 알아채는가

- [원문] 출처는 틀린 답에 대한 과신을 줄인다. 사전 등록 실험(N=308, LLM이 들어간 질의응답 앱)에서 설명 없이 출처 링크만 준 조건은, LLM 답이 틀렸을 때 동의율이 78.2%에서 68.2%로 낮고 맞았을 때는 67.2%에서 73.4%로 높았다 [16]. 틀린 답에서 참가자 정답률은 출처만 31.8%, 아무것도 없음 21.8%, 설명만 17.2%였다 [16]. 효과는 있지만 출처가 있어도 틀린 답의 약 3분의 2를 받아들였다 [계산].
- [원문] 사람들은 출처를 잘 열지 않는다. 같은 실험에서 308명 중 189명은 출처를 한 번도 누르지 않았다 [16]. 다른 실험(N=303)에서는 출처가 하나 이상 달린 답 1,976개 중 193개(9.77%)만 열렸다 [17].
- [원문] 출처가 붙어 있다는 것만으로 신뢰가 오른다. 출처 0개, 1개, 5개와 관련 출처, 무작위 출처를 나눈 실험에서 출처가 있으면 신뢰가 올랐고 「a result that held true even when the citations were random」이었다. 출처를 연 사람은 신뢰가 낮아졌다 [17].
- [원문] 근거 글을 바로 보여 주는 것은 모델의 풀이 글보다 덜 속는다. 주장 검증 실험(80명)에서 ChatGPT 풀이 글을 본 사람은 풀이가 틀렸을 때 무작위보다 낮은 정확도를 냈다. 검색된 문단을 본 조건은 그때 0.54(근거 없음 0.49)로 덜 떨어졌다 [18]. 문서에서 값을 뽑아 주는 도구 실험(162명, 답의 30%를 일부러 틀리게 함)에서 관련 문단 검색은 원문 전체를 보는 것과 비슷한 판단을 더 빨리 냈고, LLM 풀이는 오류를 덜 찾게 했다 [19].
- [원문] 설명이 정답 여부와 상관없이 받아들임을 늘린다는 결과는 LLM 전부터 있었다 [20]. 출처 쪽 저자도 「출처가 엉터리면 오히려 해가 될 수 있다」고 적었다 [16].
- [원문] 표를 사용자에게 보인 실험은 하나뿐이다. 표 행·열 강조를 16명에게 보이고 유용성과 정확성을 물었는데 대조군이 없다 [26]. 표를 함께 보일 때 틀린 답을 얼마나 알아채는지 잰 심사 논문은 찾지 못했다.
- [판단] 우리에게: 표를 답 아래에 붙이는 것은 위 실험의 「근거를 화면에 바로 보이는」 조건에 가깝다. 다만 실험의 출처는 대부분 누르는 링크였고 근거는 문단이었다. 접어 둔 표는 링크처럼 열리지 않을 가능성이 크다. 그리고 표를 붙여도 틀린 답의 상당 부분은 그대로 받아들여진다. 표 첨부는 답 정확도 개선을 대신하지 못한다.

### 질문 2. 제작사 제품은 근거를 어떤 모양으로 붙이나

| 제품 | 답에 붙는 것 | 표 언급 |
|---|---|---|
| Anthropic Citations [1] | 답 구간마다 인용 목록. 인용한 글(`cited_text`), 문서 번호, 위치(PDF는 쪽 번호 범위, 글은 글자 위치, 사용자 지정 블록은 블록 번호). 「citations are guaranteed to contain valid pointers to the provided documents」 | 없음. 「Only text citations are currently supported」 |
| OpenAI 파일 검색 [2·3] | `file_citation`: 파일 ID, 파일 이름, 답 안에 꽂을 위치(`index`). 검색 결과 글과 점수(0~1)는 `include`로 따로 요청 | 없음. 지원 파일 목록에 xlsx, csv가 없다 |
| Gemini File Search [4·5] | `file_citation`: 파일 이름, 주소, 근거 글(`source`), 쪽 번호(있으면), 그림 ID, 답의 구간(바이트 위치) | 없음 |
| Vertex AI Search 답변 [6·7] | 답 문장마다 출처 번호와 근거 점수(0~1, 문장이 근거에 얼마나 기대는지), 참조 청크 본문. 표 주석을 켜면 「a description (annotation) of the table and the table itself are assigned to a chunk」, 그 주석이 답의 출처가 될 수 있다 | 있음(표를 한 청크로) |
| Azure OpenAI On Your Data [8] | 인용 이름은 색인의 파일 이름 칸에서 만든다. 검색됐지만 인용되지 않은 문서는 따로 표시. 2026-10-14 종료됨. 표는 「consider converting it to text」 | 있음(글로 바꾸라는 권고) |
| Azure Document Intelligence [10·11] | 인용 기능이 아니라 문서 분석. 표 칸마다 행·열 번호, 합친 칸, 쪽 번호와 칸 둘레 좌표. 「docx/xlsx/pptx/html format aren't rendered」라 좌표는 PDF와 그림에만 | 있음(칸 좌표) |
| CLOVA Studio [12·13] | RAG Reasoning 모델은 답 안에 `<doc-ID>…</doc-ID>` 태그로 근거 문서 ID를 감싼다. RAG 서비스는 인용 목록에 파일 이름, 인용된 글, 글자 위치, 청크 번호, 쪽 번호를 준다 | 없음 |

- [원문] 공통점은 「모델은 근거 번호나 ID를 가리키고, 사람이 볼 글과 쪽은 시스템이 저장된 원문에서 꺼낸다」는 것이다 [1·3·5·13]. ADR-0050의 출처 번호 → 문서 대장 방식과 같다.
- [원문] 인용이 있는지와 인용이 맞는지는 별개다. Anthropic은 값마다 인용이 붙는 것을 보장하지 않는다고 적었고 [1], Microsoft의 이전 예제는 인용 ID 검사가 「not whether each claim is actually supported by its source」라고 적었다 [9]. Vertex는 문장마다 근거 점수를 따로 준다 [6].
- [판단] 우리에게: 표 칸 위치를 인용으로 주는 제품이 없으므로 「모델이 표 칸을 가리키게 하는」 기성 방식은 없다. 표를 한 덩어리로 묶어 출처 단위로 쓰는 것(Vertex의 표 주석)이 가장 가까운 실무다. 표를 붙인다면 표 단위로 가리키고 행 강조는 서버가 따로 정해야 한다.

### 질문 3. 실제로 쓰인 근거를 고르는 방법과 정확도

- [원문] 모델이 스스로 붙이는 인용은 학습해야 쓸 만하다. 긴 문서 질의응답 인용 평가에서 프롬프트만 준 Llama-3.1-8B-Instruct의 인용 F1은 19.7, 인용 예시 4만 5천 개로 학습한 LongCite-8B는 72.0, GPT-4o는 65.6이었다(GPT-4o가 판정) [23]. 2023년 7B 모델 둘은 같은 프롬프트 방식에서 대부분 문장에 형식대로 인용을 달지 못했다 [24]. 2023년 상용 생성형 검색 엔진도 인용의 74.5%만 그 문장을 뒷받침했다 [21].
- [원문] 서버가 고르는 방법은 두 갈래다. 모델 내부 값(어느 근거가 답 토큰에 영향을 줬나)으로 고르는 MIRAGE는 Zephyr 7B에서 인용 F1 45.6(스스로 인용 30.6), LLaMA 2 7B에서 27.6(26.0)이었다 [24]. 근거를 빼 가며 답의 확률이 어떻게 바뀌는지 보는 ContextCite는 어떤 모델에도 붙일 수 있지만 답 하나에 근거를 뺀 추론을 32번 더 한다 [25].
- [원문] 표 행·열 단위로 근거를 잇는 MATSA는 GPT-4o를 여러 번 부르는 다중 에이전트 방식이고, 기준보다 F1이 8~13% 높았다 [26]. 표에 기댄 근거 연결이 어려운 이유로 줄임말, 겹친 머리글, 행·열 맥락 없이는 칸을 읽을 수 없다는 점을 든다 [26].
- [판단] 우리에게: A.X는 이미 출처 번호를 쓰도록 학습했다(ADR-0039). 그러므로 「어느 표를 붙이나」의 1차 후보는 모델이 쓴 출처 번호가 가리키는 청크의 표다. 8B 모델을 학습하면 인용이 크게 나아진다는 [23]의 결과는 방향의 근거이고, 우리 모델의 출처 번호가 표를 맞게 가리키는 비율은 재 봐야 안다. 모델 내부 값 방법은 지금 서빙(Ollama)에서 내부 값을 꺼내기 어렵고, ContextCite는 답 하나에 추론 32번이 더 들어 데스크탑 GPU 12GB에서 지연이 커진다. 답에 나온 숫자와 이름을 표 칸 글자와 맞춰 행을 고르는 단순 규칙에 대한 공개 실험은 찾지 못했다. 우리 자료로 재야 한다.

### 질문 4. 큰 표를 채팅 답 안에 보여 주는 방법

- [원문] 접근성 기준(WCAG 2.2 Reflow)은 데이터 표를 가로 스크롤 예외로 둔다. 「It is acceptable to provide two-dimensional scrolling for such parts of the content」이고, 표를 따로 스크롤 상자에 넣어 나머지 글은 폭에 맞게 흐르게 하는 구현을 통과 예로 든다. 칸 하나하나의 글은 예외가 아니다 [14].
- [원문] 원본 쪽 링크: PDF 주소 끝의 `#page=N`은 표준 조각 식별자다(첫 쪽이 1) [15]. 쪽 번호는 Anthropic, Gemini, CLOVA Studio가 인용에 담아 준다 [1·5·13]. 칸을 쪽 그림 위에 표시하려면 칸 좌표가 필요한데, Document Intelligence가 PDF와 그림에 한해 칸 둘레 좌표를 준다 [10·11].
- [원문] 쪽 그림 위에 근거 영역을 모델이 그리는 연구(VISA)는 7B 모델이 후보 문서 3개에서 영역 정확도 32.3%, 답 정확도 41.8%였고, 표와 그림은 문단과 정확도가 다르다고 적었다. 사용자 실험은 없다 [27].
- [근거를 찾지 못함] 채팅 답 안에서 관련 행만 강조하거나 접는 방식을 사용자 실험으로 비교한 2022~2026년 심사 논문은 찾지 못했다. 작은 화면 표 연구는 2002년, 2005년 것만 보였다(부록 A).
- [판단] 우리에게: 33행 12열 표를 그대로 넣으면 폰에서 가로·세로 스크롤이 생긴다. 기준에 맞추려면 표를 자기 스크롤 상자에 넣고 답 글은 폭에 맞게 둔다. 관련 행 강조와 접기의 효과는 근거가 없으므로 우리 화면으로 확인해야 한다.

## 5. 반대 근거와 한계

- [원문] 출처가 있다는 것만으로 신뢰가 오르고, 무작위 출처도 그랬다 [17]. 틀린 표를 붙이면 틀린 답을 더 믿게 만들 수 있다. 출처 쪽 저자도 엉터리 출처가 해가 될 수 있다고 적었다 [16].
- [원문] 출처를 대부분 열지 않는다(308명 중 189명 [16], 답의 9.77% [17]). 접어 둔 표는 같은 운명일 수 있다.
- [원문] 근거를 보여도 틀린 답의 상당 부분은 받아들여진다. 출처 조건에서도 틀린 답 동의율이 68.2%였다 [16].
- [원문] 근거 글과 LLM 풀이를 함께 보여 줘도 근거 글만 보는 것보다 낫지 않았다 [18]. 답 글이 길게 설명하면 표를 덜 볼 수 있다.
- 자료의 한계: 사용자 실험 다섯 편 [16~20]은 영어 사용자, 일반 상식이나 과학 기사 과제이고, 근거는 문단이나 링크였다. 학교 안내 표를 근거로 한 실험은 없다. 인용 정확도 숫자 [23·24]는 영어·중국어 긴 문서 과제와 2023~2024년 모델 것이라 A.X에 옮기지 않는다. MATSA [26]는 데모 논문이고 사용자 평가에 대조군이 없다.
- 찾았지만 없음: 표를 채팅 답과 함께 보였을 때 오답 발견률을 잰 심사 논문, 관련 행 강조·접기를 비교한 최근 사용자 실험, 표 칸 위치를 인용으로 돌려주는 제작사 API(검색한 곳: ACL Anthology, ACM 서지, 제작사 문서 6곳).

## 6. 선택지와 권고

선택지

- 가. 표 전체를 접어서 붙인다: 모델의 출처 번호가 가리킨 표 하나를 범례와 함께 「표 보기」 아래 접어 둔다.
- 나. 관련 행을 펼쳐 보이고 전체 표는 접는다: 가와 같은 표를 고르고, 답에 나온 값(숫자, 이름)이 든 행과 머리글을 서버가 골라 답 바로 아래 펼쳐 보인다. 전체 표와 범례는 접어 둔다. 표 위에 게시일·학년도, 아래에 원문 쪽 링크.
- 다. 표는 붙이지 않고 원문 쪽 링크만 준다: ADR-0050의 「참고한 문서」에 `#page=N` 쪽 링크를 더한다.
- 라. 모델이 표 칸을 직접 가리키게 학습한다.

| 서비스 | 열어야 보인다. 출처를 한 번이라도 연 사람은 308명 중 119명 [16], 출처 달린 답 중 열린 것은 9.77% [17]라 오답 발견 효과가 작을 것 [판단] | 열지 않아도 근거가 보인다(근거 글을 바로 보인 조건에 가깝다 [18·19]). 틀린 행이 강조되면 오히려 오답을 믿게 할 위험 [17] | 화면이 가장 가볍다. 쪽 이동이 필요하고 HWP·HTML 첨부는 쪽이 없다 [11] |
| 비즈니스 | 서버 작업만, 모델·학습 그대로 | 행 고르기 규칙과 화면 작업이 더 든다. 모델·학습 그대로 | 가장 적다 |
| 유지보수 | 표를 출처 단위로 묶는 색인 규칙 하나 | 행 고르기 규칙이 하나 더 생긴다. 특정 학과명·금액 조건문이 아니라 「답의 값과 칸 글자 일치」라는 구조 규칙이어야 한다 | 문서 대장의 쪽 정보만 |
| 확장 | 다른 학교도 표 저장만 있으면 같다 | 같음. 행 고르기 정확도는 학교 문서마다 재야 한다 | 같음 |

- 권고 [판단]: 나. 다만 붙이기 전에 표 질문 47개로 두 가지를 먼저 잰다. (1) 모델의 출처 번호가 정답이 든 표를 가리키는 비율, (2) 답의 값으로 고른 행이 정답 행인 비율. 둘 중 하나라도 낮으면 그 부분은 가(전체 접기)로 낮춘다. 다른 해의 표를 붙이는 위험은 표 위에 게시일과 학년도를 크게 보이는 것으로 줄인다([시점 혼동 조사](시점-혼동-위험-조사-20261029.md)와 ADR-0047의 날짜 줄과 같은 방향). PDF에서 뽑은 표는 원본과 다를 수 있으니 표 아래에 원문 쪽 링크를 늘 단다 [15].
- 이유: 출처를 링크로만 주면 대부분 열지 않는다 [16·17]. 근거 글을 바로 보이면 풀이 글보다 덜 속는다 [18·19]. 제작사도 모델은 번호만 가리키고 원문은 시스템이 꺼낸다 [1·3·5·13]. 우리 모델은 이미 출처 번호를 쓴다(ADR-0039).
- 기대하지 않는 것: 표 첨부로 답 정확도가 오르지 않는다. 남은 오답 21개는 그대로다. 사용자의 오답 발견도 일부만 늘 것이다(출처 조건에서도 틀린 답 동의율 68.2% [16]).
- 버린 선택지와 이유: 라는 공개 제품에 선례가 없고 [1~13], 표 칸 근거 연결의 공개 방법은 GPT-4o 여러 번 호출이다 [26]. 학습 데이터를 다시 만들어야 한다. 서버가 모델 내부 값이나 추론 32번으로 고르는 방법 [24·25]은 지금 서빙에서 내부 값을 꺼내기 어렵고 지연이 크다. 쪽 그림 위에 칸을 자동 표시하는 것은 정확도가 낮고 [27], 칸 좌표는 PDF와 그림에만 있다 [11].

## 7. 확신도와 다음 확인

- 확신도: 중간. 「근거를 바로 보이면 덜 속고, 링크는 잘 안 연다」는 다섯 편이 같은 방향이다 [16~20]. 그러나 표 근거, 한국어, 학교 안내를 다룬 실험은 없고, 행 고르기 정확도는 아직 모른다.
- 다음 확인(언제, 무엇으로): 표 첨부 설계 전에 표 질문 47개 실행 기록으로 (1) 출처 번호 → 정답 표 비율, (2) 값 일치 행 → 정답 행 비율, (3) 붙일 표가 다른 해 문서인 비율을 잰다. 화면 시안은 33행 12열 표로 폰 폭(375px)에서 확인한다.
- 다시 볼 조건: 표 근거 사용자 실험이나 표 칸 인용을 돌려주는 제작사 API가 나올 때, 운영 서빙을 클라우드로 옮겨 모델 내부 값을 쓸 수 있게 될 때(ADR-0030), 학습한 모델의 출처 번호 정확도가 크게 바뀔 때.
