# 학습 예시 초안 모델의 로컬 후보 조사

## 요약

1. 데스크탑에서 먼저 잴 후보는 전문가 혼합(MoE) 모델 둘이다. Gemma 4 26B A4B(Google, 활성 3.8B, Ollama 16GB)와 Qwen3.6 35B A3B(Alibaba, 활성 3B, Ollama 23GB)이고, 비교 기준은 지금의 Gemma 4 12B다. 두 후보 모두 Apache 2.0이라 출력을 A.X 학습 목표로 쓰는 데 조건이 없다 [1·3·4].
2. 학습 서버(A10G 24GB)에서 잴 후보는 dense 모델 셋이다. Gemma 4 31B, Qwen3.8 27B, A.X 3.1(SKT, 처음부터 학습한 한국어 중심 모델)이다. 데스크탑에서는 절반 가까이 CPU로 넘어가 느릴 것으로 본다 [계산].
3. 우리 개발셋에서 정답 근거가 프롬프트에 있던 76문항 중 Gemma 4 12B가 64개로 가장 많이 맞혔다. Mi:dm 2.0 Base는 57, Qwen3-14B는 58이었다 [실측]. 그래서 같은 계열의 큰 모델을 1순위로 둔다. 한국 회사 발표 점수(지식·문화 문항 중심)보다 근거 읽기 실측을 앞에 둔다.
4. 큰 모델이 늘 좋은 데이터를 만들지는 않았다. 문제 풀이 점수와 데이터 생성 실력은 상관이 약했다 [13]. 크기만으로는 좋은 초안 모델을 예측하지 못했고, 품질을 모를 때는 학생과 같은 계열을 기본값으로 권한다 [12]. 우리 학생 A.X 4.0 Light는 Qwen 2.5에서 출발했으므로 Qwen 계열 후보를 하나 넣는다. 다만 그 연구에 한국어는 없다.
5. 권고: 데스크탑에서 위 셋을 같은 표본(목표 답 오류 30 + 통과 30)으로 다시 만들고 Claude가 판정한다(ADR-0048 결정 6의 선). Qwen3.6 35B A3B는 WSL 메모리를 15GiB에서 24GiB 정도로 늘려야 한다. 학습 서버 후보는 접속 정보가 오면 같은 표본으로 잰다.

## 1. 배경과 조사 질문

- 왜 조사하나: 학습 예시 계획 570개 중 Claude 판정 통과는 220개(38.6%)다. 처음 막힌 단계로 나누면 목표 답(초안 모델 Gemma 4 12B) 쪽이 124개, 재료·질문 쪽이 62개다(`../m2/6단계-통과율-원인분석-20261027.md` §8). 근거 쪽 원인은 0단계 코드(ADR-0047·0048)로 고쳤고, 초안 모델 자체를 바꿀지는 표본으로 정하기로 했다(ADR-0048 결정 6). 검토할 점(2026-10-31): ADR-0048은 큰 Gemma 4만 견주는데, 데스크탑에 올릴 수 있는 다른 계열 모델 중 더 나은 것이 없는지. 판정은 Claude로 둔다(2026-10-31 결정).
- 정하려는 것: 데스크탑과 학습 서버에서 잴 초안 모델 후보와 측정 순서.
- 조사 질문:
  1. 데스크탑(GPU 12GB, WSL 메모리 15GiB, 일부 CPU 넘김 허용)에 올릴 수 있는 오픈 모델 중 한국어 근거를 읽고 질문과 목표 답을 가장 정확하게 쓸 후보는?
  2. 학습 서버에만 올라가는 더 큰 후보는 무엇이고, 데스크탑 후보보다 낫다는 근거가 있나?
  3. 후보마다 라이선스가 출력을 다른 모델(A.X)의 학습 목표로 쓰는 것을 허용하나? 출처 국가와 계보는?
  4. 초안 모델을 고를 때 무엇을 보면 되나(크기, 계열, 벤치마크 점수)?

## 2. 범위와 방법

- 자료 기준: AGENTS.md §4 — 심사를 통과한 논문과 모델 제작사 공식 문서·모델 카드·라이선스 원문만 근거로 쓴다. 실행 도구(Ollama)의 공식 라이브러리는 파일 크기 근거로만 쓴다.
- 기간: 2025-10 이후 공개·갱신된 모델과 자료를 먼저 봤다. 그 전 논문은 '그런 현상이 있다'는 근거로만 쓴다.
- 포함: 지시 따르기 오픈 모델, 4비트 파일 약 24GB 이하. 제외: 상용 API 모델(Claude 초안은 서면 허가가 필요하다, ADR-0048 결정 1), 출력으로 다른 모델 학습을 막거나 조건을 다는 라이선스, 법률 해석.
- 검색한 곳과 날짜(2026-10-31): Hugging Face 제작사 계정 모델 목록(공식 API, 생성일순), 각 모델 카드와 LICENSE 원문, Ollama 공식 라이브러리 태그 페이지, OpenAI 모델 카드 PDF, ACL Anthology(논문 원문과 게재처).
- 고른 기준: ① 라이선스가 출력 사용에 조건을 달지 않음 ② 데스크탑 또는 학습 서버에 올라감 ③ 한국어나 근거 읽기에 대한 근거(우리 실측 > 제작사 발표) ④ 사고(thinking)를 끌 수 있음 ⑤ Ollama 공식 배포 또는 우리 변환 절차(`deploy/models/`, ADR-0036)로 올릴 수 있음.
- 건수: Hugging Face 제작사 계정 21곳의 최근 모델 목록 → 장비 조건에 맞는 지시 모델의 모델 카드 원문 19개, 라이선스 원문 7개 확인(Gemma 4는 모델 카드의 라이선스 링크) → 측정 후보 5개(데스크탑 2, 학습 서버 3). 뺀 모델과 이유는 부록 A.
- 제작사 체크리스트: Google 찾음(Gemma 4) · Alibaba 찾음(Qwen3.5·3.6·3.8) · OpenAI 찾음(gpt-oss) · Mistral 찾음(Ministral 3) · IBM 찾음(Granite 4.2) · NVIDIA 찾음(Nemotron 3.5) · Zhipu 찾음(GLM-4.7-Flash) · DeepSeek·Moonshot·MiniMax 해당 없음(텍스트 모델이 모두 4비트 24GB를 넘음, 가장 작은 Kimi Linear 48B A3B도 49.1B) · Meta 2025-06 이후 새 모델 없음 · Microsoft 범용 지시 모델 없음(MagenticBrain은 Qwen3-14B 기반 영어 에이전트 모델) · SKT 찾음(A.X 3.1) · KT 찾음(Mi:dm 2.0) · Kakao 찾음(Kanana 2) · NAVER 찾음(HyperCLOVA X SEED) · LG 찾음(EXAONE 4.5, 라이선스 비상업) · 트릴리온랩스 찾음(Gravity·Tri) · Upstage·NC AI·Motif 해당 없음(장비보다 크거나 근거 부족).

## 3. 질문별 결과

### 질문 1. 데스크탑에 올릴 후보

- [원문] Gemma 4 26B A4B: 총 25.2B, 활성 3.8B(전문가 128개 중 8개와 공유 1개), 문맥 256K, 사고 끄기 가능 [1]. Ollama `gemma4:26b-a4b-it-qat` 16GB [9]. 제작사 표의 다국어 MMMLU는 31B 88.4%, 26B A4B 86.3%, 12B 83.4%다. 긴 문맥 MRCR v2(128K)는 26B A4B 44.1%로 12B(43.4%)와 비슷하다 [1].
- [원문] Qwen3.6 35B A3B: 총 35B, 활성 3B, 40층 중 10층만 일반 어텐션(나머지는 선형 어텐션 Gated DeltaNet)이라 긴 문맥의 KV 캐시가 작다. 문맥 262K이고, 사고는 기본으로 켜져 있으며 요청마다 끌 수 있다 [3]. Ollama `qwen3.6:35b-a3b` 23GB [9]. 3.6판 카드에는 다국어 점수가 없고, 같은 크기의 앞 판(Qwen3.5 35B A3B) 카드에 MMMLU 85.2, MMLU-ProX 81.0, INCLUDE 79.7이 있다 [5].
- [실측] 우리 개발셋(2026-10-14, 같은 프롬프트로 생성 모델만 바꿈)에서 정답 근거가 프롬프트에 있던 76문항 중 맞힌 수: Gemma 4 12B 64, Qwen3-8B 60, Kanana 1.5 8B 59, Qwen3-14B 58, A.X 4.0 Light 58, Mi:dm 2.0 Base 57(`../m2/실패원인-분석-20261014.md` §7). 근거 읽기는 Gemma 4가 가장 나았다. Qwen3.6은 그때 잰 Qwen3보다 두 세대 뒤 판이라 이 결과를 그대로 옮기지 않는다.
- [계산] 데스크탑 GPU는 12,282MiB에서 화면 출력이 약 0.9GB를 쓰고, WSL 메모리는 15GiB다(`기반모델-후보-데스크탑-실측-20261001.md` §1). 파일에서 GPU에 올라가는 약 10.5GB를 빼면, CPU 쪽에 26B A4B는 약 5.5GB, Qwen3.6 35B A3B는 약 12.5GB가 남는다. 앞의 것은 지금 설정으로 되고, 뒤의 것은 WSL 메모리를 늘려야 안전하다(물리 메모리 32GB). KV 캐시와 계산 버퍼는 이 계산에 넣지 않았다.
- [판단] 두 후보 모두 활성 파라미터가 3~4B라, 일부가 CPU에 있어도 토큰당 읽는 양이 작다. dense 27~31B보다 데스크탑에서 훨씬 빠를 것으로 본다. 속도는 측정 첫 단계에서 예시 몇 개로 잰다.

### 질문 2. 학습 서버에만 올라가는 후보

- [원문] Gemma 4 31B: dense 30.7B, Ollama 19GB, MMMLU 88.4%, 긴 문맥 MRCR v2 66.4%(26B A4B 44.1%)로 같은 계열에서 가장 크다 [1·9].
- [원문] Qwen3.8 27B(2026-08 공개): dense 27B, 64층 중 16층만 일반 어텐션, 문맥 262K, 사고 끄기 가능, Ollama 18GB [4·9]. 제작사 표에서 지시 따르기 IFBench 79.5로 앞 판 Qwen3.6 27B(69.1)보다 높다 [4]. 한국어 점수는 카드에 없다.
- [원문] A.X 3.1(SKT, 2025-07): dense 34B, 한국어 중심 다국어 말뭉치 2.1조 토큰으로 처음부터 학습했다. 문맥은 32K이고 YaRN으로 131K까지 늘어난다 [6]. 제작사 표에서 KMMLU 69.73, CLIcK 77.09, Ko-IFEval 75.29로, 같은 표의 Gemma 3 27B(59.45·71.03·74.4)와 Qwen2.5 32B(61.93·68.17·73.24)보다 높다 [6]. 공식 GGUF가 없어 우리 변환 절차로 올려야 한다.
- [계산] 세 모델은 4비트로 18~21GB라 A10G 24GB에 다 올라간다. 데스크탑에서는 파일의 40% 넘게 CPU로 넘어간다. 토큰마다 CPU 쪽 가중치 7~10GB를 읽어야 해서 생성이 느릴 것으로 본다.
- [판단] 학습 서버 쪽이 데스크탑 후보보다 낫다는 직접 근거는 없다. 같은 계열에서는 큰 모델이 나았다는 연구가 있지만 [12·14], 계열이 다르면 크기로 예측되지 않았다 [12]. 우리 표본으로 재야 한다.

- [판단] Kanana 2와 HyperCLOVA X SEED로 초안을 만들면, 학습한 A.X가 그 회사 모델의 파생물이 된다. 이름과 표시 의무가 생기고, 학교 공개 서비스에 별도 허가가 필요할 수 있어 학교 인계가 복잡해진다. 그래서 후보에서 뺀다. Apache 2.0과 MIT 모델은 출력 사용에 조건이 없다.
- [판단] 중국 계보(Qwen)는 학교 제안 때 질문이 나올 수 있다. 다만 지금 운영 모델 A.X 4.0 Light도 Qwen 2.5에서 출발했다(`후보모델-학교챗봇-사용가능-재확인-20261013.md` §2). 초안 모델은 학교에 넘기지 않고 학습 목표 글을 쓰는 데만 쓴다.

### 질문 4. 초안 모델을 고를 때 볼 것

- [원문] AgoraBench(ACL 2025, CMU·KAIST 등): 6개 모델로 학습 예시 126만 개를 만들어 학생 99개를 학습했다. 문제 풀이 점수와 데이터 생성 실력은 R² 0.1 미만이거나 유의하지 않았다(그림 4). 코드 문항 만들기에서는 Llama-3.1-8B(+55.69%)가 Claude-3.5-Sonnet(+23.43%)보다 나았다 [13].
- [원문] Polyglot Teachers(EMNLP 2026, Cambridge): 모델 10개, 언어 6개(아랍어·체코어·독일어·스페인어·인도네시아어·일본어 — 한국어 없음), 학생 240개. 크기만으로는 초안 모델의 효과를 예측하지 못했다(Llama 3.1 70B가 Gemma 3 12B보다 낮음). 같은 계열 안에서는 큰 Gemma 3가 나았다. 품질을 모를 때는 학생과 같은 계열을 기본값으로 권하며, 그 모델이 그 언어를 잘할 때만 통했다(§3.2, 표 2) [12].
- [원문] Findings of ACL 2025(UW·CMU): 3B 이하 학생은 큰 모델의 긴 풀이를 꾸준히 배우지 못했다(수학 풀이) [15]. 우리 학생은 7B이고 목표 답은 짧은 근거 기반 답이라 약하게만 해당한다.
- [판단] 벤치마크 점수와 크기는 후보를 거르는 데만 쓰고, 고르는 것은 우리 표본의 Claude 판정 통과로 한다. 같은 계열의 큰 모델(Gemma 4 26B A4B)과 학생 계열(Qwen)을 한 표본에서 견주면, 두 가설(크기·계열)을 한 번에 볼 수 있다.

## 5. 반대 근거와 한계

- 크기가 늘 이기지 않는다 [12·13]. 더 큰 모델이 우리 목표 답에서 나을지는 낮은 확신으로 둔다.
- 한국어 근거가 약하다. Polyglot Teachers와 AgoraBench에 한국어가 없다. 한국 회사 발표 점수(KMMLU·HAERAE 등)는 지식·문화 문항이라 근거 읽기와 다르고, 제작사마다 평가 설정이 달라 순위에 쓰지 않는다. Gemma 4와 Qwen3.6·3.8 카드에는 한국어만 따로 낸 점수가 없다.
- 우리 실측(Gemma 4 12B 64/76)은 챗봇 답변이지 학습 예시 초안이 아니고, Qwen은 두 세대 전 판(Qwen3)이었다.
- 장비 계산은 파일 크기만 셌다. KV 캐시, 계산 버퍼, 함께 뜬 다른 컨테이너의 메모리는 넣지 않았다. 측정 첫 단계에서 실제 메모리와 속도를 본다.
- 사고 모드: Qwen3.6·3.8은 사고가 기본으로 켜져 있다. 지금 도구는 Ollama에 사고 끔(`think: false`)을 보내므로 끈 채로 잰다. 사고를 켜면 나을 수 있지만 느려져 이번에는 재지 않는다.
- 찾았지만 기준을 통과한 자료 없음: 한국어 학습 데이터 초안 모델 비교, 근거 기반 목표 답 생성에서 MoE와 dense를 견준 연구.

## 6. 선택지와 권고

| 관점 | 지금 Gemma 4 12B 유지 | 데스크탑: Gemma 4 26B A4B만 | 데스크탑: 26B A4B + Qwen3.6 35B A3B (권고) | 학습 서버까지 기다려 dense 셋도 |
|---|---|---|---|---|
| 서비스 | 목표 답 읽기 오류가 그대로 남음 | 같은 계열 확장 효과만 봄 | 크기와 학생 계열 두 가설을 한 표본으로 봄 | 가장 큰 후보까지 보지만 늦어짐 |
| 비즈니스 | 데스크탑 시간 없음 | 데스크탑 약 1시간(추정) + 판정 | 데스크탑 2~3시간(추정) + 판정, WSL 메모리 한 번 바꿈 | 접속 정보가 올 때까지 6단계가 멈춤 |
| 유지보수 | 변경 없음 | 모델 이름만 설정값으로 바꿈(ADR-0040 결정 4) | 같음. Ollama 공식 배포라 변환 절차가 필요 없음 | A.X 3.1은 변환 절차(`deploy/models/`) 필요 |
| 확장 | — | 31B로 넘어가기 쉬움 | 결과에 따라 학습 서버에서 같은 계열 큰 판(31B·Qwen3.8)으로 | 학습 서버 비용·시간 |

- 권고: 데스크탑에서 Gemma 4 12B(기준), Gemma 4 26B A4B, Qwen3.6 35B A3B로 같은 표본의 목표 답을 다시 만들고 Claude가 같은 지침으로 판정한다. 선은 ADR-0048 결정 6 그대로다(오류 30 중 15개 이상 통과로, 통과 30 중 3개 이하만 탈락으로). 같은 코드로 다시 만든 12B 결과를 함께 놓아 코드 효과와 모델 효과를 가른다. 학습 서버 후보(Gemma 4 31B, Qwen3.8 27B, A.X 3.1)는 접속 정보가 오면 같은 표본으로 잰다.
- 이유: 두 후보는 MoE라 데스크탑에서 돌릴 수 있고, Ollama 공식 배포라 바로 올릴 수 있으며, Apache 2.0이다. 우리 실측에서 근거 읽기가 가장 나았던 계열의 큰 판(26B A4B)과, 학생 계열이라는 다른 가설의 후보(Qwen3.6)를 함께 본다.
- 결정(2026-10-31): 위 권고 대신, Gemma 4 12B로 새 제작법을 먼저 잰다. 지난 질문 539개로 전후를 견주고, 12B 읽기 실수(안내 빠짐·값 틀림)가 61개에서 30개 이하로 줄지 않으면 26B A4B를 같은 표본으로 견준다. Qwen3.6 35B A3B와 학습 서버 후보는 그 뒤에 본다. 모델을 고를 때는 통과 수와 함께 학습 위험(버릇·잘못 학습)을 본다(ADR-0048 결과, ADR-0037 변경 메모).
- 버린 선택지와 이유: 12B 유지 — 목표 답 오류 124개가 그대로 남는다. 26B A4B만 — 계열 가설을 못 본다. 학습 서버까지 기다리기 — 접속 정보가 언제 올지 모른다. 개별 모델을 뺀 이유는 부록 A.

## 7. 확신도와 다음 확인

- 확신도: 높음 — 라이선스(원문). 확인함 — 26B A4B는 데스크탑에서 돌았다(2026-11-01, Ollama 24GB, CPU 58%·GPU 42%, 목표 답 하나 약 17초). 낮음 — 어느 후보가 목표 답을 더 잘 쓸지(외부 근거가 엇갈리고 한국어 근거가 없음).
- 다음 확인:
  - 데스크탑 측정 첫 단계: 후보마다 예시 3개로 메모리(`nvidia-smi`, WSL `free`)와 예시당 시간을 잰다.
  - 표본 측정: 목표 답 오류 30 + 통과 30, Claude 판정(지침 2026-10-31판).
  - 학습 서버 접속 정보가 오면 dense 셋을 같은 표본으로 — 하지 않기로 함(2026-11-01, 초안 12B 확정, ADR-0048 결과).
- 다시 볼 조건(2026-11-01 바뀜): 1회차 학습 뒤 A.X에 남은 실수가 학습 데이터에서 온 것으로 보이거나, 다음 회차에 통과 수가 모자라면 12B 생각 모드부터 같은 표본·같은 선으로 본다. 처음 조건(두 후보 모두 선 미달이면 학습 서버 후보로)은 쓰지 않는다 — 걸러진 예시는 학습에 들어가지 않아 초안 모델을 바꿔도 통과 수만 늘고, 방식이 바뀌면 사람 30개를 다시 봐야 한다.
