# M2 검색 개선 설계 — 사람이 만든 규칙에서 학습된 순위로 (이슈 #129 이후, 2026-10-14)

> M2(검색 개선)를 바로 시작할 수 있게, 무엇을 어떤 순서로 바꾸고 무엇으로 채택을 가를지 정한다. 근거는 개발셋 실측(`실패원인-분석-20261014.md`)과 원문 확인한 논문·기업 보고서(`docs/rag/research/검색개선-근거조사-20261014.md`).
> 상태: **1단계 확정**(2026-10-15, ADR-0032 — 실무·논문 대안 조사 `docs/rag/research/검색결과-합치기-대안조사-20261015.md` 뒤). 2단계 이후는 설계 제안. 결정이 필요한 것은 §8에 모았다.
> 관련: ADR-0009(채택 기준), ADR-0025(짝 비교), ADR-0026(목표), ADR-0018(테스트셋 봉인), 총괄계획 §4 M2

## 1. 한 장 요약

- **문제**: 검색은 정답 청크를 98% 찾는데, 그 뒤의 사람이 만든 규칙 세 개(표 값 질문 우선 거르기·질문 맞춤 근거 좁히기·상위 5개 자르기)가 40%를 지운다. 정답 근거가 프롬프트에 없으면 어떤 모델도 못 맞힌다(2%). [실측]
- **1단계는 이미 효과를 쟀다(E1)**: 규칙을 빼고 표 사실·BM25·벡터를 순위 융합(RRF)만 하자 개발셋 본 정답률 43.8% → 62.0%, 오답률 8.1% → 2.0%, 과잉 거절 38.0% → 20.7%(모두 p<0.05), 응답 시간도 줄었다. [실측]
- **다음 순서**: ① 순위 융합을 운영 기본 경로로 → ② 고른 모델로 상위 k(5·8·10) 정하기 → ③ 학습된 재순위(cross-encoder) → ④ 표 사실 행 단위 직렬화(재색인) → ⑤ 답할지 판단(충분한 문맥)·프롬프트 → ⑥ 임베딩·문서 맥락 붙이기 비교. 모든 단계는 개발셋 짝 비교로 채택하고, 테스트셋은 M2 끝에 한 번만 잰다.
- **목표(ADR-0026)**: 본 테스트셋 정답률 65% · 오답률 5% 이하 · 과잉 거절 20% 이하 · 출처 정확도 80%. 개발셋 기준으로 E1이 이미 정답률 62%·오답률 2%·과잉 거절 21%·출처 91%라 남은 거리는 정답률 몇 %p와 과잉 거절이다. [실측·판단]

## 3. 단계별 설계

### 1단계 — 순위 융합을 운영 기본 경로로 (규칙 세 개와 우선 경로 답 빼기)

- **문제**: 규칙이 정답 청크를 지움(§1). 우선 경로 답(모델을 거치지 않고 근거를 붙이는 답)은 12문항 중 3문항이 틀림. [실측]
- **바꿀 것** [코드 위치]: `ai-server/main.py` `_prepare_query`의 기본 `retrieval_mode`를 `rrf`로. 규칙 함수(`_prioritize_query_results` 4168행 근처, `_rerank_by_query_analysis` 4100행, `_focus_candidates_with_query_evidence` 4133행)와 우선 경로 답(`_priority_*_answer_for_request`)은 한 릴리스 동안 `rules` 모드로 남겨 되돌릴 수 있게 하고, 2단계가 끝나면 코드와 관련 점검 스크립트(`check_query_evidence_priority.py` 등)를 지운다.
- **근거**: E1 [실측] · RRF는 점수 정규화 없이 순위만 합쳐 규칙이 필요 없다(Cormack 외 2009) [원문].
- **채택 기준**: 고른 모델로 E3(§4)에서도 E1과 같은 방향의 의미 있는 차이 → **충족**(Gemma 4 12B 본 정답률 53.7% → 74.4%, p=0.0002 · 오답률 6.0% → 0.7%, p=0.02) [실측].
- **부작용 확인**: 표 값 질문(태그 '표 근거')만 따로 정답률 비교 — 규칙이 원래 지키려던 문항이다. E1에서 베이스라인만 맞힌 8문항(개발셋)은 정답 청크가 상위 5개 밖으로 밀린 3문항(→ 2·3단계)과 문맥에 있는데 결론을 흐린 5문항(표 근거 4 → 4·5단계)이었다 [실측].
- **되돌리기**: 환경 변수 하나(기본 모드)로 전환.
- **결과(2026-10-15, #169)**: 운영 기본값 전환 완료(`AI_RETRIEVAL_MODE=rrf`, 기본 생성 모델 Gemma 4 12B). 데스크탑 개발셋에서 E3와 같은 수준, 같은 모델 규칙 경로보다 정답률 53.7% → 76.9%. 표 근거 문항 60.0% → 66.7%(같은 수준, 떨어지지 않음). `1단계-순위융합-운영전환-20261015.md`
- **정리(2026-10-16, #169)**: 2단계가 끝나 규칙 함수 셋·우선 경로 답·검색 방식 설정값(`AI_RETRIEVAL_MODE`)과 관련 점검 스크립트·테스트를 지웠고, `/debug/rag-trace`도 운영 질의와 같은 순서 함수를 쓰게 했다. 위의 '한 릴리스 동안 남김'은 M0 뒤 main 릴리스가 없어 채우지 않았다 — 실제 사용자가 없고 규칙 경로로 잰 실행 기록(13번)이 남아 있어, 되돌리기는 git으로 한다(사용자 승인 2026-10-15). `1단계-규칙코드-삭제-20261016.md`

### 2단계 — 상위 k와 문맥 예산

- **문제**: E1 뒤 후보 탈락이 아직 16문항. RRF 상위 10개면 정답 청크 포함이 99 → 113문항(재연). [계산]
- **바꿀 것**: `AI_DEFAULT_TOP_K`(지금 5)와 생성 문맥 `OLLAMA_NUM_CTX`. k=5·8·10을 고른 모델로 개발셋 실행. 문맥은 그 k의 가장 긴 프롬프트 + 512(13번 방식).
- **근거**: 재현율은 k와 함께 오르지만 생성 품질은 모델별 한계 뒤 떨어진다(Databricks 2024) · 근거가 중간에 있으면 성능 하락(Lost in the Middle) [원문].
- **채택 기준**: 정답률 의미 있게 오르고 오답률·과잉 거절이 나빠지지 않는 가장 작은 k. 응답 시간은 k=5 대비 상위 5%가 1.5배를 넘는 k는 쓰지 않는다. 데스크탑의 절대 시간은 서빙 GPU(클라우드, ADR-0030)와 달라 참고만 한다 — Gemma 4 12B는 k=5에서도 생성만 상위 5% 7.27초다 [실측·판단].
- **비용**: 실행 하나 약 10~15분(데스크탑) + 애매 판정.
- **결과(2026-10-15)**: 상위 8개가 기준을 만족하는 가장 작은 k — 상위 5개 대비 정답 근거 프롬프트 포함 106 → 112·과잉 거절 18.2% → 10.7%(p=0.012)·정답률 76.9% → 83.5%(p=0.039, 판정 하나에 흔들리는 경계선), 오답률 같은 수준, 응답 상위 5% 11.24 → 9.16초. 상위 10개는 상위 8개와 같은 수준. 운영값 제안: 상위 8개·생성 문맥 12,288. `2단계-상위k-20261015.md`

### 3단계 — 학습된 재순위(cross-encoder)

- **문제**: RRF는 순위만 보고 질문과 청크의 실제 관련도를 보지 않는다. 상위 5개 안에 정답이 있어도 순서가 뒤면 모델이 놓칠 수 있다.
- **바꿀 것**: RRF 후보 20~30개 → 재순위 모델 점수 → 상위 k. 후보 두 개를 비교한다:
  - Qwen3-Reranker-0.6B(Apache 2.0, 지금 임베딩과 같은 계열 — 운영 단순) [원문]
  - bge-reranker-v2-m3(0.6B, Apache 2.0, 다국어) [원문]
- **먼저 오프라인으로**: E1 실행에 기록된 후보(개발셋)로 재순위만 돌려 정답 청크 재현율@5를 RRF와 비교(GPU 몇 분). 의미 있게 좋을 때만 AI 서버에 넣고 생성까지 잰다.
- **점수 결합도 함께**(2026-10-15 추가, ADR-0032 결정 4): 평가 기록에 검색기별 점수와 표 사실의 부모 청크 id를 남기게 한 뒤(평가 요청에서만), 볼록 결합·분포 기반 결합(DBSF)·검색기 가중치를 순위 융합과 같은 후보로 비교한다. 재순위 후보는 bge-reranker-v2-m3, 그 한국어 학습판(Apache 2.0), Qwen3-Reranker-0.6B 셋으로, 후보 수(20·30)와 벡터 위주 후보도 비교한다. 근거: 대안 조사 §4(오프라인: 합치기 방식끼리 같은 수준, 재순위만 의미 있게 앞섬).
- **근거**: Anthropic — 같은 데이터에서 재순위를 더하자 상위 20개 실패율 2.9% → 1.9% [원문]. 우리 언어(한국어)·문서에서의 크기는 직접 잰다.
- **운영 비용**: 0.6B 모델 fp16 약 1.2GB. 데스크탑 12GB에 생성 모델·임베딩과 함께 올라가는지(`ollama ps`+`nvidia-smi`), 질문당 지연(20쌍 점수)을 잰다. 클라우드 운영(ADR-0030)에서는 제약이 작다.

### 4단계 — 표 사실 행 단위 직렬화 (재색인)

- **문제**: 칸 하나짜리 표 사실의 51%가 행을 잃음. 문맥에 정답이 있는데 모든 모델이 틀린 9문항 중 6문항이 표 근거. [실측]
- **바꿀 것**: `_format_table_fact_index_text`(main.py 1777행)가 칸 하나마다 문장을 만들 때, 행 이름을 '행을 유일하게 가리는 머리 칸 경로'(예: `생활비 > 5. 국민연금`)로 바꾸고, 행 전체 문장(`_build_row_summary_fact`, 이미 있음)을 색인에 함께 둔다. 특정 표·학과 이름을 조건문으로 넣지 않는다(구조 계약).
- **근거**: TARGET — 표 검색은 표 제목 같은 메타데이터에 민감 [원문] · 우리 실측(ev-0164의 1.5 → '5').
- **측정**: ① 색인 뒤 칸 단위 사실 중 행을 가릴 수 없는 줄 비율(51% → 목표 0%), ② 표 근거 문항 정답률, ③ 색인 크기·시간(지난 전체 색인 43.9분, 표 사실 45,878개).
- **주의**: 재색인은 데스크탑 약 1시간. 색인 이름을 새로 붙여 실행 기록에 남긴다(평가셋의 근거 문서 ID는 그대로).

### 5단계 — 답할지 판단과 프롬프트

- **문제**: E1 뒤 남은 실패의 가장 큰 몫은 생성 실패 24(정답 근거가 문맥에 있는데 모름·일부·틀림). [실측]
- **바꿀 것**: 프롬프트에 '근거 글에 답이 있으면 결론을 먼저 단정하고 출처를 붙인다 / 없으면 확인할 수 없다고 하고 확인처를 안내한다'를 명시하고, 결론을 흐리는 표현('추정', '일반적으로')을 쓰지 않게 한다. 시스템 프롬프트를 바꾸므로 실행 기록의 프롬프트 지문이 바뀐다.
- **근거**: Google "Sufficient Context"(ICLR 2025) — 문맥 충분성 판단으로 답한 것 중 정답 비율 2~10% 상승 [원문]. 우리 판정 기록의 '일부' 유형(결론을 흐림)이 프롬프트 지시로 줄일 수 있는 종류다 [판단].
- **채택 기준**: 과잉 거절이 의미 있게 줄고 오답률이 늘지 않을 때.
- **다음**: 여기서 남는 '문맥에 있는데 틀림'은 학습(LoRA, 총괄계획 M2 'ML 적용')이 맡는다.

### 6단계 — 임베딩·문서 맥락 붙이기 (선택)

- **임베딩**: Qwen3-Embedding-4B(지금) ↔ KURE-v1(한국어 미세조정 bge-m3, MIT) ↔ bge-m3. 개발셋 질문과 정답 청크로 오프라인 재현율@10 비교(원문 청크 3,206개만 다시 임베딩, 데스크탑 몇 분). 의미 있게 좋을 때만 전체 재색인.
- **문서 맥락 붙이기(Contextual Retrieval)**: 긴 PDF·HWP(모집요강·규정) 청크에만 50~100토큰 맥락을 로컬 모델로 만들어 붙인다. Anthropic은 임베딩만으로 실패율 −35%를 보고했다 [원문]. 우리 문서의 3/4는 짧은 HTML이라 이득이 PDF에 몰릴 것이다 [판단]. 원문 청크 약 3,200개 × 생성 1~2초 → 1~2시간.
- 이 단계는 1~5단계 뒤에도 후보 탈락·검색 실패가 남을 때만 한다.

## 10. 네 관점

- 서비스: 사용자가 받는 답의 정답률이 오르고, 근거가 있는데 "확인할 수 없다"는 답이 줄어든다. 응답 시간은 오히려 줄었다.
- 비즈니스: 학교에 보고할 숫자(정답률·오답률)가 둘 다 좋아진다. 큰 모델·학습 없이 구조로 얻은 개선이라 운영 비용이 늘지 않는다.
- 유지보수: 사람이 만든 규칙 세 개와 우선 경로 답이 빠져 코드가 단순해진다. 표 직렬화는 색인 형식 하나를 바꾸는 구조 계약이라 문서가 늘어도 규칙이 늘지 않는다.
- 확장: 재순위·임베딩은 모델 교체만으로 바꿀 수 있는 자리에 둔다. 클라우드 운영(ADR-0030)에서 더 큰 재순위 모델로 바꾸기 쉽다.
