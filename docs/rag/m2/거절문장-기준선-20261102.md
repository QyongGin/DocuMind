# M2 6단계 — 거절 문장 바꾸기와 학습 전 기준선 (2026-11-02)

> 결정: ADR-0050 2026-11-02 변경(거절 문장은 모델이 학습으로 바로 쓴다). 계획: `1회차-준비-작업계획-20261101.md` 2-1·4-1단계.
> 실행 기록과 판정 꾸러미는 로컬 `Assets/eval/runs/`, `Assets/eval/work/m2/`에 있다(학교 글이라 커밋하지 않음).

## 1. 결론

- 운영 규칙 9·11은 옛 모양 그대로 두고 따옴표 안 거절 문장만 '학교 홈페이지 안내에서 찾지 못했습니다.'로 바꾼다. 답이 없을 때와 일부만 없을 때('수수료는 학교 홈페이지 안내에서 찾지 못했습니다.') 같은 문장이다.
- 이 프롬프트에서 학습 전 A.X의 개발셋(본)은 옛 문장과 같은 수준이다 [실측, 같은 기준으로 다시 판정]: 틀린 답 12 → 13/149, 답없음 거절 23 → 23/28, 정답 95 → 97/121.
- 처음 넣은 규칙(문장과 함께 '질문의 일부만 근거에 없으면 있는 것은 답하고 …' 지시)에서는 틀린 답 16, 답없음 거절 19였다. 답이 없는 질문에서 근거 속 다른 안내로 답했고, 규칙의 자리표시 '(없는 것)'을 답에 그대로 베낀 답도 2~3개 나왔다.
- 처음 보고한 '틀린 답 10 → 17'은 채점기와 판정 일관성 문제로 부풀어 있었다(§4).

## 3. 결과 — 같은 기준으로 다시 판정

세 실행(A, C, D)에서 판정이 갈린 22문항은 두 답을 나란히 놓고 같은 판정 지침(`Assets/eval/work/judge_instructions.md`)으로 다시 판정했다. 나머지 127문항은 세 실행의 판정이 같다.

| | 틀린 답(149) | 답없음 거절(28) | 정답(121) | 과잉 거절(121) |
|---|---|---|---|---|
| A 옛 문장 | 12 | 23 | 95 | 7 |
| C 새 문장 + 지시 | 16 | 19 | 97 | 7 |

- 짝 비교(한쪽에서만 틀린 문항): A 대 C 1 대 5(p≈0.22), A 대 D 3 대 4. 답없음 거절에서만 갈린 문항: A 대 C 5 대 1, A 대 D 3 대 3 [계산].
- 거절 말투 [실측]: D는 '찾지 못했' 17개, '확인할 수 없' 0개로 새 문장을 따른다. '(없는 것)'은 D 0개, C 2개, B 3개.

## 4. 처음 숫자가 부푼 이유

| 문제 | 예 | 결과 |
|---|---|---|
| 채점기가 '확인되지 않습니다'를 거절로 못 알아봄 | ev-0178 | 거절한 답이 틀림 |
| 채점기가 '제공되지 않으니'처럼 단정하는 말을 거절로 봄 | ev-0244(D) | 틀린 단정이 맞음 |
| 결론이 틀려도 늘어놓은 목록에 정답 낱말이 있으면 맞음 | ev-0193, ev-0239 | 틀린 답이 맞음 |
| 지난 판정이 같은 대상의 틀린 값을 '모름'으로 너그럽게 매김 | ev-0082(총 69명), ev-0169(이름 그대로) | 옛 실행의 틀린 답이 적게 셈 |

- 채점기는 저장된 판정을 '애매'로 간 답에만 쓴다(`metrics.score_record`). 자동으로 정한 맞음·틀림은 판정을 넣어도 바뀌지 않는다.
- 대응: 프롬프트를 바꾼 실행끼리 비교할 때는 판정이 갈린 문항을 두 답을 나란히 놓고 같은 기준으로 다시 판정한다. 채점기 보완은 따로 정한다(작업 계획 §5).

## 5. 원인 [판단]

- '있는 것은 답하고'는 모든 질문에 걸리는 지시라, 답이 없는 질문에서도 근거에서 무언가를 찾아 답하게 밀었다. 셔틀버스 안내의 '방학중 미운행'을 보고 '방학 동안 기숙사를 이용할 수 없다'고 했고, ATM 수수료 질문에 주차요금정산기 문의 번호를 안내했다. 답이 있는 질문은 더 완전하게 답했다(정답 95 → 97).
- 거절 문장만 바꾸면 행동이 옛 규칙과 같다(D).
- 확신도 중간: 개발셋을 한 번씩 돌렸고, 프롬프트를 조금만 바꿔도 7문항 안팎의 정오가 갈린다(A 대 D 3 대 4).

## 6. 바뀐 것

- 운영 프롬프트 규칙 9·11(`ai-server/main.py` `MANDATORY_RAG_PROMPT`)과 학습 데이터 도구의 규칙(`tools/corpus/corpus/trainset/prompts.py` `REFUSAL_RULES`)을 같은 글자로 두고 테스트로 묶었다.
- 학습 파일로 내보낼 때 지난 거절 문장 둘(옛 운영 문장, 11-02 한때 문장 '…이 내용을 찾지 못했습니다.')과 지난 규칙 둘을 지금 문장·규칙으로 바꾼다. 남은 지난 글이나 '(없는 것)'이 있으면 `export-round`가 실패로 끝난다.
- [실측] r1-g 550개와 r1-h 28개 모두 입력 규칙이 지금 규칙이 되고 남은 지난 글은 0이다. 1회차 시험 내보내기 200줄: 목표 답 55줄과 입력 200줄을 바꿨고 출처 번호를 지운 거절 26줄, 남은 지난 글 0.
- 학습 전 기준선(학습 1회차 전후 비교의 '전')은 D다. 학습 뒤 실행도 `--as-of 2026-10-31`로 같은 날짜에 잰다.
- 학습 위험: 입력 규칙과 목표 답이 같은 문장이라 규칙과 다르게 답하는 버릇은 생기지 않는다. 거절 문장만 있는 목표 답(1회차 시험 내보내기 31줄)은 화면에서 정해 둔 안내가 붙는다.

## 7. 면접 포인트

- 프롬프트 문구 하나를 바꿨더니 오답이 늘었다는 결과를 그대로 믿지 않았다. 날짜 줄을 고정해 다른 원인을 떼어 내고, 판정이 갈린 문항을 같은 기준으로 다시 판정해 채점기가 만든 차이를 걸렀다. 그다음 함께 넣은 지시문을 빼고 문장만 바꿔 다시 재서, 원인이 문장이 아니라 지시문이었음을 확인했다.
- 규칙 채점기의 한계(거절 말투 목록, 목록형 답의 낱말 일치)는 프롬프트를 바꾼 실행끼리 비교할 때 차이를 만들 수 있다. 짝 비교에서 갈린 문항은 사람(또는 같은 판정자)이 두 답을 나란히 보고 다시 판정해야 한다.
