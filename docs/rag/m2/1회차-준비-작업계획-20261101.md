# M2 학습 1회차까지 작업 계획 (2026-11-01)

> 상태: 계획. 6단계(학습 데이터) 마무리부터 7단계(학습 1회차), 사용자 화면 작업까지의 순서를 정한다.
> 결정: ADR-0049(기준 밝히기), ADR-0050(사용자 화면 답 모양). 답 모양 기준: `docs/project/챗봇-답변-형식.md`. 앞 단계 결과: `6단계-새제작법-결과-20261101.md`.

## 1. 지금 위치

- 학습 예시 계획 570개 중 273개가 통과했다(판정 지침 2026-11-01판). 1회차 200개 목표 중 일부만 있음만 5개 모자란다(15/20).
- 초안 모델은 Gemma 4 12B, 사용자 화면의 답 모양은 ADR-0050으로 정했다.

## 2. 학습 데이터는 다시 만들지 않는다

- 학습 목표 답은 모델 출력 모양(끝의 출처 번호, 운영 거절 문장)이다. 사용자 화면 모양은 서버가 만든다(`챗봇-답변-형식.md` §3).
- 학습 파일로 내보낼 때만 세 가지가 다르다.
  - 거절 문장 뒤에 출처 번호만 있으면 지운다(ADR-0050 결정 4). 통과 예시 중 28개가 해당한다.
  - 인용형 모양은 만들지 않고, 결론 먼저 모양 한 벌만 내보낸다(결정 7).
  - 옛 거절 문장을 새 문장으로 바꾼다(ADR-0050 2026-11-02 변경). 목표 답과 입력의 운영 규칙 9·11을 함께 바꾼다.

## 4. 순서를 이렇게 정한 이유

- 2를 5보다 먼저 한다. 내보낼 때 거절 뒤 번호를 지워야 학습 파일에 '답이 없는데 출처를 다는' 버릇이 들어가지 않는다.
- 2-1을 4·5보다 먼저 한다. 옛 거절 문장을 목표 답과 입력 규칙에서 함께 바꿔야 둘이 어긋나지 않는다. 운영 프롬프트가 바뀌므로 학습 전후 비교의 '전'을 새 프롬프트로 다시 잰다(4-1).
- 3을 5보다 먼저 한다. 판정 지침이 바뀌었으므로 사람 확인으로 판정을 검증한 뒤 통과 예시를 쓴다(ADR-0037 결정 4).
- 4는 데스크탑이 필요해 켜는 날에 몰아서 한다.
- 7은 학교 학습 서버를 기다리는 동안 한다. 학습한 모델은 거의 모든 답에 출처 번호를 달기 때문에 10보다 먼저 끝나야 한다.

## 5. 따로 정할 것

- 문서 대장의 유효 기간 바로잡기: '지난 안내' 표시의 전제다(ADR-0050 결정 5). 2027학년도 수시 안내처럼 추정값이 실제 기간과 다르다.
- 2회차 규모: 1회차 결과로 정한다.
- 2회차 전 개선 시험(같은 60개 표본, 같은 판정): 관계없는 출처 번호를 코드로 빼기, 코드가 찾은 실수 이유를 짚어 주고 한 번 다시 쓰기.
- 빈 양식의 칸을 묻는 질문 거르기(2회차 데이터를 만들기 전): 판정 지침의 '실제 사람이 물을 만한 질문'에 기준을 적는다. 칸 위치·개수·표시 모양을 묻는 질문과 양식 칸 글자를 그대로 옮긴 답은 탈락, 양식에 적힌 작성 요령(분량, 글자 수, 확인받을 사람)을 묻는 질문은 통과. 질문 단계에서 빈 서식을 거르는 방법도 함께 본다(ADR-0048 결정 5). 지침이 바뀌므로 사람 30개를 새로 본다(ADR-0037 결정 4).

## 6. 진행 기록

- 1단계(2026-11-01): 기준 규칙 코드, ADR-0049·0050, 6단계 결과 보고서, 이 계획, 답변 형식 기준을 커밋해 작업 브랜치에 올렸다.
- 2단계(2026-11-01): `export-round`의 기본 모양을 결론 먼저 한 벌로 바꾸고, 학습 파일로 쓸 때 거절 문장 뒤에 출처 번호만 있으면 지우게 했다(`pipeline.training_target`). 테스트 2개를 더했고, 두 동작을 일부러 되돌리면 테스트가 잡는다. 계획 570개 묶음으로 시험 삼아 내보내면 [실측] 200줄 중 27줄의 출처 번호가 지워지고, 거절 문장만 남은 답이 31줄, 확인처가 있는 거절이 9줄이다. 일부만 있음이 15개라 모자란 5자리는 여러 근거 예시로 채워졌다(4단계 뒤 다시 내보낸다).
- 학습 위험: 1회차 거절 예시 40개 중 31개가 거절 문장만이다. 화면에서는 정해 둔 안내가 붙지만, 학습한 모델이 근거에 문의처가 있는데도 안내를 빼는지 학습 뒤 개발셋 안내 충실도로 본다.
- 3단계(2026-11-01~02, 끝): 사람 확인 화면(`trainset review-html`)을 확인 시간이 덜 들게 고쳤다. 한 번에 예시 하나, 근거는 답과 같은 글이 있는 줄과 앞뒤 줄만(같은 글이 여러 칸에 되풀이되면 한 번, 전체는 펼쳐 보기), 확인할 것 네 가지, 키보드 1·2로 고르면 Claude 판정이 보이고 같으면 다음으로 넘어감, 끝나면 어긋난 수와 기준 판정, 결과 복사. 표본은 탈락도 종류를 돌아가며 고른다(ADR-0037 결정 2). [실측] 계획 570개 묶음의 표본 30개(통과 15, 탈락 15, 종류 7가지)에서 예시마다 보이는 근거 줄은 중앙 10줄(근거 전체 중앙 약 140줄)이다. 결과(2026-11-02): 검토자의 최종 판정이 30개 모두 Claude와 같다(어긋남 0개). ADR-0037 결정 3대로 나머지 예시는 Claude 판정만으로 거른다. 검토자가 첫 선택에서 놓친 것을 Claude 판정 이유가 짚은 예시가 있었고, 검토자는 그 이유를 근거와 대조해 동의했다(첫 선택은 기록하지 않았다). 사람 판정은 `trainset merge-review`로 묶음에 합쳤다. 표본 밖에서는 빈 양식의 칸을 묻는 통과 예시 6개(모두 1회차 200개 안)를 찾아 사람 판정 탈락으로 기록했다: 칸 위치·있는지·표시 모양을 묻는 질문 3개, 양식 칸 글자 '/4.5'를 그대로 옮긴 답 2개, 빈 근무 가능 시간표를 근무할 수 있다고 읽고 표를 풀어 쓴 글이 깨진 채 들어간 틀린 답 1개. 최종 통과는 273 → 267개이고, 다시 골라도 종류별 목표는 그대로 찬다(일부만 있음 15/20은 4단계에서). 기준은 §5.
- 2-1단계(2026-11-02): 거절 문장을 모델이 학습으로 바로 쓰게 바꿨다. 운영 프롬프트 규칙 9·11을 새 문장으로 고쳤고(일부만 없을 때의 꼴도 규칙 9에 적음), 학습 파일로 내보낼 때 옛 문장을 목표 답(답 맨 앞은 '이 내용을' 꼴, 문장 안은 일부만 없음 꼴)과 입력의 규칙 9·11에서 함께 바꾼다. 검사는 옛 문장과 새 문장을 모두 거절로 알아보고, 채점의 거절 낱말 목록에 '찾지 못했'을 더했다(지난 평가 실행의 답과 평가셋에는 이 낱말이 없어 지난 채점 결과는 그대로다). 학습 데이터 도구의 규칙 글자가 운영 프롬프트와 같은지 테스트로 묶었고, 동작 여섯 가지를 일부러 되돌리면 테스트가 잡는다. [실측] 계획 570개 묶음으로 시험 삼아 내보내면 200줄 중 목표 답 55줄(답 맨 앞 40, 문장 안 15)과 입력 200줄의 규칙을 바꿨고, 바꾼 뒤 옛 문장이 남은 줄은 0, 입력 200줄 모두 지금 운영 규칙을 그대로 담는다. 출처 번호를 지운 거절은 26줄이다(빈 양식 칸 질문 6개를 바꿔 넣어 27 → 26). 옛 문장이 남으면 `export-round`가 실패로 끝난다. 4-1에서 기준선을 다시 잴 때 답에 규칙 9의 '(없는 것)' 글자가 그대로 나오는지도 본다.
