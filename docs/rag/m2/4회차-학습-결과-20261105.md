# M2 학습 4회차 — 3회차 모델에 선호 학습(DPO)

> 상태: 끝(2026-11-05). 설계 `4회차-학습-설계-20261103.md`, 결정 ADR-0053(변경 메모 2026-11-05 포함). 판정 기준은 실행 전에 설계 1절에 적었다.

## 1. 결론

- **4회차 모델(`ax40light-r4:q4km`)도 미채택**이다. 개발셋에서 오답 3/149(2.0%), 답없음 거절 28/28로 운영 선은 넘었지만, 둘 다 학습 전 모델보다 의미 있게 좋아지지는 않았다(p=0.057, p=0.125). 정답률(98 → 87, p=0.019)과 과잉 거절(7 → 17, p=0.0063)은 의미 있게 나쁘고, 새 평가 데이터에서도 과잉 거절이 나쁘다(8 → 19, p=0.001). **운영 모델은 학습 전 모델(`ax40light:q4km`) 그대로 둔다.** 테스트셋은 열지 않는다.
- 목표였던 과잉 거절 감소는 일어나지 않았다. 3회차와 비교하면 개발셋 과잉 거절 15 → 17, 오답 8 → 3으로, 1~3회차와 같은 방향(틀릴 답을 거절로 바꿈)으로 조금 더 갔다. 새 평가 데이터에서는 3회차와 모든 지표가 같은 수준이다.
- [실측] 학습에 쓰지 않은 검증 쌍 14개에서 선호 답을 더 높게 본 비율은 43%였다(학습 쌍은 95%). 학습 쌍은 외웠지만 새 입력으로 일반화하지 못했다.
- [판단] 원인은 쌍 구성으로 본다. 3회차가 실제로 답 있는 입력을 거절한 쌍은 13개뿐이었고 그중 6개가 검증 몫으로 가 학습에는 7개만 들어갔다. 학습 쌍의 대부분(약 90개)은 3회차가 이미 맞게 하는 입력에서 지은 사본 쌍이었다(8절). 확신도 중간.

## 2. 4회차를 하는 이유

- [실측] 1~3회차(지도 학습)는 오답과 답없음 거절을 좋게 했지만 과잉 거절을 늘렸고(학습 전 7 → 3회차 15), 거절 문장 비율을 조정하는 방법은 2회차부터 멈췄다(3회차 보고서 9절).
- 3회차가 실제로 낸 거절·오답을 비선호 답으로 직접 주는 선호 학습으로 거절 기준을 옮긴다(ADR-0053, 근거: DPO 논문 NeurIPS 2023, Trust-Align ICLR 2025).

## 6. 결과: 개발셋(본 149문항, 같은 날 다시 잰 학습 전 모델과 짝 비교)

[실측] 평가 조건은 1~3회차와 같다(날짜 줄 켬, 기준 날짜 2026-10-31, 근거 8개, 같은 AI 서버 이미지). 학습 전 모델은 같은 날 다시 쟀고 11-03 측정과 모든 지표가 같은 수준이었다(p=1.0). 규칙 채점이 정하지 못한 4회차 답 9개는 같은 기준으로 문서 원문과 대조해 판정했다(맞음 3 · 일부 3 · 틀림 3).

| 지표 | 학습 전 | 3회차 | 4회차 | 학습 전 대비 4회차 | 3회차 대비 4회차 |
|---|---:|---:|---:|---|---|
| 오답률(149) | 11 (7.4%) | 8 | 3 (2.0%) | 같은 수준 p=0.057 | 같은 수준 p=0.125 |
| 답없음 거절(28) | 24 (85.7%) | 26 | 28 (100%) | 같은 수준 p=0.125 | 같은 수준 p=0.5 |

- 판정: **미채택**(설계 1절). 운영 선(오답 5% 이하, 답없음 거절 90% 이상)은 넘었지만, 둘 중 하나가 학습 전보다 의미 있게 좋아져야 한다는 조건과 정답률·과잉 거절이 나빠지지 않아야 한다는 조건을 못 지켰다.
- [실측] 과잉 거절 17개 = 검색 단계에서 답 근거가 빠짐 10(후보 탈락 6, 문맥 탈락 4) + 근거를 받고도 거절 7. 학습 전 모델 7개는 모두 검색 단계, 3회차 15개는 검색 9 + 생성 6이었다. DPO가 겨냥한 '근거를 받고도 거절'은 6 → 7로 줄지 않았다.
- [실측] 3회차와 갈린 문항: 3회차가 틀린 6문항 중 2문항은 4회차에서 거절로 바뀌었고, 3회차가 맞히거나 일부 맞힌 2문항(같은 문서를 묻는 질문)을 새로 거절했다. 3회차가 거절한 2문항은 답했다(맞음 1, 거절 머리말 + 일부 1).
- [실측] 문서와 다른 말로 물은 40문항의 정답: 학습 전 38, 3회차 32, 4회차 33. 표 근거 정답 28/45, 글 근거 59/76으로 3회차와 같다.

## 8. 원인 분석: 왜 과잉 거절이 줄지 않았나

- [실측] 과잉 거절 쌍 60개 중 3회차가 실제로 답 있는 입력을 거절해 생긴 쌍은 13개다. 나머지 47개는 사본에서 3회차가 한 거절(그 입력에서는 맞는 거절) 45개와 거절 문장 2개를 원본 입력에 붙여 지은 쌍이다. 원본 입력은 3회차가 이미 맞힌 문항이다.
- [실측] 검증 몫 14개 중 13개가 그 입력에서 3회차가 낸 답으로 지은 쌍이었다(과잉 거절 6, 지어내기 5, 틀린 값 2). 검증 몫은 같은 문서 묶음이 학습·검증에 갈리지 않게 혼자인 묶음에서 먼저 고르는데(`tools/train/data.py` `split_examples`), 사본 짝은 두 쌍이 한 묶음을 쓰므로 검증 몫이 사본이 아닌 쌍으로 채워졌다. 그래서 과잉 거절 실패 쌍 13개 중 6개가 검증 몫으로 가 학습에는 7개만 들어갔고, 검증 정확도 43%는 이 실패를 배우지 못했다는 뜻으로 읽힌다.
- [판단] 사본 짝(같은 질문에 근거가 있으면 답, 없으면 거절)은 3회차가 이미 하는 구분이어서 새로 옮긴 기준이 적었고, 지어내기 쌍이 멀쩡한 답 글(원본 답 45개)의 확률을 누르면서 답을 피하는 쪽으로 조금 더 기울었다고 본다. 확신도 중간. 쌍을 늘려도 같은 사본 쌍이 늘어난다면 효과가 크지 않을 것이다.
- [실측] 1~4회차 모두 같은 맞바꿈이다. 학습하면 오답이 줄고(개발셋 11~12 → 3~8, 새 평가 데이터 41~43 → 19~27) 과잉 거절이 는다(개발셋 7 → 15~22, 새 평가 데이터 8~9 → 18~36). 학습 전 모델의 개발셋 과잉 거절은 모두 검색 단계 원인이고, 3·4회차는 근거를 받고도 거절한 몫(6·7개)이 더해진다.

## 9. 다음

- 운영 모델은 학습 전 모델 그대로 둔다. `ax40light-r4:q4km`는 데스크탑에 등록된 채 비교용으로 남긴다. 4회차 어댑터와 실행 기록은 맥북 `Assets/train/round4/aws/`에 보관했고, 학습 서버의 학교 데이터(선호 쌍·학습 결과·합친 모델·변환 파일)는 지운다.
- 결정(2026-11-05): 학습 회차는 4회차로 마치고, 검색과 학습 데이터를 고치는 개선 계획을 새 이슈로 설계한다. 근거는 아래 추천과 같다.
- [판단] 추천: 학습 회차는 4회차로 마친다. M2의 학습 목표(학습한 모델을 학습 전 모델과 같은 조건으로 비교)는 1~4회차로 채웠고, 네 회차가 같은 맞바꿈을 보였다. 과잉 거절을 줄이는 데이터(3회차가 실제로 실패한 입력)는 질문 약 1,000개에서 13개만 나와, 회차를 더 하려면 데이터를 만드는 방법부터 바꿔야 한다. 확신도 중간.
- 다음 작업 후보(이슈를 닫은 뒤 따로 정한다): ① 과잉 거절 중 검색 단계 원인 10문항(학습과 무관하게 모든 모델에 해당), ② 학습 모델은 오답이 적고 학습 전 모델은 과잉 거절이 적으므로, 오답과 과잉 거절의 비용을 다시 따져 운영 선(ADR-0033)을 다시 볼지.
