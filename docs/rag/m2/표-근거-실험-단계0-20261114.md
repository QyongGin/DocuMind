## 2. 표 질문 유형 묶음

### 2-1. 만들 수 있는 문서가 적다

[실측] 문서 대장에서 평가 몫이고 서비스 색인에 든 문서는 PDF 12, HWP 8, HTML 206개다. 표가 있는 문서(파서와 로더로 표를 센 결과, 글 100자 미만·[평가질문제외] 문서 뺌)는 PDF 8, HWP 4, HTML 29개이고, 표 수는 안전진단 보고서 331, 모집요강 23, 봄내장학생 공고 15개 순이다(`inventory.py`, 표 444개).

| 무엇 | 평가 몫에서 찾은 곳 |
|---|---|
| 기호 범례(♣, ◈, 칸 색) | 모집요강 정원내·정원외 모집인원 표 |
| 머리글 칸 안 범례(이행 O, 해당없음 -) | 안전진단 보고서 점검 표 |

| HTML 표의 기호 범례 | 없음(기호는 ㈜, ☎ 정도) |

### 2-2. 만든 문항

- 만드는 법: 평가셋 설계 ⑦과 같다. 정답과 핵심 사실은 PDF 쪽 그림을 보고 썼고(HWP는 쪽 그림 도구가 없어 원본 HWP 표 격자, HTML은 원본 HTML 표), 인용은 챗봇 색인 글에서 그 사실이 든 가장 짧은 범위를 골랐다. 정답 문장을 규칙 채점에 넣어 74문항 모두 '맞음'이 나오는지 확인했다(답없음 정답에 단위 숫자를 넣었다가 '애매'가 나와 고쳤다).
- 답없음 10문항은 서비스 색인 글 703개 전체에서 낱말로 부재를 확인했다. 걸린 글이 있는 2문항은 읽어서 답이 아님을 확인하고 경고로 남겼다.
- 답 유형: 값 41, 목록 14, 답없음 10, 예아니오 7, 설명 2. 형식: PDF 61, HTML 9, HWP 4.

- 문서별: 모집요강 35, 안전진단 보고서 13, 푸른등대 요약표 7, 현역병 모집계획 6, 봄내장학생 공고(HWP) 4, HTML 4개 문서 9. 모집요강이 47%를 차지한다. 범례·주석 문항이 이 문서에만 있어서다.

- '범례의 뜻'에 단위 줄 문항 2개(푸른등대 '4' → 400만 원)를 넣었다. 칸 값의 뜻이 표 밖 줄에 있다는 같은 구조라서다. 설계 2-2의 정의보다 넓다.
- 개발셋에 이미 있는 문항(ev-0108 연계교육, ev-0043·0091·0239·0240 푸른등대 등)과 같은 질문은 피했다. 테스트셋 문항은 열지 않아 겹침을 확인하지 못했다.

### 2-4. 나누기

- 평가셋 도구의 나누기(`split.assign_parts`)를 확인 몫 30%로 썼다. 문항이 10개를 넘는 문서(모집요강, 안전진단 보고서)는 표 단위(근거의 `section`)로 나눴다. 설계 2-2의 '문서 단위'를 그대로 쓰면 모집요강이 한쪽으로 몰려 한쪽 몫이 절반이 된다.

- 고르는 몫 51문항(`table_qset_pick.jsonl`, part=dev), 확인 몫 23문항(`table_qset_confirm.jsonl`, part=test). 확인 몫을 test로 둬 실행 결과가 봉인 파일(`results_test.sealed.jsonl`)로 따로 쌓인다.

## 3. PDF 도구 비교용 표 정답

### 3-1. 표본

- 표본 틀: 범례 조사의 PDF 61개(파서 표 795개) + 실패 표가 있는 평가 PDF 2개(푸른등대 요약표, 안전진단 보고서 — 실패 표만). 61개 안에 실패 표가 있는 문서는 모집요강뿐이라 넓혔다.
- 층(앞 층에 뽑힌 표는 뒤에서 뺌, 문서당 5개 상한, 씨앗 20261114): 실패 8, 쪽 넘김 11, 여러 줄 머리글 16, 세로 병합 15, 주석·범례 15, 무작위 20. 문서 40개, 칸 6,477개.
- 실패 표 8개: 모집요강 정원내 모집인원, 전형일정, 동점자 처리기준, 전형료 감면 및 환불 기준, 감면 및 환불 신청, 푸른등대 요약표, 안전진단 분야별 진단 실시 내용, 분야별 지적사항. 봄내장학생 접수처 표(HWP)는 PDF가 아니라 뺐다.
- 뺀 표 2개: 파서가 앞 조각 연결을 놓친 140행 점검 표(tg-014), 머리글이 놓친 앞쪽에 있는 16열 기호 행렬(tg-018). 손으로 확정하기 어려워서이고, 같은 기준의 대체 사슬이 틀에 없었다.

### 3-2. 만든 법

- 칸 초안은 기준 도구(OpenDataLoader 2.2.1) JSON의 칸(PDF 글자 층 글, 병합 수)이다. 표마다 쪽 그림을 잘라 구조(머리글 줄, 합친 칸, 행 나뉨, 쪽을 넘는 연결)와 표에 딸린 주석·범례·단위 줄을 대조해 고쳤다(`gold_fixes.json`, 표마다 고친 이유).
- 칸 글은 칸 경계 안의 PDF 글자 층(pypdfium2, 파서와 다른 읽기)과 자동으로 견줬다. 84개 중 75개는 한 칸도 다르지 않았고, 다른 칸이 있는 표만 집중해서 봤다.
- 쪽 그림과 대조해 고친 표 16개의 유형: 쪽 경계에서 세로 병합이 끊김(tg-008, 012), 한 행이 두 쪽에 쪼개짐(015), 두 행 글이 한 칸에 몰림(019, 041, 048), 하위 행이 합쳐짐(051, 079), 다른 표를 이음(016, 032 — 따로 둠), 글자 층에 한글이 없음(055, 058 — 쪽 그림으로 씀), 머리글 글이 옆 칸으로 넘침(082), 파서가 표로 못 잡음(085).
- 칸 색으로 표시한 범례(모집요강 면접 학과)는 칸에 `data-fill`(초록, 보라)로 적었다. 진단 참여자 이름·서명이 든 표는 개인정보라 표본에서 바꿨다.
- HWP 짝: 같은 게시물에 같은 제목 HWP가 있는 PDF는 2개(둘 다 신청서 양식), 다른 게시물까지 넓혀도 3개다. 표본에 들지 않아 HWP 격자 초안은 쓰지 않았다.

### 3-3. 정답 형식(`Assets/eval/table_qset/table_gold/gold.jsonl`, 표 하나 = 한 줄)

| 칸 | 뜻 |
|---|---|
| `gid`, `doc`, `stratum`, `reason` | 표 ID, 대장 ID, 층, 실패 문항 |
| `parts` | 조각마다 쪽과 기준 도구의 표 id(쪽을 넘는 표는 여러 개) |
| `continues`, `repeated_header`, `link_next` | 조각이 이어지는가, 뒤 조각에 머리글이 되풀이되는가, 정답을 쓰지 않은 다음 조각과의 연결 |
| `header_rows`, `cells`, `html` | 머리글 줄 수, 칸(행·열·rs·cs·글, 칸 색·가림·칸 안 표 표시), HTML 표 |
| `notes`, `legend`, `unit` | 표에 딸린 주석 줄, 그 가운데 기호·색의 뜻 줄, 표 위 단위 줄 |
| `draft_from`, `status`, `comment` | 초안 출처, 확인/고침, 고친 이유 |

### 3-4. 지표 계산 확인과 입력 형식

- 도구 출력 입력 형식(도구 하나 = JSONL 한 파일, 문서 하나 = 한 줄): `tool`, `doc`, `pages`, `seconds`, `peak_vram_mb`, `error`, `tables`(표마다 `tid`, `page`, `bbox`, 정답과 같은 모양의 `cells`, `header_rows`, `next`, `notes`). 쪽을 넘는 표를 도구가 합쳐 주면 `pages_merged`. 형식과 지표 정의는 참조 구현 `table_metrics.py` 맨 위에 있다.
- 기준 도구 JSON을 이 형식으로 바꿔 시험 계산했다: 머리글 경로 일치율 0.654(칸 6,240), 숫자 칸 완전 일치율 0.994(3,391), 세로 병합 채움 0.980(900), 쪽 넘김 연결 정밀도 0.889(18)·재현율 0.941(17), 주석 연결 재현율 0(74, 기준 도구는 주석을 표에 잇지 않음).
- 이 숫자는 기준선이 아니다. 칸 초안이 기준 도구에서 왔고, 지금 서비스는 이 JSON이 아니라 병합 정보가 없는 마크다운을 쓴다. 단계 1에서는 서비스가 실제로 받는 출력(마크다운을 표로 되돌린 것)을 기준선으로 넣어야 세로 병합 채움을 바르게 잰다.

### 5-3. '애매' 비율과 판정 시간 어림

- [실측] 최근 개발셋 실행 14번(205문항)에서 규칙 채점이 '애매'로 남긴 답은 12~18개(5.9~8.8%)였다. 같은 문항·같은 답 글이면 저장한 판정을 다시 쓴다.
- [계산·추정] 프롬프트 후보 11개 + 기준선 2번 = 13번 실행 × (개발셋 205 + 표 질문 고르는 몫 51) = 3,328답. 개발셋 비율(약 7%)을 쓰면 '애매'는 실행마다 약 18개, 다시 쓸 판정을 빼면 새로 판정할 답은 그 절반 안팎으로 어림한다. 표 질문은 목록·답없음 비중이 높아 비율이 더 높을 수 있다(재지 않음).
- [실측, 대략] 지난 판정 기록(`judgments.jsonl`)에서 격리 판정이 한꺼번에 기록된 묶음(2026-11-03, 67건)의 기록 간격 중앙값은 77초였다. 판정 하나에 1~2분, 13번 실행에 새 판정 100~150건이면 판정 시간은 2~5시간(기계 시간)으로 어림한다. 사람은 판정이 갈린 답만 본다.
- 정확한 비율과 시간은 단계 1 첫 실행에서 잰다(설계 5절).
