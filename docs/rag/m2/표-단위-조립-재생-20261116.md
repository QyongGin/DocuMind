## 1. 결론

- 표 조각 하나가 근거로 걸리면, 같은 표의 나머지 조각과 표 주석을 함께 넣는 조립 변형 넷(R0~R3)을 만들었다. 기준선의 근거 8개는 그대로 두고 생성만 다시 한다.
- 표 번호 지도는 기준선 근거에 표가 든 문서 103개에서 표 413개를 찾았다. 근거에 나온 표 블록 429개 가운데 398개에 표 번호를 붙였다. 못 붙인 31개 중 25개는 한 행이나 한 열짜리라 표로 보지 않은 것이고, 표인데 못 붙인 것은 6개(PDF 4, HWP 2)다 [실측].
- 생성 없이 조립만 해 보면 tq-0001의 근거에 ♣ 표시가 12개에서 26개로 늘고, tq-0004·tq-0031의 근거에 ◈ 범례 줄이 R2·R3에서 들어간다. tq-0007이 필요로 하는 표 아래 줄은 기준선 근거 8개에 그 표가 없어 어느 변형으로도 들어가지 않는다 [실측].
- 프롬프트는 길어지지만 입력 한도 안이다. 어림 입력 토큰의 최대는 표 질문 5,714 → 8,476, 개발셋 7,394 → 8,625다(출력 몫을 뺀 한도 11,776) [계산].
- 가장 큰 위험은 답없음 거절이 주는 것이다. 단계 1에서 표를 통째로 주는 넓히기(c13)는 답없음 거절이 24 → 18로 줄었다 [실측, 앞 기록 2절 11-14 04:52].
- 측정(10절): R1·R2·R3 셋 다 4절 거르기를 통과했다. R0a 대비 표 질문 맞음 +4·+5·+3, 개발셋 본 틀림 −3·−4·−3, 답없음 거절 +2·+2·+2(23 → 25) [실측, 판정 84개는 Claude가 한 번].
- 셋 사이의 1~2문항 차이는 순위로 읽지 않는다(7절). 근거를 고정한 재생이라 서버 경로 측정이 따로 필요하다.
- R0를 두 번 돌린 답은 표 질문 46/47, 개발셋 205/205가 같다. R0a와 서버 경로 기준선의 답은 표 질문 16/47, 개발셋 100/205만 같고 원인은 확인하지 못했다(스트리밍 받기와 임베딩 동시 적재는 배제) [실측].

## 2. 변형

| 변형 | 근거 블록에서 바꾸는 것 |
|---|---|
| R0 | 아무것도 바꾸지 않음(재생 경로 확인용, 두 번 잼) |
| R1 표 전체 | 표 조각 자리에 같은 표의 조각을 모두 이은 표 하나. 같은 표가 뒤 블록에도 걸렸으면 거기서 뺀다 |
| R2 R1 + 기호 주석 | 표 칸의 기호와 같은 기호가 든 표 뒤 줄을 표 바로 아래에 |
| R3 R1 + 딸린 글 | 서비스 색인 PDF 표 242개를 Opus가 읽어 고른 표에 딸린 줄(종류 '표 제목' 제외)을 표 바로 아래에 |

- 주석은 「표 아래 주석(원문):」 한 줄 밑에 문서 원문 그대로 둔다. 그 블록에 이미 든 줄은 다시 넣지 않고, 표마다 한 번만 붙인다.
- 블록 머리말과 「표 검색 정보」 줄은 새로 만들지 않는다. 표를 넣어 블록이 비면 그 블록을 빼고, 그 블록의 「표 검색 정보」와 「질문 의도 추출 정보」 줄을 표를 넣은 블록으로 옮긴다(단계 1 후보 '같은 표 조각 합치기'와 같은 처리). 블록 번호는 다시 매긴다.
- 표가 4,000자를 넘으면 넓히지 않고 근거에 있던 표 줄을 그대로 두되, 머리글이 없으면 앞에 붙인다.
- R3의 줄은 모델(격리 `claude -p` Opus)이 고른 것이고 사람이 확인하지 않았다. 확인 단계에서 무관한 줄을 고른 표가 109개 중 7개로 기준(3)을 넘었다(전수 조사 인계 노트). PDF가 아닌 표에는 이 자료가 없어 R3이 R1과 같다.

## 3. 만든 것

### 3-1. 표 번호 지도 (`tools/corpus/corpus/evalset/table_map.py`)

색인을 다시 만들지 않는다. 서비스 색인(`repro-20261010-develop15e776c`)과 같은 코드로 맥북에서 문서를 임베딩 없이 다시 잘라 쓴다. 다시 자른 원문 청크와 표 원문 블록 580개가 기준선 근거 글과 글자까지 같았다 [실측].

| 규칙 | 내용 |
|---|---|
| 표 | 로더 글(PDF는 쪽마다)에서 마크다운 표 줄이 이어진 덩어리. 두 행·두 열 미만(빈 칸 하나짜리 상자 등)은 표가 아니다 |
| 쪽을 넘는 표 | OpenDataLoader JSON의 `previous table id`·`next table id`로 이어진 표를 한 번호로 묶는다. 마크다운 표와 JSON 표는 같은 쪽에서 글 겹침으로 짝 짓는다 |
| 원문 청크 조각 | 청크의 표 줄 덩어리를, 그 행이 절반 넘게 든 표에 붙인다 |
| 표 원문 블록 | OpenDataLoader JSON 표 하나를 칸 글로 적은 근거(`…_odl_N`). 같은 쪽 JSON 표와 글 겹침으로 붙인다 |
| 잇기 | 원문 청크 조각은 원문 청크끼리, 표 원문 블록은 표 원문 블록끼리 잇는다(근거와 같은 모양). 되풀이된 머리 줄과 청크 겹침으로 두 번 나온 행은 한 번만 |
| 기호 주석 | 표 칸의 기호(한글·영문·숫자·흔한 문장부호가 아닌 글자)가 든 줄을 표 뒤 12줄(다음 표나 제목 전까지)에서 고른다 |

### 3-2. 근거 고정 재생 (`regenerate.py`에 조립 단계 추가)

- 기존 '생성만 다시 돌리기'에 `--assembly R0~R3 --table-map`을 더했다. 기준선 기록의 근거 글을 `[출처 N]` 블록으로 나누고, 블록 순서의 청크 번호(`stages.final`)로 지도를 찾아 바꾼 뒤 프롬프트의 같은 자리에 넣는다. 검색과 AI 서버는 거치지 않고 Ollama를 직접 부른다.
- 결과 폴더는 실행 폴더와 같은 모양이다. 바꾼 근거 글과 프롬프트가 `eval_trace`에 남아, 고친 채점기(#261)가 바뀐 근거로 옮겨 적은 줄을 가린다. 실행 기록에 변형과 지도 해시를 남기고, 같은 폴더에 다른 변형으로 이어 돌리면 거부한다.
- 빈 지도로 조립하면 기준선 근거 글 252개가 모두 글자까지 같다(블록 나누기와 다시 쓰기 확인) [실측].
- `--stream`을 주면 서버(langchain_ollama 기본)처럼 답을 조각으로 받아 이어 붙인다. 기본은 한 번에 받기이고, 실행 기록에 남아 다른 방식으로 이어 돌리지 못한다(기준선과 답이 다른 원인 확인용, 10-3).

### 3-3. 테스트

- `tests/test_evalset_table_assembly.py` 13개(가나대학 합성 데이터). 두 쪽에 걸친 표 잇기, JSON 연결이 없으면 따로 둠, 쪽 메타데이터가 틀린 청크, 쪽 없는 문서, 블록 빼기와 사실 줄 옮기기, 주석 중복 막기, 상한, 표 원문 블록 잇기, 프롬프트 한 자리 바꾸기, 재생 기록.
- `tools/corpus` 테스트 370개 통과. 변이 일곱 가지(겹친 행 안 뺌, 쪽 넘김 연결 안 함, 같은 표 두 번 넣음, 이미 든 주석 다시 넣음, 상한 무시, 빈 상자에서 주석 찾기 멈춤, 재생에서 조립 안 함)를 모두 테스트가 잡았다.
- 받기 방식 선택(`--stream`) 테스트 3개를 `tests/test_evalset_regenerate.py`에 더해 373개 통과. 변이 네 가지(마지막 조각만 씀, 요청 본문의 stream 끔, done 없는 응답 통과, 다른 받기 방식으로 이어 돌리기 허용)를 모두 잡았다.

## 4. 재기 전에 정한 것

- 대상: 표 질문 고르는 몫 47문항, 개발셋 205문항. 확인 몫과 봉인된 테스트셋은 열지 않는다(두 기준선 실행의 문항은 모두 개발셋 몫이다).
- 실행: R0 두 번(R0a, R0b), R1, R2, R3 한 번씩. 생성 설정은 기준선과 같다(A.X 4.0 Light `ax40light:q4km`, 온도 0, 문맥 12,288, 출력 512).
- 채점: 고친 채점기(#261 브랜치)로 `score-run`, 애매는 기존 판정 방식(`judge_pool.py`, 본 세션이 판정).
- 거르기(단계 1과 같음): R0a보다 표 질문 맞음이 3문항 이상 많고, 개발셋 본 틀림이 2문항 넘게 늘지 않고, 답없음 거절이 1문항 넘게 줄지 않으면 통과. 기준을 R0a로 둔 까닭: 재생은 기준선과 생성만 다시 하므로, 같은 날 같은 경로로 잰 R0가 짝 비교의 바른 기준이다.
- 함께 볼 것: 설정별 맞음·일부·틀림·모름, R0a 대비 좋아진·나빠진 문항(판정이 바뀐 문항은 모두 읽는다), 답없음인데 답해 버린 문항 수, 입력 토큰 분포와 잘림, 대상 10문항(범례나 주석이 없어 틀린 tq-0004·0007·0031, 행이 모자라 틀린 tq-0001·0008·0024·0033·0036, ev-0021·0031).
- 재생 잡음: R0a와 R0b의 답 글이 다른 문항 수, R0a와 기준선 답 글이 다른 문항 수. 온도 0이어도 다시 생성하면 일부 문장이 달라질 수 있다(`docs/development/local-gpu/평가-실행-절차.md` 6-1, 2026-10-13 실측).

## 12. 추가 설정: 학년도 줄(Y0·Y2, 재기 전에 적음, 2026-11-16)

## 13. 추가 설정: 근거 쪽 학년도 표시(Z1·Z2, 재기 전에 적음, 2026-11-16)

학년도는 프롬프트에 표시하기로 했다(사용자 결정). 12절에서 질문 쪽 줄만 넣으면 해는 바르게 적지만 값은 다른 해 표에서 읽었고, 근거 쪽에 어느 학년도 것인지가 없다는 것이 남은 문제로 보였다. 견주는 기준은 D2(요약 문장 없음 + 표 전체 + 기호 주석).

- Z1: D2 + 질문 쪽 줄 + 근거 쪽 학년도 줄.
  - 질문 쪽(모양 z, 기준 날짜 2026-10-31): 「오늘: 2026-10-31 (2026학년도 2학기)」, 「지금 모집 중인 입시: 2027학년도」, 「직전 입시(작년에 치른 입시): 2026학년도」. 12절의 「(2025년 가을 모집)」 괄호는 뺐다(ev-0031에서 다른 학년도에 잘못 옮겨 썼다). 지금 학년도는 학년도 시작 월(3) 전이면 앞 해, 학기는 3~8월 1학기, 9월~다음 2월 2학기. 1~2월을 앞 학년도 2학기로 보는 것은 경계 풀이다.
  - 근거 쪽: 근거 블록 머리말의 「청크:」 줄(없으면 「위치:」, 「문서:」) 아래에 「학년도: 2026」 한 줄. 값은 문서 대장의 `academic_year`. 없는 문서는 줄을 넣지 않고, 제목이나 게시일에서 짐작하지 않는다.
