# M2 학습 1회차 계획 — A.X 4.0 Light QLoRA와 개발셋 전후 비교

> 상태: 계획(2026-11-03). 이슈 #223. 이 계획은 `1회차-준비-작업계획-20261101.md`의 8단계(학습 가능성 실측)와 9단계(학습 1회차)를 자세히 적는다. 실행 절차는 `tools/train/README.md`.

## 1. 목표와 판정

- 목표: 1회차 학습 파일 200개로 A.X 4.0 Light에 LoRA를 학습해, 같은 프롬프트에서 틀린 답과 답없음 거절이 나아지는지 본다(ADR-0033 결정 1).
- 주 지표(실행 전 고정, ADR-0035 결정 4): 틀린 답(오답률), 답없음 거절. 같은 문항 짝 비교(ADR-0025)로 하나라도 의미 있게 좋아지고 나머지와 정답률이 의미 있게 나빠지지 않으면 채택한다.
- 운영에 쓰려면 더해서 오답률 5% 이하, 답없음 거절 90% 이상(ADR-0033 결정 2).
- 학습 전 기준선 [실측, 같은 기준으로 다시 판정]: 개발셋(본) 틀린 답 13/149(8.7%), 답없음 거절 23/28(82%), 정답 97/121. 실행 `Assets/eval/runs/20261102-m2-s6-refusal-sentence-asof1031`(로컬), 보고서 `거절문장-기준선-20261102.md`.
- [계산] 주 지표로 갈릴 수 있는 문항: 틀린 답 13문항이 모두 고쳐지고 새로 틀리는 문항이 없으면 13 대 0(p<0.001), 답없음 거절은 놓친 5문항이 모두 고쳐져도 5 대 0(p=0.0625)이라 답없음 거절만으로는 의미 있는 차이에 닿지 못한다. 그래서 채택은 사실상 틀린 답에서 갈린다.

## 2. 데이터

- 1회차 학습 파일 200개(로컬 `Assets/train/round1/round-ga.jsonl`): 사실 40, 표 40, 절차 35, 거절 안내 30, 여러 문서 25, 일부만 있음 20, 범위 밖 거절 10. 반출 범위 검사 통과, 평가셋과 겹침 0(`1회차-준비-작업계획-20261101.md` §6).
- 검증 몫 20개를 종류 비율대로 떼어 회차 고르기에만 쓴다(사실 4, 표 4, 절차 3, 거절 안내 3, 여러 문서 3, 일부만 있음 2, 범위 밖 거절 1). 같은 문서 묶음은 학습 몫과 검증 몫에 갈라지지 않는다(문서와 상관없는 범위 밖 거절만 예외). 개발셋으로 회차를 고르지 않는다(판정에 쓸 문항을 미리 보는 셈이 된다).
- [실측] 길이: 개발셋 205문항에서 A.X가 받은 운영 프롬프트는 중앙 3,481토큰, p95 4,969, 최대 7,394토큰(Ollama가 센 값). 학습 예시(입력+답)는 글자 수로 어림해 중앙 약 3,440토큰, 최대 약 8,200토큰(가장 적게 눌리는 비율 1.72자/토큰으로 계산). 학습 전에 실제 토크나이저로 다시 세고, 최대 길이를 넘는 예시가 있으면 자르지 않고 멈춘다.

## 3. 학습 설정

| 항목 | 값 | 근거 |
|---|---|---|
| 방식 | QLoRA: 원본을 4비트(NF4, 이중 양자화)로 올리고 LoRA 어댑터만 학습 | [판단] bf16 원본만 약 15GB라 8천 토큰 학습에 24GB GPU가 빠듯하다. TRL은 `quantization_config`와 `peft_config`를 함께 주는 방식을 QLoRA 학습으로 안내한다 [원문 TRL v1.17.1] |
| 어댑터 | r=16, alpha=32, dropout 0.05, 모든 선형 층 | [판단] 200개로 말투·형식을 고치는 학습이라 작은 어댑터로 시작한다 |
| 학습할 부분 | 답(completion)만 | [원문 TRL v1.17.1] "By default, the trainer computes the loss on the completion tokens only" — 근거 문서를 외우지 않게 한다 |
| 최대 길이 | 8,192토큰 | [원문 TRL v1.17.1] `max_length` 기본값 1024. 그대로면 중앙 3,400토큰 예시의 답이 잘린다. A.X 4.0 Light는 16,384토큰까지 받는다 [원문 모델 카드] |
| 끝 토큰 | `<|im_end|>` | 서빙 틀(Ollama `Modelfile.tmpl`)의 stop과 같아야 답이 같은 자리에서 끝난다. TRL은 Qwen 계열에서 끝 토큰을 채팅 틀과 맞추라고 한다 [원문 TRL] |
| 학습률·회차 | 1e-4, 최대 3회차, 코사인, 워밍업 5% | [원문 TRL] 어댑터 학습은 보통 1e-4 정도. 회차는 검증 손실이 가장 낮은 것을 남긴다 |
| 배치 | 1개 × 기울기 누적 8 | [계산] 180개면 회차마다 23걸음, 3회차 69걸음 |
| 채팅 틀 확인 | '안녕하세요'를 공식 틀로 감싸 6토큰인지 | 운영 모델 등록 때 확인하는 값과 같다(`deploy/models/ax40light/recipe.env`) |

## 4. 절차

1. 준비(학습 서버): 저장소 받기, 학습 라이브러리 설치(TRL 1.17.1, Transformers 5.22.1, PEFT, bitsandbytes), 운영 모델과 같은 원본 커밋(`ba21c20e`)을 내려받기.
2. 한 바퀴 시험(8단계): 20개로 10걸음 학습 → 합치기 → 4비트 변환 → 데스크탑 Ollama 등록(`ax40light-smoke:q4km`) → 답 하나 확인. 단계별 시간과 최대 GPU 메모리를 적는다.
3. 본 학습(9단계): 180개 학습, 검증 20개로 회차 고르기 → 합치기(GPU) → 운영 모델과 같은 변환 도구(llama.cpp b11312 이미지)로 Q4_K_M → 데스크탑에 `ax40light-r1:q4km`로 등록(이전 모델은 남긴다, ADR-0011).
4. 전후 비교: AI 서버의 생성 모델만 바꿔(`OLLAMA_LLM_MODEL`) 개발셋을 학습 전과 같은 날짜(`--as-of 2026-10-31`)로 묻는다. AI 서버 코드가 기준선 실행과 다르면 학습 전 모델도 같은 코드로 다시 잰다. 판정이 갈린 문항은 두 답을 나란히 놓고 같은 기준으로 다시 판정한다.
5. 정리: 학습 서버의 학교 데이터와 결과물을 지우고 인스턴스를 중지한다.

## 5. 학습 위험과 확인할 것

- 과잉 거절: 1회차 거절 예시 40개 중 31개가 거절 문장만이다. 과잉 거절(답이 있는데 거절)이 늘면 채택하지 않는다.
- 정해진 말투: 거절 문장과 '[출처 N]'을 학습하므로 답 끝 출처 번호 비율, 거절 문장 모양, 같은 문구 반복을 전후로 센다.
- 링크: 목표 답 링크 45개 중 11개 뒤에 조사가 붙어 있다. 화면은 링크 끝을 한글 앞에서 끊는다(#220).
- 양자화 차이: 학습은 4비트 원본 위에서 하고 합치기는 bf16 원본에 한다. 운영 모델과 같은 변환으로 비교하므로 전후 차이는 학습에서 온 것으로 본다.
- 메모리: [판단] QLoRA 7B, 8천 토큰, 기울기 체크포인트면 24GB 안이다. 넘치면 최대 길이를 넘는 예시를 빼지 않고 학습 몫을 나눠 원인을 적는다.

## 6. 학습 서버와 데이터 범위

- 학교가 준 인스턴스는 g5.xlarge(A10G 24GB), Deep Learning OSS Nvidia Driver AMI GPU PyTorch 2.13(Ubuntu 26.04)이고 리전은 미국 동부(us-east-1)다 [실측, AWS 콘솔 2026-11-03].
- ADR-0010은 서울 리전을 적었다. 리전 결정은 사용자 확인 뒤 ADR-0010에 변경 메모로 남긴다. 올리는 것은 학습 파일 200개(3.0MB, 공개 홈페이지 글로 만든 예시, 개인정보 검사 통과)와 공개 모델뿐이다.
