# 학습 토크나이저의 공식 규칙 사용 (2026-11-28)

> 상태: 끝남(2026-11-28). 이슈 #280. 학습은 다시 돌리지 않았다.
> 날짜와 상위 문서: 2026-11-28, 상위 [M2 README](README.md) 1절, 결정 [ADR-0033](../../adr/0033-LLM-학습은-M2에서-반드시-한다.md) 변경 메모

## 결론

- 학습 스크립트(`train_qlora.py`, `train_dpo.py`)가 토크나이저를 `TokenizersBackend.from_pretrained`로 부르게 고쳤다. 원본 폴더의 공식 `tokenizer.json`을 고치지 않고 그대로 쓰는 호출이다. 두 스크립트는 `official_tokenizer.load_tokenizer` 한 함수를 같이 쓴다.
- 학습 전 확인에 숫자가 든 글 세 개를 넣었다. 채팅 틀을 씌운 토큰이 공식 `tokenizer.json`으로 센 토큰과 하나라도 다르면 학습을 시작하지 않는다. 메시지에 어느 숫자가 어떻게 갈렸는지 적는다.
- 지금까지의 학습 어댑터(4회차, 표 읽기 시험 학습, 1차, 2차는 실행 기록으로 확인, 1~3·5회차는 같은 고정 판이라 판단)는 숫자를 한 글자씩 자르는 옛 규칙으로 학습됐다. 새 학습과 견줄 때는 4절의 조건 차이를 적는다.
- 하지 않은 것: 운영 모델 파일(GGUF)과 변환 스크립트는 그대로다. 운영은 처음부터 공식 규칙이었다. AI 서버의 토큰 세기 파일은 #274에서 고친다.

## 1. 원인

| | 학습(고치기 전) | 공식 `tokenizer.json`, 운영 Ollama |
|---|---|---|
| 부른 클래스 | `Qwen2Tokenizer` | 파일 그대로 |
| 정규화 | NFC | 없음 |
| 숫자 | 한 글자씩(`110` → `1`, `1`, `0`) | 이어진 숫자를 병합 규칙대로(`110` → `110`) |
| 「안녕하세요」 채팅 틀 | 6토큰 | 6토큰 |

- transformers 5.8.0부터 `AutoTokenizer`는 `config.json`의 `model_type`(A.X 4.0 Light는 `qwen2`)이 「Hub에 적힌 토크나이저 클래스가 틀린 모델」 목록에 있으면 `tokenizer_config.json`의 `GPT2Tokenizer` 대신 등록된 `Qwen2Tokenizer`를 고른다. 5.7.0까지는 공식 규칙이었다. 바뀐 곳은 [transformers PR 45741](https://github.com/huggingface/transformers/pull/45741)이다.
- `Qwen2Tokenizer`는 자기 `__init__`에서 정규화와 사전 분리(pre-tokenizer)를 새로 만들고, `tokenizer.json`에서는 어휘와 병합만 가져온다.
- 학습 전 확인(`check_chat_template`)은 숫자도 문장부호도 없는 「안녕하세요」만 봐서 두 규칙 모두 6토큰이라 차이를 잡지 못했다.

## 2. 고친 내용

| 곳 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 토크나이저 부르기 | 두 스크립트가 각자 `AutoTokenizer.from_pretrained` | `official_tokenizer.load_tokenizer` 하나(`TokenizersBackend.from_pretrained`) |
| 학습 전 확인 | 「안녕하세요」 6토큰, 끝 토큰 한 토큰 | 그대로 두고, 숫자가 든 글 세 개(학년도, 금액, 전화번호, 표 칸, NFD로 쓴 한글)를 채팅 틀로 감싸 공식 파일로 센 토큰과 견줌 |
| 저장할 토크나이저 | 확인 없음 | 임시 폴더에 저장해 다시 읽고 같은 글을 공식 파일과 같게 자르는지 확인 |
| 실행 기록 | 없음 | 부른 클래스, 공식 `tokenizer.json` SHA256, 어댑터 폴더에 저장된 `tokenizer.json` SHA256 |
| 테스트 환경 | pytest만 | transformers 5.22.1, tokenizers 0.23.3(학습 서버와 같은 판), Jinja2 |

- 기대 값은 상수로 박지 않았다. 학습할 때마다 원본 폴더의 `tokenizer.json`을 tokenizers 라이브러리로 직접 읽어 센다. 그래서 transformers 판을 올려 부르는 규칙이 또 바뀌어도 학습 전에 멈춘다.
- 어긋나면 두 자리 이상 숫자마다 학습과 공식이 자른 토큰을 나란히 적고, 숫자마다 한 글자씩 잘렸으면 「숫자를 한 글자씩 자르는 규칙이 붙었다」고 적는다.
- 어댑터 합치기(`merge_adapter.py`)는 바꾸지 않았다. 토크나이저를 저장하지 않고, 원본의 `tokenizer.json`과 설정 파일을 합친 폴더에 그대로 복사한다. 변환과 Ollama 등록은 이 폴더를 쓴다.
- 선호 학습(`train_dpo.py`)은 어댑터 폴더에 토크나이저를 저장하지 않으므로 실행 기록에 클래스와 공식 파일 해시만 남긴다.

옛 방식으로 부르면 학습 전 확인이 이렇게 멈춘다(공식 파일, 일부):

```text
자르는 규칙 확인 실패: 채팅 틀을 씌운 글이 학습 94토큰, 공식 tokenizer.json 68토큰.
'2026' 학습 ['2', '0', '2', '6'] / 공식 ['202', '6']; '110' 학습 ['1', '1', '0'] / 공식 ['110']; …
숫자를 한 글자씩 자르는 규칙이 붙었다(모델 종류별 토크나이저 클래스가 불렸는지 본다)
```

## 3. 확인한 값

공식 파일은 운영 모델과 같은 원본 리비전(ba21c20)의 `tokenizer.json`(SHA256 e3973ece…)이다. transformers 5.22.1, tokenizers 0.23.3, 모델 가중치 없이 쟀다.

| 확인 | 결과 |
|---|---|
| 「안녕하세요」 채팅 틀 | 6토큰(고치기 전과 같음) |
| 끝 토큰 `<\|im_end\|>` | 한 토큰 |
| 표 읽기 1차, 2차 학습 파일 전체(학습 몫과 검증 몫 5,187개)의 채팅 틀 토큰 | 5,187개 모두 공식 파일로 센 토큰과 같음 |
| 가장 긴 예시 | 7,631토큰(길이 상한 8,192 안) |
| 저장한 `tokenizer.json` | SHA256이 공식 파일과 같음(e3973ece…). 고치기 전은 4050a8c9… |
| 테스트 | 25개 통과(새로 8개). 가나대학 글로 학습한 작은 바이트 BPE 토크나이저와 `model_type: qwen2` 폴더로 실제 문제를 줄여 재현한다 |
| 변이 확인 | 7개 모두 잡힘: 호출을 `AutoTokenizer.from_pretrained`로 되돌리기, 숫자 글 확인 빼기, 숫자 없는 글만 남기기, 저장 파일 확인 빼기, 한 글자 분리 안내 빼기, `load_tokenizer`에서 두 확인 호출을 하나씩 빼기 |

## 4. 지난 어댑터와 견줄 때 적을 조건 차이

- 학습 라이브러리 판은 1회차(2026-11-03)부터 transformers 5.22.1로 고정돼 있었다. 실행 기록이 남은 학습 9개가 모두 이 판이고, 어댑터 폴더에 저장된 `tokenizer.json` 7개가 모두 옛 규칙 해시(4050a8c9…)다. 1~3·5회차는 실행 기록을 찾지 못했지만 같은 고정 판으로 깔았으므로 옛 규칙이었다고 판단한다.
- 서빙은 처음부터 공식 규칙이었다. 지난 어댑터는 학습 때와 다른 숫자 토큰을 운영에서 받았다. 학습 전 모델(사전학습)과 운영은 같은 규칙이다.

| 조건 | 1차, 2차(옛 규칙) | 새 학습(공식 규칙) |
|---|---|---|
| 숫자 토큰 | 한 글자씩 | 공식 병합대로 |
| NFC | 적용(글이 바뀌는 예시 1차 16, 2차 9) | 없음 |
| 답에 숫자가 든 예시 | 1차 3,280/3,433, 2차 1,636/1,754가 답 토큰이 다름 | 기준 |
| 예시 하나의 전체 토큰 | 공식보다 중앙 +5.4%(1차), +6.1%(2차) | 기준 |
| 어댑터 폴더 `tokenizer.json` | 4050a8c9… | e3973ece…(공식 파일) |

- 학습 걸음 수는 예시 수로 정해져 바뀌지 않는다. 예시당 토큰이 줄어 한 걸음에 보는 토큰 수와 걸린 시간이 달라진다.
- 같은 데이터로 다시 학습해 1차, 2차와 견주면 바뀐 것은 토크나이저 규칙 하나다. 보고서에 이 차이를 적고 숫자를 낸다.

## 5. 근거 원문 위치 (transformers 5.22.1)

- `tokenization_utils_tokenizers.py`의 `TokenizersBackend.convert_to_native_format`: `cls is TokenizersBackend`이거나 클래스에 자기 `__init__`이 없을 때만 `tokenizer.json`을 고치지 않고 넘긴다. 그 밖이면 어휘, 병합, 후처리만 꺼낸다.
- `models/auto/tokenization_auto.py`: `qwen2`가 `Qwen2Tokenizer`로 등록돼 있고, `MODELS_WITH_INCORRECT_HUB_TOKENIZER_CLASS`에 있으면 Hub 클래스 대신 등록된 클래스를 쓴다.
- `models/qwen2/tokenization_qwen2.py`: `__init__`에서 `normalizers.NFC()`와 숫자 한 글자 정규식(`\p{N}`)의 `Split`을 붙인다.
- 공식 문서 [Tokenizers](https://huggingface.co/docs/transformers/main/en/fast_tokenizers) 「Fallback to TokenizersBackend」 절: 이렇게 만든 토크나이저는 “encodes and decodes exactly as `tokenizer.json` specifies”. 같은 문서는 qwen2를 Hub 클래스가 틀린 모델로 적어 `TokenizersBackend`로 간다고 읽히지만, 5.22.1 코드는 등록된 `Qwen2Tokenizer`를 고른다. 그래서 문서가 아니라 코드와 재현 값으로 정했다.
- 버린 방법: `AutoTokenizer.from_pretrained(..., tokenizer_type="gpt2")`는 `GPT2Tokenizer`가 코드로 만든 사전 분리가 지금 공식 파일과 우연히 같을 뿐, 파일을 그대로 쓰지 않는다. `PreTrainedTokenizerFast(tokenizer_file=...)`는 채팅 틀과 끝 토큰이 비어 학습 코드에 그대로 쓸 수 없다.

## 6. 남은 일

- 표 읽기 학습을 공식 규칙으로 다시 한다(학습 서버, 학습 데이터 파일은 그대로).
- AI 서버가 프롬프트 토큰을 세는 `tokenizer.json`과 모델 대장의 토크나이저 해시는 #274에서 공식 파일로 바꾼다.
