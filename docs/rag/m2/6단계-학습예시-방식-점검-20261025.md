## 1. 요약

- 첫 묶음은 초안 60개에서 학습에 쓸 수 있는 예시가 18개(30%)였다. 버려진 42개의 사유를 모델 제작사(OpenAI·Anthropic·Meta·Google·Qwen)의 방식과 견주니 문제가 일곱 가지로 모였다.
- 가장 큰 차이는 둘이다. ① 예시 종류를 Gemma가 의도한 대로 정하고 실제로 받은 근거로 확인하지 않았다. ② 학습할 학생 모델(A.X)이 지금 무엇을 맞히고 틀리는지 재지 않고 예시를 만들었다. 제작사는 둘 다 한다.
- 바꿀 것은 설계 합의 안의 고칠 것 둘(안내 빠짐, 서식 청크)과 결정이 필요한 다섯이다. 결정은 §5 순서로 하나씩 묻는다.

## 3. 모델 제작사가 학습 데이터를 만드는 방식

공식 자료에서 공통으로 보이는 원칙 일곱 가지다.

| 원칙 | 누가 | 근거 |
|---|---|---|
| 평가를 먼저 만들고, 평가 → 프롬프트 → 학습을 되풀이한다 | OpenAI | [12] |
| 학습 예시는 운영 때 받는 입력과 같은 모양이고, 응답 종류 비율도 실제 사용을 따른다(거절이 많으면 거절이 늘어난다) | OpenAI | [6·11] |
| 맞는 행동(답할지 거절할지)은 모델이 받은 문서가 정한다. 답없음 질문은 실제로 검색한 결과에 답이 없을 때만 답없음이다 | Anthropic, Salesforce | [5·1] |
| 학생 모델이 직접 여러 번 답하게 해 고른다. 일관되게 틀리게 단정하는 질문은 거절을 가르친다("know what it knows") | Meta, Qwen, NAVER Cloud | [15·2·4] |
| 예시마다 주제·품질·난이도를 매기고, 개인정보·중복·잘못된 예시를 거른다 | Meta, Google | [15·16] |
| 판정 모델은 사람 판단과 맞는지 먼저 보고 늘리며, 생성한 모델과 다른 모델로 판정한다 | OpenAI, Anthropic | [13·14] |
| 질은 양보다 앞서고, 양은 절반과 전체를 학습해 견줘 가늠한다. 못 하는 것은 그 행동을 보여 주는 예시를 더한다 | OpenAI | [11] |

## 4. 문제와 바꿀 것

### 문제 1. 예시 종류를 의도로 정하고, 받은 근거로 확인하지 않았다

- 증상: 자동 검사에서 모양 15건이 떨어졌다. 거절용으로 만든 질문인데 검색이 답이 든 청크를 가져와 Gemma가 답했고, 답용으로 만든 질문인데 근거에 답이 없어 거절했다. 질문 청크가 근거 8개에 없는 7건과 답 근거가 프롬프트에서 지워진 4건도 같은 뿌리다 — 의도한 상황과 학생이 실제로 받는 프롬프트가 다르다.
- 원인: 종류를 질문 초안 단계에서 정하고, 근거를 붙인 뒤에는 '의도와 맞는가'만 검사했다.
- 제작사 방식: 맞는 행동은 받은 문서가 정한다 [5]. 답없음 질문은 만든 뒤 실제 색인에서 검색해 청크마다 답이 없는지 확인해 확정한다 [1]. 학습 예시는 운영 입력과 같아야 한다 [6·11].
- 바꿀 것: 근거를 붙인 뒤 프롬프트에 든 근거로 종류를 다시 정한다(답 / 일부만 있음 / 거절 + 안내). 목표 답이 그 종류의 모양과 근거 대조를 통과하면 살리고, 종류별 개수는 확정된 종류로 다시 채운다.
- 버린 대안: 지금처럼 버리기 — 데스크탑 시간을 쓰고 만든 예시를 첫 묶음에서 20건(모양·청크 없음·지워진 정답 중 하나라도 걸린 수, 겹침 뺌) 버렸다. 이 중 `shape_check`(모양 검사)에만 걸리고 다른 자동 검사는 모두 통과한 것이 11건이고, 그중 10건은 목표 답 끝 줄에 `[출처 N]`이 있어 `kind`를 바꾸면 Claude 판정으로 넘길 수 있다(2026-10-26 집계, 예: `r1-c-0011` — `kind=refuse_guide`인데 근거 5·7에 답이 있어 목표 답이 "대학봉사 외에 학과봉사로도 지원이 가능합니다. [출처 5][출처 7]"). 질문 초안을 더 정교하게 해 의도를 맞추기 — 검색 결과는 초안 단계에서 알 수 없다.
- 부작용: 종류 비율이 흔들린다(문제 5와 함께 다룬다). 종류를 바꾼 예시는 목표 답을 다시 만들어야 할 수 있다(답용 질문의 거절 답에 확인처가 빠진 경우).
- 확인: 다음 묶음에서 '모양' 탈락 수와 종류별 통과율.

### 문제 2. 학생 모델(A.X)이 지금 무엇을 맞히는지 재지 않았다

- 증상: 예시마다 학습 전 A.X 답을 한 번 받아 두었지만 쓰지 않는다. A.X가 이미 맞히는 쉬운 예시와 틀리게 단정하는 예시가 같은 비중으로 들어간다.
- 원인: 설계에서 학습 전 A.X 답을 '전후 비교용'으로만 두었다(설계 §4).
- 제작사 방식: Meta는 학생 모델 답을 여러 번 뽑아 원문 대비 정답을 채점하고, 일관되게 틀리게 단정하는 질문에 거절을 가르친다 [15 §4.3.6]. 지도 학습 데이터도 최신 모델의 여러 답 중 보상 모델이 고른 것을 쓴다 [15 §4.2.2]. Qwen은 작은 모델에 교사 답 따라 쓰기 뒤 학생 답을 교사가 채점하는 단계를 더했다 [2]. NAVER Cloud 등은 여러 번 답하게 해 잰 아는 정도로 학습 비중을 조절했다 [4]. Anthropic도 같은 질문을 여러 번 돌려 답이 엇갈리면 환각 신호로 본다 [5].
- 바꿀 것(제안): 근거를 붙일 때 A.X 답을 여러 번(예: 4번) 받아 자동 검사로 채점하고 예시마다 '맞힘 수'를 기록한다. 쓰임은 셋이다. ① 다 맞히는 예시는 줄이고 틀리거나 엇갈리는 예시를 늘린다. ② 틀리게 단정한 A.X 답은 버리지 않고 '나쁜 답'으로 보관해 2회차 선호 학습(DPO)에 쓴다 — 기준 모델이 따로 필요 없다 [10]. ③ 전후 비교 때 '원래 못 맞히던 예시'를 따로 본다.
- 버린 대안: 학생 답을 교사가 토큰마다 채점하는 방식 그대로 — Gemma와 A.X의 토크나이저가 달라 토큰 단위로 맞출 수 없고, A10G 24GB에 두 모델을 함께 올리기 어렵다 [판단]. A.X 통과 답을 목표 답으로 쓰기 — 운영 A.X 답은 출처 번호를 거의 달지 않아(56개 중 1개) 목표 답 모양(ADR-0039)에 맞지 않는다.
- 부작용: 데스크탑 시간이 예시당 A.X 생성 3번분(약 7초) 늘어난다 [계산 — 응답 중앙 2.35초 × 3].
- 확인: 1회차 학습 전후에서 '원래 못 맞히던 예시'의 개선.

### 문제 3. 목표 답이 문서의 안내를 빠뜨린다

- 증상: Claude 탈락 16건 중 7건이 안내 빠짐 — 근거에 신청 방법·기한·문의처가 있는데 목표 답이 결론만 말했다.
- 원인: 목표 답 지시문(`corpus/trainset/prompts.py`)이 '있으면 이어서 쓴다'로만 적혀 있고, 안내 빠짐을 자동 검사가 못 잡아 Claude 판정에서야 걸린다.
- 제작사 방식: 모델이 못 하는 것은 그 행동을 보여 주는 예시를 더하고 [11], 채점 기준은 구체적인 규칙으로 쓰며 코드 채점을 먼저 둔다 [14].
- 바꿀 것(설계 합의 안): 지시문을 '근거의 [출처 N]에 전화번호·주소·기한·신청 경로가 있으면 결론 다음 문장에 그대로 쓴다'로 구체화하고, 같은 조건을 자동 검사로 넣어 걸린 예시는 검사 결과만 돌려주고 Gemma로 다시 쓴다. Claude 판정 이유는 Gemma에 돌려주지 않는다(ADR-0010·0040).
- 버린 대안: 초안 모델 바꾸기 — 다시 볼 조건(ADR-0040)은 지시문을 고쳐도 안 될 때다.
- 확인: 작은 묶음에서 Claude '안내 빠짐' 비율.

### 문제 4. 질문 재료의 품질 관리가 얕다

- 증상: 개인정보 수집 동의 같은 서식 청크가 질문 재료로 56개 중 5개 뽑혔다. 주제·난이도 정보 없이 청크를 고른다.
- 원인: 상투문 거르기가 줄 단위라, 문서마다 글자가 조금씩 다른 서식 글을 못 거른다.
- 제작사 방식: 주제 분류·품질 점수·난이도 점수로 예시를 고르고 [15 §4.2.3], 개인정보·중복을 거른다 [16].
- 바꿀 것(설계 합의 안): 여러 문서에 되풀이되는 글자 묶음(5-gram) 비율로 서식 청크를 거른다. 난이도는 문제 2의 A.X 맞힘 수로 대신한다.
- 확인: 다음 묶음의 서식 청크 수(0 목표).
- 2026-10-26 측정 뒤 결정: 새 거르기 규칙을 만들지 않는다. 청크 단위 반복률(5개 문서 이상에 나오는 5글자 묶음 비율)로 거르면 첫 묶음 서식 청크 6개 중 4개를 잡지만 정상 청크 4개(여러 해 모집요강 등)도 함께 버린다. 줄 단위 '거의 같은 줄'(같은 비율 0.85 이상)로 거르면 학교 문서 전체에서 2,516줄이 더 빠지는데, 접수기간·문의처 전화번호·근로장학금 시급처럼 우리가 가르치려는 안내 줄이 많았다. Meta도 줄 단위 중복 제거가 "frequent high-quality text"까지 지운다고 적었다(Llama 3 §3.1.1). 서식 문구 질문은 질문 지시문(양식 문구를 재료로 쓰지 않음)과 Claude 판정 6번(실제로 쓸 만한 질문인가)으로 거르고, 새 묶음에서 비율을 다시 잰다.
- 질문 단계 검사(`r1-c-0050`처럼 재료 청크에 없는 절차를 묻는 질문)도 새 규칙을 만들지 않는다. '답 근거가 질문에 답하는가'는 뜻을 따져야 해 규칙으로 가를 수 없고, 그런 예시는 ADR-0041의 안전장치(청크가 검색됐는데 거절하면 종류를 바꾸지 않음)로 떨어진다. 새 묶음에서 빈도를 잰다.

### 문제 5. 응답 종류 비율의 근거가 약하다

- 증상: 계획은 거절 30%·일부만 있음 10%다. 평가셋의 답없음은 14.7%(개발셋 본 18.8%)다. 학습 전 A.X는 이미 과잉 거절이 7.4%다.
- 원인: 비율을 계획 §5에서 판단으로 정했고, 이전 조사에서 30%의 출처를 원문으로 확인하지 못했다(`../research/학습셋-제작-실무조사-20261021.md` §4).
- 제작사 방식: 응답 종류 비율은 실제 사용을 따른다. 거절이 운영보다 많으면 모델이 거절을 너무 자주 한다 [11].
- 바꿀 것(제안): 운영 질문 기록이 없으니 평가셋 비율을 대신 기준으로 삼아 거절을 약 20%로 낮추는 안. 1회차에서 과잉 거절과 답없음 거절을 함께 보고 다시 정한다.
- 부작용: 답없음 거절(89.3%, 목표 90%)을 올리는 힘이 약해질 수 있다.
- 확인: 1회차 전후의 과잉 거절·답없음 거절.

### 문제 6. 데이터 양을 정하는 방법이 없다

- 증상: 1회차 200개 뒤 본 학습 규모를 '1회차 결과로 정한다'고만 적었다.
- 제작사 방식: 예시를 두 배로 늘릴 때마다 비슷하게 좋아진다고 보고, 절반과 전체를 학습해 견줘 더 모을 가치를 가늠한다 [11]. 50개의 잘 만든 예시로 시작해 평가하기를 권한다 [6].
- 바꿀 것(제안): 1회차에서 100개와 200개를 같은 설정으로 학습해 개발셋에서 견주고, 늘어나는 폭으로 2회차 규모를 정한다.
- 부작용: AWS 학습 한 번과 개발셋 생성 실행 한 번이 더 든다.

### 문제 7. 사람 표본을 방식이 굳기 전에 받으려 했다

- 증상: 문제 1~5를 고치면 데이터를 만드는 방식이 바뀌어, 지금 30개 판정은 다시 해야 한다(ADR-0037 결정 4).
- 제작사 방식: 판정 모델은 사람 판단과 꾸준히 맞는 것을 본 뒤 늘린다 [13]. 신뢰도를 먼저 시험하고 늘린다 [14].
- 바꿀 것: 방식을 고친 뒤 새 첫 묶음에서 30개를 한 번 본다. 어긋남 수에 더해 일치율과 κ(우연 일치를 뺀 일치도)를 적는다.

### 문제 8. 질문 말투가 실제 사용자와 다르다

- 증상: 첫 묶음 질문 글자 수 중앙 44자. 말투를 넷(짧은 구어체·정중체·상황 설명형·쉬운 한국어)으로 돌렸지만 모두 문서의 공식 용어를 그대로 쓴다(예: "재전기공사공제조합장학회 2025년도 제20기 장학생 선발에서 일반전형의 성적기준은 무엇인가요?"). 실제 사용자는 "전기공사 장학금 성적 기준"처럼 짧게 묻는다.
- 근거: DataMorgana(TII, ACL 2025 Industry Track)는 합성 질문이 "may not be realistic (e.g., contain too many technical terms)"라 짚고, 말투를 짧은가·긴가, 자연스러운 말인가·검색어형인가로 나눠 비율을 정한다("concise-and-natural": 평소 말하듯 쓴 10단어 미만). OpenAI는 예시를 "as realistic as possible"로 [6], Anthropic은 평가가 실제 질문 분포를 따르게 [14] 한다. 합성 질문은 사람 질문보다 표현이 덜 다양하다(Kambhatla 외, EMNLP 2025 Findings).
- 바꿀 것(제안): 말투에 검색어형·15자 안팎 줄임 구어를 더하고 비율을 정한다. 사용자가 모를 공식 명칭을 베끼지 않게 지시하고 글자 수 상한을 둔다. 많이 묻는 주제는 학교 FAQ 문서를 질문 재료로 더 자주 뽑아 대신하고, 운영(M6) 뒤 실제 질문 기록을 더한다. 평가셋에도 같은 말투 문항을 넣어 효과를 잰다.
- 조심: 줄임말 질문은 검색이 근거를 못 찾을 수 있다(생성 학습으로는 안 고쳐짐 — ADR-0041에 따라 '못 찾으면 거절' 예시가 된다). Gemma의 '요즘 말투'가 어색한지는 사람 표본에서 본다.
- 초안 모델을 Claude·GPT·Gemini로 바꾸는 안은 버렸다 — 세 회사 약관 모두 출력으로 경쟁 모델을 개발하는 것을 금하고(해석 위험을 운영할 학교가 진다), Claude는 평가셋 초안·판정을 맡고 있어 채점이 편든다(Li 외 "Preference Leakage", ICLR 2026). ADR-0040 그대로.

## 6. 이 점검에서 배운 것

- 버린 예시의 사유를 세어 보니, 하나하나의 실수가 아니라 '의도한 상황과 실제 입력이 다르다'는 한 뿌리였다. 실패를 사유별로 세는 것이 고칠 곳을 찾는 가장 빠른 방법이었다.
- 제작사들은 학생 모델이 실제로 무엇을 아는지부터 잰다. 우리는 '좋은 답'만 만들고 '누가 배우는가'를 보지 않았다.
- 정답 종류는 모델이 실제로 받는 입력으로 정해야 한다. 만드는 사람의 의도(질문 재료 청크 하나)로 정하면 학습 입력(근거 8개)과 정답이 어긋난다 — 학습-운영 불일치(training-serving skew)를 데이터 단계에서 만난 것이다(ADR-0041).
- 설계 때의 가정("질문 재료 청크에 없으면 학교 문서 전체에도 없다")을 측정으로 확인하지 않았다. 학교 문서는 규정·시행세칙처럼 같은 내용이 여러 곳에 있다.
- 근거 자료는 심사 통과 논문과 모델 제작사 공식 자료로 좁혔다. 최신 프리프린트와 블로그는 빠르지만, 조사 초안에서 학회 표기·저자·약어가 틀린 것이 여러 번 나왔다.
