# M2 2단계 — 근거 개수(상위 k) 5·8·10 비교 (Gemma 4 12B·순위 융합, 2026-10-15)

> 생성 모델에 넣는 근거 청크 수를 정하기 위해, 같은 개발셋을 상위 5·8·10개로 돌려 같은 문항끼리 비교했다. 채택 기준은 실험 전에 설계 문서에 정해 둔 것을 그대로 쓴다.
> 관련: `검색개선-설계-20261014.md` §3 2단계, 1단계 보고서 `1단계-순위융합-운영전환-20261015.md`, ADR-0025(짝 비교)·ADR-0026(목표)

## 1. 결론

- **상위 8개가 채택 기준을 만족하는 가장 작은 k다.** 상위 5개 대비 정답률 76.9% → 83.5%(2 / 10, p=0.039), 과잉 거절 18.2% → 10.7%(p=0.012), 출처 정확도 90.9% → 95.9%(p=0.031)로 의미 있게 나아졌고, 오답률은 0.7% → 1.3%로 같은 수준(1 / 2, p=1.0)이다. 응답 시간 상위 5%도 상위 5개보다 짧다(9.16초 대 11.24초). [실측]
- 상위 10개는 상위 8개와 모든 지표가 같은 수준이고(정답률 83.5% 대 82.6%), 상위 5개 대비 정답률은 같은 수준(p=0.12)이다. 근거를 더 넣어도 더 나아지지 않았다. [실측]
- 근거 강도(§6): 정답 근거가 프롬프트에 들어간 문항 106 → 112(판정과 무관, 줄어든 문항 0)와 과잉 거절 감소(p=0.012)는 확실하다. 정답률 향상(p=0.039)은 판정 하나에 흔들리는 경계선이라 '오르는 방향'으로만 말한다. 확신도 중간.
- 개발셋 값이다. 성공 기준 판정은 M2 끝 테스트셋으로 한다.

- 판정: 애매 상위 8개 18건·상위 10개 23건을 본 세션이 판정 지침으로 전수 판정(`Assets/eval/work/packets/s2-k*-gemma4-12b`). 상위 10개의 판정이 갈릴 수 있던 두 건 — 연계교육 문항(ev-0108)은 정답 학과·인원을 말했지만 다른 학과의 "연계교육 모집 정원 50명"을 지어 붙여 틀림, 자기소개서 첨삭 문항(ev-0296)은 정답 대신 문서에 있는 첨삭 컨설턴트를 안내해 일부.

## 6. 근거 강도 — 무엇은 확실하고 무엇은 경계선인가

상위 8개를 추천하는 근거를 강도별로 나눈다. 설득에 쓸 때는 1·2를 앞에 두고, 3은 '방향'으로만 말한다.

### 1) 판정과 무관하게 확실한 것 [실측]

- **정답 근거가 프롬프트에 더 들어간다.** 정답 청크가 생성 모델이 받은 프롬프트(문맥)에 있었던 문항: 상위 5개 106 → 상위 8개 112 / 121. 5개에만 있던 문항 0, 8개에만 있던 문항 6(p=0.031). 실행 기록의 단계별 후보를 채점기 규칙(`stage_hits`)으로 센 값이라 사람·Claude 판정이 들어가지 않는다.
- **실패 원인이 예상한 곳에서 줄었다.** 못 맞힌 문항 중 '후보 탈락'(정답 청크를 찾았는데 상위 k 밖으로 밀림) 14 → 6. 생성 실패는 9 → 9로 그대로다. 근거 수를 늘린 효과가 겨냥한 실패 유형에서만 나타났다.

### 2) 판정이 들어가지만 강한 것 [실측]

- **"모른다"는 답이 줄었다.** 과잉 거절 22 → 13 / 121(갈린 문항 10 / 1, p=0.012). 성공 기준 목표(20% 이하, ADR-0026)를 5개(18.2%)는 아슬아슬하게, 8개(10.7%)는 여유 있게 넘는다.
- **틀린 답은 늘지 않았다.** 오답률 0.7% → 1.3%(1 / 2, p=1.0). 늘어난 한 건(ev-0116)은 규칙 채점이 확정한 것으로, 판정 지침으로는 맞음이다(§3).

### 3) 방향은 같지만 통계로는 경계선인 것 [실측·계산]

- 정답률 76.9% → 83.5%, 차이 +6.6%p(95% 신뢰구간 1.1~12.1%p, 짝 비율 차 Wald), 갈린 문항 2 / 10, p=0.039.
- 경계선인 이유:
  - 판정 하나만 바뀌어도(2 / 9 또는 3 / 10) p=0.065·0.092로 기준(0.05)을 넘는다.
  - 상위 8·10개를 각각 5개와 비교했으므로 두 번 비교 보정(본페로니, 0.05 / 2 = 0.025)을 하면 정답률은 기준을 넘지 못한다(과잉 거절 p=0.012는 넘는다).
  - Claude 판정을 빼고 규칙 채점만으로 세면(애매는 맞음 아님) 88 → 94, 3 / 9, p=0.146 — 방향은 같고 의미 있는 차이는 아니다.
  - 같은 설정을 두 번 돌린 결과(E3 생성만 ↔ 1단계 실시간)도 0 / 3문항이 갈렸다. 한 번 실행끼리 비교할 때 3문항 정도는 흔들릴 수 있다.
- 그래서 "정답률이 6.6%p 오른다"가 아니라 **"정답 근거가 더 들어가고 '모른다'는 답이 줄며, 정답률도 오르는 방향"**으로 말한다.

### 4) 실제로 갈린 12문항 [실측]

상위 5개와 8개의 결과가 갈린 문항을 하나씩 열어 봤다(개발셋 본 문항, 판정은 §2).

| 바뀜 | 문항 수 | 내용 |
|---|---|---|
| 모름 → 맞음, 정답 청크가 8개에서 새로 프롬프트에 들어옴 | 5 | 면접학과 원서비 합계, 학과 모집 정원(2건), 은행 계좌 등록 방법, 2학기 등록금 납부 시기 — 5개일 때는 "확인할 수 없다" |
| 모름 → 맞음, 정답 청크는 5개에도 있었음 | 2 | 휴학생 장학금 신청 가능 여부, 자유전공학부 학과 선택 범위 — 근거가 늘자 결론을 단정 |
| 일부 → 맞음 | 3 | 면접 진행 순서(도착 시각 추가), 학과 실습실 목록(빠진 실습실 채움), 예비군 버스 신청 전 전입신청 |
| 맞음 → 일부 | 2 | 최대 6개 학기 지원 장학금 둘 중 하나를 빠뜨림, 신입생 첫 학기 휴학을 "허가하지 않는다" 대신 "제한된다"로 약하게 말함 |

- 좋아진 10문항 중 7문항이 '모른다'에서 '맞음'으로 바뀌었다 — 과잉 거절 감소(위 2)와 같은 현상이다. 그중 5문항은 정답 청크가 새로 프롬프트에 들어온 문항이라, 근거 수를 늘린 효과가 직접 보인다.
- 나빠진 2문항은 근거가 늘면서 답이 짧아지거나 표현이 약해진 경우로, 틀린 값을 단정한 것은 아니다.

### 5) 이론 근거 [원문]

- Databricks, "Long Context RAG Performance of LLMs"(2024-08-12): 검색 문서를 늘리면 재현율은 오르지만 "Longer context is not always optimal for RAG" — 모델마다 특정 길이 뒤 품질이 떨어진다. 검색 개수는 생성 모델과 작업에 맞춰 정한다. → 상위 10개가 8개보다 나아지지 않은 결과(같은 수준, 프롬프트 중앙 4,557 → 5,522토큰)와 맞고, '기준을 넘는 가장 작은 k'를 고르는 이유다.
- Liu 외, "Lost in the Middle"(TACL): 관련 정보가 긴 입력의 중간에 있으면 성능이 크게 떨어진다. → 근거를 많이 넣을수록 정답 근거가 중간에 놓일 수 있어 무작정 늘리지 않는다. 재순위(3단계)로 정답 근거를 앞으로 당기면 적은 k로도 같은 효과를 낼 수 있다.
- 출처 원문 확인: `docs/rag/research/검색개선-근거조사-20261014.md` §2-2.

### 6) 결론과 확신도

- **추천 유지: 상위 8개.** 미리 정한 기준(정답률 p<0.05 · 오답·과잉 거절 비악화 · 응답 1.5배 이하)을 통과한 가장 작은 k이고, 판정과 무관한 근거(정답 근거 포함 +6, 후보 탈락 14 → 6)와 강한 근거(과잉 거절 p=0.012)가 같은 방향이다. 바꾸는 비용이 작고(설정값, 응답 중앙 +0.25초) 되돌리기 쉽다.
- **확신도: 중간.** 정답률 향상 크기는 경계선이다.
- **확인 시점:** ① M2 3단계(재순위)를 채택하면 k를 다시 잰다(재순위 뒤 상위 5개가 순위 융합 상위 10개와 비슷했음, R1) ② M2 끝 테스트셋에서 한 번 확인한다(ADR-0018) ③ 그 사이 같은 설정을 한 번 더 돌리면 한 번 실행의 흔들림 폭을 줄일 수 있다(데스크탑 약 20분).
