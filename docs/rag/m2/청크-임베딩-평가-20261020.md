# 임베딩·청킹·청크 평가와 A.X 학습의 목표 (M2, 2026-10-20)

> 사용자 질문(2026-10-20): "A.X를 학습시켜서 무슨 결과를 얻으려는가? 지금 임베딩·청킹 방식과 청크를 평가해 봐."
> 자료: 서비스 색인(데스크탑 Chroma, 문서 698개, 읽기만 함), 지금 운영 설정 실행 `20261016-exp-s3-scores-gemma4-12b`(순위 융합·근거 8개·재순위 꺼짐, 개발셋 205문항), 이번에 새로 잰 질문 임베딩 비교(개발셋 답 있는 177문항). **개발셋만** 썼다(ADR-0018).
> 스크립트·결과(로컬, 커밋 안 함): `Assets/eval/work/m2/chunk_stats.py`·`chunk_stats.out`(색인 통계), `vector_instr.py`·`score_vi.py`(질문 지시문 비교).
> 관련: ADR-0033(학습 필수), ADR-0010(학습 데이터는 서비스 파이프라인을 거친 결과로), `A.X-기준-계획-20261017.md` §4·§5, `실패원인-분석-20261014.md`, `3단계-재순위-점수결합-20261016.md` §4

## 1. 결론

1. **임베딩은 문제가 아니다.** 벡터 검색만으로 정답 청크가 상위 8개에 드는 문항이 본 121 중 114, 상위 20개면 120이다. 모델 카드가 권하는 질문 지시문을 붙여도 114 → 117(갈린 문항 1 / 4, p=0.375)로 같은 수준이다. [실측·원문]
2. **정답 근거가 프롬프트에 못 들어간 9문항 중 검색이 놓친 것은 없다.** 9문항 모두 검색 단계 후보에 정답 청크가 있었다. 5문항은 정답 청크가 근거 8개 안(1·1·2·2·8위)에 들었는데 **프롬프트를 만들 때 원문을 빼고 발췌만 남기는 규칙**이 답을 지웠다. 2문항은 청크 글에 문서 제목(학과 이름)이 없어 벡터 순위가 낮았고, 2문항은 벡터 1·3위였는데 순위 융합의 같은 점수 처리에서 밀렸다. [실측·코드]
3. **프롬프트의 근거 블록 1,640개 중 967개(59%)가 원문 없이 발췌만 들어간다.** 정답 근거가 프롬프트에 있는데 틀린 11문항 중 8문항도 정답 문서 블록(전부 또는 일부)이 발췌만이다 — 원인인지는 아직 모른다. [실측·판단]
4. **청크 모양의 약점**: 300자 미만 청크 36%, 글자가 거의 없는 청크 10%(대부분 HTML 제목만), 제목 경로 머리말이 없는 검색용 청크 30%(HWP 141 / 142, HTML 38%), 문서 제목은 어느 청크에도 붙이지 않음, 같은 글 반복(교통 안내 29벌 등). 표 사실은 색인 항목의 93%이고 한 PDF가 그 54%, 칸 단위 표 사실의 58%가 행을 가릴 수 없다. [실측·코드]
5. **계획에 주는 것**: 학습 데이터는 서비스 프롬프트 형식 그대로 만든다(ADR-0010). 발췌 규칙·청크 머리말·표 사실 형식은 그 형식의 일부이므로 **학습 데이터 전에 정해야 한다.** 그때 계획은 표 행 단위 색인을 학습과 나란히 두어, 학습한 프롬프트와 운영 프롬프트가 어긋날 수 있었다. → §7(2026-10-20 사용자 결정으로 계획을 고침)

## 2. A.X를 학습시켜 얻으려는 것

결정 원문: ADR-0033 결정 1·2, 계획 §5. [원문]

| 가르칠 행동 | 지금 숫자(A.X, 근거 5개 프롬프트, 2026-10-14) | 운영 채택의 선(ADR-0026·0033) |
|---|---|---|
| 근거로만 답하기(근거 줄 인용 → 결론) | 틀린 답 10 / 149(Gemma 1). 근거 없이 답함 3 · 표 잘못 읽음 5 · 글 잘못 읽음 2 | 오답률 5% 이하, 학습 전보다 의미 있게 늘지 않음 |
| 근거가 없으면 거절 + 문서의 문의처·방법 안내 | 답없음 거절 82.1% · 안내 충실도 48.0% | 답없음 거절 90% 이상 · 안내 충실도 50%(보조) |
| 표의 행·열을 맞춰 값 읽기 | 위 틀린 답 중 5 | (오답률에 포함) |

- 그 밖의 결과: 학교가 준 학습 서버를 목적대로 쓰고, 학교 제안 때 "학교 문서로 학습한 모델"을 근거로 낸다. 작은 모델(4비트 약 4.4GB, 생성 약 2배 빠름)을 운영 모델로 쓸 수 있게 된다. [원문, ADR-0033·0034]
- 학습이 고치지 못하는 것: **정답 근거가 프롬프트에 없는 실패**. 모델은 프롬프트에 없는 사실을 맞힐 수 없다(문맥에 없을 때 모델 열 개 모두 1~2 / 45, `실패원인-분석` §7). 이 몫은 아래 §3~§6이 다룬다. [실측]

| 항목 | 지금 | 평가 |
|---|---|---|
| 모델 | Qwen3-Embedding-4B, Ollama `qwen3-embedding:4b`(Q4_K_M, 2,560차원, 모델 최대 문맥 40,960) | [실측 `ollama show`] |
| 임베딩 문맥 | 2,048토큰. 넘는 글 1개(2,907자, 끝이 잘림) | 영향 작음 [실측] |
| 질문 지시문 | 질문 글을 그대로 임베딩(`_embed_texts([question])`) | 모델 카드는 붙이라고 권함. 실측 차이는 같은 수준(아래) [코드·원문·실측] |
| 벡터만 상위 k 정답 청크(본 121) | 상위 3: 100 · 5: 109 · 8: 114 · 10: 117 · 20: 120 | 3단계 보고서 §4 값(114)과 같음 — 재현 [실측] |

모델 카드 원문(https://huggingface.co/Qwen/Qwen3-Embedding-4B, 2026-10-20 확인): "not using an `instruct` on the query side can lead to a drop in retrieval performance by approximately 1% to 5%", 문서 쪽은 "No need to add instruction for retrieval documents", 지시문은 영어로 쓰라고 권함.

질문 지시문 비교(개발셋 답 있는 177문항, 색인은 그대로 두고 질문 임베딩만 바꿈, 벡터 검색 결과의 지금 순서, 정답 판단은 채점기와 같음):

| 질문 임베딩 | 본 상위 3 | 상위 5 | 상위 8 | 상위 10 | 상위 8 짝 비교(지시문 없음만 / 이 방식만, p) |
|---|---|---|---|---|---|
| 지시문 없음(지금) | 100 | 109 | 114 | 117 | 기준 |
| 지시문 없음, 한 번 더 | 100 | 109 | 114 | 117 | 0 / 0 (후보 순서 177 / 177 같음) |
| 모델 카드 예시 지시문 | 99 | 111 | 117 | 119 | 1 / 4, p=0.375 |
| 학교 문서용 지시문 | 94 | 109 | 115 | 118 | 4 / 5, p=1.0 |

- 쉬운 56문항은 상위 5 이상에서 모두 56. [실측]
- 판단: 지시문은 방향상 +3이지만 의미 있는 차이가 아니고, 학교 문서용 문구는 상위 3에서 방향상 낮다(9 / 3, p=0.146, 같은 수준). 지금 바꿀 이유가 약하다. 임베딩 모델 교체(KURE-v1 등)도 벡터가 정답을 이미 상위 20에 120 / 121 넣으므로 계획대로 조건부로 둔다. [판단]
- 덤: 데스크탑을 켠 뒤 한 번 미리 임베딩하고 같은 질문을 두 번 돌렸을 때 벡터 후보 순서가 177 / 177 같았다. 계획 1단계(첫 임베딩 흔들림) 때 참고한다. [실측]

## 6. 남은 실패의 원인 다시 나누기 (개발셋 본, 지금 운영 설정)

정답 근거가 프롬프트에 없던 9문항(계획 §1의 '검색 쪽 9'):

| 원인 | 문항 | 고칠 곳 |
|---|---|---|
| 정답 청크가 근거 8개 안에 들었는데 발췌 규칙이 답을 지움 | 5 (ev-0031·0070·0072·0110·0127, 순위 8·2·1·2·1) | 프롬프트 근거 블록 만들기 |
| 청크에 문서 제목(학과)이 없어 벡터 순위가 낮음 | 2 (ev-0017 13위, ev-0079 8위) | 청크 머리말 |
| 벡터 1·3위였는데 순위 융합에서 BM25 상위 후보에 밀림(같은 점수면 BM25 쪽이 먼저) | 2 (ev-0092·ev-0021) | 재순위(계획 2단계) |

- 9문항 모두 검색 단계 후보에는 정답 청크가 있었다 → 검색이 못 찾은 문항은 0. [실측]
- 정답 근거가 프롬프트에 있는데 틀린 11문항 중 8문항은 정답 문서 블록이 전부 또는 일부 발췌만이다(전부 발췌 6 · 일부 2 · 원문 1 · 정답 문서 블록 없음 2). 발췌가 표의 머리 행을 떨어뜨려 값을 잘못 읽게 하는지는 실험으로 본다. [실측·판단]

## 7. 계획에 주는 것 — 결정 (2026-10-20 사용자)

- 근거: ADR-0010 "학습 데이터는 서비스 파이프라인을 거친 결과로 만든다(같은 로더·청킹·프롬프트)". [원문]
- 결정: 학습 데이터 전에 **프롬프트에 들어가는 근거의 모양**을 정한다 — ① 발췌만 남기는 규칙을 끄고 원문을 넣기(4단계 프롬프트 단계에 포함) ② 검색용 청크에 문서 제목 머리말 ③ 표 행 단위 색인. ②·③은 재색인 한 번으로 묶어 새 5단계(옛 8단계)로 두고, 학습 데이터·학습 회차는 6·7·8단계로 밀었다(`A.X-기준-계획-20261017.md` §4). 셋 다 학과·금액 조건문이 아니라 구조 계약이다. [판단]
- 근거 블록은 이미 `문서: 파일 이름` 줄을 보여 주므로, 문서 제목 머리말은 프롬프트보다 검색(임베딩·BM25)에 쓰는 글을 바꾸는 일이다. 그래서 재색인이 드는 ③과 같은 단계에 둔다. [코드·판단]
- 버린 안: 지금 순서대로 학습과 표 색인을 나란히 — 학습한 프롬프트와 운영 프롬프트가 달라져 학습 효과를 운영에서 잴 수 없다. 임베딩 교체·지시문 — 실측 차이가 같은 수준. [판단·실측]
- 확신도: 높음(발췌 규칙이 정답을 지운 5문항은 직접 확인), 중간(발췌를 끄면 틀린 답이 줄어드는지, 프롬프트가 길어져 생기는 부작용). 검증 시점: 4단계(원문 넣기)·5단계(색인 글 형식) 개발셋 실행.

## 8. 재는 법과 한계

- 색인 통계는 Chroma의 세 컬렉션을 페이지로 나눠 모두 읽어 셌다(쓰기 없음). '글자 50자 미만'·'파일 이름 앞 12자'는 대략의 지표다.
- 질문 지시문 비교는 AI 서버의 벡터 검색 함수를 그대로 불렀고(요약 청크 20 + 원문 청크 20, 표 사실은 부모 청크로 펼침), 정답 판단은 채점기 함수(`_covers`, 허용 근거 문서)다. 생성은 돌리지 않았다.
- 실패 원인은 실행 기록의 단계별 후보와 프롬프트 글로 문항마다 확인했다. 개발셋 121문항 기준이라 문항 하나가 0.8%p다.
