# M2 5단계 — 색인 글 형식: 문서 제목 머리말과 PDF 표 행 단위 (2026-10-21)

> 계획: `A.X-기준-계획-20261017.md` §4 5단계. 설계 원본: `검색개선-설계-20261014.md` §3 '4단계 — 표 사실 행 단위 직렬화', 근거: `청크-임베딩-평가-20261020.md`(문서 제목 없는 청크, 표 칸 사실 58% 행 모호). 채택 규칙: ADR-0035(보완 2 — 이 단계 실행 전에 적음).
> 실행(로컬, 커밋 안 함): BM25 제목만 `Assets/eval/runs/20261020-m2-s5-bm25title-ax`, 새 색인 `20261021-m2-s5-index-ax`(색인 이름 `s5-20261021-34bce94`, 재색인 전 백업 `20261021-001137`). 기준선: `20261020-m2-s2-ax-off`(2단계, A.X·재순위 끔). 분석 스크립트 `Assets/eval/work/m2/s5/`, `Assets/eval/work/m2/s5_power.py`.

## 1. 결론

1. **미채택이다(ADR-0035, 실행 전에 정한 주 지표).** 정답 청크가 순위 융합 상위 5개 안에 든 문항이 102 → 105 / 121(기준선만 3 / 5단계만 6, p=0.51)로 의미 있게 좋아지지 않았다. [실측]
2. **답 지표는 모두 같은 수준이지만 방향이 나쁘다**: 정답률 76.9 → 74.4%(6 / 3, p=0.51), 오답률 6.0 → 9.4%(2 / 7, p=0.18), 근거 8개 안 정답 청크 112 → 108(7 / 3, p=0.34). 답없음 거절 89.3%·과잉 거절 7.4%는 같다. 안내 충실도(본+쉬운 63)는 47.6 → 49.2%. [실측]
3. **겨냥한 두 문항이 고쳐지지 않았다**: 문서 제목이 없어 순위가 낮다고 본 ev-0017(전자공학과 디지털공학)·ev-0079(화학생명공학과 단위조작)는 20 → 17위, 14 → 13위에 그쳤다. 같은 학과의 다른 페이지도 모두 같은 학과 이름 제목을 갖게 되어 제목이 그 학과 안에서는 페이지를 가르지 못한다. '제목 없음'이 원인이라는 2026-10-20 분석은 이 두 문항에 대해 틀렸다. [실측·판단]
4. **부작용 두 가지**: ① 해마다 비슷한 문서의 제목('2022~2026학년도 지원/성적현황')이 '학년도·전형' 질문과 겹쳐 모집요강 청크를 밀어냈다(ev-0110·0142, BM25 제목만 바꾼 실행에서도 같음). ② 재색인 뒤 근거 8개 밖으로 밀린 PDF 표 문항(ev-0230 안전진단 가스안전 1등급 5 → 10위, ev-0031·0161 모집요강 7·8 → 9위)은 표 사실이 5,270개 늘어난 경쟁과 함께 나타났다 — ev-0230은 그 결과 '0개소'로 틀렸다. [실측·판단]
5. **색인 글 지표는 목표대로 바뀌었다**: 머리말 없는 검색용 청크 30% → 0%, 같은 표의 다른 행·이름이 같은 다른 표 때문에 생긴 표 칸 사실 모호 44% → 0.07%(남은 14%는 열 이름 겹침, §5). 형식은 고쳤지만 그것이 이 단계의 주 지표(검색)를 움직이지 못했다. [실측]

## 2. 바꾼 것 [코드]

| 자리 | 전 | 후 |
|---|---|---|
| 검색용 청크(벡터 검색에 쓰는 글) | 믿을 수 있는 제목 경로가 있을 때만 머리말(30%는 머리말 없음), 문서 제목 없음 | 문서 제목 줄 + 제목 경로 줄. 제목 경로 첫 칸이 문서 제목과 같으면 한 번만 |
| BM25 채점 글 | 제목 경로 두 번 + 본문 | 같은 머리말(문서 제목 + 제목 경로) + 제목 경로 + 본문 — 제목 경로 가중은 그대로 |
| 재순위로 보내는 글(지금은 꺼짐) | 본문 앞 1,200자 | 같은 머리말 + 본문, 앞 1,200자 |
| PDF 표 칸 사실 문장 | `표 이름: 첫 칸 행 정보는 (행 경로=…;) 열=값이다.` | `표 이름: 행 경로 행 정보는 열=값이다.` — 행 경로는 같은 표 안에서 행을 유일하게 가리는 머리 칸 경로 |
| 행 경로 | 묶음 행 + 첫 칸(병합 칸이면 여러 행이 같음) | 경로가 같은 행끼리는 그 행들을 가르는 가장 왼쪽 열의 값을 붙여 나간다. 병합 칸 글이 단어째 되풀이되면 한 번으로 |
| 표 이름 | 표 제목(없으면 문서 제목 경로, 그것도 없으면 '문서 표') | 한 문서에서 이름이 같은 표가 둘 이상이면 뒤에 `(17쪽 표)`, 같은 쪽이면 `(18쪽 표 1)` |
| PDF 표 행 문장 | 없음(칸 하나에 문장 하나만) | 칸 사실이 둘 이상인 행마다 `표 이름: 행 경로 행 정보는 열=값; 열=값이다.` 한 문장을 표 사실로 함께 색인(420자에서 자름, 마크다운 표의 행 사실과 같은 글 표 사실) |

- 문서 제목은 업로드 파일 이름에서 확장자를 뗀 것이다. 업로드 파일 이름은 문서 대장 제목으로 만든다(`corpus upload`). 학과·표 이름을 보는 조건문은 없다(구조 계약).
- 예(가나대학 합성 테스트): 첫 칸 '생활비'가 세 행에 병합된 장학금 표의 금액 칸이 `가나대학 장학금 요약표: 생활비 행 정보는 장학 금액=1.5이다.`에서 `가나대학 장학금 요약표: 생활비 > 3. 마바 장학 행 정보는 장학 금액=1.5이다.`로 바뀐다.
- 코드와 테스트는 develop에 넣지 않고 브랜치 `exp/m2-s5-index-text`에 보관한다(§8). 테스트: `ai-server/tests/test_index_text_format.py`(10개), 기존 점검 스크립트 `check_opendataloader_json_indexing.py`를 새 문장 형식으로. 전체 110개 통과. 커밋 뒤 동작 7가지(문서 제목 빈 값·행 경로 안 늘림·같은 이름 표 안 가름·행 문장 안 만듦·재순위 글 머리말 없음·BM25 글 제목 없음·되풀이 낱말 그대로)를 하나씩 망가뜨려 모두 테스트가 잡는 것을 확인했다.

## 5. 남긴 문제 — 한 행 안의 열 이름 겹침

- 열 이름이 겹치는 표 190개 중 175개가 실습실 정밀안전진단 결과보고서(대장에서 평가 몫) 한 문서다. 실습실별 세부 표는 머리 행과 값 행이 번갈아 나오는 서식형('점검분야' 행 아래 '부적합 건수' 행)이고, 요약표는 '등급' 아래 머리 행이 숫자(1·2·3)라 첫 행만 열 이름으로 읽는 지금 해석으로는 어느 열의 값인지 잃는다. [실측]
- 결정(2026-10-20 사용자): 이번 재색인에 넣지 않는다. 다른 문제(열·서식 해석)라 따로 설계하고, 평가 몫 문서라 학습 데이터 형식(6단계)에는 영향이 없다. 버린 안: 이번에 함께 고침 — 재색인을 한 번 아끼지만 새 구조 규칙을 설계·검증해야 하고 세 변경이 섞여 5단계 효과를 설명하기 어렵다.

## 6. 재는 법

- 데스크탑, 이 브랜치, A.X 4.0 Light · 순위 융합 · 근거 8개 · 생성 문맥 12,288 · 재순위 끔 · 온도 0. 평가셋 v3, 개발셋 205문항(본 149 + 쉬운 56).
- BM25 제목만: 새 코드를 지금 색인 그대로에 올려 실행(BM25 글은 질문할 때 만들어 재색인이 필요 없다). 검색용 청크·표 사실은 옛 형식 그대로다.
- 재색인: 백엔드 DB와 문서 번호는 그대로 두고 AI 서버에서만 문서마다 색인 항목을 지우고(`DELETE /documents/{id}`) 같은 원본 파일과 같은 대장 정보로 다시 처리(`POST /documents`, 백엔드가 보내는 칸과 같음). 지우기 전에 문서마다 파일 이름·대장 정보·항목 수를 스냅샷으로 남기고, 원본 파일 698개는 대장의 SHA256과 같은 것을 확인했다.
- 재색인 결과 [실측]: 698개 문서 모두 성공, 54.2분(2026-10-04 첫 색인 43.9분). 가장 큰 문서(실습실 정밀안전진단 결과보고서)가 1,095초(전 825초). 항목 수가 맥북 재현 예측과 같다 — documents 54,354(원문 청크 3,206 + 표 사실 51,148) · retrieval_chunks 3,206 · source_blocks 3,654. 문서마다 원문 청크 수와 대장 정보(파일 이름·ledger_id·출처 주소·게시일·학년도·카테고리)가 재색인 전과 같다.
- 재색인 중 Ollama 로그에서 색인 임베딩도 입력 캐시를 다시 쓰는 것(`cached n_tokens = 103`)이 보였다. 앞부분이 같은 글을 이어서 받으면 생긴다(1단계 '질문 임베딩 흔들림'과 같은 원인). 문서 제목 머리말로 같은 문서의 청크가 같은 줄로 시작해 재사용이 늘 수 있다. 차이는 코사인 거리 약 0.0003 수준이라 이번 비교를 막지는 않지만, 같은 문서를 다시 색인하면 벡터가 미세하게 다른 이유 중 하나다(`docs/development/알려진-문제.md`).

## 8. 판정 (ADR-0035)

| 묶음 | 주 지표(상위 5) | 정답률 | 오답률 | 운영 조건 | 판정 |
|---|---|---|---|---|---|
| 문서 제목 머리말 + 표 행 단위 | 같은 수준(3 / 6, p=0.51) | 같은 수준(나쁜 쪽) | 같은 수준(나쁜 쪽) | 실패 0, 잘림 0, GPU 그대로 | **미채택 — 운영은 2단계 기준선 그대로, 5단계 닫음(2026-10-21 사용자 결정)** |

- 처리: 데스크탑 색인을 재색인 전 백업(`20261021-001137`)으로 되돌리고 develop 코드로 복귀한다(데스크탑이 꺼져 있어 다음에 켤 때 — 되돌리기 전에 5단계 색인도 백업해 둔다). 5단계 코드는 develop에 넣지 않고 브랜치 `exp/m2-s5-index-text`에 보관한다.
- 학습 데이터(6단계)는 운영 형식(2단계 기준선)으로 만든다. 표 칸 사실의 행 모호가 프롬프트에 남으므로, 자동 검수에서 정답이 모호한 표 근거(같은 표 이름·행 이름·열에 값이 여럿)에만 기대는 예시를 걸러 '표의 행·열을 맞춰 값 읽기'(계획 §5 ③)를 틀린 정답으로 가르치지 않게 한다.
- 버린 안: 표 행 경로만 다시 재기 — 칸 사실 문장만 바꾸면 검색 경쟁 부작용은 줄겠지만, 검색 지표로는 겨냥 문항이 적어 이번처럼 p<0.05에 닿기 어렵고, 채택하려면 '형식 결함 수정은 나빠지지 않으면 채택' 같은 규칙을 새로 정해야 한다. 미리 정한 규칙대로 닫았다.
- 확신도: 높음(주 지표가 움직이지 않음, 겨냥한 두 문항이 그대로), 중간(부작용의 몫 나누기 — 묶음으로만 쟀다). 다시 볼 조건: 학습 뒤에도 표 읽기 틀림이 남으면 표 행 경로만 따로 재는 안을 다시 본다.
