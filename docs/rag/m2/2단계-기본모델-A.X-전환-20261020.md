# M2 2단계 마무리 — 운영 기본 생성 모델을 A.X 4.0 Light로 (2026-10-20)

> 계획: `A.X-기준-계획-20261017.md` §4 2단계의 남은 일. 결정: ADR-0034 결정 4(기본 모델은 A.X 새 기준선을 잰 뒤 바꿈), ADR-0036(공개 목록에 없는 모델은 변환 스크립트로 등록, 모델 준비 단계는 이미 등록된 모델을 내려받지 않음). 측정 근거: `2단계-A.X-새기준선-20261020.md`.

## 1. 결론

1. 운영 기본 생성 모델이 Gemma 4 12B에서 A.X 4.0 Light(`ax40light:q4km`)로 바뀌었다. AI 서버 코드·compose·데스크탑 compose·환경 예시 네 곳의 기본값이 같고, 테스트가 이를 지킨다. [실측]
2. 데스크탑 compose가 우회(`--no-deps`) 없이 A.X로 뜬다. 모델 준비 단계 둘이 "등록돼 있음, 내려받지 않음"을 남기고 끝났고, AI 서버 시작 기록이 `llm_model=ax40light:q4km`이다. A.X(5.2GB)와 임베딩(4.1GB)이 100% GPU에 올라갔다(GPU 9,665 / 12,282MiB). [실측]
3. A.X 변환·등록 절차가 저장소(`deploy/models/`)로 옮겨졌다. 스크립트로 공식 원본부터 다시 만든 파일의 SHA256이 2026-10-01 파일과 같았고(`a1681e9b…f35b`), 다시 등록한 모델의 채팅 틀은 입력 토큰 수가 공식 틀과 같았다(6). 다른 사람이 같은 모델을 다시 만들 수 있다. [실측]
4. A.X는 개발셋에서 운영 채택의 선(오답률 5% 이하·답없음 거절 90% 이상, ADR-0033)을 아직 조금 넘지 못한다(오답률 6.0%, 답없음 거절 89.3%). 이번 변경은 그 선의 판정이 아니라 ADR-0034 결정 3·4(앞으로의 M2 실험과 기본값은 A.X)를 따른 것이다. 4단계(프롬프트)와 학습이 이 몫을 겨냥한다. [실측·판단]

## 3. 확인한 것 [실측]

| 확인 | 방법 | 결과 |

| 모델 준비 단계의 세 경우 | 맥북: 같은 정의를 맥북 Ollama에 붙여 실행 / 데스크탑: compose 올리기 | 있는 모델은 건너뜀(종료 0), 공개 목록에 없는 이름은 안내 메시지와 함께 실패(종료 1), 데스크탑에서 두 단계 모두 건너뜀 |
| 다시 만들 수 있는가 | 데스크탑에서 새 볼륨에 `convert.sh` 실행 | 원본 내려받기 포함 약 8분, 16비트 13,847MiB → Q4_K_M 4,226MiB, SHA256 2026-10-01과 같음 |
| 등록·채팅 틀 | 다시 만든 파일을 시험용 이름으로 `import.sh` | 입력 토큰 6(공식 틀과 같음), 등록된 파일 지문이 지금 쓰는 `ax40light:q4km`과 같음, 틀·설정 같음. 같은 이름(`ax40light:q4km`)에는 덮어쓰지 않고 멈춤 |
| 기본값 일치 테스트 | 네 파일을 하나씩 다른 이름으로 바꿈(변이 확인) | 네 경우 모두 실패로 잡음 |
| AI 서버 테스트 | 맥북, Ollama에 닿지 않게(`OLLAMA_BASE_URL=http://127.0.0.1:9`) | 100 passed, 1 skipped |
| 실제 질문 | 데스크탑 AI 서버에 질문 3개 | 출처 8개로 답함. 응답 79.2초(재시작 뒤 첫 질문, 검색 준비 73.2초) · 5.4초 · 2.1초 |

- 재시작 뒤 첫 질문이 느린 것은 BM25 색인과 표 사실 캐시를 첫 질문 때 만드는 기존 동작이다(`_get_bm25_sparse_index`·`_get_table_fact_cache`). 생성 모델과 무관해 고치지 않고 `docs/development/알려진-문제.md`에 적었다. 평가 응답 시간은 첫 문항을 빼고 잰다(2단계 보고서 §3.2).
- 바꾸기 전 모델 준비 단계는 올릴 때마다 다시 내려받았다: 데스크탑 Ollama 목록에서 `qwen3-embedding:4b`·`gemma4:12b-it-qat`의 수정 시각이 그날 앞서 compose를 올린 때(조회 약 6시간 전)로 바뀌어 있었다. 내용 지문(ID)은 그대로였다. 공개 목록의 같은 이름이 새 판으로 바뀌면 모르는 사이에 모델이 바뀔 수 있었다.

## 4. 한계와 남은 것

- 맥북 compose(`docker-compose.yml`만)에는 모델 준비 단계가 없다. 맥북에서 A.X를 쓰려면 같은 스크립트를 맥북 Docker에서 돌리거나 GGUF를 받아 직접 등록해야 한다. 지금은 맥북에서 생성을 돌리지 않는다.
- 학습한 모델 등록은 같은 `import.sh`를 쓰도록 만들었지만, 학습 서버에서 GGUF를 옮겨 오는 절차는 계획 3·7단계에서 실제로 해 보고 README를 채운다.
- Ollama 이미지(`ollama/ollama:latest`)는 고정하지 않았다(지금 데스크탑 0.30.7). 판을 올리면 임베딩 흔들림 측정(`임베딩-흔들림-수정-20261020.md` §2)과 채팅 틀 확인(`import.sh`의 입력 토큰 수)을 다시 한다.
- 비교 기준 Gemma로 평가할 때는 실행 명령 앞에 `OLLAMA_LLM_MODEL=gemma4:12b-it-qat`를 붙인다(셸 환경값이 `.env`보다 먼저다). Gemma는 공개 목록에 있어 모델 준비 단계가 그대로 처리한다.

## 5. 면접 포인트

- "모델 파일도 의존성이다." 같은 이름 아래 내용이 바뀌면 재현이 깨지므로, 공개 목록의 모델은 등록된 판을 고정하고 직접 변환하는 모델은 원본 커밋·변환 도구 이미지 지문·결과 파일 해시를 대장에 남겼다. 다시 만들어 같은 해시가 나오는지로 절차를 검증했다.
- "기본값이 여러 곳에 있으면 테스트로 묶는다." AI 서버·compose·모델 준비 단계·환경 예시 중 한 곳만 바뀌면 AI 서버가 등록되지 않은 모델을 부르므로, 네 곳이 같은지 보는 테스트를 두고 한 곳씩 일부러 바꿔 잡는지 확인했다.
