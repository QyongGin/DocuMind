## 1. 결론

(11-14 11:15 결론)

- 단계 1(프롬프트)에서 거르기(설계 4-1)를 통과한 것은 '같은 표 조각 합치기'(c04) 하나다. 표 질문 맞음 20 → 23, 개발셋 틀림 11 → 12, 답없음 거절 24 → 23. 고르는 몫 47문항의 짝 비교로는 같은 수준(p 0.25)이라 효과는 단계 3의 확인 몫에서 정한다. 단계 1은 색인을 그대로 둬서 같은 설정을 두 번 재면 답 글이 모두 같다(잡음 0).
- 표를 통째로 주는 넓히기는 예산을 둬도(c13) 표 질문은 가장 많이 맞혔지만(24) 답없음 질문에서 넓힌 표의 값을 끌어와 거절이 줄었다(24 → 18).
- 단계 2(표 청크) 9개 가운데 거르기 규칙으로 통과한 것은 주석 붙이기(묶음) 하나지만, 청크가 글자까지 같은 주석 붙이기(기호)는 떨어졌다. 같은 설정으로 다시 색인만 해도 표 질문 ±1, 개발셋 틀림 +2만큼 움직여, 단계 2의 차이는 모두 이 잡음 폭 안팎이다. 단계 2에서 효과가 있다고 말할 수 있는 후보는 없다.
- 후보가 노린 구조(합친 칸, 여러 줄 머리글, 쪽을 넘는 표, 주석)의 문항만 봐도 맞음 차이는 1문항 안팎이다.
- PDF 도구는 지금 도구(OpenDataLoader 2.2.1)를 그대로 둔다(MinerU는 설치 환경 문제로 재지 못함). 답 검증은 둘 다 떨어졌다: 값과 칸 대조 규칙은 틀린 답을 거의 못 잡고(113개 중 6), 다른 모델 검사는 틀린 답 86개를 잡지만 맞는 답을 약 190개 거른다.
- [판단] 표 질문의 남은 오답은 표를 어떻게 쪼개 넣느냐보다, 근거에 든 표에서 맞는 행·열을 고르지 못하는 데서 난다(다른 해 표의 값, 다른 행의 값, 분류 칸을 등급 분야로 읽기). 청크·프롬프트 모양을 바꾸는 후보로는 이 오답이 거의 움직이지 않았다.
- 정할 것: ① 단계 3 조합에 c04만 넣을지, 잡음으로 본 주석 붙이기(묶음)도 넣을지. ② 색인을 바꾸는 후보를 다시 잴 때 다시 색인을 여러 번 해 평균을 낼지(후보 하나에 약 29분).

- t2html은 표 청크 후보 가운데 표 질문 맞음이 가장 많고 다른 두 지표도 기준 안이지만 통과선(23)에 1문항 모자란다. 경계 판정 하나가 있다: tq-0069(전자공학과 2021년 취업 인원)는 첫 문장에서 맞는 값 4명을 말한 뒤 다른 표를 보고 '2021년에 6명이 취업했다'고 적어 결론이 엇갈렸다. 지난 판정에서 결론이 엇갈린 답을 맞음으로 본 적이 없어 '일부'로 뒀다. 이 답을 맞음으로 보면 23으로 통과선에 닿는다. 또 다시 색인 잡음(기준선을 다시 색인한 t2rebase)이 나오기 전이라 +2가 잡음보다 큰지 아직 모른다.
- 단계 2의 길이로 멈춤(격자 1, 주석(위치) 1, 칸마다 머리글 줄 2)은 출력 상한 512토큰을 다 쓴 긴 목록 답이다(프롬프트는 문맥 한도보다 한참 작음) [실측].
- 다시 색인 잡음 [실측]: 후보를 모두 끈 채로 같은 작업 볼륨에서 평가 몫 PDF 12개를 한 번 더 다시 색인하자(t2rebase), 답 글이 개발셋 21/205문항, 표 질문 17/47문항에서 달라졌고 표 질문 맞음 20 → 19, 개발셋 틀림 14 → 16, 답없음 거절 21 → 22로 움직였다. 코드와 설정이 같아도 다시 색인만으로 거르기 허용 폭(개발셋 틀림 +2)만큼 움직인다. 단계 1은 색인을 그대로 두고 프롬프트만 바꿔 잡음이 0이었다(기준선 두 번의 답 글 252개가 모두 같음). [판단] 단계 2 후보 가운데 이 잡음 폭(표 질문 ±1, 개발셋 틀림 ±2)을 분명히 넘어 나아진 것은 없다. HTML 표의 표 질문 +2도 잡음 폭을 조금 넘는 정도라 단계 2만으로는 효과를 말할 수 없다.
- 주석 붙이기(기호)는 평가 몫 PDF에서 청크를 2개만 바꾸는데도(모집요강의 8·9번 청크) 표 질문 +2, 개발셋 틀림 +3으로 움직였다 [실측]. 판정이 바뀐 12문항(개발셋 5, 표 질문 7) 가운데 바뀐 청크를 검색 후보로 받은 문항은 4개뿐이다 [실측, 청크 번호를 후보 기록의 chunk_index와 맞춰 셈]. 나머지 8문항의 변화는 다시 색인 잡음이다. 잡음이 이 정도 크기라는 둘째 근거로 본다 [판단].
- **주석 붙이기(묶음)의 통과는 잡음이다** [실측 + 판단]: 평가 몫 PDF 12개에서 기호 후보와 묶음 후보의 청크·색인 항목이 글자까지 같다(맥북에서 임베딩 없이 뜬 청크 기준, 둘 다 모집요강 8·9번 청크에 같은 주석 줄을 붙임). 같은 색인 내용을 두 번 다시 색인했을 뿐인데 기호는 22 / 17 / 21로 탈락, 묶음은 23 / 16 / 22로 통과했다. 거르기 규칙으로는 통과지만 후보의 효과로 보지 않는다. 고르는 몫 47문항과 지금 거르기 폭으로는 색인을 바꾸는 후보를 가를 수 없다는 것이 단계 2의 가장 분명한 결과다.
- 노린 문항만 따로 [실측]: 표 질문 47문항 가운데 '쪽을 넘는 표' 태그 8문항의 맞음은 기준선 2, 쪽을 넘는 표 합치기 2로 같았다. '여러 줄 머리글' 21문항은 기준선 6, 머리글 전체 되풀이 7이다. 후보가 겨냥한 문항에서도 움직임이 1문항 안팎이다.
- t2grid [실측]: 판정이 바뀐 문항은 개발셋 14개, 표 질문 8개이고 모두 다시 색인한 PDF 12개의 청크를 검색했다. 좋아진 쪽(정보통신공학과 모집 정원, 푸른등대 장학금 선발 인원)과 나빠진 쪽(같은 장학금 표에서 다른 행의 인원, 안전진단 표에서 '기계/물리' 열 이름을 등급 분야로 읽음)이 같은 표들에서 함께 나왔다. [판단, 추측] 격자로 바꾸면 합친 칸 값이 여러 행에 되풀이돼 행이 길어지고, 모델이 다른 행의 값을 집는 일이 늘었을 수 있다(청크를 견줘 확인하지는 않음). 다만 기준선의 다시 색인 잡음(개발셋 틀림 11 → 14)과 크기가 비슷해, 나빠졌다고 단정하지는 않는다. 거르기는 표 질문 맞음이 늘지 않아 떨어졌다.
