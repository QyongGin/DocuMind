# M2 6단계 — 학습 예시 제작법 0단계 코드: 근거 시점 맞춤·답없음 구성·왕복 검사 기준 (2026-10-31)

> 상태: 맥북 코드 끝(테스트·변이 확인). 데스크탑 측정(ADR-0047 측정 1·2단계, ADR-0048 결정 6 표본 비교) 전.
> 결정: ADR-0047(근거 시점 맞춤), ADR-0048(제작법 고치기와 초안 모델 비교). 원인 분석은 `6단계-통과율-원인분석-20261027.md` §8.

## 1. 요약

- 학습 예시가 계획의 39%만 남는 원인 중 코드로 고칠 수 있는 것을 고쳤다: 근거에 그날 없던 문서가 섞이는 것(시점 91), 질문을 만든 청크만 정답으로 보던 왕복 검사(48 중 30은 답이 있었음), 초안 모델에게 맡기던 거절 판단과 확인처 고르기(32), 출처 번호 찾기(28), 표 질문 지시문과 판정 지침의 충돌(16).
- 운영 챗봇은 바뀌지 않는다. AI 서버에 더한 칸은 학습 예시 도구만 보내고, 날짜 줄은 설정으로 꺼 둔다(개발셋으로 해가 없는지 잰 뒤에 켬).
- 기존 세 묶음 539개에 새 검사를 다시 돌리면 23개가 새로 살아나고 새로 떨어지는 것은 없다. 서식 표 거르기(ADR-0048 결정 5)는 기준값을 찾지 못해 구현하지 않았다(§4).

## 2. 바꾼 것 — 데이터 흐름 순서로

### 2.1 AI 서버: 평가 전용 요청 칸 (`ai-server/main.py`)

- `QueryRequest`에 `exclude_ledger_ids`(뺄 문서의 대장 번호), `exclude_chunk_ids`(뺄 원문 청크), `as_of`(프롬프트의 '오늘' 날짜)를 더했다. `/query`만 받는다.
- `CandidateExclusion.excludes(meta, chunk_id)`: 대장 번호, 원문 청크 id, 표 사실의 부모 청크(`parent_chunk_id`), 검색용 청크의 부모 청크(`_retrieval_parent_chunk_id`)로 판단한다. 답이 든 원문 청크를 빼면 그 청크에서 나온 표 사실·검색용 청크도 함께 빠진다.
- 세 검색기가 후보를 개수로 자르기 전에 뺀다: `_lookup_bm25_raw_chunk_candidates`·`_lookup_lexical_table_fact_candidates`는 정렬 전에 건너뛰고, 벡터는 Chroma가 개수를 정해 돌려주므로 `_query_chroma_vectors_excluding`이 두 배씩 늘려 받아(상한 `AI_VECTOR_EXCLUSION_MAX_RESULTS`, 기본 400) 거른 뒤 자른다. 자른 뒤에 빼면 빈자리를 다음 후보가 채우지 못한다.
- 날짜 줄: `AI_PROMPT_DATE_LINES_ENABLED`(기본 false)를 켜면 `_build_rag_prompt`가 맨 위에 `오늘: YYYY-MM-DD`(한국 시간, 요청의 `as_of`가 있으면 그 날짜), `_format_context_block`이 `문서:` 다음 줄에 `게시: YYYY-MM-DD`(색인 메타데이터 `posted_at`)를 넣는다. 게시일 없는 페이지·규정에는 없다.
- 운영 경로: 칸이 비면 검색기를 지금과 같은 인자로 부른다(`eval_only`·`exclude_kwargs`를 비워 둠). 평가 기록(`eval_trace`)에 `exclusion`(뺀 개수·기준 날짜)과 `runtime.prompt_date_lines`를 남긴다.

### 2.2 학습 예시 도구: 근거 시점 맞춤 (`tools/corpus/corpus/trainset/timeline.py`, `pipeline.run_attach`)

- `ledger_dates(con)`: 데이터셋 색인에 올라간 문서의 게시일·유효 기간(첨부는 부모 날짜).
- `the_day`: 그날 = 질문 재료 문서의 게시일, 없으면 근거를 붙이는 날.
- `excluded_ledger_ids(day, dates, keep_old)`: 그날 뒤에 올라온 문서는 늘, 그날 이미 만료된 문서는 `keep_old`가 아니면 뺀다. `keeps_old_versions(item_id)`가 예시 번호의 해시로 약 10%를 정해(다시 돌려도 같음) 옛 판을 남긴다.
- `run_attach`가 예시마다 위 목록과 `as_of`를 AI 서버에 보내고, 예시 기록에 `timeline`(기준 날짜·옛 판 남김·뺀 문서 수)을 남긴다. `corpus trainset attach --no-timeline`이면 그 전처럼 붙인다(비교용).

### 2.3 학습 예시 도구: 답없음 예시 구성 (`pipeline._construct_refusal`, `refusal_contact_blocks`)

- 거절 + 확인처 종류의 질문은 사실 질문과 같은 지시문(`prompts.FACT_RULE`)으로 만들고 답 근거를 받는다.
- 근거를 붙인 뒤 `checks.hint_blocks`로 답 근거가 든 블록을 찾아 그 청크를 `exclude_chunk_ids`로 빼고 다시 붙인다(최대 3번). 빼도 답이 남거나 답 근거가 없으면 그 예시는 실패로 남긴다.
- 확인처를 고를 블록은 재료 문서의 다른 청크, 같은 게시글(본문·첨부), 같은 묶음(`group_id`)의 문서다(`plan.document_family`). 목표 답 지시문은 그 블록의 연락처·사이트만 후보로 보이고, 후보가 없으면 거절 문장 하나만 쓰게 한다.
- 자동 검사에 셋을 더했다: `답 근거 없음`(근거에 답이 남지 않았나), `거절함`, `확인처 출처`(고른 블록 밖의 확인처를 붙이지 않았나). 옛 묶음 기록(구성하지 않은 거절 예시)은 전처럼 검사한다.

### 2.4 학습 예시 도구: 왕복 검사·출처 번호·지시문 (`checks.py`, `prompts.py`, `judge.py`)

- 왕복 검사: '질문을 만든 청크가 근거 8개 안에 있나'에 더해 '답 근거가 든 블록이 있나'도 통과로 본다(`hint_blocks`).
- 출처 번호: 코드가 짚은 답 근거 블록 번호를 목표 답 지시문에 "이 부분은 [출처 N]에 있다"로 알려 준다.
- 표 질문 지시문: "질문에 행 이름과 열 이름을 담는다" → "행과 열은 묻는 사람이 평소 쓰는 말로 가리키고, 표 머리글·칸 이름을 그대로 옮기지 않는다".
- 시점 규칙(`prompts.AMBIGUOUS_RULE`, 목표 답 지시문과 판정 지침이 함께 씀): "오늘 기준으로 유효한 근거로 답하고 기준을 밝힌다. 근거가 모두 지난 학기 것이면 그렇다고 밝히고 확인처를 안내한다." 판정 지침 판 2026-10-31.

## 3. 확인한 것

- 테스트(가나대학 합성 데이터): AI 서버 새 테스트 11개, 전체 111개 통과(실제 DB가 필요한 1개 건너뜀). 학습 예시 도구 새 테스트 19개, 전체 282개 통과. 운영 프롬프트 골든 테스트 그대로 통과.
- 변이 확인(커밋 뒤 동작을 일부러 망가뜨리고 그 파일만 되돌림): AI 서버 6개, 근거 시점 6개, 왕복·지시문 5개, 답없음·문구 9개 — 모두 테스트가 잡았다. 처음 돌린 AI 서버 변이 하나는 반복문을 끝나지 않게 만들어 테스트가 멈췄다 — 변이마다 시간 제한을 걸고 그 변이를 '받은 것 안에서만 빼기'로 바꿔 다시 돌렸다.
- 기존 묶음에 다시 돌리기 [실측]: 539개 중 23개가 새로 살아나고(전에는 왕복 검사로만 떨어짐, 아직 판정 전) 새로 떨어지는 것 없음.

## 4. 측정으로 바꾼 것

- 출처 번호를 코드가 짚은 블록으로 강제하는 안(ADR-0048 결정 3의 처음 문구)은 기존 묶음에서 7개를 새로 떨어뜨렸고, 그중 4개는 Claude 판정을 통과한 정상 답이었다(채용 공고 대신 재공고, 같은 센터의 다른 안내처럼 같은 값이 든 다른 블록을 인용). 강제하지 않고 지시문에 알려 주는 데만 쓴다.
- 서식 표 거르기(결정 5): 표 종류 계획 153개에서 빈 칸 비율은 서식 표를 가르지 못했다(빈 칸 0~10% 93개 중 질문을 못 만들었거나 칸 이름을 베낀 것 20개). 숫자 든 칸 20% 미만인 표 43개를 빼면 그런 예시 12개가 줄지만 통과하던 6개도 잃는다. 구현하지 않고 결정 4의 효과를 새 묶음에서 본다.
- 두 측정은 ADR-0048 결과 칸에 적었다.

## 5. 한계

- 그날 판단은 대장 유효 기간에 기댄다. 7~8월에 올린 2학기 공지가 8월 31일에 만료되는 결함(2026년 42개)은 아직 그대로다(별도 결정).
- 답없음 구성은 답 근거의 값·글자로 블록을 찾는다. 같은 답을 다른 말로 적은 블록은 못 찾아 근거에 남을 수 있다 — 판정이 잡아야 한다.
- 확인처 블록의 '같은 묶음'은 제목 기반 묶음이라, 해마다 제목이 다른 같은 안내는 같은 묶음으로 보지 않는다.
- 날짜 줄이 A.X 답에 도움이 될지는 아직 모른다(외부 근거의 효과가 작거나 엇갈림 — 측정 1단계).
