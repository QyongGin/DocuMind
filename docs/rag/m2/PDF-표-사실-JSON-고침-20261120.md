# PDF 표 사실을 OpenDataLoader JSON 칸으로 바로잡기

> 상태: 끝(2026-11-20). 이슈 #264. 앞 단계 [표 질문 오답 진단](표-질문-오답-진단-20261118.md), [프롬프트의 표 사실을 원본 표 청크로 바꾸면 나빠진다](표-사실-빼기-측정-20261119.md).

## 1. 결론

- [실측] 지금 프롬프트에 들어가는 표 사실(마크다운 경로)은 값 있는 칸의 24.3%에 틀린 열 이름이 붙는다. 이 변경이 고친 JSON 경로는 0.7%다(고치기 전 1.4%).
- [실측] JSON 경로의 결함 여덟 개를 고쳤다. 칸 단위로 맞는 칸이 67.6% → 91.4%, 행을 가리지 못하는 칸이 27.5% → 4.7%다. 표 단위로는 표 이름 없는 표 311 → 45, 행 이름이 대부분 숫자인 표 92 → 16, 표 사실을 못 만든 표 78 → 43이고, 머리글 경로 일치율은 0.962 → 0.976이다.
- [실측] 프롬프트의 표 사실 줄을 JSON 경로 줄로 바꿔 다시 생성해도 답은 같은 수준이었다(표 질문 맞음 21 → 22, 개발셋 본 틀림 7 → 7). 그래서 색인 때 표 사실 고침만 반영하고, 프롬프트의 표 사실은 바꾸지 않는다. 다음은 검색 단계(표 질문 틀림 26 중 12)다.

## 2. 칸 단위 정확도

표 정답(머리글 있는 표 76개, 값 있는 칸 5,836개)의 데이터 칸마다 그 칸의 표 사실을 넷으로 갈랐다. 세로로 합친 칸은 덮은 행마다 하나로 셌고, 빈칸과 「-」 786칸은 뺐다.

- 맞음: 값이 표 사실에 있고, 열 이름이 정답 머리글 경로와 같고, 행 이름(JSON 경로는 행 이름과 행 경로)이 정답 표의 그 행 하나를 가린다.
- 틀린 열 이름: 값은 있는데 열 이름이 다르다. 모델이 틀린 사실을 받는다.
- 행을 못 가림: 값과 열 이름은 맞는데 행 이름이 비었거나 숫자거나 여러 행이 같은 이름이다.
- 표 사실 없음: 그 칸이 어떤 표 사실에도 없다.

| 코드 | 맞음 | 틀린 열 이름 | 행을 못 가림 | 표 사실 없음 | 틀린 열 이름이 있는 표 |
|---|---:|---:|---:|---:|---:|
| 마크다운 경로(지금 프롬프트) | 1,661 (28.5%) | 1,417 (24.3%) | 2,207 (37.8%) | 551 (9.4%) | 22 |
| JSON 경로 고치기 전 | 3,946 (67.6%) | 83 (1.4%) | 1,605 (27.5%) | 202 (3.5%) | 5 |
| JSON 경로 고친 뒤 | 5,337 (91.4%) | 38 (0.7%) | 275 (4.7%) | 186 (3.2%) | 3 |

- [실측] 마크다운 경로는 문서를 서버와 같은 업로드 단계로 잘라 청크마다 만든 줄로 쟀다. 다시 만든 줄은 서버 함수(`_extract_table_facts`) 출력과 청크마다 같다.
- [실측] 마크다운 경로의 틀린 열 이름은 대부분 둘째 머리글 줄이 빠진 것이다(1,067칸, 예: 「수시1차 > 일반고」 칸이 `수시1차=50`). 마크다운 표는 머리글을 한 줄만 담아, 서버가 본문 첫 줄을 보고 둘째 머리글인지 짐작하는데, 청크가 표 중간에서 시작하면 첫째 머리글 줄만 다시 붙기 때문이다. 다음은 위 줄의 묶음 머리글이 붙거나 합친 칸 때문에 값이 밀린 것(329칸)이다.
- [실측] 마크다운 경로의 행을 못 가림은 행 이름(주어)으로 첫 글 열을 쓰는 탓이다(예: 학과 열 「항공운항과」가 실습실 여러 행에 같다).
- [실측] 고친 JSON 경로의 표 사실 없음은 판정 못 함 86칸을 빼면 80자 넘는 글 칸을 건너뛴 것(36칸, 행 전체가 빠진 10칸 따로)이 가장 많다.

## 3. 표 사실을 쓰는 이유와 위험

- 쓰는 이유 [실측]: 모델(A.X 4.0 Light 7B)은 마크다운 표에서 칸을 세다 밀려 읽는다. 표 사실은 값마다 열 이름을 붙여 이를 막는다. 프롬프트에서 표 사실을 빼고 원본 표 청크만 주면 개발셋 본 틀림이 6 → 14로 늘었다([표 사실 빼기 측정](표-사실-빼기-측정-20261119.md)).
- 위험 [실측]: 틀린 열 이름이 붙은 줄은 모델에게 틀린 사실을 준다. 지금 프롬프트의 줄은 값 있는 칸의 24.3%가 그렇다. 80자 넘는 글 칸은 표 사실이 없고(JSON 경로), 마크다운 경로 줄은 420자에서 잘린다.
- [실측] 그런데 표 사실의 정확도를 올려도(JSON 경로 줄로 바꿔도) 답은 같은 수준이었다(6절). 진단에서 표 사실 탓 오답은 표 질문 26문항 중 4였다.
- [판단] 그래서 표 사실은 빼지 않고, 정확도가 높은 JSON 경로를 색인에 반영하되, 프롬프트 교체는 답에서 이득이 확인될 때 한다.

## 4. 연번 열을 왜 건너뛰나

- [실측] 행 이름이 숫자면 행을 가릴 수 없다. 고치기 전 JSON 경로에서 행 이름이 숫자인 행은 11개 문서의 표 155개, 2,230행이었다. 실습실 정밀안전진단 보고서 한 문서 안에서 행 이름 「1」이 표 19개에 나온다.
- [실측] 연번은 사라지지 않고 칸 값으로 남는다. 고친 뒤 126개 표, 2,057행에서 `마케팅공학실습실(1) 행 정보는 연번=1이다.`처럼 연번이 칸 값이 된다. 행 이름이 숫자인 행은 226행으로 줄었다(연번이 아닌 숫자 첫 열, 예: 연도).

## 5. 무엇을 고쳤나

PDF 표 사실은 두 경로로 만들어진다. 질의 때 마크다운 표에서 머리글을 다시 짐작하는 마크다운 경로와, 색인 때 OpenDataLoader JSON 칸에서 만드는 JSON 경로다. 머리글은 JSON 경로가 맞지만, JSON 경로는 표 이름과 행 이름을 자주 잃고 일부 표에서 표 사실을 만들지 않았다. 아래 표 단위 숫자는 평가에 쓰는 PDF 29문서(표 요소 595개)에서 센 것이다.

| 결함 | 고침 | 커밋 | 고치기 전(develop) | 고친 뒤 |
|---|---|---|---:|---:|
| 표 이름 없음: 표 이름을 그 쪽 제목에서만 가져옴 | 표 바로 앞 짧은 줄을 표 이름으로, 쪽을 넘어 제목과 표 이름을 이음 | `7174848` | 311 | 45 |
| 표 이름 후보에 단위 표시 줄(「(단위: 명, 백만 원)」), 번호나 기호뿐인 줄(「IV」, 「❍」), 문장(「…합니다.」)이 들어감 | 줄 모양만 보고 후보에서 빼고 다음 순위(앞 쪽 표 이름, 제목 경로)로 넘김 | `118c572` | | |
| 행 이름이 연번 숫자: 행 이름을 늘 첫 칸으로 정함 | 연번 열을 건너뛰고 행을 가르는 이름 열을 행 이름으로 | `8b8372a` | 92 | 16 |
| 목록 항목 안의 표를 후보로 모으지 못함 | 목록 항목 아래 표도 표 사실로 만듦 | `a181739` | 78 | 43 |
| 왼쪽에 묶음 열(계열, 학부)이 여럿인 표의 행 이름 | 세로로 합친 묶음 열은 행 경로로, 다음 이름 열을 행 이름으로 | `ce598c2` | | |
| 가로로 합친 머리글 칸(「교육과정 연계대상」) 아래 하위 머리글 줄(「대학」, 「학과」)을 데이터 줄로 읽음 | 합친 칸 아래가 서로 다른 글이고 숫자 값이 없으면 하위 머리글로 읽음 | `c8a1f45` | | |
| 칸 글과 표 이름의 PDF 빈 문자(`\x00`, 예: 「반영\x00 총점」) | 칸 글과 제목을 읽을 때 공백으로 바꿈. 빈 문자만 든 제목은 표 이름으로 쓰지 않음 | `8146b0d`, `ad29ce9`, `686265f` | 칸 값 1,634곳, 행 이름 1,489곳, 열 이름 249곳, 표 이름 6개 | 0 |
| 가로로 합친 칸이 행 경로에 두 번(「기계공학과 > 미참여 > 미참여」) | 행 경로에 같은 글은 처음 하나만 | `72e8138` | | |

- [실측] 행 이름 확인: 표 정답 85개 가운데 도구 표와 맞춘 83개 표의 1,029행에서, 행 이름과 행 경로로 정답 표의 그 행 하나를 가려내는 비율이 develop 0.645 → 0.921이다. 나빠진 표는 하나다(군별 모집 분야 표, 가려낸 행 8 → 7). 같은 학과가 군마다 다른 행이라 학과 열 하나로는 행을 가를 수 없다.
- [실측] 표 이름 후보 거르기(`118c572`): 29문서에서 표 이름을 정하는 표 552개 중 12개가 바뀌었다. 5개는 단위 줄이나 문장 대신 표 위 제목(「다. 화학약품 또는 가스누출 시 행동요령」 등)을, 6개는 이름 없음을 받았다(「2」, 「본인은 … 지원합니다.」). 1개는 법조문 문장으로 끝나는 목록 항목 대신 그 위 줄 「□ 개인정보 수집‧이용 동의」를 받았는데, 어느 쪽이 맞는지 가리지 못했다. 이 거르기로 표 이름 없는 표가 39 → 45가 됐다.
- [실측] 하위 머리글 줄(`c8a1f45`): 29문서 595개 표에서 머리글 줄 수가 바뀐 표는 5개이고 모두 하위 머리글(「과학고, 외국어고 …」, 「교시, 수업시간」 등)이다. 표 정답 문서 40개에서는 19개가 바뀌었고, 틀린 열 이름 칸이 81 → 38, 머리글 경로 일치율이 0.962 → 0.976이다. 처음 규칙은 표 전체 폭으로 합친 제목 줄 아래의 「항목 | 값」 줄까지 머리글로 읽어 양식 표 하나가 나빠졌다. 그래서 위 줄 전체가 한 칸이면 하위 머리글로 보지 않게 좁혔고, 그 뒤 나빠진 정답 표는 없다. 표 사실이 있는 표가 471 → 470이 됐는데, 빠진 표의 줄은 머리글을 값으로 읽은 줄(「수시=검정고시 출신자」)뿐이었다.
- [실측] 빈 문자 고침으로 빈 문자가 끼어 건너뛰던 긴 글 칸이 표 사실이 되어 표 5개에서 표 사실이 15개 늘었다.
- 고침마다 지은 학교(가나대학) 표로 테스트를 붙였고, 커밋 뒤 고침을 되돌려 테스트가 잡는지 봤다. 특정 학과명이나 값을 조건으로 쓰는 규칙은 없다.

## 6. 근거 고정 재생: 프롬프트 표 사실을 JSON 경로로 바꾸면

방법: 기준 실행(5회차 A.X 4.0 Light, 재순위 켬, 근거 8개, 같은 표 번호의 조각을 합친 프롬프트)의 프롬프트에서 「표 검색 정보」 절의 PDF 행 표 사실 줄만, 같은 표 같은 행의 JSON 경로 줄로 바꿔 다시 생성했다. 같은 행은 근거 청크 → 표 번호 → OpenDataLoader 표 요소(쪽, 요소 id)로 표를 먼저 정한 뒤 그 표 안에서 값이 가장 많이 겹치는 행으로 찾았다. 점수가 같은 행이 둘 이상이면 바꾸지 않았다. 처음 방법(표를 정하지 않고 문서 전체에서 찾음)은 값이 같은 다른 표의 행을 넣었다. 표 질문 47문항 중 13문항이었고, 고친 뒤 다른 표의 행으로 바뀐 줄은 0이다.

바뀐 프롬프트마다 기준 프롬프트와 새 프롬프트를 모델을 한 번 올린 상태에서 한 번씩 생성해 짝으로 견줬다. 측정은 JSON 경로 코드 `ce598c2` 기준이다. 뒤의 커밋(빈 문자, 행 경로 중복, 표 이름 정리, 표 이름 후보 거르기, 하위 머리글 줄)은 다시 재지 않았다.

재기 전에 적은 기준

| 판단 | 표 질문 맞음 | 개발셋 본 틀림 | 확인 몫 맞음 |
|---|---|---|---|
| 바꿔도 된다 | 기준 + 2 이상 | 그리고 기준 + 1 이하 | 그리고 기준 이상 |
| 바꾸면 안 된다 | 기준 − 3 이하 | 또는 기준 + 3 이상 | 또는 기준 − 2 이하 |
| 그 사이 | 같은 수준 | | |

결과(바뀐 프롬프트: 표 질문 38, 개발셋 63, 확인 몫 15)

| 지표 | 기준 재생 | JSON 경로 표 사실 | 판단 |
|---|---:|---:|---|
| 표 질문 맞음(47) | 21 | 22 | +1 |
| 표 질문 본 틀림 | 13 | 15 | (기준 밖) |
| 개발셋 본 틀림(205) | 7 | 7 | ±0 |
| 개발셋 답없음 거절 | 26 | 26 | |
| 확인 몫 맞음(23) | 13 | 13 | ±0 |

확인 몫은 방법을 고르는 데 쓰지 않은 표 질문 23문항이다. 생성 232개 모두 잘림 없이 끝났다.

판정이 바뀐 문항(기준 → JSON 경로)과 원인

| 문항 | 바뀜 | 원인 |
|---|---|---|
| 수능 영어 7등급 가산점 | 틀림 → 맞음 | JSON 줄에 「7등급=가산점 없음」이 있다(마크다운 줄은 6등급에서 끝남) |
| 작년 수시1차 항공운항과 경쟁률 | 틀림 → 맞음 | 틀렸던 표 이름이 입시결과 표 이름으로 바뀌고 행 경로 「항공운항과 > 수시1차」가 붙었다 |
| 기계공학과 전문대졸 모집인원 | 모름 → 맞음 | 값(◈)은 같고 열 이름이 「수시1차·수시2차·정시 > 전문대졸」로 나뉘었다 |
| 항공기운항정비실습실 2등급 분야 | 맞음 → 틀림 | PDF 도구가 첫 데이터 행을 머리글로 읽은 지적사항 표 줄(「등급=기계/물리」)을 모델이 골랐다 |
| 정원외 수시2차 수급자 1명 학과 | 일부 → 틀림 | 전년도 입시결과 표의 열이 「수시2차 > 수급자 > 모 집」으로 분명해져, 모델이 2027 모집인원 표 대신 그 표에서 골랐다 |
| KRX국민행복재단 3차 심사 | 모름 → 틀림 | JSON 줄은 「심사기준 > 3차=면접」으로 맞는데 모델이 2차 값을 답했다 |

## 7. 같은 프롬프트는 같은 답을 낸다

- [실측] 표 질문 38개 기준 프롬프트를 모델을 한 번 올린 상태에서 한 번 더, 모델을 내렸다(`keep_alive` 0) 다시 올린 뒤 한 번 더 생성했다. 두 번 모두 38/38이 기준 재생과 글자까지 같았다. 모델은 세 번 모두 GPU에 다 올라 있었다(29/29층, 문맥 12,288).
- [실측] 2026-11-17에 받은 기준 답과는 38 중 28만 같다(개발셋 63 중 48, 확인 몫 15 중 13). 원인은 모른다. Ollama 컨테이너가 그 사이에 새로 만들어졌지만, 같은 컨테이너에서 11-20에 받은 확인 몫 답도 2개가 달라 그것만으로는 설명되지 않는다.
- [판단] 그래서 짝 비교는 모델을 한 번 올린 상태에서 기준과 비교 대상을 함께 생성해야 한다. 이번 숫자는 그렇게 쟀다.

## 9. 한계

- PDF 도구가 첫 데이터 행을 머리글로 읽은 표(지적사항 표 등)는 그대로 둔다. 이 표의 JSON 줄은 머리글이 틀리다.
- 행 이름 열을 하나만 고르므로, 두 열을 함께 봐야 행이 갈리는 표(군별 모집 분야)는 가려내지 못한다.
- 판정은 Claude가 한 번 했다(새로 판정한 답 12개, 어느 쪽 답인지 가린 채). 사람 확인은 하지 않았다.
- 표 질문 본 틀림은 13 → 15로 늘었다. 판단 기준에 넣지 않은 지표라 결론을 바꾸지 않았지만, 나빠진 원인 둘(머리글 오독 표, 다른 해 표)은 남은 일이다.
- 재생 측정은 `ce598c2` 기준이다. 뒤의 커밋은 표 사실 글만 조금 바꾸므로(빈 문자, 행 경로 중복, 표 이름 정리, 표 이름 후보 거르기, 하위 머리글 줄) 답을 다시 재지 않았다.
- 표 이름이 없으면 서버는 표 사실 글에 문서 제목 경로를 대신 쓴다. 큰 절 제목이 목록 항목으로 읽히는 PDF(모집요강)는 제목 경로가 갱신되지 않아, 지나간 제목이 그 자리에 들어간다. 이번 고침의 범위 밖이다.
- 칸 단위 정확도의 표 정답은 OpenDataLoader JSON 칸에서 초안을 만들고 쪽 그림과 대조한 것이라 JSON 경로에 유리하고, 사람 확인 전이다. 표 사실 줄을 정답 행 하나에 잇지 못해 판정하지 못한 칸이 마크다운 경로 107칸, JSON 경로 86칸이다(표 사실 없음에 넣어 셌다). 머리글 없는 양식 표 9개(값 있는 칸 208개)는 열 이름을 판정할 수 없어 뺐다.
- 고친 뒤에도 남는 틀린 표 사실은 대부분 PDF 도구가 표를 잘못 읽은 표에서 나온다(두 행의 글을 한 칸에 모음, 글자 층에 한글이 없음, 쪽을 넘는 합친 칸). 표 사실 코드로는 고칠 수 없다.
- 표 이름 후보 거르기는 줄 모양만 본다. 「③ … 집행 불가」, 「○ (2차 면접 심사) … 영어 면접 포함」처럼 번호나 글머리가 붙은 항목 줄은 제목과 모양이 같아 그대로 표 이름이 된다.
- 표 전체 폭으로 합친 제목 줄 바로 아래의 하위 머리글 줄은 데이터 줄로 둔다(예: 대학교원 자격기준 표). 그 아래가 「항목 | 값」 줄인 표와 모양으로 가를 수 없어서다.
