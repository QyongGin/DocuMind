# PDF 표 사실을 OpenDataLoader JSON 칸으로 바로잡기

> 상태: 끝(2026-11-20). 이슈 #264. 앞 단계 [표 질문 오답 진단](표-질문-오답-진단-20261118.md), [프롬프트의 표 사실을 원본 표 청크로 바꾸면 나빠진다](표-사실-빼기-측정-20261119.md).

## 1. 결론

- [실측] 색인 때 PDF 표 사실을 만드는 JSON 길(`opendataloader_contract_adapter.py`)의 결함 여섯 개를 고쳤다. 표 이름 없는 표 311 → 34개, 행 이름이 대부분 숫자인 표 92 → 17개, 표 사실을 못 만든 표 78 → 43개다. 머리글 경로 일치율 0.962는 그대로다.
- [실측] 프롬프트의 표 사실 줄을 이 JSON 길 줄로 바꿔 근거 고정 재생을 하면, 표 질문 맞음 21 → 22, 개발셋 본 틀림 7 → 7, 확인 몫 맞음 13 → 13이다. 재기 전에 적은 기준으로 같은 수준이다.
- [판단] 그래서 색인 때 표 사실 고침은 반영하고, 프롬프트의 표 사실을 JSON 길로 바꾸는 서비스 반영은 하지 않는다. 다음은 검색(표 질문 틀림 26 중 12가 검색 단계)이다.

## 2. 무엇을 고쳤나

PDF 표 사실은 두 길로 만들어진다. 질의 때 마크다운 표에서 머리글을 다시 짐작하는 길 ①(머리글 경로 일치율 0.746)과, 색인 때 OpenDataLoader JSON 칸에서 만드는 길 ②(0.962)다. 머리글은 길 ②가 맞지만, 길 ②는 표 이름과 행 이름을 자주 잃고 일부 표에서 표 사실을 만들지 않았다. 아래는 그 결함과 고친 커밋이다. 숫자는 평가에 쓰는 PDF 29문서(표 요소 595개)에서 표 단위로 센 것이다.

| 결함 | 고침 | 커밋 | 고치기 전(develop) | 고친 뒤 |
|---|---|---|---:|---:|
| 표 이름 없음: 표 이름을 그 쪽 제목에서만 가져옴 | 표 바로 앞 짧은 줄을 표 이름으로, 쪽을 넘어 제목과 표 이름을 이음 | `7174848` | 311 | 34 |
| 행 이름이 연번 숫자: 행 이름을 늘 첫 칸으로 정함 | 연번 열을 건너뛰고 행을 가르는 이름 열을 행 이름으로 | `8b8372a` | 92 | 17 |
| 목록 항목 안의 표를 후보로 모으지 못함 | 목록 항목 아래 표도 표 사실로 만듦 | `a181739` | 78 | 43 |
| 왼쪽에 묶음 열(계열, 학부)이 여럿인 표의 행 이름 | 세로로 합친 묶음 열은 행 경로로, 다음 이름 열을 행 이름으로 | `ce598c2` | | |
| 칸 글의 PDF 빈 문자(`\x00`, 예: 「반영\x00 총점」) | 칸 글을 읽을 때 공백으로 바꿈 | `8146b0d` | 칸 값 1,634곳, 행 이름 1,489곳, 열 이름 249곳 | 0 |
| 가로로 합친 칸이 행 경로에 두 번(「기계공학과 > 미참여 > 미참여」) | 행 경로에 같은 글은 처음 하나만 | `72e8138` | | |

- [실측] 행 이름 확인: 표 정답 85개 가운데 도구 표와 맞춘 83개 표의 1,029행에서, 행 이름과 행 경로로 정답 표의 그 행 하나를 가려내는 비율이 develop 0.645 → 0.921이다(행 이름만으로는 0.599 → 0.889). 표 정답에는 행 이름 열 표시가 없어, 행 이름과 행 경로의 낱말이 모두 든 정답 행이 하나뿐인지로 쟀다.
- [실측] 나빠진 표는 하나다(군별 모집 분야 표, 가려낸 행 8 → 7). 같은 학과가 군마다 다른 행이라 학과 열 하나로는 행을 가를 수 없다. 행 이름 열을 하나만 고르는 규칙의 한계로 둔다.
- [실측] 빈 문자 고침으로 빈 문자가 끼어 건너뛰던 긴 글 칸이 표 사실이 되어 표 5개에서 표 사실이 15개 늘었다(표 사실이 있는 표 470 → 471).
- 고침마다 지은 학교(가나대학) 표로 테스트를 붙였고, 커밋 뒤 고침을 되돌려 테스트가 잡는지 봤다. 특정 학과명이나 값을 조건으로 쓰는 규칙은 없다.

## 3. 근거 고정 재생: 프롬프트 표 사실을 JSON 길로 바꾸면

방법: 기준 실행(5회차 A.X 4.0 Light, 재순위 켬, 근거 8개, 같은 표 번호의 조각을 합친 프롬프트)의 프롬프트에서 「표 검색 정보」 절의 PDF 행 표 사실 줄만, 같은 표 같은 행의 JSON 길 줄로 바꿔 다시 생성했다. 같은 행은 근거 청크 → 표 번호 → OpenDataLoader 표 요소(쪽, 요소 id)로 표를 먼저 정한 뒤 그 표 안에서 값이 가장 많이 겹치는 행으로 찾았다. 점수가 같은 행이 둘 이상이면 바꾸지 않았다. 처음 방법(표를 정하지 않고 문서 전체에서 찾음)은 값이 같은 다른 표의 행을 넣었다. 표 질문 47문항 중 13문항이었고, 고친 뒤 다른 표의 행으로 바뀐 줄은 0이다.

바뀐 프롬프트마다 기준 프롬프트와 새 프롬프트를 같은 모델 적재에서 한 번씩 생성해 짝으로 견줬다. 측정은 JSON 길 코드 `ce598c2` 기준이다. 뒤의 두 커밋(빈 문자, 경로 중복)은 다시 재지 않았다.

재기 전에 적은 기준

| 판단 | 표 질문 맞음 | 개발셋 본 틀림 | 확인 몫 맞음 |
|---|---|---|---|
| 바꿔도 된다 | 기준 + 2 이상 | 그리고 기준 + 1 이하 | 그리고 기준 이상 |
| 바꾸면 안 된다 | 기준 − 3 이하 | 또는 기준 + 3 이상 | 또는 기준 − 2 이하 |
| 그 사이 | 같은 수준 | | |

결과(바뀐 프롬프트: 표 질문 38, 개발셋 63, 확인 몫 15)

| 지표 | 기준 재생 | JSON 길 표 사실 | 판단 |
|---|---:|---:|---|
| 표 질문 맞음(47) | 21 | 22 | +1 |
| 표 질문 본 틀림 | 13 | 15 | (기준 밖) |
| 개발셋 본 틀림(205) | 7 | 7 | ±0 |
| 개발셋 답없음 거절 | 26 | 26 | |
| 확인 몫 맞음(23) | 13 | 13 | ±0 |

확인 몫은 방법을 고르는 데 쓰지 않은 표 질문 23문항이다. 생성 232개 모두 잘림 없이 끝났다.

판정이 바뀐 문항(기준 → JSON 길)과 원인

| 문항 | 바뀜 | 원인 |
|---|---|---|
| 수능 영어 7등급 가산점 | 틀림 → 맞음 | JSON 줄에 「7등급=가산점 없음」이 있다(마크다운 줄은 6등급에서 끝남) |
| 작년 수시1차 항공운항과 경쟁률 | 틀림 → 맞음 | 틀렸던 표 이름이 입시결과 표 이름으로 바뀌고 행 경로 「항공운항과 > 수시1차」가 붙었다 |
| 기계공학과 전문대졸 모집인원 | 모름 → 맞음 | 값(◈)은 같고 열 이름이 「수시1차·수시2차·정시 > 전문대졸」로 나뉘었다 |
| 항공기운항정비실습실 2등급 분야 | 맞음 → 틀림 | PDF 도구가 첫 데이터 행을 머리글로 읽은 지적사항 표 줄(「등급=기계/물리」)을 모델이 골랐다 |
| 정원외 수시2차 수급자 1명 학과 | 일부 → 틀림 | 전년도 입시결과 표의 열이 「수시2차 > 수급자 > 모 집」으로 분명해져, 모델이 2027 모집인원 표 대신 그 표에서 골랐다 |
| KRX국민행복재단 3차 심사 | 모름 → 틀림 | JSON 줄은 「심사기준 > 3차=면접」으로 맞는데 모델이 2차 값을 답했다 |
| 실습실 2등급 목록, 기기분석실습실(2) 풍속, 정보통신공학과 정원 | 나빠짐 | 관련 행 값은 두 줄이 같고 표기(` > `, 행 이름 열 쌍)만 다르다 |
| 외부 차량 30분 주차 요금 | 틀림 → 맞음 | 바뀐 줄은 주차와 무관한 등록금 표뿐이다 |

- [판단] 고친 결함이 직접 원인인 문항은 나아졌다(2문항). 남은 결함(머리글 오독 표)과 다른 해 표 고르기가 1문항씩 나빠졌다. 나머지 4문항은 관련 값이 같은데 프롬프트 글이 조금 달라져 답이 바뀌었다.

## 4. 같은 프롬프트는 같은 답을 낸다

- [실측] 표 질문 38개 기준 프롬프트를 같은 적재에서 한 번 더, 모델을 내렸다(`keep_alive` 0) 다시 올린 뒤 한 번 더 생성했다. 두 번 모두 38/38이 기준 재생과 글자까지 같았다. 모델은 세 번 모두 GPU에 다 올라 있었다(29/29층, 문맥 12,288).
- [실측] 2026-11-17에 받은 기준 답과는 38 중 28만 같다(개발셋 63 중 48, 확인 몫 15 중 13). 원인은 모른다. Ollama 컨테이너가 그 사이에 새로 만들어졌지만, 같은 컨테이너에서 11-20에 받은 확인 몫 답도 2개가 달라 그것만으로는 설명되지 않는다.
- [판단] 그래서 짝 비교는 같은 적재 안에서 기준과 비교 대상을 함께 생성해야 한다. 이번 숫자는 그렇게 쟀다.

## 5. 결정(2026-11-20)

- 색인 때 표 사실(JSON 길) 고침은 반영한다. 이 길은 문서를 색인할 때만 돈다(`OPENDATALOADER_JSON_TABLE_FACTS_ENABLED`, 데스크탑 설정은 켜짐, compose 기본값은 꺼짐). 머지 뒤에는 PDF를 다시 색인해야 색인의 표 사실 청크가 바뀐다.
- 프롬프트의 「표 검색 정보」 줄(질의 때 마크다운에서 만드는 길 ①)을 JSON 길로 바꾸지 않는다. 근거 고정 재생에서 같은 수준이었고, 진단에서 표 사실 탓 오답은 표 질문 26문항 중 4였다.
- 다음은 검색 단계(재순위가 표 조각을 밀어냄, 다른 해 표 고르기)다.

## 6. 한계

- PDF 도구가 첫 데이터 행을 머리글로 읽은 표(지적사항 표 등)는 그대로 둔다. 이 표의 JSON 줄은 머리글이 틀리다.
- 행 이름 열을 하나만 고르므로, 두 열을 함께 봐야 행이 갈리는 표(군별 모집 분야)는 가려내지 못한다.
- 판정은 Claude가 한 번 했다(새로 판정한 답 12개, 어느 쪽 답인지 가린 채). 사람 확인은 하지 않았다.
- 표 질문 본 틀림은 13 → 15로 늘었다. 판단 기준에 넣지 않은 지표라 결론을 바꾸지 않았지만, 나빠진 원인 둘(머리글 오독 표, 다른 해 표)은 남은 일이다.
- 재생 측정은 `ce598c2` 기준이다. 뒤의 두 커밋은 표 사실 글만 조금 바꾸므로(빈 문자, 경로 중복) 답을 다시 재지 않았다.
