# 기반 모델 최종 선정 계획 — Gemma 4 12B와 A.X 4.0 Light (2026-10-15)

> 학습하고 운영할 기반 생성 모델을 두 후보 중에서 고르기 위해, 두 모델의 장점을 공정하게 따지는 비교 순서와 고르는 규칙을 실험 전에 정한다.
> 상태: **합의**(2026-10-15 사용자 — "이 계획으로 문서화"). 아직 실행 전이다.
> 관련: ADR-0018(테스트셋 봉인), ADR-0025(짝 비교), ADR-0026(성공 기준), ADR-0027(모델 고르는 순서), ADR-0030(운영 서빙은 클라우드), ADR-0031(기반 모델), ADR-0032(순위 융합), `검색개선-설계-20261014.md`, `실패원인-분석-20261014.md` §6-1, `docs/rag/m1/모델비교-20261014.md` §6

## 1. 한 장 요약

- **목적**: 학습(LoRA)하고 운영할 기반 모델을 Gemma 4 12B와 A.X 4.0 Light 중에서 고른다.
- **라이선스는 가르지 않는다**: 두 모델 모두 Apache 2.0이고 사용료·사용자 수 제한이 없다. Gemma 4는 Google 블로그·Google 라이선스 문서·Hugging Face 저장소, A.X 4.0 Light는 SKT 저장소·LICENSE 파일·모델 카드와 바탕 모델 Qwen2.5-7B 저장소에서 원문으로 확인했다(2026-10-15). [원문]
- **지금까지의 차이**(E3, 개발셋, 같은 순위 융합 프롬프트): 정답률은 같은 수준인데 틀린 답이 A.X 10건 · Gemma 1건(p=0.012)이다. A.X는 과잉 거절이 적고, 다음 할 일 안내·한국어 지문 읽기(KorQuAD)가 낫고, 생성이 약 두 배 빠르다. Gemma는 답없는 질문을 모두 거절했다(A.X 82.1%). [실측]
- **핵심 질문**: A.X의 틀린 답을 Gemma와 같은 수준으로 줄이고, 답없는 질문의 거절을 90% 이상으로 올릴 수 있는가.
- **고르는 규칙은 지금 고정한다**: ADR-0027 순서를 그대로 쓴다. A.X의 틀린 답이 같은 수준으로 줄면 정답률(같은 수준) → KorQuAD(A.X가 높음)로 가서 A.X가 1순위가 된다. 그래서 규칙을 바꾸지 않아도 A.X의 장점이 반영된다. [계산·판단]
- **순서**: ① 근거 인용 후 답(프롬프트) → ② 한 번 더 확인(검증 호출) → ③ M2 검색 단계(답을 만드는 모델은 Gemma, 표 색인 뒤 A.X도 잼) → ④ 베이스라인 ②에서 최종 선정. ①·②는 두 모델에 같은 방법을 넣는다.

## 2. 두 모델의 장점과 약점 (지금 근거)

| 항목 | A.X 4.0 Light | Gemma 4 12B | 판정 · 근거 |
|---|---|---|---|
| 정답률(본, 개발셋) | 71.1% | 74.4% | 같은 수준 p=0.48 [실측] |
| 틀린 답(본 149문항) | 10건(6.7%) | 1건(0.7%) | Gemma 나음 p=0.012 [실측] |
| 답없음 거절(본 28문항) | 82.1% | 100% | 같은 수준 p=0.063, 성공 기준 선 90%는 A.X만 미달 [실측] |
| 과잉 거절(본) | 11.6% | 19.0% | A.X 나음 p=0.012 [실측] |
| 다음 할 일 안내(쉬운 38문항) | 47.4% | 26.3% | A.X 나음 p=0.008 [실측] |
| KorQuAD 1.0 EM(500문항) | 78.2 | 74.2 | A.X 나음 p=0.038 [실측, 13번] |
| 생성 속도(데스크탑) | 86.3토큰/초 | 46.8토큰/초 | 생성 시간 중앙 1.58초 대 3.27초 [실측] |
| 최대 문맥 | 16,384토큰 | 256K토큰 | [원문] 모델 카드 |
| 크기 · 학습 뒤 합칠 때 16비트 가중치 | 7.26B · 약 14.5GB | 11.95B · 약 23.9GB | [원문·계산] 학습 서버 RAM 16GB |
| 계보 | Qwen2.5-7B(Alibaba) + SKT 한국어 추가 학습 | Google | [원문] |

- 같은 지표가 프롬프트에 따라 갈렸다: 지금 운영 검색(규칙 경로)의 프롬프트로 잰 13번(본 250문항)에서는 틀린 답이 A.X 25건 · Gemma 17건으로 같은 수준(p=0.077)이었다. 한 번의 결과로 단정하지 않는다. [실측]

## 3. A.X가 틀린 10건 (E3, 개발셋)

실행 기록의 '정답 청크가 문맥에 있었나', 평가셋의 '표 근거' 표시, 판정 기록으로 나눴다. [실측]

| 종류 | 건수 | 같은 문항에서 Gemma | 겨냥하는 단계 |
|---|---|---|---|
| 근거가 없는데 답함(정답 청크가 문맥에 없음 1, 답없는 문항 2) | 3 | 3건 모두 거절(답없는 2건은 맞게 거절) | ① 근거 인용 후 답, ② 한 번 더 확인 |
| 표를 잘못 읽음(옆 줄 값, 일부만 더함 등) | 5 | 4건 맞음, 1건 거절 | ① · ③(표 행 단위 색인) · 학습 |
| 글을 잘못 읽음(요금 계산, 선택 범위) | 2 | 1건 맞음, 1건 거절 | ① · 학습 |

- ADR-0031은 이 10건을 "9건이 문맥의 표·글을 잘못 읽음, 1건이 답없는 문항"으로 적었다. 실행 기록으로 다시 보면 7건 + 3건이다(ADR-0031 2026-10-15 변경에서 고침).
- 가정 계산: 근거 없이 답한 3건만 거절로 바뀌고 나머지가 그대로면 A.X 틀린 답 7건(4.7%) 대 1건, p=0.070으로 같은 수준이 되어 ADR-0027 2단계를 통과한다. 이때 답없음 거절은 89.3%(25/28)로 아직 90% 선 아래다 — 답없는 질문 중 하나를 더 거절해야 한다. [계산]

## 4. 고르는 규칙 (실험 전에 고정)

1. 4단계(베이스라인 ②)에서 두 모델을 그때까지 채택한 같은 설정(검색·프롬프트·확인 호출)으로 본 250문항(개발셋 + 테스트셋, 테스트셋은 M2 끝 한 번 — ADR-0018)에 잰다.
2. ADR-0027 순서로 고른다: ① 학습 조건 ② 틀린 답이 가장 적은 후보와 짝 비교해 의미 있게 많으면 빼기 ③ 정답률 ④ 같은 수준이면 KorQuAD(13번 측정값을 그대로 쓴다) ⑤ 그래도 같으면 과잉 거절이 낮은 쪽.
3. 성공 기준의 선(ADR-0026): ②까지 고른 모델이 오답률 5% 이하·답없음 거절 90% 이상을 넘지 못하고 다른 모델은 넘으면, 다른 모델을 고른다. 둘 다 넘지 못하면 M2를 끝내지 않는다(ADR-0026).
4. 속도·운영 비용은 순위에 넣지 않는다. 데스크탑은 개발·평가용이고 운영 GPU는 M6 전에 클라우드에서 정한다(ADR-0030). 고른 모델의 응답 시간은 그 GPU에서 따로 확인한다.
5. 결과를 본 뒤 규칙을 바꾸지 않는다. 바꿔야 할 사정이 생기면 이 문서에 날짜와 이유를 남기고 사용자 확인을 받는다.

## 5. 단계별 설계

### ① 근거 인용 후 답 (프롬프트)

- **바꿀 것**: 시스템 프롬프트에 일반 원칙 세 가지를 넣는다 — 답에 쓸 근거 줄(표의 행이나 문장)을 먼저 그대로 옮긴다 / 옮길 줄이 없으면 확인할 수 없다고 하고 문서에 있는 문의처·확인처를 안내한다 / 답의 숫자·이름은 옮긴 줄에서만 가져온다. 특정 문항·학과·금액을 겨냥한 문장은 넣지 않는다(AGENTS.md §4).
- **문구는 실행 전에 고정**해 이 폴더에 남기고 사용자에게 보인다. 결과를 보고 고치면 새 변형으로 기록한다(변형은 두 개까지).
- **먼저 확인**: 답 형식이 바뀌면 채점 규칙(필수 사실·금지 값 검사)이 인용한 줄의 다른 숫자를 답으로 오해할 수 있다. 표본 10개로 채점이 맞는지 먼저 본다.
- **실행**: 데스크탑 AI 서버(검색 순서는 순위 융합 하나, #169)에서 E3와 같은 상위 5개(`--top-k 5`)로 `evalset run --system-prompt-file`로 개발셋 205문항을 모델마다 한 번씩 돈다. 비교는 (가) 같은 모델의 E3 실행 ↔ 새 실행, (나) 같은 프롬프트에서 두 모델.
- **채택**(서비스 프롬프트에 넣을지): 두 모델 모두에서 정답률이 의미 있게 떨어지지 않고, 오답률 또는 과잉 거절이 의미 있게 줄 때(`검색개선-설계` §2와 같은 기준). 이것은 M2 5단계(답할지 판단 프롬프트)의 일부를 앞당긴 것이다.
- **비용**: 데스크탑 실행 두 모델 합쳐 약 25분(E3 기록: A.X 약 6분, Gemma 약 13분, 검색 포함이라 조금 더) + 애매 판정(본 세션).

### ② 한 번 더 확인 (검증 호출)

- **바꿀 것**: 답을 만든 뒤 같은 모델에 "답의 숫자·이름이 옮긴 근거 줄에 그대로 있고 질문에 답하는가"를 예/아니오로 묻고, 아니오면 답을 '확인할 수 없음 + 문의처'로 바꾼다.
- **먼저 오프라인 스크립트로**(`Assets/eval/work/`, Ollama 직접 호출) ①의 답에 붙여 재고, 효과가 있을 때만 AI 서버 기능으로 넣는다(별도 PR, 테스트·변이 확인).
- **재는 것**: 틀린 답 감소와 함께 부작용(맞는 답을 거절로 바꾼 수), 응답 시간. A.X는 생성 시간 중앙 1.58초라 두 번 불러도 Gemma 한 번(3.27초)과 비슷하다 — A.X의 속도 장점을 정확도에 쓰는 방법이다. [계산]

### ③ M2 검색 단계 (`검색개선-설계-20261014.md` 2~4단계)

- 검색만 바꾼 효과를 보려고 **M2 검색 실험에서 답을 만드는 모델은 Gemma 4 12B로 고정**한다(지금 성공 기준 선을 모두 넘는 쪽).
- 4단계(표 행 단위 색인)가 끝나면 같은 프롬프트로 A.X를 생성만 다시 돌린다(약 6분). 표를 잘못 읽은 5건을 겨냥하는 단계이기 때문이다. 2·3단계(상위 k·재순위)는 A.X의 틀린 종류와 관련이 작아 A.X를 다시 재지 않는다.

### ④ 최종 비교 (베이스라인 ②)

- 4절 규칙대로 고르고 ADR-0031을 확정하거나 대체한다. 그 뒤 학습(LoRA)으로 넘어간다.

## 6. 버린 대안

| 대안 | 버린 이유 |
|---|---|
| 지금 Gemma로 확정하고 A.X는 베이스라인 ②에서만 다시 비교 | A.X의 틀린 답을 줄일 방법을 시험하지 않으면 A.X의 장점(속도·거절·안내·KorQuAD)이 공정하게 평가되지 않는다. |
| 모델마다 다른 프롬프트로 각자 최선을 찾기 | 차이가 모델 때문인지 프롬프트 때문인지 섞이고, 조정 노력이 두 모델에 같았는지 확인할 수 없다. 채팅 틀처럼 모델 고유 형식만 각자 공식대로 쓴다. |
| 속도·운영 비용을 고르는 순서에 넣기 | 결과를 본 뒤 규칙을 바꾸는 것이 되고, 틀린 답보다 앞설 수 없어 예상되는 경우에는 결과가 같다. 운영 GPU는 아직 정하지 않았다(ADR-0030). |
| M2 모든 단계에서 두 모델을 잼 | 판정이 약 두 배이고, 상위 k·재순위는 A.X의 틀린 종류와 관련이 작다. |
| 두 모델을 모두 학습해 비교 | 학습 서버 비용·시간이 두 배다. 베이스라인 ②에서 두 모델이 아주 가까우면 그때 다시 검토한다. |

## 7. 위험과 확인

| 위험 | 확인 방법 | 시점 |
|---|---|---|
| 개발셋 과적합 — 틀린 10문항을 이미 알고 있다 | 문구는 일반 원칙만, 실행 전에 고정, 변형 두 개까지, 최종은 테스트셋 포함 본 250 | ①·②, ④ |
| 작은 숫자 — 10 대 1은 한두 건 판정에 p가 흔들린다 | 판정 이유를 남기고 갈릴 수 있는 건을 따로 표시해, 빼고도 결론이 같은지 본다 | 단계마다 |
| 프롬프트마다 결과가 뒤집힘(13번 25 대 17 → E3 10 대 1) | 최종 선정은 운영에 쓸 설정으로만 한다(ADR-0031 결정 3) | ④ |
| 답 형식 변경이 채점을 흔듦 | 표본 10개로 채점 확인 후 실행 | ① 전 |
| A.X 최대 문맥 16,384토큰 | M2 2단계에서 근거를 늘릴 때 가장 긴 프롬프트 길이를 함께 기록 | ③ |

## 8. 사람 시간

- 사용자: 단계마다 결과 승인(결론·추천·질문 하나), 실행 때 데스크탑 켜기. ① 문구 확인 한 번.
- 본 세션: 실행, 애매 판정(지침 `Assets/eval/work/judge_instructions.md`), 보고서.

## 9. 네 관점

- 서비스: 틀린 답을 가장 엄하게 막으면서, 답을 더 자주 주고 다음 할 일까지 안내하는 모델이 이길 기회를 연다.
- 비즈니스: 두 모델 모두 Apache 2.0이라 라이선스 비용·위험이 같다. A.X가 이기면 작은 모델이라 운영 GPU 비용이 낮아질 수 있다 [판단].
- 유지보수: ①·②는 모델과 무관한 일반 원칙이라 어느 모델을 고르든 남는다. 고르는 규칙을 실험 전에 고정해 인계받은 담당자도 같은 결론을 재현할 수 있다.
- 확장: 새 후보가 나와도 같은 순서(같은 설정 → ADR-0027)로 넣어 볼 수 있다.

## 10. 검증 시점

- ① 끝: 두 모델의 전후 짝 비교와 채택 여부 보고.
- ② 끝: 틀린 답·부작용·응답 시간 보고, AI 서버에 넣을지 결정.
- ③ 4단계 끝: A.X 생성만 다시 돌리기 결과.
- ④: 최종 선정 → ADR-0031 확정 또는 대체.
