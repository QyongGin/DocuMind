# M2 남은 계획 — A.X 4.0 Light 기준, 학습 트랙 포함 (2026-10-17)

> 기반 모델을 A.X 4.0 Light로 정하고(ADR-0034) LLM 학습을 반드시 하기로 하면서(ADR-0033), M2에서 남은 일을 데스크탑(답 품질)과 학교 AWS 학습 서버(학습) 두 트랙으로 다시 짠다.
> 대체: `모델선정-비교계획-20261015.md`. 이어받음: `검색개선-설계-20261014.md`(측정 방법 §2, 4단계 표 행 단위 색인), `3단계-재순위-점수결합-20261016.md`.
> 상태: 계획(2026-10-17). 단계마다 결과를 보고하고 다음 단계로 간다.

## 1. 목표

- M2 끝: 학습한 A.X로 본 테스트셋을 한 번 재서 ADR-0026 성공 기준을 넘는다(정답률 65% 이상 · 오답률 5% 이하 · 과잉 거절 20% 이하 · 출처 정확도 80% 이상 · 쉬운 문항 90% 이상 · 답없음 거절 90% 이상).
- A.X의 약점 두 가지를 없앤다: 틀린 답(같은 프롬프트에서 10 / 149), 답없는 질문의 거절(82.1%). [실측, ADR-0034]
- 보조: 안내 충실도(지금 Gemma 32%, A.X는 쉬운 문항에서 Gemma보다 높았음)를 50% 쪽으로.

## 2. 단계

| 순서 | 단계 | 어디서 | 무엇을 | 끝난 기준 |
|---|---|---|---|---|
| 0 | 흔들림 고치기 | 맥북(코드) | 근거 꼬리표 단어 정렬을 고정하고, 평가 전에 질문 임베딩을 한 번 먼저 부른다(알려진 문제 두 줄) | 같은 설정 재실행끼리 프롬프트가 205 / 205 같음 |
| 1 | A.X 새 기준선 | 데스크탑 | 지금 운영 설정(순위 융합·근거 8개·생성 문맥 12,288)에서 생성 모델만 A.X로 개발셋 실행, Gemma와 같은 문항 비교. 데스크탑 GPU에 재순위 서버까지 올라가는지도 잰다 | 틀린 답·답없음 거절·정답률·속도 표, GPU 메모리 실측 |
| 2 | 학습 가능성 실측 | 학교 AWS 학습 서버 → 데스크탑 | A.X로 작은 학습 한 번(예시 수십 개)을 끝까지: LoRA 학습 → 병합(RAM 16GB, 필요하면 스왑) → GGUF 4비트 변환 → 데스크탑 Ollama 서빙 → 같은 프롬프트로 답이 나옴 | 단계별 걸린 시간·최대 메모리, 막힌 곳 |
| 3 | 프롬프트 단계 | 데스크탑 | 근거 줄을 먼저 옮기고 결론, 근거가 없으면 거절 + 문서의 문의처·확인처 안내, 답이 쓴 근거 번호 남기기. 문구는 실행 전에 고정해 보인다(옛 모델 선정 ① + 검색 개선 5단계를 합침) | A.X 전후 짝 비교, 채택 여부 |
| 4 | 학습 데이터 | 데스크탑 + AWS | 학습 몫 문서로 데이터셋용 색인(M1 9번) → 질문 초안(오픈 모델, ADR-0010) → 서비스 검색으로 근거 붙이기(3단계 프롬프트 형식) → 자동 검수 + 표본 검토 | 1회차용 200개 통과 |
| 5 | 학습 1회차(시험) | AWS → 데스크탑 | 200개로 LoRA, 개발셋 생성만 다시 돌려 전후 비교 | 틀린 답·답없음 거절 변화, 학습 시간 실측 |
| 6 | 학습 2회차(본) | AWS → 데스크탑 | 전체 학습 데이터로 LoRA | 전후 비교, 운영에 쓸지 결정(ADR-0033 결정 2) |
| 7 | 표 행 단위 색인 | 데스크탑 | 표 사실이 행 이름을 잃지 않게 색인 글을 바꾸고 재색인(검색 개선 설계 4단계) | 표 근거 문항 비교 |
| 8 | 학습 3회차(보강) | AWS → 데스크탑 | 남은 틀림 유형만 데이터를 더해 학습 | 전후 비교 |
| 9 | 운영 전환·테스트셋 | 데스크탑 | 고른 설정(재순위 켬/끔 포함)으로 운영값을 바꾸고 테스트셋 한 번 | ADR-0026 판정 → M2 끝 |

- 두 트랙은 나란히 간다: 데스크탑 0·1·3·7, AWS 2·4·5·6·8. 본 학습(6)은 프롬프트가 굳은(3) 뒤.
- 재순위(3단계, 기능은 꺼 둔 채 머지)는 1에서 A.X로 GPU에 함께 올라가는지 보고 켬·끔을 다시 잰다.
- 검증 호출(옛 모델 선정 ②)은 학습 뒤에도 틀린 답이 남을 때만 한다.

## 3. 학습 설계

| 항목 | 정한 것 | 근거 |
|---|---|---|
| 가르칠 것 | ① 근거로만 답하기(근거 줄 인용 → 결론) ② 근거가 없으면 거절 + 문서의 문의처·방법 안내 ③ 표의 행·열을 맞춰 값 읽기 | A.X 틀린 10건: 근거 없이 답함 3, 표 잘못 읽음 5, 글 잘못 읽음 2 [실측, 옛 모델 선정 계획 §3] |
| 예시 종류 | 근거 있는 질문(답) · 근거 없는 질문(거절 + 안내) · 엉뚱한 근거만 있는 질문(거절) · 표 질문 | ① ~ ③에 하나씩 대응 [판단] |
| 입력 형식 | 서비스와 같은 시스템 프롬프트 + 서비스 검색으로 붙인 근거 | ADR-0010 |
| 데이터 출처 | 학습 몫 문서만(평가 문서 제외) | ADR-0008·0010 |
| 초안 모델 | Apache 2.0·MIT 오픈 모델(A.X 자신 포함). EXAONE·Claude 출력은 쓰지 않음 | ADR-0010, `A.X-4.0-Light-사용권-조사-20261017.md` §3.4 |
| 방법 | LoRA(16비트 가중치에 LoRA, GPU가 모자라면 QLoRA) | [계산] 7B 16비트 LoRA 약 22GB, QLoRA 약 6GB (A10G 24GB) |
| 회차 | 1회차 시험(200개) → 2회차 본 → 3회차 보강 | 회차마다 전후 비교로 다음 회차의 데이터를 고친다 |
| 재는 것 | 오답률·답없음 거절(가장 엄함) → 정답률 → 과잉 거절 → 안내 충실도, 학습·병합 시간 | ADR-0026·0033 |
| 테스트셋 | 마지막(9)에 한 번만 | ADR-0018 |

## 4. 위험과 확인

| 위험 | 확인 | 시점 |
|---|---|---|
| 병합할 때 RAM 16GB 부족(16비트 약 14.5GB) | 스왑을 켜고 실측. 안 되면 병합 없이 LoRA를 GGUF로 바꿔 Ollama에 붙이는 길을 잰다 | 2 |
| 학습 뒤 답을 더 적극적으로 해 틀린 답 증가 | 근거 없는 예시(거절)를 일정 비율 넣고, 오답률을 첫 지표로 본다 | 5 |
| 학습 데이터 오류가 학습됨 | 자동 검수 + 표본 검토(ADR-0010). 사람 검토 범위는 4 전에 정한다 | 4 |
| 개발셋에 맞춘 학습 | 학습 데이터는 학습 몫 문서로만, 개발셋 문항을 데이터에 넣지 않음 | 4 |
| A.X의 최대 문맥 16,384토큰 | 근거 8개 프롬프트 최대 약 9,800토큰으로 여유. 근거를 늘리는 설계는 이 한도 안에서 | 1 |

## 5. 사용자가 할 일

- 데스크탑 켜기(1·3·7·9와 각 회차 평가).
- 학교 AWS 학습 서버 켜기와 접속 정보(2부터). 서버를 맥북에서 접속하는 설정은 아직 없다.
- 결정: 프롬프트 문구 확인(3 전), 학습 데이터 사람 검토 범위(4 전), 학습한 모델을 운영에 쓸지(6 뒤).
