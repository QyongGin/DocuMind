# 개발셋 실패 원인 분석 — 정답 근거는 어디서 사라지나 (M2 준비, 이슈 #129) — 2026-10-14

> M2 검색 개선을 시작하기 전에, 지금 챗봇이 틀리는 이유를 단계·장치 수준까지 수로 나눴다. 자료는 **개발셋만** 썼다(테스트셋 문항의 프롬프트·검색 기록은 열지 않음, ADR-0018).
> 자료: 베이스라인 실행 `20261012-baseline`(EXAONE 3.5 7.8B, AI 서버를 거침, 평가셋 v3로 다시 채점), 13번 모델 비교 실행(같은 프롬프트를 다른 모델에 넣은 것). 분석 스크립트는 로컬 `Assets/eval/work/m2/`(커밋 안 함).
> 관련: ADR-0026(목표 65%), ADR-0025(짝 비교), `docs/rag/m1/베이스라인-측정-20261012.md` §3, `docs/rag/m1/평가셋-v3-20261013.md`, 설계 문서 `docs/rag/m2/검색개선-설계-20261014.md`

## 1. 결론

1. **답변 정확도의 상한은 검색이 정한다.** 정답 근거 청크가 프롬프트에 **있으면** 모델 열 개(기준 EXAONE + 후보 아홉)가 70~84%를 맞혔고, **없으면** 45문항 중 1~2문항(2~4%)만 맞혔다. [실측]
2. **검색은 정답을 거의 다 찾는데, 그 뒤의 사람이 만든 규칙이 지운다.** 개발셋 본 문항(답 있는 것) 121개 중 검색 단계 후보에 정답 청크가 있는 문항이 119개(98%)인데, 최종 후보 5개에 남는 문항은 72개(60%)다. 사라진 47개는 표 값 질문 우선 거르기 19 · 질문 맞춤 근거 좁히기 12 · 상위 5개 자르기 16. [실측]
3. **같은 검색 결과를 규칙 없이 순위 융합(RRF, Reciprocal Rank Fusion)만 하면** 정답 청크가 상위 5개에 99개(82%), 상위 10개에 113개(93%) 들어간다(새로 들어오는 문항 +33, 잃는 문항 −6, 상위 5개 기준). [계산, 기록된 후보로 재연]
4. **표 사실(table fact)이 행을 잃는다.** 칸 하나짜리 표 사실이 프롬프트에 들어간 개발셋 48문항 중 19문항(40%)에서, 같은 표·같은 행 이름·같은 칸에 값이 여러 개라 어느 행의 값인지 알 수 없었다(해당 줄 97/191, 51%). 예: 장학금 표에서 '생활비' 행이 여러 개라 국민연금 장학금 금액 1.5를 다른 행과 구분하지 못하고, 모든 모델이 '5'(행 번호)를 금액으로 답함. [실측·코드]
5. 정답 근거가 문맥에 있었는데 **열 모델이 모두 틀린 8문항** 중 5문항이 표 근거 문항이고, 그중 2문항은 모델을 거치지 않는 우선 경로 답(표 사실 그대로 붙임)이었다. [실측]

6. **실험으로 확인했다(E1, §6).** 같은 EXAONE으로 규칙만 빼고 순위 융합 상위 5개를 쓰자 개발셋 본 문항 정답률 43.8% → 62.0%(p=0.0005), 오답률 8.1% → 2.0%, 과잉 거절 38.0% → 20.7%, 쉬운 문항 70.9% → 94.5%. 응답 시간은 줄었다(중앙 2.54 → 2.46초). [실측]

→ M2의 첫 작업은 모델이나 프롬프트가 아니라 **검색 뒤 규칙을 학습된 순위(융합 + 재순위)로 바꾸고, 표 사실을 행 단위로 다시 만드는 것**이다. 설계와 실험 계획은 `검색개선-설계-20261014.md`.

## 4. 규칙을 끄면 — 기록된 후보로 재연

같은 실행의 단계별 후보 목록(순서 포함)만으로 "이 단계를 쓰지 않으면 상위 k개에 정답 청크가 들어가나"를 셌다. 새 후보는 만들 수 없으므로 검색 단계 후보 안에서의 재배열만 본다. [계산]

| 바꾸기 | 상위 k | 정답 청크 포함 | 지금 대비 들어옴 | 지금 대비 빠짐 |
|---|---|---|---|---|
| 지금(규칙 전부) | 5 | 72 (60%) | — | — |
| 좁히기만 끔(규칙 재순위 순서) | 5 / 10 | 79 / 90 | +7 / +18 | 0 / 0 |
| 우선 거르기 전 합친 순서 | 5 / 10 | 81 / 112 | +20 / +40 | −11 / 0 |
| **표 사실·BM25·벡터 순위 융합(RRF, k=60)** | **5 / 10 / 20** | **99 / 113 / 118** | **+33 / +42 / +46** | **−6 / −1 / 0** |

- RRF 상위 5개에서 잃는 6문항 중 지금 맞히는 것은 4문항(우선 경로 1 포함)이다. 순 효과는 정답 청크 포함 +27문항. [계산]
- 1번 결론의 '문맥에 있으면 70~79% 맞힘'을 곱하면, 상위 5개 RRF로 개발셋 본 정답률이 약 44% → 약 60%, 상위 10개면 약 65~70% 근처가 기대치다. 문맥이 길어지면 모델이 근거를 덜 쓰는 효과(Liu 외, 2023)는 이 계산에 없다 → **실험으로 확인한다(§6).** [계산·판단]

## 5. 표 사실이 행을 잃는 문제

- 색인할 때 표의 칸 하나마다 문장 하나를 만든다: `{표 제목}: {행 이름} 행 정보는 {칸 이름}={값}이다.` (`_format_table_fact_index_text`, main.py:1777). 행 이름은 첫 칸(행 머리)이라, 병합 셀(예: 장학금 유형 '생활비')처럼 여러 행이 같은 이름을 가지면 **값이 어느 행 것인지 사라진다.** [코드]
- 개발셋 프롬프트에서 센 결과: 칸 하나짜리 표 사실이 들어간 48문항 중 19문항, 줄 191개 중 97개(51%)가 행을 가릴 수 없었다. 예(개발셋): ev-0011·ev-0042·ev-0043(장학금 표의 '생활비' 행), ev-0031(모집 인원 표), ev-0006(휴학 종류 표). [실측]
- 직접 피해: ev-0164(국민연금 장학금 학기당 금액) — 프롬프트에 금액 줄 `장학 금액=1.5`와 이름 줄 `장학금명=5. 국민연금`이 따로 있어, A.X 4.0 Light·Qwen3-8B·Gemma 4 E4B·EXAONE 모두 '5'라고 답했다. [실측]
- 고칠 방향: 행을 유일하게 가리는 머리 칸들(예: 유형 > 장학금명)을 행 이름으로 쓰거나, 한 행의 모든 칸을 한 문장(`머리글=값; …`)으로 만든다. 같은 코드에 행 전체 문장을 만드는 함수(`_build_row_summary_fact`, main.py:1026)가 이미 있어, 색인 형식을 바꾸는 범위로 고칠 수 있다(규칙이 아니라 구조 계약). [코드·판단]

## 6. 실험 E1: 규칙 없이 순위 융합(개발셋, EXAONE, 상위 5개)

**무엇을 바꿨나** [코드]: AI 서버에 평가 요청에서만 켜는 옵션 `retrieval_mode=rrf`를 더했다(브랜치 `exp/#129-rrf-retrieval`, 커밋 `661abc1`). 켜면 표 사실·BM25·벡터 결과를 RRF(k=60)로 한 줄로 세워 상위 5개를 쓰고, 우선 거르기·규칙 재순위·좁히기와 우선 경로 답을 쓰지 않는다. 생성 모델(EXAONE 3.5 7.8B)·온도 0·문맥 8,192·출력 512·시스템 프롬프트·색인은 베이스라인과 같다. 운영 요청(옵션 없음)은 지금 경로 그대로다(테스트 8개, 변이 확인 4/4).

| 본 과잉 거절 | 33.1% → **11.6%** | 31 / 5 · <0.0001 | 34.7% → **19.0%** | 26 / 7 · 0.0013 |
| 출처 정확도 | 67.8% → 90.9% | 2 / 30 · <0.0001 | 67.8% → 90.9% | 2 / 30 · <0.0001 |
| 쉬운 정답률 | 76.4% → **92.7%** | 2 / 11 · 0.02 | 80.0% → **100%** | 0 / 11 · 0.001 |

- 세 모델(EXAONE·A.X 4.0 Light·Gemma 4 12B) 모두 같은 방향으로 크게 좋아졌다 → 규칙을 빼고 순위 융합하는 효과는 생성 모델에 따라 달라지지 않는다. ADR-0032의 채택 기준(고른 모델로 같은 방향)을 채웠다. [실측]
- 두 모델 사이(같은 융합 프롬프트): 정답률 같은 수준(71.1% 대 74.4%, p=0.48), 오답 A.X 10 · Gemma 1(p=0.012), 과잉 거절 A.X 11.6% · Gemma 19.0%(p=0.012). ADR-0027 2단계에서 A.X 4.0 Light가 빠져 1순위가 Gemma 4 12B로 바뀌었다(ADR-0031, `docs/rag/m1/모델비교-20261014.md` §6). [실측]
- A.X 4.0 Light는 순위 융합 뒤 거절이 크게 줄었지만(33.1% → 11.6%), 문맥의 표 값을 잘못 읽은 틀림이 남았다(10건 중 9건 — 주차 요금·선발 인원·징계 양형 등). 표를 행 단위로 직렬화하는 4단계가 이 종류를 줄일 것으로 본다. [실측·판단]
- Gemma 4 12B 남은 실패(개발셋 본 121 중 맞음 아닌 31): 과잉 거절 23 · 일부 7 · 틀림 1. 거절이 대부분이라 다음 몫은 상위 k·재순위(근거를 더 넣기)와 답할지 판단 프롬프트(5단계)다. [실측]

## 8. 한계

- 반사실 재연은 기록된 후보 안에서만 순서를 바꾼다. 실제로 규칙을 끄면 우선 경로 답이 사라지고 프롬프트도 바뀌므로, 정답률은 실험(§6)으로 잰다.
