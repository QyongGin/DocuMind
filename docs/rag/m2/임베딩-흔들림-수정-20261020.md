# M2 1단계 — 질문 임베딩 흔들림 고치기 (2026-10-20)

> 계획: `A.X-기준-계획-20261017.md` §4 1단계(끝난 기준: 같은 설정 재실행끼리 벡터 검색 결과 205 / 205 같음).
> 처음 발견: `1단계-규칙코드-삭제-20261016.md` §5(디버그 추적과 `/query`의 첫 호출만 질문 벡터가 다름, 같은 설정 재실행에서 벡터 검색 결과가 다른 문항 3 / 205).
> 측정 자료는 데스크탑에서 개발셋 질문으로 쟀다. 스크립트(로컬, 커밋 안 함): `Assets/eval/work/m2/emb_*.py`, `verify_trace.py`.

## 1. 결론

1. **원인은 '첫 계산'이 아니라 Ollama 입력 캐시다.** 바로 앞 요청과 같은 글이거나 앞부분이 겹치는 글을 받으면, Ollama가 앞 계산을 다시 써서 벡터가 조금 달라진다(같은 질문을 바로 다시 보내면 cos 거리 0.00034). 새로 계산한 벡터는 앞 요청·순서·Ollama 재시작·생성 모델 동시 적재와 무관하게 같았다. [실측]
2. **고친 방법**: 질문을 임베딩하기 직전에, 직전 글을 모르거나 직전 글과 첫 글자가 같으면 짧은 글 하나로 캐시를 비운다. AI 서버가 임베딩 요청을 한 줄로 세워 직전 글을 기억한다. [코드]
3. **결과**: 데스크탑의 실제 AI 서버로 개발셋 205문항을 순서대로·거꾸로·같은 질문 두 번씩 물었더니 질문 벡터와 벡터 검색 후보(청크 id·거리)가 205 / 205 같았다. 같은 조건에서 옛 방식(같은 질문을 바로 다시 임베딩)은 205 / 205 벡터가 달랐다. 계획 1단계의 끝난 기준을 채웠다. [실측]

## 2. 원인 실측 [실측]

데스크탑, Ollama 0.30.7, `qwen3-embedding:4b`(Q4_K_M), 임베딩 문맥 2,048. Ollama 캐시 칸은 1개(`n_seq_max = 1`).

합성 질문(가나대학) 하나를 앞 요청을 바꿔 가며 임베딩했다. 기준은 겹치지 않는 글 뒤에서 계산한 벡터다.

| 앞 요청 | 기준과 차이 |
|---|---|
| 서버를 막 띄운 뒤 첫 계산 | 없음 |
| 겹치지 않는 글 | 없음(기준) |
| 앞부분 낱말이 같은 다른 질문(가나대학 2027학년도 …) | 없음 |
| 한 요청에 다른 글과 함께 | 없음 |
| **같은 질문(바로 다시)** | **cos 거리 0.00034, 값 최대 차 0.0017** |
| 같은 질문 세 번째 | 두 번째와 같음 |

개발셋 답 있는 177문항을 조건을 바꿔 임베딩했다(기준: 순서대로 한 번).

| 조건 | 완전히 같은 질문 |
|---|---|
| 같은 순서로 한 번 더 | 177 / 177 |
| 생성 모델(Gemma 4 12B)을 함께 올린 뒤 | 177 / 177 |
| Ollama 재시작 뒤 | 177 / 177 |
| **거꾸로** | **175 / 177** |

- 거꾸로에서 달라진 2문항: 하나는 바로 앞 요청이 같은 질문이었고(앞 측정의 마지막 질문 = 거꾸로의 첫 질문), 하나는 바로 앞 질문과 첫 낱말이 같았다("휴학은 …" 뒤의 "휴학은 …"). 앞부분이 겹치면 늘 달라지는 것은 아니지만(위 합성 질문은 같았다), 달라질 수 있다.
- 평가 실행기는 질문마다 한 번, 같은 순서로 묻는다. 그래서 같은 순서의 재실행은 대부분 같지만, 실행 첫 질문(앞 요청이 그때그때 다름), 실패한 문항을 이어 묻기, 디버그 추적 뒤의 같은 질문에서 흔들린다. 운영에서는 다른 사용자의 질문이 앞 요청이 된다.

## 4. 바꾼 것 [코드]

- `ai-server/main.py`
  - `_embed_query(question)`: 질문 하나를 임베딩한다. 임베딩 요청을 잠금(`_embedding_lock`)으로 한 줄로 세우고, 직전에 보낸 글(`_last_embedded_text`)을 모르거나 첫 글자가 같으면 짧은 글(`∎`, 질문이 이 글자로 시작하면 `∴`)을 먼저 보내 캐시를 비운다. 운영 질의(`_prepare_query`)와 디버그 추적(`_trace_query_retrieval`)이 이 함수를 쓴다.
  - `_embed_texts(texts)`: 색인용 그대로. 같은 잠금 안에서 부르고, 여러 글을 한 번에 보내면 Ollama가 마지막에 계산한 글을 알 수 없으므로 직전 글을 '모름'으로 둔다.
- `ai-server/tests/test_query_embedding_cache_reset.py`(가나대학 합성 질문): 첫 질문은 비운 뒤 질문 벡터를 돌려줌, 같은 질문 반복은 비움, 첫 글자가 다르면 안 비움, 첫 글자가 같으면 비움, 여러 글 임베딩 뒤에는 비움, 비우는 글이 질문과 첫 글자가 겹치지 않음.

## 6. 한계와 다시 볼 조건

- '첫 글자가 다르면 캐시를 다시 쓰지 않는다'는 토큰 구조에서 나온 판단이고, 개발셋 177문항을 두 순서로 잰 결과와 맞는다. Ollama 판이 바뀌면 캐시 동작이 바뀔 수 있어, 판을 올릴 때 §2의 측정을 다시 한다.
- 직전 글은 AI 서버 프로세스 안에서만 안다. 지금은 AI 서버 하나(uvicorn 프로세스 1개)만 임베딩 모델을 부른다. 프로세스를 늘리거나 다른 서비스가 같은 Ollama로 임베딩하면 다시 본다.
- 이 수정 전 실행과 프롬프트를 비교할 때는 벡터 검색 결과가 다른 문항부터 가른다.
