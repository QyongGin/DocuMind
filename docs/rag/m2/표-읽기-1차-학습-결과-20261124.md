# 표 읽기 1차 학습 결과 (2026-11-24)

> 상태: 끝남. 9, 10절의 남은 문제와 다음 할 일은 덧붙임 절과 [2차 학습 결과](표-읽기-2차-학습-결과-20261124.md)에서 다뤘다.

**결론: 범례 읽기는 학습으로 크게 늘었지만(범례 검증 몫 36/64 → 60/64), 표 질문 목표 4개와 과잉 거절은 모두 목표에 못 미쳤다. 개발셋 정답은 지켰다(94 → 89, p=0.40). 가장 큰 부작용은 실제 검색 조건에서 표 질문을 거절하는 버릇이다(두 번 모두 거절 2 → 13문항).** [실측]

- 지금 위치: M2 표 근거 문제, 표 읽기 학습의 1차 학습(시험 학습 1·2 다음). 학습 서버(AWS g5.xlarge)에서 학습하고 데스크탑 Ollama로 쟀다.
- 결과 파일(로컬 자료, 커밋 안 함): `train/table-trial3/eval-desktop/`(조건표 `summary.json`, 목표 `목표별-현재값.json`, 개발셋 `dev_summary.json`, 따로 센 것 `extra.json`, 코드 채점 `score/score3_t3.json`·`score/score_t3.json`), 학습 기록 로컬 자료 `train/table-trial3/aws/t3/run_manifest.json`.
- 근거 표시: [실측] 결과 파일에서 읽은 값, [계산] 그 값으로 계산, [판단] 해석.

## 1. 문제와 목표

문제: 표 질문 43문항 중 학습 전 모델(A.X 4.0 Light)이 정답 표만 받고도 17문항만 맞힌다. 원인은 범례(♣, ◈ 같은 기호의 뜻이 표 밖에 있음), 주석(※ 줄), 해 고르기(「작년」을 맞는 해의 표로 푸는 것), 여러 줄 머리글이다(목표와 데이터를 정한 경위는 11절).

목표별 달성 [실측, 판정 = 격리 Opus, 「두 번 모두 맞음」만 맞음으로 셈]:

| 목표 | 재는 것 | 학습 전 | 시험 학습 2 | 1차 학습 | 목표 | 달성 |
|---|---|---:|---:|---:|---:|---|
| 표와 범례 읽기 | 범례 9문항(①) | 2 | 3 | 5 | ≥6 | 못 미침 |
| | 표 질문 43문항(①) | 17 | 17 | 20 | ≥25 | 못 미침 |
| 근거 속 주석 적용 | 주석 4문항(①) | 3 | 2 | 2 | ≥3 | 못 미침 |
| 맞는 해의 표 고르기 | 「작년」 5문항(⑤) | 0 | 2 | 0 | ≥3 | 못 미침 |
| 지킬 것 | 개발셋 정답(121) | 94 | 71 | 89 (p=0.40) | 통계로 낮지 않음 | 지킴 |
| | 개발셋 과잉 거절 | 3 | 24 | 8 | ≤6 | 못 미침 |

- 조건 이름: ① 정답 표만 준 프롬프트, ⑥가 정답 표를 다른 모양(줄글)으로 바꾼 것, ③ 정답 청크를 조립한 것, ⑤ 실제 검색 결과. 표 질문 문항은 로컬 자료 `eval/table_qset/table_qset_pick_measure.jsonl`.
- 학습 전 개발셋 정답은 어젯밤 93이었다. 오늘 1차 학습과 갈린 문항을 두 답 나란히 다시 판정하면서 학습 전 답 2개의 판정이 바뀌어(ev-0012 틀림→맞음, ev-0087 맞음→틀림) 94가 됐다 [실측]. 「뒤 판정이 이김」 규칙대로 94로 비교한다.
- 묶음 3 검증 몫은 학습 전이 이미 94%라 +20%p를 낼 자리가 없었다 [계산]. 계획 때 87개(82 맞음)였던 몫은 17:11 재검수 뒤 84개가 남았다.

## 2. 학습 데이터

출처: 로컬 자료 `train/table-trial3/out-final/조립-요약.md`, `report.json` [실측].

- 학습 3,137개, 검증 296개. 조립 검사 16가지 모두 0(입출력, id·표·문서 겹침, 평가 문서·평가 질문, 날짜, 토큰 상한, 안내 붙임).
- 종류(학습): 여러 행 모으기 1,000, 한 칸 값 727, 범례 405(변환 가 245, 나 160), 가장 큰·작은 값 149, 연도 116(직접 91, 상대 21, 답없음 4), 표 답없음 77, 주석 43(적용 7, 안 걸림 36), 기호 칸 읽기 7, 표가 아닌 예시 613(사실 238, 절차 168, 여러 근거 108, 답없음 72, 일부만 27).
- 만든 방법: 질문 초안은 데스크탑 Gemma, 답 값과 짚는 줄(「확인한 행:」 목록)은 코드가 표에서 계산, Opus는 검수만 했다. Claude 출력은 학습 파일에 넣지 않았다.
- 범례 변환: 실제 표의 글 열을 코드로 기호 열(♣ 등)과 표 아래 범례 줄로 바꿨다. 학습 전 모델이 범례 변환 검증 몫 40개 중 25(63%)만 맞혀 어려운 부분을 겨냥한다고 보고 계속 만들었다.
- 버린 것, 주석 변환: 첫 설계는 질문과 무관한 주석을 결론에 붙이는 버릇 위험이 있었다. 고친 설계는 학습 전 모델이 적용 13/13을 이미 맞혀 배울 것이 없었다. 그래서 실제 주석 예시(적용 7)만 썼다 [실측].
- 표가 아닌 예시 613개(20%): 표만 학습하면 표가 아닌 질문에도 짚는 줄을 쓰는 버릇(시험 학습 2에서 104문항 중 62)을 막으려고 섞었다.
- 안내 65개: 학교 표 예시 65개(학습 55, 검증 10)에만 결론 뒤에 안내 문장(방법, 기한, 문의처, 사이트)을 붙였다. 690개 중 599개는 근거에 안내가 없었다.
- 입력 틀: 측정 프롬프트와 같게 첫 줄 학년도 학기, 「지금 모집 중인 입시」·「직전 입시」 두 줄, 근거 블록 「학년도:」 줄을 변환기로 넣었다. 「오늘」이 근거 게시일보다 앞선 132개는 날짜를 옮겼다.
- 뺀 것: 묶음 2 검수 탈락 233, 검증 표와 같은 표를 쓴 학습 예시 24, 6회차 표가 아닌 후보 55, 순천향 편입학 검증 5(학습 쪽을 살림).
- 검수: 학교 표 한 칸 값 327개 검수에 215 통과(66%), 검수 대조 30개 중 검수 오류 3(10%). 범례 검수 대조 45개 중 검수 오류 2(4%) [실측].
- 학습 전 모델로 잰 난이도: 범례 검증 36/64(56%), 묶음 3 검증 79/84(94%) [실측, 오늘 같은 채점기로 다시 셈].
- 출처: 위키 57.7%, 학교 42.3%(검증 57.1 / 42.9). 앞선 판 보고의 위키 66%는 셈 버그였다(파일은 그대로) [실측].
- 답 토큰 중앙 88, 최대 398. 예시 토큰 중앙 2,601, 최대 8,041. 학습 총 9.12M토큰 [실측].

## 3. 학습 방법

- 설정: 시험 학습 2와 같다. LoRA r16 α32 dropout 0.05, NF4, 최대 8,192토큰, 배치 1 × 누적 8, 2회, cosine, warmup 5%, seed 42, lr 1e-4(로컬 자료 `train/table-trial3/학습-설정-점검.md`, `run3.sh`).
- 2회를 고른 근거 [실측, 지난 다섯 학습 기록]: 1회당 걸음 수가 많을수록 2회째 검증 손실 변화가 작았다(19걸음 −27%, 23걸음 −9%, 38걸음 −11%, 77걸음 −3%, 102걸음 −2%). 이번은 1회 393걸음이라 2회째 이득이 작거나 다시 오를 수 있어, 150걸음마다 저장해 손실 최소 지점을 쓰기로 했다 [판단].
- 실제 시간 [실측, `aws/t3/run3.log`]: 본 학습 시작 23:08:44, 학습 끝 05:10:35, 합치기·변환 끝 05:23:23. 학습 21,220초(5.9시간, 검증 6번 포함), 최대 GPU 메모리 8.99GiB.
- 속도 [계산]: 검증 1번 약 310초를 빼면 걸음당 24.6초, 약 942토큰/초. 계획(946토큰/초, 6.1시간)과 맞았다.

## 덧붙임: 실제 검색 거절 13문항의 원인 확인 (2026-11-24 오전, 판정 호출 없음)

**1. 정답 값이 입력에 없는 문항은 43문항 중 9문항이다(학습과 무관).** (같은 날 낮에 바로잡음: 처음에는 청크 번호로만 견줘 「정답 청크가 빠진 것 25문항」이라고 적었다. 실제 검색 입력은 표 조각 하나가 오면 같은 표 전체와 기호 주석을 붙이는 조립(R2, 상한 4,000자)을 거치므로 청크 번호로 세면 과하게 잡힌다. 11-21 측정의 `cells_check.json`(정답 값과 행·열 이름이 프롬프트에 있나)으로 다시 셌다.) 정답 값이 없는 9문항은 tq-0001, 0005, 0010, 0024, 0026, 0033, 0036, 0041, 0047이고, 11-18 추적(`diag-20261118/trace.jsonl`)에서 아홉 모두 정답 인용이 색인과 검색 후보에 있었다. 재순위에서 9번째 밖으로 밀리거나(0005, 0010, 0033, 0036), 다른 해 표가 대신 오거나(0024, 0026), 최종 8개에 들고도 발췌에서 행이 빠졌다(0041, 0047). 문항이 잘못 만들어진 것은 아니다(같은 정답 표를 주면 Opus 43/43). 거절 13문항 중 정답 값이 없던 것은 4문항(0005, 0010, 0033, 0036), 값이 있던 것은 9문항이다. 값이 있던 34문항에서 거절은 학습 전 1 → 학습 뒤 9다. 같은 청크의 내용이 ③과 다른 13문항 중 12문항은 원본 표 줄이 같고 붙은 표 사실 줄 수만 달랐다. 원본 표 행까지 빠진 것은 아래 tq-0018 하나다. 예: tq-0018은 정답 청크가 출처 1로 왔지만 1,006자가 587자로 줄면서 원본 표 행이 빠지고, 표 사실 줄에는 합친 칸(6~9등급)이 「6등급=가산점 없음」으로만 남아 7등급 값이 없다.
