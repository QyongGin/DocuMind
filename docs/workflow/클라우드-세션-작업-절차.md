# 클라우드 세션 작업 절차

> Claude Code 클라우드 세션(claude.ai/code, 데스크탑 앱의 Cloud, 휴대폰 Code 탭, `claude --cloud`)에서 DocuMind 작업을 이어 갈 때의 절차다. 규칙은 로컬과 같고(루트 `AGENTS.md`), 쓸 수 있는 자료와 장비만 다르다.
> 근거: Claude Code 공식 문서 "Use Claude Code in the cloud", "Get started with Claude Code in the cloud", "Configure cloud environments", "Settings files and precedence"(2026-10-07 원문 확인).

## 1. 클라우드 세션이 보는 것

클라우드 세션은 Anthropic이 관리하는 VM(Ubuntu 24.04)에서 GitHub 저장소를 새로 클론해 시작한다. 커밋된 것만 보인다.

| 자료 | 클라우드 세션 | 이유 |
|---|---|---|
| 코드, `AGENTS.md`(`CLAUDE.md`), `docs/` 현재 문서(현재 상태·ADR 포함) | 있음 | 커밋돼 있음(2026-10-07~) |
| `docs/archive/`(지난 기록, 옛 memory-bank 포함) | 없음 | 커밋하지 않음. 필요하면 로컬 세션에서 본다 |
| `docs/local/`(접속 정보·개인 문서) | 없음 | 커밋하지 않음 |
| `Assets/`(문서 대장·원본·평가셋·백업) | 없음 | 학교 데이터는 공개 저장소에 올리지 않음 |
| 사용자 메모리(`~/.claude/projects/.../memory/`), `~/.claude/settings.json` | 없음 | 맥북에만 있음. 작업 규칙은 `AGENTS.md` §4로 옮겨 둠 |
| 데스크탑(Tailscale 주소) | 없음 | 네트워크가 허용 목록(Trusted) 밖은 막힘 |
| `claude` CLI | 기본 설치 목록에 없음 | `evalset cross`·`fence`(내부에서 `claude -p` 실행)는 맥북 사용자 터미널에서 |

## 2. 시작하기

1. claude.ai/code를 연다(데스크탑 앱이면 새 세션에서 **Cloud** 선택).
2. 저장소 선택에서 `QyongGin/DocuMind`를 고르고 브랜치를 **`develop`**으로 바꾼다. 기본 브랜치 `main`은 릴리스 때만 갱신되어 최신 작업이 없다.
3. 환경은 **Default**(네트워크 Trusted) 그대로 쓴다. PyPI·npm·Maven 같은 패키지 저장소에 접근된다.
4. 권한 모드는 Auto 또는 Plan을 고른다(클라우드에는 Manual이 없다).
5. 첫 메시지 예: `AGENTS.md 순서대로 읽고 현재 상태를 한 줄로 보고해. 그다음 <할 일>.`

맥북 터미널에서 바로 보낼 때는 저장소 폴더에서 아래처럼 한다. 현재 브랜치를 GitHub에서 클론하므로 먼저 push한다.

```bash
claude --cloud "AGENTS.md 순서대로 읽고 현재 상태를 보고한 뒤 <할 일>"
```

## 3. 클라우드에서 할 일과 맥북에서 할 일

| 작업 | 어디서 | 이유 |
|---|---|---|
| 코드 작성·리팩터링, 합성 데이터(가나대학) 테스트, PR 만들기 | 클라우드 가능 | 저장소와 테스트만 있으면 됨 |
| 설계 문서·보고서·ADR·현재 상태 문서 정리 | 클라우드 가능 | 현재 문서가 커밋돼 있음 |
| 평가셋 문항 작성, 문서 대장 조회, `corpus upload`·`evalset export-index` | 맥북 | `Assets/` 학교 데이터와 데스크탑이 필요 |
| `evalset cross`·`evalset fence` | 맥북 사용자 터미널 | `claude -p`와 로그인이 필요 |
| 색인·평가 실행, 모델 비교, GPU 측정 | 데스크탑(맥북에서 SSH) | 데스크탑 GPU 스택 |

## 4. 테스트 실행 (클라우드 VM)

| 모듈 | 명령 | 클라우드 확인 |
|---|---|---|
| `tools/corpus` | `cd tools/corpus && python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt && .venv/bin/python -m pytest -q` | 아직 안 함 |
| `ai-server` | `cd ai-server && python3 -m venv venv && venv/bin/pip install -r requirements.txt -r requirements-dev.txt && venv/bin/python -m pytest -q` | 아직 안 함 |
| `backend` | `cd backend && ./gradlew test` | 아직 안 함 |

첫 클라우드 세션에서 돌려 보고 "클라우드 확인" 칸을 고친다. 설치가 5분을 넘기면 환경 설정의 setup script로 옮길지 검토한다.

## 5. 커밋 전 공개 검사

이 저장소는 공개다. 커밋하기 전에 올라갈 파일에 아래가 없는지 본다.

```bash
git diff --cached --name-only
git diff --cached | grep -nE "100\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}|PASSWORD=|ghp_[A-Za-z0-9]{20}|sk-[A-Za-z0-9]{20}"
```

- 두 번째 명령은 출력이 없어야 한다(이 문서를 고친 커밋이면 이 검사 줄 자체가 한 번 걸린다). Tailscale 주소는 `<WSL IP>`·`<Windows IP>` 같은 자리표시로 쓰고 실제 값은 로컬 `docs/local/접속정보.md`에 둔다.
- 학교 문서 원문을 길게 옮기지 않는다(근거는 대장 ID와 짧은 인용으로).
- 개인정보(이름·연락처)를 쓰지 않는다.

## 6. 끝내기와 넘기기

1. 작업 브랜치를 push하고 `docs/workflow/PR-작성-및-머지-절차.md`대로 PR을 만든다. 초안을 사용자에게 먼저 보인다.
2. 같은 PR에 `docs/project/현재-상태.md`를 갱신하고, 결정이 있었으면 ADR을 함께 넣는다. 이슈의 Projects 상태를 옮긴다.
3. 로컬 세션과 클라우드 세션이 동시에 현재 상태 문서를 고치지 않는다. 한쪽 PR이 develop에 머지된 뒤 다른 쪽은 `git pull origin develop`부터 한다.
4. 클라우드 세션을 맥북으로 가져올 때는 저장소 폴더에서 `claude --teleport`를 쓴다(같은 claude.ai 계정, 작업 트리가 깨끗해야 함).
