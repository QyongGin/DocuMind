DocuMind #73 RAG 개선 설명

표 값은 찾았는데,
왜 AI 답변은 “없다”고 했을까?

이번 문제는 “검색 실패”가 아닙니다. 서버는 표 안의 금액을 찾았고, 그 값을 AI에게도 넘겼습니다. 그런데 마지막 답변 작성 단계에서 모델이 그 값을 제대로 쓰지 못했습니다.

한 줄 결론

검색은 성공 원서 접수 비용 표를 찾았고, 30,000원과 50,000원도 구조화해서 뽑았습니다.
근거 전달도 성공 `/debug/rag-trace`의 `final_context` 안에 표 값 근거가 실제로 들어갔습니다.
답변 작성은 실패 AI가 근거를 보고도 “구체적인 금액이 없다”고 잘못 답했습니다.

현재 흐름을 쉽게 보면

1

문서에서 표를 찾음

모집요강 안의 “전형료 및 면접고사료” 표를 찾았습니다.

2

표 값을 쪼갬

행, 열, 값을 따로 뽑았습니다. 예를 들면 “면접학과 / 계 / 50,000원”입니다.

3

AI에게 근거를 넘김

근거는 들어갔지만, 원문과 설명이 같이 길게 섞여 있습니다.

4

AI가 답변을 잘못 씀

중요한 금액 값을 놓치고 “명시되어 있지 않다”고 답했습니다.

우리가 실제로 확인한 근거

GCP에서 `final_context`를 확인했을 때, AI에게 넘어간 내용 맨 앞쪽에 아래 값이 있었습니다.

구조화 표 값 근거: - 표 제목: 1. 전형료 및 면접고사료 / 행: 비면접학과 / 열: 전형료 / 값: 30,000원 - 표 제목: 1. 전형료 및 면접고사료 / 행: 비면접학과 / 열: 계 / 값: 30,000원 - 표 제목: 1. 전형료 및 면접고사료 / 행: 면접학과 / 열: 전형료 / 값: 30,000원 - 표 제목: 1. 전형료 및 면접고사료 / 행: 면접학과 / 열: 면접고사료 / 값: 20,000원 - 표 제목: 1. 전형료 및 면접고사료 / 행: 면접학과 / 열: 계 / 값: 50,000원

그래서 지금 실패 원인은 “표를 못 찾음”이 아니라 “찾은 표 값을 답변에 제대로 반영하지 못함”입니다.

그럼 왜 답변이 틀렸나?

문제

중요한 값이 다른 글 속에 묻힘

AI에게 주는 입력 안에는 표 값, 원문 발췌, 표 설명, 섹션 정보가 한꺼번에 들어갑니다. 모델은 그중 무엇을 가장 먼저 믿어야 하는지 헷갈릴 수 있습니다.

문제

이상한 섹션 이름이 섞임

`섹션: 147,000㎡` 같은 값이 아직 prompt 쪽에 남아 있습니다. 사용자 출처에서는 제거했지만, AI에게 주는 내부 글에는 일부 남아 있어 혼란을 줄 수 있습니다.

문제

모델 입력 방식도 확인 필요

EXAONE 같은 채팅형 모델은 보통 “시스템 지시”와 “사용자 질문”을 나눠 주는 방식이 더 안정적입니다. 현재 코드가 평문 하나로 길게 넘기는지, 채팅 형식으로 넘기는지 확인해야 합니다.

문제 아님

출처 표시 문제는 아님

화면의 출처에는 이미 전형료 표가 잘 보입니다. 따라서 지금 고칠 곳은 출처 카드가 아니라 AI 답변 생성 단계입니다.

하면 안 되는 해결책

  • `원서 접수 비용`이라는 질문만 따로 조건문으로 처리하면 안 됩니다.
  • `전형료`, `면접고사료` 같은 특정 문서의 단어를 계속 코드에 추가하면 유지보수가 어려워집니다.
  • 서버가 항상 “비면접학과는 30,000원” 같은 고정 문장을 직접 만들면 다른 문서에서 깨질 수 있습니다.
  • 문서를 다시 업로드하거나 DB를 지우는 방식으로만 해결하면 원인을 못 고칩니다.

해야 하는 해결책

핵심은 특정 질문을 맞히는 것이 아니라, “표에서 뽑은 값은 답변에 반드시 반영해야 하는 근거”라는 규칙을 일반화하는 것입니다.
  1. AI에게 실제로 어떤 형태로 입력되는지 확인합니다. 평문 한 덩어리인지, 채팅형 메시지인지, Ollama의 EXAONE 템플릿이 적용되는지 봐야 합니다.
  2. 표 값 근거를 더 눈에 띄는 위치로 올립니다. “반드시 답변에 반영할 표 값” 영역을 일반 규칙으로 만들고, 표 제목, 행, 열, 값을 짧게 정리합니다.
  3. 이상한 섹션 이름을 prompt에서도 제거합니다. 사용자 출처에서만 `147,000㎡`를 숨기는 것이 아니라, AI에게 주는 내부 문맥에서도 같은 필터를 적용합니다.
  4. 웹사이트와 ai-server를 따로 검증합니다. ai-server `/query`가 맞는데 웹사이트만 틀리면 backend 연결 문제이고, 둘 다 틀리면 prompt 또는 모델 입력 방식 문제입니다.

어려운 말 정리

RAG AI가 그냥 기억으로 답하지 않고, 문서에서 찾은 근거를 보고 답하게 하는 방식입니다.
SourceBlock 사용자에게 보여줄 원문 조각입니다. 검색용으로 꾸민 글이 아니라 실제 문서에 가까운 글입니다.
RetrievalChunk 검색이 잘 되도록 만든 조각입니다. 제목이나 문맥을 붙일 수 있지만, 사용자에게 원문처럼 보여주면 안 됩니다.
TableFact 표를 “행 / 열 / 값”으로 풀어낸 정보입니다. 예: 면접학과 / 계 / 50,000원.
Prompt AI에게 답변하라고 넘기는 입력문입니다. 질문, 규칙, 찾은 근거가 같이 들어갑니다.
EXAONE 현재 답변을 만드는 언어 모델입니다. 좋은 근거가 들어가도 입력 형식이 약하면 중요한 값을 놓칠 수 있습니다.

이번 상태를 사람 말로 바꾸면

DocuMind는 이제 문서 안의 표를 찾아서 “비면접학과는 30,000원, 면접학과는 총 50,000원”이라는 값까지 뽑을 수 있습니다. 하지만 그 값을 AI가 답변에서 반드시 쓰도록 만드는 마지막 전달 방식이 아직 약합니다. 다음 작업은 검색을 더 고치는 것이 아니라, 찾은 표 값을 AI가 놓치지 않도록 입력 형식을 정리하는 것입니다.

다음 작업 한 문장

EXAONE에 넘기는 입력을 점검하고, 구조화된 표 값을 “반드시 답변에 반영할 근거”로 분리해서 전달하도록 바꾼다.
